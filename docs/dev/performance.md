# 缓存、性能与测速

缓存与性能设计、各步耗时、测速与对照的做法（从开发说明搬来，第四十一轮）。改代码不能变慢：`node tools/bench-median.mjs 5 --against <提交>` 比，超过 +5% 要压回去。

## 缓存与性能设计

结果全部逐值不变（见“测试”）；每一项提速都有自己的“新旧算法逐位相同”测试。

- **撤销缓存**：最近几步的完整推导结果都存着（地区 8 步、星球 6 步，相同的数组几步共用，合计不超过 200 MB），撤销、重做直接换回；更早的从那一步影响到的那一层重算。
- **内容共用**（第四十七轮，`core/small-copy.ts`）：`small.content` 不可变，撤销记录、比较、预览的克隆按引用共用，快照、预览的回复里内容没换时不发（`src/content-post.ts`）；每步的撤销记录只留不是内容的那段 JSON。量到的数见 [第47轮](history/第47轮.md)。
- **按内容缓存**：气候里和地形有关的那部分（风、水汽输送图、洋流）、汇流，地形没变就不重算；星球气候分层缓存（只取决于纬度的、只取决于海陆的各留两份）；地物识别按地形缓存，只改气候时不重找陆块、海、山脉。
- **只算变了的**：重画一片只重算圈里的格；高程按陆块复用（没改过的陆块原样留着）；离海岸、离河的距离场从上一份改起；省份只修补变了陆海的格、起名线性；生态脚本按格记住结果，只重算输入变了的格；生成器的采样按网格缓存。
- **内核**：噪声内核去掉闭包，高程的噪声因子按网格缓存；汇流路由（`core/routing.ts`，Priority-Flood 填洼后按最陡下降，结果无环）的缓冲区在迭代间复用；约束求解试算不分配对象；类型化数组的堆（`core/heap.ts`，优先级相同时先进先出，平地上的顺序可复现）。
- **画面**：平移、缩放时半分辨率画、挪用带边距（0.35）的场景，渲染器的场景、叠加层的河、地名在同一帧重建（`motionEpoch`），停下 250 毫秒补全分辨率并分两帧做（这一帧地图、下一帧叠加层）；移动中海岸线按场景放大的倍数淡一些、颜色按同一个场景像素取，省界、轮廓按画面像素补偿，深浅与停稳时一样；缩小到一格不到 6 像素时河沿中线分档缓存（Path2D 每加一个点约一微秒），放大后只加看得见的河；着色器不算看不见的细节；河的图层（overlay.ts 的 `riverLayer`，停稳与移动中各一张）画成一张离屏画布，渲染器上传成纹理、在合成着色器里按每像素的陆海混进去（只在陆地上，排在省界、高亮之前；`version` 变了才上传，导出每块另画 `riverLayerTile`）；省份着色、省界、高亮取格用合成着色器的 `provCell`，与 core/display.ts 的 `provinceCell` 同一条规则（水面像素只取水面格；陆地像素取到水面格时改取 `PROVINCE_LAND_RING` 上第一个陆地格，再没有时取 `island-types.ts` 的 `landProvinceCells` 表——每个水面格、小礁离它最近的陆地省的格，CPU 上沿网格一圈圈找，上传成 `uLandCell` 纹理；导出 `subcell.ts` 的 `rasterizeWorld` 用同一张表）；高程纹理两个通道（`packElevation`：高程与 colors.ts 的 `shoreElevation`——陆地格上是挨着的水面里最浅的高程），水下的水深、浅水只按第二个通道插值；改完后的闪烁不每帧重画整张图；编号层用不读纹理的顶点着色器；MapView 不在每帧查 DOM。
- **叠加层**（第四十轮，见“叠加层与排版提速”）：鼠标在同一格里动、工具的预览键（`moveKey`）没变时不重画；叠加层分底下、图形、上面三段，静态的键（世界、镜头、画布、除图形以外的选项……）与图形都没变时什么都不画；排地名按格子查避让（`BoxIndex`）、只在量字时设字体，悬停的地名只在排版用得上它时进键，转球的一次手势里沿用版面、只重新投影；片区名的几何与字分开缓存，第一次要时空闲时算；风、洋流的块最多留 384 块，新的一档空闲时算；国家的档案不按国家重建，中文排序用同一个 `Intl.Collator`、按国家的对象缓存，附庸按“宗主 → 附庸”的表，列表的旗按旗的对象缓存、行不变不重画。
- **投影（整个星球的等面积、球形）**：镜头的 x、y 在投影平面上（`projection.ts`，等距圆柱时镜头上没有 `proj`，走原来的路，逐像素不变）。编号层、地形层、切线层照旧画成等距圆柱的一块“场景”（`sceneNeed` 按画面上 25 × 25 个点反算出要的范围与东西、南北两个方向的密度，密度按 2^¼ 取整，受纹理边长与像素总数所限）；合成着色器（`FS_COMPOSE_PROJ`，由星球的合成着色器替换出来）每个像素按投影反算回世界坐标再到场景上取，省界、轮廓看的相邻像素、0.6/1.2 格的圆圈都在世界坐标上，一格合几个像素按这个像素自己的比例。看得见整个半球、或者看得见极点时场景是整圈经度（转动球只重新合成，每帧约 3 ms）；放大后只画看得见的一块，现在的场景还盖得住、密度够（移动中五折、停稳九折以上、不密过 2.2 倍）就照用。球形看着极地（纬度 20° 以上、画面上有离极点 30° 以内的地方）时场景改成以极点为中心的等距方位投影，用球面上真正的三角形与 Voronoi（`polarGeometry`，只取离那一极 0.95 以内的），格的坡度在顶点换到那个平面上的方向再插值——等距圆柱的显示三角网在极点附近横跨很宽的经度，投影到球上会成放射状的条纹。河的图层画在场景那一块上（`riverLayerScene`，极地的场景逐点换算），合成时按场景上的位置取。叠加层另画（`overlay-proj.ts`：点按投影算，线沿大圆加密后逐点投影，球的背面、等面积的左右两边断开）。工具只经过 `env.zoom`（`effectiveZoom`：投影正中的比例）与指针（`screenToWorld` 反算，投影之外给边上的一点、不在地图上；极地的场景时按 `nearestCell` 取格）。
- **空闲预热**（第三十一轮，`Engine.warmSteps`）：从检查点打开的世界网格是新的，按网格的缓存全是空的，以前打开后的第一笔要多等 0.6–1.5 秒（重新采样生成器、整个求解高程、气候与地物只取决于海陆的几层）。现在 Worker 在新建、打开以后空闲时一段一段地把这些缓存填上，只往缓存里放东西（世界、推导、历史都不动），结果不变：
  - 生成器分段采样（`terrain.ts` 的 `warmTerrainSteps`：每段 8000 格，`generate.ts` 的 `sampleComponentRange`、`planet-gen.ts` 的 `samplePlanetRange` 与一次采完逐值相同；有地形脚本的星球一次采完），放进按网格的缓存，再让这个世界的缓存命中它，连同海底的场、海岸噪声；
  - 高程按开始时复制下来的海陆、抬升、岩性，按整块陆地分几段求解放进记忆（`elevation.ts` 的 `warmElevationSteps`：一块陆地的结果只取决于它自己，分几段与一次算完相同），再算一遍海底的记忆；
  - 气候：星球只取决于纬度的一层、陆地占比、只取决于海陆的一层（含洋流）分三段（`warmClimateSphereSteps`），地区的网格反查、边的方向、格距、背景风带与日照、陆地占比与偏转前的风（`prepareClimatePlane`）；
  - 地物各段的缓存（`prepareFeatures`，再按现在的推导 `detectFeatures` 一遍，结果不用）。
  - Worker（`src/worker.ts`）：新建、打开后空闲 60 ms 起开始，段与段之间 `setTimeout(0)` 让出线程；排进来任何请求（`queue`）就停下、丢掉这一轮，请求都做完了再从头来一轮（做过的几样一查就跳过：键对得上、记忆里已有这一份），一整轮做完才算预热好。最长的一段约 0.1–0.5 秒（星球的洋流那一段最长）。
- **地区气候的分层缓存**（第三十一轮，`climate.ts` 的 `planeLayers`，与星球的 `sphereStatic` / `sphereLand` 同一个做法）：格距与按它算的比例（`planeGeo`）、背景风带与季风的系数和降水里只取决于纬度的部分（`planeStatic`，按纬度、倾角、自转、比例尺）、偏转前的风（`planeWinds`，按陆地占比的那份数组认）、日照温度与海面的饱和水汽量（`planeSun`）。抬山、改岩性、放湖只重算地形有关的部分。
- **输运图与梯度**（第三十一轮）：边的单位方向按网格缓存（`edgeDirs`）；算权重时顺带标出参与排序的边、数好入度（`kahnOrder` 的 `given`），星球的 `buildFlowSphere` 把滞后边、参与排序的边、入度并成一遍；梯度的最小二乘里只取决于网格的部分按网格缓存（`mesh.ts` 的 `gradGeo`：每条边的 w·dx、w·dy，每格的 sxx、sxy、syy、det；`gradientAt` / `gradientField` 与 `gradient` 逐值相同，不再每格分配数组），气候的地形梯度、陆地占比的梯度、水文的坡度用它。水文的格面积按网格缓存（`cellAreaKm`）。
- **高程记忆的快路**（第三十一轮，`elevation.ts` 的 `fromMemo`）：整份照用最近的一份记忆，只找与它不同的格（海陆不同，或陆格的抬升、岩性按位不同）碰到的陆块再与别的几份逐块比、比不上的重算。一块陆地逐块比不相同当且仅当它的格或挨着它的海格里有这样的格，所以与以前把每块陆地都找一遍、逐格比的结果相同（`elevationMemo.fast = false` 是以前的做法，`elevation-memo.test.ts` 对照）。
- **大格局**（第三十二轮）：板块的栅格（约 50 ms）按种子、类型、形态缓存四份，缩略图与成品共用；海平面的排序按不含重画的地壳高度（`seaB0`）缓存，重画一片、撤销、重做不再重排；求解里软底补的比例与 A^m 一样按汇水面积、到下游的距离沿用。
- **平原与河口**（第三十三轮）：求解里的一遍只看这块陆地自己的输入（与先后无关），按陆块的记忆照旧，记忆的键不变；画面上的海岸场（`displayCoast`）、悬停的陆海（`coastOf`）多按流向、汇水面积、“最高的山”认（三角洲向海凸出），这几样不变时照旧用缓存；分汊在描河里，描河照旧按内容缓存（`river-pack.ts` 的 `riversKey` 已经比流量、流向、高程），描河本身的提速见下面“描河”。
- **描河**（第三十三轮提速）：Worker 每改一笔都把整个世界的河重描、打包一遍（`src/worker.ts` 的快照 → `river-pack.ts` 的 `worldRivers`：读的东西按内容没变时用上一次的，变了就整个重描），主线程再按新的高程数组算一遍地形层的海岸场（`displayCoast`）。第三十三轮的分汊让描一遍河多了将近一倍（类地星球 36 → 69 ms），测速里没有这一步，所以没看出来；现在测速里有了（见“测速与对照”的 `rivers`、`coast`）。结果逐位不变（`river-memo`），金标准一个都没有重录：
  - **按画面海岸场的查询跨几次描河记下来**（`core/coast-memo.ts`）：河口走到岸线（`walkShore`、`shoreCross`）、河口那一点的岸线（`mouthShore`）、沿法向找岸线（`shoreAlong`）、岸线的法向（`seawardNormal`）、圆与岸线的交点（`circleShores`）、一段线的点都在陆地上（`allLand`）。键是全部参数（按位）；算的时候读到哪几格（`displayCoastAt` 找到的三角形、`shoreCrossing` 沿边走时的两格、`coastSmooth`）由 `coastReads` 记下来，连同那几格的 coast、elevation、frag 三样；下一次问同一个键、这几格的三样都没变就直接用（同样的参数、同样读到的值，算出来就一样）。嵌套的查询读到的格也算外面一层读的。网格、海岸破碎度换了全部作废，最近四次描河都没用到的丢掉；结果放进去、取出来各复制一份。只改气候时海岸场几乎不变，改地形只有附近几格变了，九成以上的查询用得上。
  - **三角洲分汊的几何**（在哪一处分、成了哪几股：`planBranches`）也记下来：键是主流的全部点、河口那格、想分几股；另外记下读到的格与“问别处”的答案（`BranchAsk`：已有的河口在不在附近、附近别的河的线相不相交、这一次已经分出去的几股相不相交），下一次按那时的 ends、lines、made 照样再问一遍，答得都一样才用（`planHolds`）。流量、粗细、`joins` 每次照常改。
  - **海岸值只重算变了的格**（`subcell.ts` 的 `coastValues`）：记下上一次的输入（陆地程度、陆海的副本：数组可能被就地改过）与结果，网格、种子、幅度相同时只重算这两样变了的格；三角洲凸出（`deltaBulge`）沿海格走、取最大改用按格的数组与戳记（以前是 Map），走的先后与取的值不变。
  - **闭包与退回**：带子（`riverRibbon`）的加密（`densify`）、沿河的长度、来回平滑（`smoothWidth`，两遍共用同一份 1 − exp(−Δs / λ)）、半宽、细小的弯曲、法向、外接框都是模块里的小函数（以前的 `put`、`normals` 是闭包，几样数组都成了闭包里的变量，整个函数都慢；河线对象的样子各式各样，riverRibbon 碰到新的样子时优化过的代码会退回去，循环放在外面就不受牵连：星球轴倾角那一步之后画带子常要 76–81 ms，现在 33–45 ms），河线的点与流量先抄进类型化数组，粗细倍数每个河线点先算一次；线段相交（`segCross`）的叉积、`riversKey` 的散列不再每次调用新建闭包（分汊的检查每次描河要调几十万次 `segCross`；`tsx` 跑的测速里每新建一个闭包还要多调一次 `__name`）。
  - 新出现的河口照旧要从头算（湿度一下调大、几百条新河）：那几步描河与 1bace6b 差不多。
- **湖与海岸**（第三十四轮）：冰川刻蚀在求解里按陆块，记忆的键不变（只取决于种子、比例尺、新建时的纬度，键里本来就有）；冰盖的场（`glacialField`）、海岸类型（`coastStyle`，按生成器的分量对象，分量换了只重算变了的格与两圈邻格）、岸段的噪声按网格缓存；按陆海定的一份（`landStyle`：峡湾只在挨海的格）只看峡湾格与邻格的陆海，没变时还是同一个数组；湖面格去掉沙坝顺带在 `displayCoast` 认湖面的那一遍里做（以前单独扫一遍有沙坝权重的格，约九千格，每次 0.05 ms，测速的 coast 一步只有约 0.4 ms）。描河的记忆每格多记两个数。着色器里噪声只在用得上的地方取（峡湾只在陆地、沙坝只在离岸那一带、小湖群只在权重 > 0 的地方），顶点着色器拆开时不用三角函数，插值量打包成两个，合成另用两个通道的海岸值纹理，小湖群的水面标出来不再一圈圈找水面格（见“湖与海岸”）。
- **还没编译好的代码**（第三十二轮提速）：JS 引擎（V8，浏览器与 Node 一样）先解释执行，函数用得多、循环转得多了才编译优化。新建、打开以后的头几笔里，写在一个大函数里的一段段逐格循环常常还没编译好就走完了：循环里换到优化代码（OSR），出了这段循环又因为后面的代码还没有类型信息退回去，下一段再来一遍；同一笔在一直开着的世界上只要三分之一到一半的时间（星球画陆地头两次约 1.1 秒、之后约 0.45 秒）。所以热的逐格循环放在小函数里（几个参数、类型固定）：小函数的循环很快就编译好，下一次调用直接用优化过的代码。拆出来的都是逐行照搬（运算、先后不变），由金标准逐值把关：星球气候的洋流（`ocean.ts` 的 `computeOcean` 分成挡流陆地、每行的海岸距离、流函数、海流、上涌、海温输运、纬度带偏离几段）、只取决于海陆的一层与陆地占比的模糊、海风与背风、降水输运（`rainSetup`、`moistureSweeps`），地区气候的入流权重、背风、两季温度、降水准备，水文（`computeHydrology` 的认湖、湖的收支、产流、累加、流量与流域、坡度），植被（场、适宜度、份额），高程求解的每一轮（`solvePass`、`diffusePass`），地物的陆海段（群岛、海岸、半岛、海峡、海湾、海与洋）。以后写新的逐格计算也照这样：一段循环一个小函数，大函数只管先后。
- **地物与水文的几处缓存**（第三十二轮提速）：水文的坡度按高程、海陆、比例尺缓存（`hydrology.ts` 的 `slopeMemo`，只改气候、画河时不重算；地形湿度指数照旧按双精度的坡度算）；地物的“地势”一段拆成山脉与主峰（按山地格表与高度）、高原与平原（按两张格表）、盆地（按陆海与高度）三小段各自缓存——内流湖随气候涨落时湖面变了，以前整段重算，现在多半只有平原那一张表变了；盆地的“附近最高”（`nearMax`）两份数组轮换，不再每遍复制。湖里的岛只从湖岸的格出发（邻接是对称的，挨着湖面的格就是湖面格的邻格），碰到海、地图边就停，走过的格标成“不是”（`enclosedDry`），不再把整块大陆的干陆地走一遍；大河一遍记下每格流量最大的上游与河口（`riverHeads`），不再建整张上游表。都有与以前写法逐值相同的测试（`features-memo`）。
- **大陆轮廓之后的加工**（第三十五轮提速）：第三十五轮的地形让测速里几笔加工比 02b7adf 慢了 6–35%（抬山碰到两块陆地、湖多了、人文那一段头几次调用的抖动），这一轮逐值不变地压回去（`cell-memo`，金标准一个都没有重录）：
  - **人文的几层按格记下**（`core/human/cell-memo.ts`）：自动的地形类别、资源每格只取决于这一格的输入（干不干、挨海 / 河 / 湖的标记、纬度、主导的生态、高程、坡度、年均温、湿润指数、地形湿度；资源另看这一格生效的类别）与规则、种子，宜居度另看有河的格的流量。引擎整个重算以后（`computeHuman` 的自然的那条路）按网格记下这一次的输入（复制一份，按位比）与结果，下一次规则、种子、比例尺都一样时只重算输入变了的格（资源再加生效的类别变了的格、宜居度再加流量变了的有河的格），别的格照抄上一次的；什么都没变时直接用上一次的数组。改一笔多半只变几成的格（区域测速里画河约 1%、放湖约 5%、抬山约 18%、画陆地约 43%，改湿度、纬度时全变），测速里加工的人文那一段区域 13–46 → 3–24 ms、星球 20–60 → 5–34 ms（同一次对照，02b7adf → 现在）。每格的算式拆成小函数（`classOf`、`resourceOf`、`habAt`），整个重算与只重算一部分用同一个；人文的输入里每格的纬度按网格、建世界时的纬度与挪过的度数记一份。只画地形类别、资源（`Dirty.Human`）那条路照旧。
  - **海底：陆海不变时**（`elevation.ts` 的 `sameLandSeafloor`，`seafloorStats.coast`）：海岸上堆山改了岸边海格的属性（挨着的陆地的抬升），以前要按“改动附近 limit 加十格”重算一大片（地区约三分之一张图）；现在离岸距离与最近的岸边格只取决于陆海，照用上一次的，只重算属性变了的岸边格管着的格、再往外三圈平滑与 landness 变了的海格。
  - **还没编译好的代码**（同上一轮的做法，原样照搬进小函数）：地区与星球气候里剩下的逐格循环（纬度、高程梯度换成每 km、风加上山挡风的变化量、图外来流、大陆度、两季温度与降水、海温上岸）、山挡风（`deflectWind`：逐格的变化量、扩散的一遍、写出）、输运图（地区的 `buildFlow`、星球的 `buildFlowSphere`：出流比例、相互指向只留一边、滞后边与入度、逆序的边、入流表）、星球的只取决于海陆的一层（`sphereLand`）与洋流（上涌、海上回到平衡的比例）、高程求解开头的几段、海底（变了的海格、岸边海格、只走海格的 Dijkstra、平滑之前的宽度、深度：以前“第 k 个要重算的格”是两种闭包，现在是一张格表）、地物的连通块、步数距离、海与洋（队列换成类型化数组）、生态的几个大类（一遍走完再按大类排好，与每类一遍 `components` 的先后相同）。星球加工的气候一段少了两三成（同一次对照：轴倾角 373 → 248 ms、画陆地 438 → 289 ms），地区一到三成（放湖 98 → 64 ms）。
  - **两种常用代价的 Dijkstra**（`mesh.ts` 的 `graphDistanceSame`、`graphDistanceAvoid`）：求解里陆上的海岸距离、洋流的离挡流陆地的距离以前每次传一个新的闭包，`graphDistanceOwner` 里调用它的地方见过各式各样的闭包、内联不了；同样的堆、同样的先后，结果逐值相同。
  - **星球的陆地占比**：东西方向的模糊首尾相接的列号查表（以前每一项取两次余数），南北方向的高斯权重每个 d 先算一次（以前每个像素都重算 exp），加的先后不变。地物的坡度按 `gradientAt`（与 `gradient` 逐值相同，不每格分配数组）。
  - **省份**（`provinces.ts`）：省份的格数（`provinceSizes`）先按编号数在类型化数组里，再按每个编号第一次出现的先后放进 Map（键、值、先后都与逐格 set 的相同；编号大得离谱时照旧）；改了陆海以后修补省份先查一次每个编号是陆地省还是海省，不再逐格查 `small.provinces`。重做（再放一次岛，只有命令与修补省份）在加这一项前后的两次对照里区域 24 → 18 ms、星球 40 → 32 ms。
- **还慢的**：改海陆时整个星球的洋流、风、地名，要更快得多线程计算（见“待办”）；改海陆时地区的大尺度陆地占比（约 270 遍扩散，约 0.1 秒）每次整个重算。
- **峡湾**（第三十六轮，`core/fjords.ts`）：谷网跟着海岸类型按网格缓存（键与峡湾权重相同）；谷网按块（约 900 km）建，重画一片时只重建峡湾权重变了的格往外三圈、这一带附近地壳高度变了的格往外一圈碰到的块（第三十六轮（续）；与整张重建逐值相同；一块都不碰时谷网、表号、峡湾纹理都照用）；淹到哪里按谷里的点所在的格与两圈以内的陆海缓存（`fjordData`，按块的数组记，没变时是同一个对象，`displayCoast`、导出、悬停共用）；幽灵海岸自己留一份（与现在的陆海相同时就是现在的那一份）；描河记下的查询每格多比峡湾表的摘要，海岸类型的 b 去掉表号再比（一带多了、少了几格时后面的格的表号都挪一位，表的内容没变的查询照用）；只看正负的捷径按峡湾的下界（表是空的不算位置）、岛礁的范围；星球上接缝外的影子三角形对回画面三角形的表按网格算一次（三格的数字键）。新建、打开以后的空闲预热顺带建好。
- **描格**（第三十七轮）：鼠标下的格与钉住的格是合成着色器的两个 uniform（`renderer.setFocus`），不走高亮纹理：移动鼠标不再上传高亮，`focusKey`（两格的格号与陆水）在合成的键（停稳、投影的两个）里，换了格才重新合成一次；着色器先按到格心的远近（`FOCUS_REACH` 3.2 格）排除，只有格附近的像素多算五次 `focusAt`。`displayCellAt` 没有切线时描格的格就是省份格（不多算一次）。
- **图层提速**（第三十九轮，见“图层提速”）：合成着色器先判断再跳过（省份格用得上才算、省界淡出为 0 时不取相邻像素、国界外面一圈看不出时不取、帝国外沿早停、离边界远的格不取环上的点：`near.ts` 的 H 与 ρ）；描格不在合成的键里，变了时只在新旧描格的几块里重新合成；着色拆成底子与每种模式的一层、各缓存几份，渲染器按对象是不是同一个上传，只有地形层读的变了才重画地形层（`layersVersion`），只有合成读的变了只重新合成（`modeVersion`）；uniform 的位置按程序记住；`?perf` 开关（`window.__perf`）。
- **画风**（第三十八轮）：画风的 uniform（`styleUniforms`）与签名（`mapStyleKey`）按画风对象记住（`WeakMap`），每帧只上传；换画风、改画风不重算，合成的键（停稳、投影的两个）里的签名变了才重新合成一次。

## 测速与对照（第三十一轮）

`tools/bench.ts` 的普通一轮（不带 `--pack`）按用户的加工逐步计时，区域 4 万格（种子 3、“几块大陆”），`--globe` 整个星球（类地 6.26 万格）。键（`--json` 最后一行）：

- 步骤：`newWorld`、`relief`（抬山，半径 6 格）、`erod`（岩性）、`tempBrush`（冷暖笔）、`paintLand`（沿海一笔，真改海陆）、`island`、`reroll`（重新生成一片）、`rerollFjord`（第三十六轮（续）：峡湾权重最大的海岸陆格上重新生成一片；没有海岸类型的旧提交上跳过）、`river`（画河）、`lake`（放湖）、`humidity`、`latShift`（星球上是轴倾角）、`undo1`–`undo6`、`redo`；`openCheckpoint`、`coldRelief`（从检查点恢复到新的网格对象上，所有按网格的缓存都是空的，像刷新后打开，再抬一笔）、`warmup` / `warmupLongestChunk` / `warmRelief`（先 `warmSteps` 预热再抬同一笔）、`hotRelief`（一直开着的世界上同一笔）；`--long` 加 `longReplay`（约 200 条混合命令的文档按固定种子挑出来，在新网格上整段重放）、`longCheckpoint`；`--library`（第四十七轮：世界带着一整个时代库，步骤相同）加 `libEdit`、`libUndo`、`libRedo`、`libContent`、`libContentUndo`、`libNoop`（不重算的几步，几十次的中位数）、`libPost`（发给主线程的小数据）、`undoKB`（一步的撤销记录，千字）。
- `步骤.阶段`：`elevation`、`climate`、`solve`、`hydrology`（含一遍遍的植被）、`vegetation`、`human`、`features`（引擎的 `lastTimings`），`apply`（命令本身，含生成器的组合），`sample`（生成器采样，`terrain.ts` 的 `terrainLaps`），`elev.scan` / `elev.solve` / `elev.finish`（高程的认陆块与比记忆、求解、收尾，`elevation.ts` 的 `elevationLaps`）。
- `步骤#计数`：`#landmasses`（重算的陆块）、`#lakes`（湖的地物）、`#mouths`（河口）。计数不是毫秒，用来看改动有没有改变要做的事。
- 描河（第三十三轮提速）：每一步之后另计 Worker 接着做的描河并打包（`river-pack.ts` 的 `worldRivers`，与 `src/worker.ts` 的快照一样：读的东西没变时用上一次的；键 `步骤.rivers`）与主线程地形层的海岸场（`display.ts` 的 `displayCoast`，高程换一份副本，像收到的新数组；键 `步骤.coast`），不算进这一步自己的耗时（与以前的对照照样能比）。加工各步（抬山到重做）的这两样加起来记成 `rivers`、`coast` 两步，与加工一样按第六条门槛比。以前测速不含描河，第三十三轮分汊让描河慢了将近一倍也没看出来。旧的提交上没有这两个函数时跳过。

对照两个提交（第六条门槛：加工不比旧的慢 5% 以上；重新生成一片不慢；新建不超过 1.8 倍；长文档重放不超过 1.3 倍）：

```bash
node tools/bench-median.mjs 5 --against <旧的提交> --out /tmp/region.json -- --long
node tools/bench-median.mjs 5 --against <旧的提交> --out /tmp/planet.json -- --globe --long
node tools/bench-median.mjs --all --compare /tmp/planet.json /tmp/planet.json   # 存下的再看（--all 连同各阶段；两个文件都是 --against 存的时比 base 与 head）
```

`--against` 在系统的临时目录里 `git worktree add` 旧的提交（用完删掉），把现在的 `tools/bench.ts` 复制过去，旧、新交替各跑几次（机器忙闲两边一样），打出对照表，比旧的慢 5% 以上、多 2 ms 以上的加工标 ⚠。所以 `bench.ts` 只能用旧的提交里也有的接口，后加的（`warmSteps`、`elevationLaps`、`terrainLaps`）用 `import * as` 取、没有时跳过。跑的时候别改代码（新的一边每次都读工作区）。机器忙时数字会飘 10% 上下，只看同一次对照里的相对快慢。

这台机器（Mac，8 核）的基线在 `tools/bench-baseline/`：`r31-region.json`、`r31-planet.json` 是第三十一轮之前（1421485）五次的中位数；`r31-ab-region.json`、`r31-ab-planet.json` 是下面这次对照（`base` 1421485，`head` 第三十一轮），第三十二轮起与 `head` 比；`r32-ab-region.json`、`r32-ab-planet.json` 是第三十二轮提速后的对照（`base` aa065b7，`head` 第三十二轮（提速），见“大格局与长河”的速度一节）。`r33-ab-region.json`、`r33-ab-planet.json` 是第三十三轮（提速）的对照（`base` 1bace6b，`head` 第三十三轮（提速），带 `rivers`、`coast` 两步，见“平原与河口”的速度一节）。`r34-ab-region.json`、`r34-ab-planet.json` 是第三十四轮的对照（`base` 45c9354，`head` 第三十四轮，见“湖与海岸”的速度一节）。`r35-ab-region.json`、`r35-ab-planet.json` 是第三十五轮（提速）的对照（`base` 02b7adf，`head` 第三十五轮（提速），见“大陆轮廓”的速度一节；第三十五轮自己的那一次对照记在那一节的表里）。`r36-ab-region.json`、`r36-ab-planet.json` 是第三十六轮（续）的对照（`base` 598382d，`head` 第三十六轮（续），多了 `rerollFjord` 一步，见“峡湾”的速度一节；第一版的那一次对照被换掉了），以后与 `head` 比。

测速量的是新建以后的头几笔：每个函数才跑过一两次，很多还没编译好（见“缓存与性能设计”里“还没编译好的代码”），所以同一笔每次跑的差别大（区域岩性一笔在 190–350 ms 之间，偶尔多出一百多 ms），五次的中位数也会差 10% 上下；要看清楚哪一段慢，`--all` 看各阶段，或者多跑几次。
