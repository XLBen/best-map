# 第五十轮的设计

这一轮改了什么见 [更新记录](../../更新记录.md)；现在的文件见 [开发说明](../../开发说明.md) 与 docs/dev/ 下的各篇。

用户定的：**世界保留全部内容**。以前生成人文之后，没用到的文化、政体、取值……会自己从世界里消失。这一轮去掉，清理只在点“整理本世界”时做（变淡和新的按钮在第六十二轮）。

## 生成后不再移出

`pruneHumanContent` 和它的调用去掉。`prune.ts` 只留 `dropBroughtContent`：删掉人文、删掉国家时带进来的内容一起移出。这一段没动，它是用户明确的删除，不是生成的副作用；要不要也改成留着，等用户定。

**动手之前的模拟对不对**：用同一段脚本在 e25587c 和这一轮上各跑一遍（1.2 万格，中世纪、奇幻、现代），比 r29 的十四项摘要：

| 路径 | 结果 |
| --- | --- |
| 生成人文 + 国家 + 城市地标 | 三种都逐项相同 |
| 先加一遍包再重新生成国家、人文（界面走的路） | 三种都逐项相同 |
| 新建国家（档案里的“新国家”） | 政体、文化都相同 |
| 不先加包就重新生成国家 | 不同：以前只看得到清理后的政体。界面不走这条路（都包着 `withPackImports`）。现在这条和上面那条逐项相同 |
| 不先加包就重新生成人文、**拖发源地** | 中世纪、现代的 `pop` 不同，别的相同；奇幻全同 |
| 换时代重新生成 | 不同，见下 |

所以模拟说的“名字、国家、城市不变”对生成这一步成立。多出来两处：

- **拖发源地**不经过 `withPackImports`，以前看到的是清理后的取值，现在看到的和第一次生成一样，所以人口的取值有变化（国家、城市不变）。
- **换时代**：旧时代的政体、派系、取值留在世界里，也参与生成。以前只留上一次用到的，一样参与，只是少一些（政体 8 → 30 种，取值 32 → 52 个）。不想要时先整理。第五十二轮选一个库时再定，写进了 `limits.md`。

## 文化组的比重

`cultureGroup.weight`，只决定参不参与：0 不参与，别的和没写一样，各组占多少仍是命令写的权重（第五十二轮选库时用它给出命令）。判断在 `usableGroups`，`generateHuman` 和 `humanBlockers` 都走它：

- 0 的组不进 `human.groups`，没有发源地、没有人、不是国家的主流文化；和命令里没选它**逐项相同**（测试）。
- 全是 0 时不生成，结果里写“没有文化”。
- 改成 0 后重新生成：组退出，它的锁定发源地也去掉。
- 内置的组都没写，所以 r29 不变。
- `pack.sameIgnore: ['weight']`：只差比重算同一项，再加一遍包时跳过，世界里的比重不变。
- 勾上一个包时不跟着勾比重是 0 的组（`defaultGroupsOf`）。

## 压缩世界文件

`compactWorldDoc` 只去掉“加了又删”的两条。以前的第 3、4 步（加了没用上的去掉、末尾补一条整理）没了，`CompactResult` 也不再有 `removed`、`kept`。世界里有的一项不少，由 `worldDigest` 核对（它算着 `small`）。

## 清理

`unusedContent` 多看四种：文化、文化组、地名风格、时代（用户说前三种；不加时代的话换过时代的世界永远清不掉旧时代）。

- **有先后**：文化在组之前，组在风格之前（`TIDY_KINDS`），后面的按“前面移出之后的世界”查，所以一个没人的组和它的文化、风格能一步移出。
- **世界默认的风格不算没用到**（`styleUsage` 不算它，`styleInUse` 算）。
- **选了的组留着**：`human.groups` 里的组算在用，组里没人的文化移出，和以前生成后的样子一样。
- `planTidy` 的 `only`（一个包的“移出没用到的”）以前按列的先后、按移出前的世界查，组里有文化时组就走不了。现在排好先后、一项项查。
- 移出时引擎报“还在用”（一个文化因为地图会变留下，它的组就移不掉）：以前会把异常抛出 `planTidy`，现在写进 `kept` 的原因。

清理后 r29 的十四项摘要、`mapDiff` 都不变，没有找不到的 `hard` 引用。`auto`、`strip` 类的引用可能找不到（政体的换说法写到移出的文化组），和以前的清理一样，那些本来就允许缺。

## 顺手要改的（世界留着内容的连带）

- **改过的项重新生成时多一份 `id-2`**。“重新生成”之前会把包再加一遍，世界里改过的项和包里的不一样，就撞名加一份 `x-2`。以前没人用的 `x-2` 生成后被清理掉，现在会一直留着。所以包没换的再生成只补世界里**没有的 id**（`ImportPicks.onlyMissing`，`withPackImports` 和 `regenerateWith` 用），改过的留着并参与生成。换了包的照旧撞名。
- **打开世界文件不再提示“有 N 项没用到”**：现在每个世界都有，提示没有意义了。`showNotice` 没人用了，去掉。打开也少算一遍整理。
- `tidyOrigins` 每条命令都走一遍：世界留着内容以后这里多了约 0.1 ms（`libEdit` +5%、`libContent` +7%）。一般什么都没少，加了一条不拼新表的路，压回 ±1%。

## 大小与速度

世界带着中世纪整个库（18 组、144 个文化）、生成时选 3 组，1.2 万格：

| | e25587c | 这一轮 |
| --- | --- | --- |
| 世界文件（命令） | 357 KB | 357 KB（一字不差） |
| 压缩后写出去的 | 355 KB | 357 KB（+0.5%） |
| 压缩用时 | 766 ms | 298 ms |
| `small.content` | 99 KB | 308 KB |
| `small` | 192 KB | 407 KB |

文件几乎不变：加内容的命令以前就在文件里，清理只改内存里的世界。

`bench-median 5 --against e25587c -- --kept`（新的，4 万格，生成后接着改；负载 3–4）：

| 步骤 | 旧 | 新 |
| --- | --- | --- |
| `libEdit` | 2.16 | 2.13 ms |
| `libUndo` | 3.18 | 3.22 ms |
| `libContent` | 2.15 | 2.16 ms |
| `libContentUndo` | 3.11 | 3.19 ms |
| `libPost` | 2.18 | 2.22 ms |
| `libHuman`（改人口） | 12.3 | 9.95 ms |
| `libCountry`（改档案） | 8.84 | 6.32 ms |
| `libSaveDoc` | 3.32 | 3.25 ms |
| `undoKB` | 154 | 160 千字 |
| `genHuman` | 764 | 724 ms |
| `hotRelief` | 267 | 236 ms |

第四十七轮的共用照样成立：生成不碰 `small.content`，还是同一个对象（测试查），撤销记录只多了 `origin` 的 6 千字。人文的几步反而快了，原因没查，不算这一轮的提速。

区域（`-- `，没有人文，代码路径没变）：第一次标 rerollFjord +6%、humidity +13%；同一提交对照自己标 erod +7%、tempBrush +7%；再量一次标 tempBrush +6%、hotRelief +5%，前两步是 -6%、-1%。**没有一步两次都慢**。`-- --library`：全部在 ±2%，没有标。星球没有量（区域没有两次都慢的）。`overlay-ab`、`compose-ab --quick` 都是 0 不同。

## 金标准

`golden-hashes`、`golden-full`、`r31-digests`、`r29-digests`、`shader-hashes` 一个没重录（`small` 也没变：这些世界没有生成人文）。

只有 `core/raster-identity.test.ts` 里 `world.json` 的四个值重录：游戏文件包里带着世界文件，第一行写着版本 12。用版本 11 写同一份文件，摘要和原来的值一样（`c4e280ae…`、`78c3ce0d…`），所以只差这个数字；第四十三轮升版本时也是这样。
