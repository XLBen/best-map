# 第六十六轮的设计

这一轮改了什么见 [更新记录](../../更新记录.md)；现在的文件见 [开发说明](../../开发说明.md) 与 docs/dev/ 下的各篇。第六十六、六十七轮的计划是“看库就是添加”：导入弹窗并进资源库面板。这一轮做逻辑，不动面板的样子；第六十七轮照这里的接口做界面，删掉弹窗。

## 勾选按库记（`src/ui/packs/pick-store.ts`，新）

第六十五轮的勾选在导入窗口里，换来源库就清空。现在每个来源库记自己的：

```ts
interface PickFor { need: ContentRef; for: ContentRef }        // need 是点灰的行 for 时一起勾上的
interface PickState { picks; off; added: readonly PickFor[] }
type PickDest = 'world' | { lib: string };                      // 全部库共用一个目的地
```

- 键是资源库里的键；读进来的文件是 `file:名字`（`setFileSource(名字, 包)` 给出键，`dropFileSource` 去掉，第六十七轮接到标题下拉）。
- 读：`picksOf(键)`、`pickCount(键)`（“已勾 N”，就是 `picks.length`）、`pickedSources()`（勾过的库和项数）、`pickPreview(键, ctx)`（清单，`because` 写好“为了 X 加的”）、`pickAsk`。
- 改：`togglePickIn`、`setPicksIn`、`removePickIn`、`pickNeedsIn`（点灰的行，几选一时传选的那一个）、`clearPicks(键?)`、`setPickDest`。
- 目的地 `pickDest(ctx)`：选过的（世界、我的库还在）；没选过时有世界是本世界，没有时第一个我的库，都没有时 `null`。不能从一个库加到它自己（`pickAsk` 是 `null`）。
- 清掉：添加成功后（`pick-add.ts` 的 `addPicked`）、清空、换世界。换世界看 `worldEpoch`（新建、打开时加一），同一个世界改了内容不算。不在信号里改：读的时候纪元不对就当作空的，写的时候从空的开始，所以画面上读也不会在渲染时改状态。

连带的规则原样从 `page-import.ts` 搬过来，写成纯函数 `pickOn`、`pickOff`、`pickRows`、`pickRemove`、`pickWithNeeds`（给定来源、目的地和勾选，算新的勾选）。导入窗口的 `togglePick`、`setPicks`、`removeRow` 照旧从 `page-import.ts` 导出，现在只是用窗口里的勾选调这几个函数；`ImportWindow` 多了 `added`。**导入窗口的勾选没有放进按库记的状态**：窗口这一轮还要照旧能用，测试里每次打开都是新的；第六十七轮删窗口时这件事就没了。

## 点灰的行

`import-gates.ts` 的 `gated` 多了两项：

- `resolvable`：要的东西在这个来源里勾得到（`any` 时有一个就行）。变量要有取值（目的地没有时代时，来源的时代还要写着它）、放得下；内容要在来源里、能用到目的地、它自己能选（它也灰着时看它要的勾不勾得到）。“需要时代”勾不到。
- `choices`：勾得到的那几个，去掉重复的。`any` 时界面让用户选一个。

`pickWithNeeds(ask, 勾选, X, 选的?)`：

1. X 不灰时照常勾；放不下（`full`）、勾不到时返回 `null`，勾选不动。
2. 灰的：把 `choices` 一起放进 picks（`any` 时用传进来的那一个；只有一个能选时可以不传），记下 `{ need, for: X }`。要的东西自己也灰着时再把它要的勾上，为的都是 X；里面的几选一用第一个能选的。勾上后 X 还灰着时也返回 `null`。
3. 用户自己勾过的不记“为 X 加的”（去掉 X 时它不跟着走）。

去掉的规则（`tidyAdded`，每次取消、×、整段取消之后走）：

- X 或要的那一项不在勾选里了，那一条记录就没了。
- 为 X 加的那一项没有别的 X 了：试着去掉它；去掉后别的勾着的项（或子项）进不来的，说明别人也要它，留着，算用户自己勾的。
- 去掉为 X 加的那一项时，X 又灰了，`settled` 照第六十五轮的规则把它拿掉；X 别的要的照上一条。

清单（`withForNotes`）：为别的项加的行，`because` 写“为了社会主义共和国加的”（几项时“为了甲、乙加的”）。行的状态 `rowLook` 的灰行多了 `resolvable` 和 `choices`（几选一时）。

量到的：现代 → 只有奇幻时代的世界，点社会主义共和国，勾上它和意识形态，清单 19 项，和第六十四轮“勾意识形态再勾政体”一样。青铜与古典 → 只有中世纪时代的世界，草原游牧灰着写“需要阿尔泰或鞑靼或斯基泰人 等”，四个都勾得到（两个组、两个文化），不选不勾，选斯基泰人就勾上两项。

## 只勾一个文化时组参与生成

第六十五轮：只勾直隶人，组“汉”跟着来，比重写 0，重新生成后地图上没有直隶人。

现在 `walkOnce` 给跟着来的文化组记 `member`：是勾的（或子项）文化的 `culture.group` 带来的。`closure.ts` 的 `withWeight` 把 `member` 的组当作勾的组：用来源的比重，来源是 0 时去掉这个 0；别的跟着来的组照旧写 0。组里只有勾的文化（跟着来的组不带下级，规则没变）。

**和设计不一样**：设计写“比重用来源库的值”。内置的四个历史库里大部分组的比重是 0（中世纪 71 个组里 53 个，比重 0 是“这个时代默认不带”），照原样写 0 的话勾这些组里的文化，重新生成后还是看不到，和这一条的目的相反。所以和“点名勾的组”一样：比重 0 去掉。汉在中世纪没写比重，两种写法结果一样。

**比重回来（第六十四轮的 `weightBack`）**：目的地已经有这个组、比重是 0（第六十五轮导入的、用户在“文化 ⋯”里取消的），来源不是 0 时：

- 勾整组：和以前一样，`fixable`，比重回来，引用补上。
- 勾组里的文化（这一轮加的）：比重也回来，只回比重，引用不补（跟着来的只是要它在）。清单那一行是跟着来的，写“直隶人要它”，不写“勾上才参与生成”。
- `fixable` 的判断本身没改，还对：只在目的地是 0、来源不是 0 时成立。勾过文化之后组的比重已经是来源的，组的状态是 `have`，不再写“勾上才参与生成”。

实际上能把组当作“去不掉的引用”带来的只有 `culture.group`：“限谁用”、地标的组是 `dep: 'gate'`，目的地没有就去掉，不跟着来。所以“别的引用带来的组写 0”现在碰不到，`hasZeroWeightGroup`（清单底下那句“组的比重是 0”）改成看写进去的比重。

生成不走导入，金标准、r29 摘要不受影响。

## 添加并重新生成（`src/ui/packs/pick-add.ts`，新；`regen.ts`）

- `regen.ts` 加 `addedNeed(small, 添加之后的内容, lib)`：就是面板顶上那个按钮的 `regenNeed`，拿添加前的内容当“上次生成时”的内容来比。所以人文、国家、城市那张表（HUMAN、GOV、SETTLE）和全部细则（后加的变量和它的取值不算、比重 0 的组不算、没有国家时政体不算……）都是同一份，没有另写；表也就不用导出。`regenCommand` 的参数只要 `scopes`。
- `addRegenLabel(need)`：“添加并重新生成国家”“添加并重新生成人文”“添加并重新生成城市”；人文和国家都要时“添加并重新生成人文和国家”（设计只写了三个，这是第四个，`regenNeed` 本来就有这一种）。不要时 `null`。
- `contentAfter(内容, 命令)`：只看 `set_content`（从资源库加进世界的都是它）。算重新生成的命令要用添加之后的内容：新加的组要参与（`beyondWeights` 看世界里的组），库里生成要用的、刚加进来的不再加一遍。
- `worldAddCommand(ask, { path, onto, regen }, lib)`：`importCommand` 之后，`regen` 并且需要时接上 `regenCommand`（它是 batch 时摊开），一个 batch，撤销条写“添加“意识形态”等 19 项，重新生成国家”。`regen` 字段是要重新生成什么（不接也给，按钮名字用）。
- `addRegenButton(ask, lib)`：按钮的字。加到库里、没勾、世界没生成过那一样时 `null`。
- `runAdd(请求, ctx)`：世界里走 `queueWorld`，库里 `setPack`（撤销条“添加 N 项”）。导入窗口的 `runImport` 改成调它（多了 `regen` 选项，窗口没用）。
- `addPicked(键, ctx, { regen })`：按库记的勾选加到选的目的地，成功并且世界没换时清掉这个库的勾选。

锁定的国家：重新生成国家是 `regenerate_countries`，锁定的照旧留着（领土、政体、名字都不变；盟友、对手是和别的国家的关系，别的国家重新长了，这两项跟着变，和面板顶上的按钮一样）。

## 没做、没验证的

- 没有在应用里走过（这一轮没有界面）。`addPicked` 加到世界的那一半要 Worker，只在测试里走了库的那一半和命令本身。
- `importLabel` 写第一个勾的行，变量排在最前，所以点社会主义共和国时撤销条写的是“添加“意识形态”等 19 项”。想写点的那一项要把勾选的先后传进去，没改。
- 世界正在用的库里比重 0 的组（按代码推断，没有写测试）：勾这个库里的文化，组的比重回来了，但这个组是“库里有的”，重新生成人文时不会自己加进来（`beyondWeights` 只算别的库加来的组），要在“文化 ⋯”里勾上。这时 `addedNeed` 也不算它，所以不出按钮，和“勾一个文化就看得到”不一致。测试走的都是从别的库加（奇幻世界加中世纪的直隶人）。
- 没有测速：生成、编辑走的代码没改（`core/` 只动了导入的闭包和把几个函数搬了文件）。
