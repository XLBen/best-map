# 第七十一轮的设计

这一轮改了什么见 [更新记录](../../更新记录.md)；文件见 [core.md](../core.md)、[ui.md](../ui.md)。主题是把生态（生态 / biome）的数据和代码理一遍：名字、一处定义、去掉旧的写法、界面上的几处字。界面的大改（一个编辑器、少几种底图）留给第七十二轮，这一轮只改字。

**生成的世界逐值不变**：金标准、`r29`、`libraries`、`biome-legacy`、着色器的哈希一个都没重录；只重录了 `raster-identity` 里四个 `features.csv`（类型字，见最后一节）。

## 一个东西几个名字

存的字段和命令名不改（`small.species`、`add_species`、资源包的 `biomes`），只在 [core.md](../core.md) 的“生态”一节写清：生态 = `species`（世界里、命令、检查器）= `biome`（内容种类、资源包的段、工具）= `vegetation`（算哪里长什么那一步，结果是 `derived.dominant`，底图“生态分区”的 id 是 `dominant`）。

资源库面板里“生态与水系”这一层以前在代码里叫 `water`，和真正的水（河、湖、水系工具）混在一起。改叫 `ecology`：路由 `{ p: 'ecology' }`、卡片 id、`ECOLOGY_KINDS`、`ecologyHub` / `EcologyHub`、`EcologyHubPage`、`PageWater.tsx` → `PageEcology.tsx`。卡片 id 只在界面里（库的 `arrange` 存的是内容种类的 id），不进存档。总表、生态页的“水系”一段这些真的是水系的，名字照旧（`WaterTablePage`、`BiomeWaterSegment`）。

## 一处定义

- **内置生态的 id**：新的 `core/packs/biome-ids.ts`（`BIOME_ID`），`packs/nature.ts` 用它建 15 种生态；`packs/water.ts` 七条河湖的 `biomes`、`packs/base.ts` 牲畜、木材的规则点名生态时用它。“某一大类都算”的用 `nature.ts` 的 `builtinBiomesIn(group)`：奇幻的虫群侵占的森林（以前手写的 `FORESTS`）、毛皮的苔原类。`base.ts` 因此有了两个运行时的引用，`src/worker-imports.test.ts` 里对照“看得出只引用类型”的那一句跟着改（`['./biome-ids', './nature']`）。
- **一种生态算哪一大类**：只在 `species.ts` 的 `biomeGroupOf`。以前 `features.ts` 的 `speciesGroup` 一处（写了 `group` 用它，没写的按导出用的地形 `terrain` 猜），地标的“荒漠里”“森林里”“绿洲”（`human/landmarks.ts`）和圈地名猜类型（`guessRegionKind`）各自只看 `terrain`。现在三处都用 `biomeGroupOf`。对每个内置库的每一种生态，“是荒漠”“是森林”两种认法逐个相同（`core/packs/biome-ids.test.ts`）；只有写了 `group` 又写了不一样的 `terrain` 的自定义生态会不同（比如大类森林、导出地形 desert：以前地标当它是荒漠，现在是森林）。
- **颜色**：`colors.ts` 里两处现建 `speciesRgb` 合成 `speciesRgbOf`；预览的幽灵层（`GhostLayers`）自己写的一串模式判断换成 `terrainLikeMode`。后者多了人文的几种底图（地形类别、资源、文化、国家……）：这几种底图下，刚变成陆地 / 海 / 湖、四周三圈都没有同类邻格的格，兜底颜色从灰色、`[40,50,70]` 换成按深浅的海色、低地色（和这些底图的底子一致）。只在这种很少见的兜底上不同，`compose-ab` 的 714 组都相同。

### 没去掉的：按导出用的地形猜大类

本来打算去掉 `speciesGroup` 按 `terrain` 猜的那一段，给每种内置生态写明 `group`。试过以后不行：奇幻的水晶丛林、死亡森林、虫群占领区没写 `group`，靠 `terrain`（jungle、forest）算进大片的森林；它们又自带地名设定，“自然长成的一片自己起名”（`namesNaturally`）的条件正是“有地名设定、没写大类”。给它们写上 `group: 'forest'`，它们就不再自己起名；为此改 `namesNaturally` 只看地名设定，又会让“给针叶林加一个地名设定”（`core/features-biome.test.ts` 查着：自然长成的仍是森林，不另算）变成另起名字。两条规则要的东西只能靠“没写大类、按地形算进森林”分开，所以留着，挪到 `biomeGroupOf` 里写明为什么。第一次全量测试就是这一条挂的（1 个），退回后全过。

## 去掉旧的

- `species.ts` 的 `OLD_DEFAULT_COLORS`、`NEW_DEFAULT_COLORS`、`speciesColor`：第十三轮以前的默认颜色在画的时候换成新颜色。旧存档不必兼容，画的就是生态自己的 `color`（15 处调用改成 `sp.color`）。这只改“读”的时候的换色，世界文件的格式不变，`DOC_VERSION` 不加。新世界的生态本来就是新颜色，金标准、着色器对照都不变；只有在第十三轮以前存的、又一路打开着用到现在的世界里（`DOC_VERSION` 已经升过多次，实际上打不开）才会看到旧颜色。`island-kinds.test.ts` 去掉换色的那条，“新配色差得更开”留着（旧颜色表写进测试里）。
- 导入窗口里“旧版的生态文件”那一句去掉。读生态数组（`readPack` 的 `legacy: 'biomes'`）没去：生态编辑器的“导出”现在写的还是这种数组，去掉就读不回自己导出的文件。第七十二轮做一个编辑器时把导出改成资源包，再去掉这一条。
- 调试用的开关（`waterPlanDebug.baseFirst`、`reuseFirstBase`、`scriptPassDebug`、`vegetationStats`）都留着：`reuseFirstBase` 是正经的计划字段，另外三个是“新旧逐位相同”“少算几遍”的测试在用（`water-rules`、`water-fantasy`、`water-real-speed`），去掉就少了这些对照。

## 字

- “自然”包的说明按个数写（`${DEFAULT_SPECIES.length} 种`，现在 15）；`builtin-tree.ts`、`world.ts` 的注释、`docs/dev/core.md`、`docs/dev/tests.md` 的“13 种”改成 15。
- 生态的 `terrain` 在资源库的表单里叫“导出用的地形”（以前叫“地形类别”，和地形类别那一层撞名），改成下拉，选项写中文；生态编辑器里的下拉同样写中文。表在新的 `core/export-terrain.ts`（id、中文名、地形图的颜色），`export.ts` 的 `TERRAIN_COLORS` 由它拼出（先后、数值不变）。存的还是 id。

## 地名的类型字跟着生态

大类地物的类型字（`FEATURE_INFO`）：沙漠 → 荒漠、冻原 → 苔原、冰原 → 冰盖、沼泽 → 沼泽湿地；圈地名的“沙漠” → 荒漠（`REGION_KIND_INFO`）；“地名”图层里那一组的说明。地名表、圈地名的底部条、导出的 `features.csv` 的 `type_name` 一列跟着变。类型字不存在世界里（按类型现查），所以世界、金标准都不变。

**起出来的名字没改**（“某某沙漠”“某某冻原”这些来自地名风格的模板）。试过把“中文·默认”的三条模板（`{dry}{color}沙漠`、`{cold}{nature}冻原`、`{cold}{nature}冰原`）换成荒漠、苔原、冰盖：21 个测试的摘要变了（金标准、`golden-full`、`r29`、六个库、`speed-identity`、`class-ground`……都是地物名字或带着地名风格的小数据），其中 `core/biome-legacy.test.ts` 的两条直接从资源包重新导入地名风格，它的摘要是不许改的冻结参照，测试文件也不许改，所以这一步没做，模板原样退回。别的 90 套地名风格里的“沙漠”“冻原”是外文地名的译名（Sands → 沙漠、Waste → 荒漠，同一套里两个词分开译），本来就不该机械地换。要改名字，得先决定能不能重录 `biome-legacy` 的摘要。

### 重录了什么

只有 `core/raster-identity.test.ts` 的四个 `features.csv`：

| 键 | 旧 | 新 | 变的行 |
| --- | --- | --- | --- |
| `region 256x128 features.csv` | `9698b3fc1317bece` | `d879faeb63032e51` | 苔原 1、沼泽湿地 2 |
| `region 300x150 features.csv` | `0e541387367e8929` | `2626ee7413b613be` | 同上 |
| `planet 256x128 features.csv` | `82a278aed64b92ae` | `e5a59ed7184288df` | 冰盖 2、苔原 2、沼泽湿地 7 |
| `planet 300x150 features.csv` | `07a8df239a487d49` | `0ed2ae609fa283fc` | 同上 |

核对：用一个临时测试导出这两个世界的 `features.csv`，只把 `type_name` 一列的荒漠 / 苔原 / 冰盖 / 沼泽湿地换回沙漠 / 冻原 / 冰原 / 沼泽，四个摘要都等于原来记着的值；别的列里没有这几个新字。所以这四个文件只差类型一列的字。别的测试都没变（类型字只改这一项之前，全量 207 个文件、2414 个测试全过）。
