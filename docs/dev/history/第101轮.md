# 第一百零一轮的设计：离线能用、自动化检查、拆 `core/script.ts`、文档与许可证

这一轮改了什么见 [更新记录](../../更新记录.md)。十二轮计划（第九十到一百零一轮）的最后一轮，五件事：**打开过一次以后断网也能用**；自动化检查的工作流；把 1878 行的 `core/script.ts` 拆开；文档对一遍；许可证。前提和前几轮一样：用户是对系统完全无知的新手，结果要可以预料。

生成的结果逐值不变：金标准、摘要、着色器的哈希、界面的快照（`tool-replay.json`、`input-mouse.json`）、`raster-identity` 一个都没有重录。世界文件的格式没变（`DOC_VERSION` 还是 22），IndexedDB 的库还是第 8 版。没有加任何依赖：`package-lock.json` 没动，`package.json` 只多了 `"license": "MIT"` 一行。没有发布任何东西，没有碰任何远端。

## 1. 离线能用

目标：用 `dist/` 起的页面打开过一次以后，断了网（或服务器关了——一键开启的那个黑色窗口关了就是这样）刷新还能打开、世界还在、能接着画。做法是一个手写的 service worker 加一份页面的 manifest。

### 几个文件

- `src/offline/sw-core.ts`：规则，**都是纯函数**——清单怎么认（`readPrecache`）、一个请求怎么答（`route`）、启用一版以后留哪几份缓存（`afterActivate`）、这个页面是不是那一版打包出来的（`pageIsFrom`）、在哪里登记（`canRegister`）。
- `src/sw.ts`：service worker 本身，只接线（装、启用、答请求、听页面的三句话），155 行，只引用上面那一个文件（测试查着）。
- `tools/offline-plugin.ts`：Vite 插件，只在 `vite build` 时。打包的最后一步（`closeBundle`）把 `dist/` 走一遍、算每个文件的 sha256，生成清单；把 `src/sw.ts` 另打成一个普通的脚本；写 `dist/sw.js` = 一行清单（`self.__MAP2_PRECACHE={…};`）+ 那个脚本。
- `src/offline/register.ts`：页面这一头（`OfflineWatch`）。浏览器的那几样（`navigator.serviceWorker`、定时器）都从外面给，单元测试里是假的。
- `src/state/offline.ts`：界面看的两个信号（`offlineReady`、`updateReady`）、什么时候去登记（界面画出来、页面载入完了以后；载入迟迟不算完时最多等 5 秒）和“重新载入用上新版本”的那一下；`src/ui/shell/UpdateBanner.tsx`：顶上的一条和“更多”最下面的一行。
- `public/manifest.webmanifest`、`public/icon.svg` 和三张 PNG；`index.html` 多了四行（主题色、manifest、图标）。

### 清单与缓存

量过大小再定的：

| | 个数 | 合计 | 什么时候存 |
| --- | --- | --- | --- |
| 壳：`index.html`、主脚本、样式、四个 Worker、`acorn`、manifest、图标、第三方许可证 | 14 | 6,679,847 字节（约 6.7 MB；主脚本 3.08 MB、导出 Worker 2.17 MB、计算 Worker 0.98 MB） | 装的时候全部存下；少一个、有一个对不上就不算装好 |
| 字体：霞鹜文楷按 `unicode-range` 切的小文件 | 97 | 约 4.6 MB（7–65 KB 一个） | 用到哪个存哪个；页面打开二十秒以后请 service worker 在后台一个一个补齐 |

- **壳先存、字体后补**：壳不全页面就打不开；字体只有手绘画风用，而且一段地名只用到其中几个文件。把 4.6 MB、97 个请求放进“装”里会让第一次打开时和生成世界抢，而且任何一个字体取不到整个就装不上。后台补齐是页面请的（`{type: 'fill'}`，每次打开页面说一次），service worker 中途被浏览器停掉也没关系，下次接着补。
- **离线时没存到的字**：`@font-face` 是 `font-display: swap`，取不到字体文件时那几个字用后备的字体画（和第八十七轮“字体还没载入”时一样）。`render/label-font.ts` 对同一个字这次打开页面只请一次，所以联网以后要重新载入才补上。
- **版本**是全部文件的内容和 service worker 自己的代码算出来的（sha256 的前 16 位）：没改代码重新打包，`sw.js` 一字不差，浏览器不会当成新版本。每一版自己一份缓存 `map2-sw-<版本>`。
- **存下之前都核对内容**：清单里记着每个文件的 sha256，装的时候、用到时存字体的时候都先算一遍，对不上的不存。这是量过才加的：`vite preview` 找不到文件时给的是 `index.html`（200）——service worker 正好在重新打包的那一会儿去装的话，会把一份 HTML 当成脚本存下来，以后联网、断网打开的都是坏的。现在这种时候这一次不算装好（它的缓存删掉），等浏览器下一次查。
- 不进清单的：`sw.js` 自己、点开头的文件（一键开启记的 `.map2-source-hash`）。

### 一个请求怎么答（`route`）

| 请求 | 怎么答 |
| --- | --- |
| 刷新、打开这个页面（`mode: 'navigate'`，地址是这一段的根或 `index.html`，带不带 `?`、`#` 都算） | **先问网络**：拿到正常的回答就用它（转去别处的照转）；连不上、出错（404、5xx）、3 秒没有回音，给存下的 `index.html` |
| 这一版清单里的壳 | 先看这一版自己存的；没有（不该发生）问网络，对得上就存下 |
| 这一版清单里的字体 | 先看这一版自己存的；再看别的版本存过的同名文件（名字带内容哈希，抄过来）；再问网络，对得上就存下 |
| 这一段地址下 `assets/` 里、清单里没有的（旧页面要的旧名字的文件） | 看以前的版本存过没有；没有照平常问网络，不存 |
| `POST` 等不是读的、别的网站的、这一段地址以外的、带 `?` 的文件、清单里没有的（开发服务器的 `/src/…`、`/@vite/…`、`/__map2/engine.js`） | **不管**，浏览器照平常的办 |

计算 Worker 是从 data: 地址开的（主线程先把引擎文件的字取来——这一下经过 service worker，从缓存里来），它自己不归 service worker 管，本来也不联网。存储、网格、导出三个 Worker 的文件在壳里。

**刷新为什么先问网络**（没有用常见的“页面也先看缓存”）：

1. 联网时刷新拿到的就是服务器上现在的那一份，和没有 service worker 时一样——“刷新 = 最新的”是人人都懂的规矩。
2. **开发服务器和一键开启用同一个地址**（`localhost:5191`）。页面先看缓存的话，装过一次打包好的程序以后，这个地址上的开发服务器就再也看不到了（打开的永远是存下的那一版）。先问网络，开发服务器开着时拿到的就是它的页面；它的模块都不在清单里，一个不拦；开发的页面起来以后再把这个地址上登记的 service worker 取消掉（`OfflineWatch.start` 里 `prod` 为假的那一支），开发时的行为和以前一样。

### 更新：不换掉正在用的页面

规矩一句话：**新的一版装好以后等着，页面说“现在启用”它才启用**。service worker 里没有无条件的 `skipWaiting`（整个文件里只在收到页面的 `skip-waiting` 时调一次，测试查着）。

页面知道有一版装好了的时候（`registration.waiting`，或 `updatefound` 之后它到了 `installed`），先问它“你是哪一版、壳里有哪些文件”（`info`，经 `MessageChannel` 回）：

- **这个页面的脚本都在它的壳里**（`pageIsFrom`）——页面本来就是新的一版，是联网时刷新、重新打开拿到的：马上请它启用。启用不会换掉这个页面上的任何东西，所以不用说。
- **不在**——页面是旧的：告诉界面（`updateReady`），顶上出现“有新版本，重新载入后用上”。用户点“重新载入”：先 `autosaveNow()` 把这张地图存好，再请它启用，等它接管（`controllerchange`，最多 4 秒），然后 `location.reload()`。没存成时浏览器照平常那样先问“要离开吗”。
- 问不出来（等 3 秒没有回话）：当作页面是旧的。

几种情况下用的是哪一版：

| 情况 | 结果 |
| --- | --- |
| 正在用，后台来了新版本 | 接着用现在这一版，顶上多一条；点了“重新载入”才换。不点，用多久都行 |
| 联网，自己按刷新 / 关了再打开 | 新版本（页面从网络来）；随后它请等着的那一版启用，之后断网打开的也是新的 |
| 断网，刷新 / 打开 | 上一次启用的那一版 |
| 同一个地址开着几个页面，其中一个换成了新版本 | 别的页面不重新载入、不被换掉；它们还会要自己那一版的文件（导出用的 Worker、字体、`acorn`），从**留着的上一版的缓存**里来 |
| 一个旧页面跨过两次更新还不重新载入 | 它那一版的缓存已经删了，要到的文件可能拿不到——和没有 service worker 时程序更新后的旧页面一样 |
| 装到一半失败（断网、撞上重新打包、文件对不上） | 这一次不算；正在用的一版原样，界面上不说；浏览器下次再查 |

**留两版**（`KEEP_VERSIONS`）：启用一版时，把“启用过的版本”记在一份很小的缓存里（`map2-offline-meta`），留现在的和上一版，更早的删掉；装好了但从没启用过的（被更新的一版顶掉了）也删；别的一版正在装的那一份不删（装之前先记一笔“正在装哪一版”）。这些都在 `afterActivate` 里，是纯函数。

**世界的格式**：service worker 只存程序，不碰世界。旧的一版程序遇到新的一版存的自动保存，走的是原有的那条路——`core/doc-version.ts` 的 `docAge` 认出“比这一版新”，`src/backups.ts` 启动时把它原样挪进“留着的旧世界”（第九十一、九十四轮），不去打开、不会写坏；换成新版本以后那一行上有“打开”。这条路只看世界文件里的版本号，和程序是从网络来的还是从缓存来的无关（读代码确认的，没有另外造一个“更新的版本”去冒烟）。会走到它的情形：新版本改了世界的格式，而某个页面还在用旧的一版（没点“重新载入”，或断着网打开）。

### 界面上说什么

照 [ui-design.md](../ui-design.md) 定的，都很少：

- **离线时不多说**。`navigator.onLine` 靠不住，而且断网时没有什么做不了的（除了没存到的字体）——所以没有“你现在离线”的条、没有图标。
- **能不能离线**：只在“更多”最下面一行灰字“断网时也能打开这个页面”（壳存好、service worker 启用了才有）。没有弹提示：第一次打开时用户正在挑缩略图、看帮助，不该再多一句；想确认的人在“更多”里看得到。浏览器不支持、隐私模式、开发服务器上没有这一行。
- **有新版本**：顶上一条 `.notice.banner.update-note`——“有新版本，重新载入后用上”、主要的按钮“重新载入”、×。关了以后“更多”最下面那一行换成这一句和“重新载入”，找得回来。
- 帮助多一步“离线、装到桌面”（六条）；使用说明多一节。

### 相对的 `base`

- **`tools/launchers.test.ts`**：原来的两条没动；加了一条——`launch.mjs` 算“源码变没变”时带着 `vite.config.ts` 引用的每一个 `tools/` 下的文件。

### 冒烟第十六段

`tools/smoke-offline.mjs`（`--only 16`）。这一段自己另起一个静态服务器，把 `dist/` 放在子路径 `/sub/map/` 下，另开一个存储是空的浏览器环境；“断网”是把这个服务器真的停掉（连着的也断开）。走的：

1. 打开 → service worker 装好、接管页面、壳 14 个文件都在这一版的缓存里；“更多”最下面写着“断网时也能打开这个页面”；叫它补字体 → 97 个都存下。
2. 画一笔、等自动保存 → 停服务器 → 带 `?` 的请求连不上、`POST` 连不上（没有拿存下的去答）。
3. 刷新 → 页面打开（不是自救页、不是“页面还没打开”）、陆地逐字节相同、存着的步数没变 → 再画一笔、自动保存多一步 → 地址写成 `…/index.html` 再刷新一次也打得开。
4. **一份对不上的“新版本”**（清单换了版本号，服务器上有一个文件的内容不是清单里记的）→ 不装：没有等着的、没有留下它的缓存、页面上不说。
5. **新版本**（另拷一份 `dist/`，主脚本换个名字，旧名字的从服务器上拿掉，照 `sw.js` 第一行的格式写一份新清单）→ 旧页面顶上“有新版本，重新载入后用上”；没有重新载入、还是旧的脚本、世界没动；“更多”最下面也有这一句；照常能画、能保存。
6. 另开一个页面 → 它打开的就是新版本；不用点，新版本启用了；上一版的缓存留着；旧页面还是没被换掉，它要自己那一版的主脚本（服务器上已经没有了）还拿得到。
7. 旧页面点“重新载入”→ 用上新版本、陆地逐字节相同；再停服务器、刷新 → 打开的是新版本，存着的缓存正好两版。

**前十五段的断言和脚本没有改弱**，也没有哪一段要绕过 service worker：读过才知道它们没有一步是靠“把请求挡掉”做的——自救页、打开卡住、没有 WebGL2、主体一运行就出错，都是往页面里注入脚本（`Page.addScriptToEvaluateOnNewDocument`）再换一下网址上的 `?` 重新载入；带 `?` 的导航 service worker 照样先问网络。所以 `Network.setBypassServiceWorker` 没有用上，产品里也没有加开关。前十五段现在是在 service worker 接管着页面的情况下走的。`tools/smoke.mjs` 里动的只有：接上第十六段、主服务器认 `.webmanifest` 和 `.txt` 两种类型、多认一个环境变量 `MAP2_SMOKE_CHROME_ARGS`（另外给 Chrome 的参数，自动化检查的机器上用）。

## 3. 拆 `core/script.ts`

1878 行的一个文件，里面本来就按职责分了节。照第四十一轮拆 `core/commands.ts` 的做法：代码搬进 `core/script/`，`core/script.ts` 留着当入口、照旧导出全部（51 个名字，一个不多一个不少），别处的 56 处引用一个没改。

| 文件 | 行 | 原来的哪一节 |
| --- | --- | --- |
| `core/script.ts` | 42 | 入口：整段说明、导出 |
| `script/format.ts` | 357 | 容器与格式、变量 |
| `script/shadow.ts` | 48 | “出错”里被遮住的名字那一段（`SHADOW`、`POISONED`） |
| `script/issues.ts` | 145 | 出错（其余的） |
| `script/helpers.ts` | 317 | 辅助函数；加上“运行”里的 `describe` |
| `script/editor.ts` | 28 | 编辑器用 |
| `script/compile.ts` | 274 | 编译、行号 |
| `script/inputs.ts` | 229 | 输入 |
| `script/run.ts` | 301 | 运行 |
| `script/purity.ts` | 182 | 纯度检查 |

**原样搬**：用一段一次性的脚本切的（没有进仓库）——把各节的行原样写进新文件，给别的文件要用的声明加上 `export`，生成 `import`。切完另用一段脚本核对：旧文件第 51 行起的 1690 行（不算空行，去掉行首的 `export`），和九个新文件去掉 `import`、文件头上一行说明之后的行，作为多重集合一模一样；没有拼接的六个文件里行的先后也和旧文件一样。

和“一节一个文件”不一样的三处，都是为了不绕成圈、不变慢：

- **“编译”和“行号”在一个文件里**：编译要行号那一节的 `firefoxSyntaxLine`，行号要编译那一节的 `build`。
- **`SHADOW`、`POISONED` 单独一个文件**；**`describe` 跟着辅助函数走**：出错的说明要辅助函数的名字表（猜“是不是想写 rand”），辅助函数在模块顶层就要 `SHADOW`（做遮住全局名字的替身）、颜色的报错要 `describe`。按节硬切，“出错”和“辅助函数”、“辅助函数”和“运行”就互相引用，而且是顶层就用——谁先载入谁就读到还没初始化的名字。
- **拆的时候唯一新写的一行**：`helpers.ts` 末尾的 `export const RUN_STATE = RUN;`，`compile.ts`、`run.ts` 用 `import { RUN_STATE as RUN }` 拿它（函数体里还是写 `RUN`，一个字没动）。不直接导出 `RUN` 是量出来的：见下面。

新加了 `export` 的有 18 个原来的内部名字（别的文件要用的），加上 `RUN_STATE`；它们不从 `core/script.ts` 出去。`core/script-split.test.ts` 钉着：入口导出的名字和拆之前一样、入口里只有说明和导出、新文件每个不超过 800 行、新文件之间运行时的引用不绕成圈、不值引用 `commands.ts` / `generate.ts` / `terrain.ts` / `planet-gen.ts`。

**不变慢**：脚本的运行是热路径。照任务书用同一个 Node 进程里新旧成对交替的量法（旧的 `core/` 是 `git archive c40b65d` 解到草稿目录里的；2 万格的一块地区、五种带脚本的内置奇幻生态；四样：忘掉按格记住的结果后涂一笔冷暖、让引擎把脚本真的重跑一遍；一段长在哪里的脚本在全部陆地格上连跑 8 遍；颜色脚本连跑 8 遍；编译 60 段没见过的源码）。这个量法有三个坑，都是量的时候踩到的，写在这里：

1. **旧的那一份要和仓库是同一种模块**。解出来的 `core/` 旁边没有 `package.json`，tsx 就把它当 CommonJS 编（别的文件里的函数每调一次都要过一道取值）：第一遍量出来新的比旧的“快”19%（长在哪里）、51%（颜色）——全是假的。给旧的那一份放上同样的 `package.json`（`"type": "module"`）以后才可比。
2. **同一个进程里先建的那一边和后建的那一边不一样**（差几个百分点，时正时负）。所以每一样新旧**换着位置各跑一轮**，两轮的比值取几何平均；另跑两轮“旧的自己比自己”看这个办法的宽度。
3. **“长在哪里”那一样在一个进程里会落在快慢两档上**（同一份旧代码，一个进程里最快 21.7 毫秒、另一个进程里 24.2 毫秒，和新旧无关），所以它另用“每个进程只量一边、新旧的进程交替着起”再量一遍。

结果（最后一次改源码之后量的；新 ÷ 旧 − 1，负的是新的快）：

| | 同一个进程里成对交替（每样 15 对，换着位置两轮的几何平均）：成对比值的中位数 / 各自最快的一次 | 对照：旧的自己比自己 | 每个进程只量一边（新旧各 6 个进程交替着起，每个进程 9 次）：相邻两个进程之比的中位数 / 各自最快的一次 | 最快的一次（毫秒）新 / 旧 |
| --- | --- | --- | --- | --- |
| 引擎把五种带脚本的生态重跑一遍（涂一笔冷暖） | −4.9% / −1.8% | +1.1% | −0.3% / +0.3% | 61.98 / 61.81 |
| 长在哪里的脚本 × 8 遍（7460 格） | +1.5% / +1.8% | +1.7% | +0.5% / +0.1% | 21.52 / 21.51 |
| 颜色脚本 × 8 遍 | +0.1% / −0.5% | −0.5% | −0.2% / −0.6% | 10.12 / 10.19 |
| 编译 60 段 | +0.7% / −0.3% | −0.6% | −0.3% / +0.1% | 4.97 / 4.96 |

都在这个办法自己的宽度（“旧的自己比自己”也有 ±2%）以内，没有一样到 +5%。两边算出来的东西逐值相同（推导的几层的摘要、脚本输出的和）。“引擎”那一样一次 60–80 毫秒、次与次之间差得多（中位数比最快的一次大两成），所以同一个进程里的 −4.9% 不当真；分进程量是 −0.3%。

`RUN` 的别名是这样量出来的：直接 `export const RUN` 时，颜色脚本稳定地慢约 3%（两种量法都是：成对 +2.5% / +3.4%，分进程 +3.5%）——Node 的模块里导出的名字每次读都要过一道，`helpers.ts` 里的辅助函数每格读它好几次；换成别名（`RUN` 自己不导出）以后回到 0 上下。打包后的程序里没有这回事。

## 取舍

- **刷新先问网络，不是先看缓存**：见第 1 节。代价是很慢的网络上刷新要多等最多 3 秒才给存下的那一份。
- **“有新版本”是一条能关的提示，不是问话框**：不打断正在画的人。
- **没有在“可以离线了”时弹提示**：见“界面上说什么”。
- **没有自己定时去查新版本**（`registration.update()`）：浏览器在打开、刷新页面时自己查。一键开启的用法里，重新打包以后总要重新打开页面。
- **只留两版缓存**：留得更多占地方（一版约 7–11 MB），而跨两次更新还不重新载入的页面很少。
- **service worker 不用模块、不拆文件**：打成一个普通的脚本，各家浏览器都认。
- **图标没有另画一张“可遮罩的”**：同一张图四周留够了边，两种用途都指它。
- **CI 里最慢的五个文件单独跑**：不是跳过。一起跑时它们在忙的机器上超时（本机就这样），那样每晚都是红的，没有用。

## 没做的、要知道的

- **只在无头 Chrome 里走过**：断网（停服务器）、更新、子路径。Firefox、Safari、iPad、手机都没有试；真的“装到桌面 / 主屏幕”没有做过（manifest 只是照规范写的，Chrome 的“安装”图标出不出来没有亲眼看）；iPad 上装成应用以后的存储和 Safari 里的是不是同一份没有验证。
- **用调试协议断网没有试**：冒烟里的“断网”是把服务器停掉。真的没有网络时浏览器的行为（比如 `fetch` 多久才失败）可能不一样——刷新时最多等 3 秒就给存下的那一份，是为这个留的。
- **只在单元测试里走过的**：`OfflineWatch` 的各条路里“问不出它是哪一版”“等不到它接管、到点照样重新载入”“连着来两版只说一次”“登记失败不出错”“开发服务器上把以前登记的取消掉”；`afterActivate` 里“正在装的那一版不删”“从没启用过的删掉”；`route` 的全部分支里冒烟没走到的（别的网站、`HEAD`、子路径以外）。
- **读代码推的、没有验证**：旧的一版程序遇到新的一版存的世界时挪进“留着的旧世界”（原有的路，这一轮没有改，也没有另造一个版本号更高的世界去走）；开发服务器的页面被以前登记的 service worker 管着时模块一个不拦（`route` 的单元测试里有这些地址，没有真的在 5191 上试——任务书不让碰）；`vite preview` 给 `sw.js` 的响应头各家浏览器都认。
- **第一次打开、程序还没存好（几秒钟）就断网**：下次断着网打不开。
- **字体**：断网时没存到的字写成后备的字体；同一个字这次打开页面只请一次，联网以后要重新载入才补上。
- **浏览器自己清存储**（空间紧张、Safari 很久不用）会把程序和世界一起清掉——这一轮没有新做什么（第九十四轮申请过“持久”的存储）。

- **自动化检查没有跑过**（见第 2 节）。
- **图标只是一张简单的图**，没有请人看过在各家的主屏幕上好不好看。
