# 第七十八轮的设计

这一轮改了什么见 [更新记录](../../更新记录.md)。用户定的（第七十七至八十轮的计划）：**省份划分的规则成为资源包里的内容**，
“省份 ⋯”里只留“划分省份 / 换一种划分”。用同样的规则划出来的省份逐值不变。

## 以前 → 现在

| 以前（每个世界的 `small.provinceRules`，“省份 ⋯”里调） | 现在（资源库里的“省份划分” `provinceRules`） |
| --- | --- |
| `size`（小 · 中 · 大 = 20 · 40 · 80 格）与第二十七轮的滑块 `sizeCells`（有它时不看 size） | `size`（格数，按 4 万格的一块地区标定；就是 `sizeCells ?? 那三档`）。滑块 8–200（以前滑块的范围），格式收 4–400 |
| `varied`、`wasteland`、`lakeMode`、`seaByDistance` | 同名的开关、两选一 |
| `riverCost`、`ridgeCost`（没露出来） | “沿河”“沿山脊”两个滑块（0–20，步长 0.5） |
| `seed` | 世界的 `small.provinceSeed`（不是规则；“换一种划分”加一） |

- 命令：`generate_provinces` 只有 `seed`（省略时沿用世界记着的），`regenerate_provinces` 只有 `cells`，都改成严格的格式（`.strict()`）：旧的 `rules`、`size` 报错。`set_lake_mode`（“只整理湖”）去掉了，见下面“湖”。`provinceRulesPatchSchema`、`provinceSizeCells`、`setLakeMode` 去掉了。
- 世界：`small.provinceRules` → `small.provinceSeed`；内容里多一份 `content.provinceRules`（与 `origin`）。世界文件的版本 17 → 18。
- 核心读规则的地方都读世界的那一份（`core/province-rules.ts` 的 `worldProvinceRules`）：整体划分、重新划分一片、陆海变了以后的修补（`fillUnassigned`）、按国界切开（`fitProvincesToCountries`）、湖与陆地的整理（`lakeProvinceFix`）。

## 这种内容

- `core/province-rules.ts`：格式、内置的一份 `DEFAULT_PROVINCE_RULES`（id `standard`，名字“默认”；不叫 default：称号表里的“其余的”键是 default，引用表的检查会当成引用；数值与以前的默认逐个相同：40 格、按地形、无人区、湖单独成省、近海小远洋大、沿河 4、沿山脊 2）。计算 Worker 只用到这一个小常量（世界里没有省份划分时的默认），不打包内置的库。
- `core/content/province-kind.ts` 登记进登记表（在画风之后、自定义场之前：资源包里的段 `provinceRules` 排在最后）。放在 `small.content`，命令是通用的 `set_content`。
- **一个世界只有一份**（`maxInWorld: 1`）。几份同时在的话，用哪一份要另有一个“选的是哪一份”（像画风的 `small.mapStyle`），面板上还要多一个选择，和“只留划分省份 / 换一种划分”相反。一份时：资源库里本世界的那一页就是生效的规则；库里有几份时，加另一份要先移出现在的（清单里灰着写“最多 1 个”）。
- **没有时按默认**：移出以后照内置的那一份划（与以前没改过规则的世界一样），不拦着移出（没有“还在用”）。清理（`TIDY_KINDS`）不看它，不会被“清理没用到的”清掉。
- **内置的一份在每个库的“基础”里**，新世界带上（`worldPartsOf` 本来就带基础，没加新的小包）；资源库首页“地理”一段多一张卡片“省份划分”（`page-layout.ts`、图标 `LandPlot`），页面分四段：基本、大小（大小、按地形、无人区）、湖与海、省界（`page-segments.ts`）。
- 引用表（`link-rules.ts`）：没有引用。融入（`arrange.ts`）、库与世界的差异（`source-diff.ts`）、闭包、换库都是通用的，不用改；换库时两个库的“默认”是同一份。
- 从库里添加到已经划过省的世界时，清单底下写“在“省份 ⋯”里划分省份后才用上”（`pick-other.ts` 的 `regenLine`）。面板顶上的“重新生成”只管人文、国家、城市，不管省份：划分省份在“省份 ⋯”里，改了的人自己点。

## 湖：改了马上整理

世界里的省份一直照着规则的“湖”整理：放湖、删湖、湖干了、改地形以后，引擎按规则把湖面的格放进湖省或并进陆地省（`lakeProvinceFix`）。
以前规则只在划分省份和“只整理湖”时变，所以整理时用的和划出来的总是同一个。现在规则在资源库里改，改了“湖”却不整理的话，
下一次改地形会顺手把全世界的湖整理成新的样子，结果难以预料。所以：

- 省份划分的 `dirty`：湖的归属变了（加、改、移出时按生效的规则比）是 `names`，别的是 `none`。不是 `none` 的一步之后引擎本来就会按新的湖整理省份（`fixLakeProvinces`），记进这一步的命令（`provinceFix`，重放、重做照用），只动湖与陆地之间的格，别的省份不动——与以前的 `set_lake_mode` 是同一个函数、同样的结果（核对见下）。
- 所以 `set_lake_mode` 和“⋯”里的“只整理湖”去掉了：在资源库里改了湖就是整理湖。
- 别的几项（大小、按地形、无人区、近海、沿河、沿山脊）改了不重算，“划分省份”才用上（同第七十七轮时代里的国家大小）。

## 行为上的不同

- **修补按世界现在的规则**：以前改了陆海以后的修补（并进不太大的相邻省）按上一次划分时的规则；现在按世界里现在的规则。只在资源库里改了大小、没重新划分时不同（修补用新的目标大小），用默认、改了就划分的世界一样。
- **“一个国家”的大小滑块去掉了**（`CountrySizeBox`、`SizeSlider`、`provinceAreaText`，`regenerate_provinces.size`）：以前这一次划分用另一个大小，但划完以后的填补（`fillUnassigned`）和按国界切开照旧按世界的大小，本来就不是完全按那个大小。现在重新划分一片（选一国的格也一样）按世界的规则；要别的大小先在资源库里改。
- “省份 ⋯”里的按钮：“划分省份”（按世界的规则和现在的种子；以前叫“重新划分”“按新规则重新划分”）、“换一种划分”（种子加一）。鼠标停在上面照旧先画出新的省界。旁边一句“省份多大、按地形、无人区、湖……在资源库的‘省份划分’里改”（`copy.ts` 的 `PROVINCE_RULES_NOTE`）和“省份划分”按钮：打开本世界那一份的页面；世界里没有时开本世界的省份划分列表（`packs/open-province.ts`）。

## 核对：结果逐值不变

两个临时的测试（不提交），在第七十七轮的代码（82e28a7，另检出的 git worktree，接上同一份 node_modules）和这一轮上各跑一遍，逐项比较。

**1. 同样的操作，旧的命令与新的写法**（`proof/r78-proof.test.ts`，同一个文件两边都能跑：按有没有“省份划分”这种内容分开写命令）。
旧的写 `generate_provinces { rules }`、`regenerate_provinces { cells, size }`、`set_lake_mode`；新的先把规则写进世界的“省份划分”（`set_content`，和现在的一样时不多一步），再 `generate_provinces { seed }`，湖用 `set_content` 改。
每个世界导出全部类型数组（网格、原因、自定义场、推导连同人文的、修正场）的摘要、地物，和整个小数据（JSON）。一共 123 个世界：

- 金标准的三组操作（`referenceHashes`、`extendedHashes('region' / 'planet')`）；
- 一块地区（1.2 万格）上十二种规则：默认、小、大、`sizeCells` 120 与 9、不按地形、没有无人区、湖并进陆地省、近海远洋一样大、沿河 10、沿山脊 0、几项一起改；每种依次划分、重新划分一片、画陆地、画海（修补按规则）、换湖的归属（旧的 `set_lake_mode`）、换一种划分、撤销，每一步都比；
- 整个星球（5000 格）：默认、小 + 湖并进、重新划分一片、画陆地、`sizeCells` 150 + 没有无人区；
- r29 的七种设置（古典到科幻，带国家、城市）：生成人文、重新生成国家、重新划分一个国家（世界的规则）、带着国家按 `sizeCells` 25 不按地形划分、按同样的大小重新划分另一个国家（旧的写 `size: 25`）。

结果：**类型数组、地物的摘要 9020 项，不同 0 项**。小数据不同的只有这几类：

| 路径 | 处数 | 是什么 |
| --- | --- | --- |
| `provinceRules` | 120 | 去掉的字段 |
| `provinceSeed` | 120 | 种子搬到这里 |
| `content.provinceRules`、`origin.provinceRules` | 各 120 | 新世界带的“省份划分”与它的来源（`[medieval, base]`） |
| 金标准两组的 `small` 摘要 | 2 | 同上 |

另一个脚本逐个核对了这 120 个世界：旧的 `small.provinceRules` 换算过来（`sizeCells ?? 小 · 中 · 大`、六个开关和数、`seed`）与新的内容和 `provinceSeed` 逐项相同（38 种不同的规则）。

**2. 重录的摘要**：重录之后，在两边临时给 `core/digest.ts` 加一层：算 JSON 的摘要时去掉 `provinceRules`、`provinceSeed` 这两个键（世界里、内容里、来源里的都去掉），并记下每一次的结果。
两边各跑一遍重录过的八个测试文件（`golden-full`、`biome-legacy`、`class-ground`、`speed-identity`、`solver-identity`、`ocean-plane`、`libraries`、`raster-identity`），
七个文件一共 16390 次摘要（15724 次类型数组、666 次 JSON）**两边逐个相同**，先后也相同；`raster-identity` 用的是自己的哈希，只有 `world.json` 四项变了（世界文件：版本 18，划分省份的命令只写种子），图片、高度、表格一项没变。

## 测速

核心只是换了读规则的地方（世界里的那一份，取第一项），划分、修补的算法不变。`tools/bench.ts` 划分省份按有没有“省份划分”这种内容写命令
（旧的提交上 `{ rules: { seed } }`；那时的格式不严格，新的写法不报错、只是丢了种子，所以不能像第七十七轮那样先试再退）。

| erod | 215 → 200 | 201 → 207（+3%） | 379 → 391（+3%） | 379 → 367 |
