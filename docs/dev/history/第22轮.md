# 第二十二轮的设计

从开发说明里搬来（第四十一轮）。这一轮改了什么见 [更新记录](../../更新记录.md)；现在的文件见 [开发说明](../../开发说明.md) 与 docs/dev/ 下的各篇。

## 时代、文化、人口（第二十二轮）

人文的第二批：一个世界一个时代，人口按宜居度分到各格，每格记人数最多的 4 个人口群体（群体 = 文化 + 时代每一维的取值），文化圈就是“每格人口里占多数的文化”，地名跟着当地的文化。都只读自然的推导，不反向改地形（`core/human/`）。生成的顺序是 文化圈 → 国家（第二十三轮，见“国家与政体”）→ 人口 → 国家的移民。

**四种内容**（`human/era.ts` 的格式，`human/pop-kinds.ts` 登记；都是 `store: 'content'`，命令 `set_content`，改了重算到 `human`）：

| 种类 id | 全称 | 资源包的段 | 世界里 | 内置的 |
|---|---|---|---|---|
| `era` | 时代 | `eras` | `small.content.era` | `BUILTIN_ERAS` |
| `popValue` | 人口维度的取值 | `popValues` | `small.content.popValue` | `BUILTIN_POP_VALUES` |
| `cultureGroup` | 文化组 | `cultureGroups` | `small.content.cultureGroup` | `BUILTIN_CULTURE_GROUPS` |
| `culture` | 文化 | `cultures` | `small.content.culture` | `BUILTIN_CULTURES` |

内置的不是总在的（不像地形类别）：在资源库里启用，或者生成人文时自动复制进来（`generate.ts` 的 `ensureHumanContent`：时代、它那几维的内置取值、用到的文化组、世界里一个文化都没有的组的内置文化、文化用的内置地名风格；世界里已有同 id 的不动）。世界里的列表按启用的先后（`worldEras` / `worldPopValues` / `worldCultureGroups` / `worldCultures`），编号 = 下标 + 1，0 是没有；某一维的取值 `dimensionValues(small, 维度 id, 时代 id?)`（只列属于这一维、不限时代或包括这个时代的）。

**偏好**（`preferenceSchema`）：按格的条件（与地形类别的规则同一种写法，见上一节的“按格的条件”，可以写 `classes`——只有起伏；森林、荒漠、草原写 `terrain` 或 `biomes`）加一个倍数 `factor`（0–20）。第二十七轮把内置包里写植被类别的偏好一次改成了生态的条件：和平原写在一起的（“平原、草原、森林”）改成平原上的那几种地形；和起伏写在一起的（“干草原、沙漠、高原”）拆成起伏的一条与“别的起伏上的植被”一条，不会在同一格连乘两次。写了的几项都满足时宜居度乘以它，几条都满足时连乘。例：`{ "classes": ["mountains", "peaks"], "factor": 4 }`（矮人喜山）、`{ "coast": true, "factor": 1.5 }`、`{ "tempMin": -2, "tempMax": 16, "factor": 2 }`、`{ "terrain": ["desert"], "factor": 0.3 }`。

**带权重的一组 id**（`weightedIdsSchema`）：`["a", ["b", 3]]`——`"a"` 权重 1，`["b", 3]` 权重 3（编辑器的 `weighted`）。

**时代**（`eraSchema`）：

```json
{
  "id": "medieval",
  "name": "中世纪与近世",
  "description": "封建领地与王国……",
  "color": "#a0703c",
  "dimensions": [{ "id": "religion", "label": "宗教", "required": true }],
  "popDensity": 2.7,
  "sparsity": 1.6,
  "urbanization": 0.1,
  "unclaimed": { "minHabitability": 0.05, "nomads": 0.35 },
  "seaClaimKm": 0,
  "defaultGroups": [["western", 3], ["eastern", 3], ["mideast", 2], ["southasia", 2], ["slavic", 1.5], ["steppe", 1.5]],
  "cultureGroups": ["western", "eastern", "steppe", "nordic", "…"],
  "governments": [], "factions": [], "resources": ["grain", "livestock", "…"]
}
```

- `dimensions`：文化之外的维度（文化总是第一维，不写），按先后，最多 3 维。`id` 是维度的 id（取值的 `dimension`、文化的 `tendencies` 的键都用它；几个时代可以共用同一个 id，比如 `religion`），`label` 是名字（宗教、种族、民族认同、意识形态……），`required`：每个人都有这一维的取值（文化没写倾向时在这一维的全部取值里平分；不写时没有倾向的文化在这一维是空的）。
- `popDensity`：默认的人口密度，人 / km² 陆地（湖面不算）。默认总人口 = 它 × 干的陆地面积（`defaultTotalPop`）。按地球大小（陆地约 1.49 亿 km²）标定：中世纪 2.7 → 约 4 亿；青铜时代约 0.2–0.4，古典约 1.3，近世约 4，近现代约 10，现代约 50（内置的取值见下面的“内置的时代与文化”）。
- `sparsity`：人口有多集中，每格的人数 ∝ 宜居度 ^ sparsity（0.5–5；1 均匀些，青铜时代 2.5–3 挤在河谷里）。
- `urbanization`：城市化率 0–1（第二十四轮放城市时用）。
- `unclaimed`：宜居度低于 `minHabitability` 的格人口再乘以 `nomads`（0 没人住，1 照常）。青铜时代 `{0.25, 0.05}` 大片空地；中世纪、DnD `{0.05, 0.3}` 稍差的地方也住了人、游牧民住恶劣的地方；现代 `{0.01, 0.8}` 全部填满。第二十三轮国家也按它留无主地。
- `seaClaimKm`：领海（第二十三轮）：离岸多少 km 以内的海算国家的，0 是海不归任何国家。内置的按“地图上看得出一圈近海”定（近现代 40、现代 120、科幻 200），不是法律上的 22 km：一格约 100 km 时 22 km 一格都占不到。
- `defaultGroups`：新建向导默认勾的文化组与各占多少；`cultureGroups`：这个时代能用的文化组（省略时不限；只是给界面的提示，命令不拦）。
- `governments`、`factions`：这个时代能用的政体、派系（第二十三轮，见“国家与政体”）；`resources`：以后的轮次用的资源 id，现在只是存着。`countryKm2`、`years`（第二十三轮）：国家平均多大、年份的范围，见“国家与政体”。

**人口维度的取值**（`popValueSchema`）：

```json
{ "id": "ancestor-rites", "dimension": "religion", "name": "祖灵信仰", "color": "#9a6a4a",
  "description": "祭祀祖先与地方神灵。", "eras": ["antiquity", "medieval", "industrial", "modern"],
  "prefs": [{ "classes": ["hills", "mountains", "forest"], "factor": 1.5 }] }
```

- `dimension`：属于哪一维（时代的 `dimensions` 里的 id）。`eras`：只在这些时代里有（省略时不限；内置的都写明了，几个时代共用同一维的 id 时靠它分开，比如奇幻的宗教与历史上的宗教都是 `religion`）。
- `prefs`：有这一取值的人在哪里更多（矮人 × 山地）——只影响一格里的成分（这一维取哪个值），不影响一格的总人数。

**文化组**（`cultureGroupSchema`）：

```json
{ "id": "elves", "name": "精灵", "color": "#3c964b", "description": "……",
  "prefs": [{ "classes": ["forest", "woods"], "factor": 3 }, { "classes": ["desert", "steppe"], "factor": 0.4 }],
  "eras": ["fantasy"] }
```

- `prefs`：喜欢的地理：发源地按“宜居度 × 偏好”挑，扩张时偏向这些地方（走一条边的代价 ÷ √偏好），人口也更多住在这里。
- 同一个组里的文化互相兼容（第二十三轮国家用）。

**文化**（`cultureSchema`）：

```json
{ "id": "yamato", "group": "eastern", "name": "汐见人", "color": "#d26900", "nameStyle": "ja-kanji",
  "weight": 1, "description": "……",
  "tendencies": { "religion": [["ancestor-rites", 4], ["awakening", 2.5], ["sky-way", 1], ["secular", 3], ["elder-dragons", 3]] },
  "prefs": [{ "coast": true, "factor": 1.5 }] }
```

- `group`：文化组的 id。`nameStyle`：地名风格的 id（`core/packs/names/` 里的内置风格，或世界里启用的）；生成时内置的会自动启用。
- `weight`：在组里占多少（省略为 1）：组里的人按它分。
- `tendencies`：默认倾向，维度 id → 带权重的取值。生成时每格按 权重 × 取值的偏好 × e^(1.6·噪声) 再取 2.5 次方归一（噪声按地图上的位置，波长约 1200 km：同一种宗教成片），占比不到 4% 的去掉，每维最多 3 种。世界里没有的取值跳过——所以几个时代的取值可以写在同一张表里，每个时代只认它有的（上面的汐见人：中世纪认前三种，现代多认“无宗教”，奇幻只认“古龙崇拜”）。权重不分时代：同一个取值在每个时代都是同一个权重，要按时代变就用不同 id 的取值。因为取 2.5 次方，比最大的小 4–5 倍的取值只在噪声偏向它的地方成片出现。
- `prefs`：自己喜欢的地理，与组的连乘。

**写内置的时代与文化**（给写内容的人）：

1. 时代：`core/packs/eras/<时代 id>.json`，写 `{ "era": {...}, "values": [...] }`（`values` 是只属于这个时代的取值，可以省略）；在 `core/packs/eras/index.ts` 的 `ERA_FILES` 里加一行。
2. 几个时代共用的一维的取值：`core/packs/eras/values/<维度>.json`，一个数组，每项用 `eras` 写明在哪几个时代里有；在 `VALUE_FILES` 里加一行。同一个 id 只算先列的那一个（`VALUE_FILES` 在 `ERA_FILES` 前面）。
3. 文化组：`core/packs/eras/cultures/<组 id>.json`，写 `{ "group": {...}, "tendencies": {...}, "cultures": [...] }`；在 `CULTURE_FILES` 里加一行。资源库里按这几张表的先后列出。`tendencies` 是组里文化的默认倾向（格式同文化的 `tendencies`，只在文件里有，文化组本身没有这一项）：文化自己写了的那几维换掉组的（不是合并），没写的照抄组的；读进来的 `BUILTIN_CULTURES` 每个都带着完整的倾向。
4. id 用小写字母、数字、连字符；名字不超过 20 个字；颜色 `#rrggbb`。同一个时代能用的文化组、文化，同一维、同一个时代的取值，色差（CIE76）要分得开（`eras-builtin.test.ts` 查：组、取值 > 18，文化 > 14，同组的文化 > 18）；文化组、文化不要太暗、太亮、太灰。
5. 文化的名字用自己编的、有那种语言味道的（“卡尔维人”，不写“德国人”）；文化的 `nameStyle` 写内置风格的 id（见“地名风格的写法”的 27 种，每一种都有文化在用）。
6. 偏好的倍数一般 0.3–4；组的偏好决定发源地落在哪、地盘往哪长（偏好太强时组会挤在一小块里）。只写喜欢的不够时加一条不喜欢的（草原组的森林、山地 × 0.5，西欧的干草原、沙漠 × 0.7），不然地盘会被权重大的组挤到别处。倾向的权重写相对大小（3 : 1）。
7. 每个文化在它能用的每个时代（时代的 `cultureGroups` 里有它的组、组的 `eras` 里有这个时代）的每一维都要有这个时代认的倾向，不靠“每人都有”的平分（测试查）。
8. 维度的取值的名字用通用的叫法或自己编的，不照搬真实宗教的教义文字；意识形态按光谱细分时每一维最多十几种。
9. `population.test.ts` 用内置的中世纪与西欧、东亚、草原三组生成，记着金标准（改了这几样的数据就要重录那两组哈希）；`eras-builtin.test.ts` 查全部内置的内容（见“测试”）。

**世界里的数据**（`world.ts`）：
- `small.human`：`{era, seed, groups: [{id, weight, cultures?}], totalPop, perWeight, hearths: [{group, culture?, cell, locked?}], nextGroup}`——生成用的参数、每一份“生成权重”合多少人（修补新陆地用）、发源地（文化组的写 `group`，组里文化的另写 `culture`；拖过的 `locked`）、下一个群体的编号。
- `small.popGroups`：群体的编号 → `{culture, values: {维度 id: 取值 id}}`（没有这一维的取值时不写）。生成后按第一次出现的格重新编号（1 起，`groups.ts` 的 `compactGroups`）；笔刷用到新的群体时往后加（`GroupTable`）。
- 原因（可选，生成时才建，撤销到那之前时去掉，进撤销、检查点、快照）：`causes.popTotal`（Float32，每格的人数）、`causes.popGroup`（Uint16，n × 4：第 i 格是 `[4i, 4i + 4)`，按占比从大到小，0 是空位）、`causes.popShare`（Uint8，n × 4，占比 /255，4 个加起来不超过 255，剩下的是“其他”）、`causes.popManual`（Uint8，1 是笔刷、档案改过的格，第一次改时才建）。读一格用 `readComp(causes, i)`（`[{code, s}]`，s 是 0–1，code 0 是“其他”）。
- 推导：`derived.habitability`（Float32，0–1，总有，水面为 0）；只在生成过人文时有：`popDensity`（Float32，人 / km²）、`popCulture`、`popCultureGroup`（Uint16，人口里占多数的文化、文化组的编号，0 没有人）、`popValue`（Uint16，n × 维度数，按维度分段：第 k 维是 `[k·n, (k+1)·n)`，`valueLayer(world, k)` 取那一段，编号是 `dimensionValues` 的下标 + 1）、`cultureNear`（Uint16，最近的文化：从有人的格按步数往外扩，海、没人的地方也有，地名用）。占多数按 4 个群体里同一个文化（组、取值）的占比相加，“其他”不算，一样多时编号小的。`HUMAN_DERIVED` 加了 `habitability`，`POP_DERIVED` 是人口的几层；都不进金标准的 `digestWorld`。
- 没生成过人文的世界：原因、小数据里一项都不多（`habitability` 是推导，不进金标准）。

**宜居度**（`human/habitability.ts`，推导，自然改了、画了地形类别就重算，只画人口时照用上一份）：每格 = 生态的宜居分 × 冷 × 水与海岸 × 地势 × 地形类别（起伏）的倍数，截到 [0, 1]，只算干的陆地。
- 生态的宜居分：生态写了 `habitability`（0–1，生态编辑器、`update_species` 改，只改它时重算到 `human`）就用它；内置的 13 种按 `BIOME_HABITABILITY`（第二十七轮：原来的生态分 × 原来植被类别的倍数，植被只算一遍——冰盖 0.002、苔原 0.1、针叶林 0.31、温带阔叶林 0.72、温带草原 0.6、地中海灌木 0.71、亚热带常绿林 0.68、稀树草原 0.57、热带干燥林 0.54、季雨林 0.53、雨林 0.25、沼泽 0.18、荒漠 0.042）；别的按生态的地形（plains 0.8 … desert 0.05、arctic 0.065）与最适合的气温估（`biomeHabitability`）。
- 冷：年均温 0 °C 以下渐渐变少，−15 °C 以下只剩一成。
- 水：有河（流量够画成河）时先至少 0.45 ×（0.6 + 0.4 × min(1, 生态分 / 0.6)）（荒漠里的大河两岸也能住人；第二十七轮按植被打折，以前是植被类别乘上去的，所以荒漠、沼泽的河边与以前差不多），再 ×1.35–1.8（河越大越多）；挨着海 ×1.3，挨着湖 ×1.2。
- 地势：海拔 1500 m 以上渐渐变少，5000 m 以上只剩 5%；坡度 ×1 / (1 + 坡度 / 30)。
- 地形类别：类别写了 `habitability`（0–3）就用它，内置的按 `CLASS_HABITABILITY`，只按起伏（平原 1，丘陵 0.92，高原 0.82，山地 0.5，山峰 0.09；第二十七轮比以前略高，因为植被的那一份现在也乘在起伏上）。改了以后同样的世界、同样的时代总人口不变（按默认密度 × 陆地面积），宜居度的平均变了 1–2%。

**生成**（`human/generate.ts` 的 `generateHuman`，分步，每一步是一个 `HumanStage {id, run(ctx)}`，共用的东西在 `GenContext`，见 `human/context.ts`）：
1. **文化圈**（`human/cultures.ts`）：
   - 发源地个数：全世界 max(组数, 陆地面积 / 2500 万 km²)，按权重分给各组，每组至少一个。按“宜居度 × 组的偏好 × (1 + 0.35·噪声)”挑，与已有的发源地隔开 0.6·√(陆地面积 / 个数)（挑不出来时放宽），装不下这一组那一份的小岛得分低；同一组的第二个靠近第一个。权重大的组先挑，每一轮每组挑一个。拖过的（`locked`）留在原处（变成了海的挪到最近的陆地）。
   - 地盘：各组从发源地按代价同时往外长（`space.ts` 的 `growByBudget`），每格归先到的那一组，一组占的“宜居的面积”（km² × 宜居度）到了按权重分的那一份就停下、让给别人，最后谁都没占到的格归最近的。代价：陆上 km × 通行难度（第二十七轮：起伏 × 植被，`cellMovement`）× (1 + 高低差 / 600) × 过河 1.5；进湖 ×3；下海 ×8、海上 ×4、上岸 ×2（跨海贵但能过）；÷ √组的偏好。海也分给了各组。
   - 组里的文化：在组的地盘里同样挑发源地（一个文化一个）、按文化的权重分地盘。拖到组的地盘外的文化发源地那一格归这个组。
   - 结果：`ctx.groupOf`、`ctx.cultureOf`（每格是第几个组、第几个文化，−1 没有）、`ctx.hearths`。
2. **国家**（第二十三轮，见“国家与政体”：`countries` 一步在人口之前，改 `ctx.popScale`（每格人口权重的倍数）；`country-mix` 一步在人口之后）：别的步也可以用 `registerHumanStage(stage, {before: 'population'})` 插进来。`humanStages()` 列出现在的步骤。
3. **人口**（`human/population.ts`）：每格的权重 = km² × min(1.5, 宜居度 × 文化的偏好)^sparsity（宜居度低于 `minHabitability` 再 × `nomads`，× `popScale`）；每个文化分到 总人口 × 组的权重比例 × 组里文化的权重比例（地盘里没有能住人的格的文化那一份分给别的），在自己的地盘里按权重分。成分：本地的文化，文化圈边上掺邻近的文化（离另一个文化的地盘 d km，掺 0.5·e^(−d / 格距)）；每个文化各维按倾向分（见“文化”），各维的组合里取最多的 4 种。手改过的格在保留手改的重新生成里不动（总人口扣掉它们的人）。
4. 写进 `small.human`、整理群体的编号。内容（时代、组、文化、风格）缺的从内置的复制进来。

**命令**（都是 `Dirty.Human`：只重算人文的几层与名字；撤销记 `popTotal / popGroup / popShare / popManual` 四个数组）：
- `generate_human {era, groups: [{id, weight, cultures?: id[]}], totalPop?, seed?}`：生成（已有人文时整个换掉，手改的不留）。`totalPop` 省略时按时代的默认密度，`seed` 省略时用世界的种子。历史“生成人文“中世纪” · 3 个文化组 · 4.0 亿”。不认识的时代、文化组报错。
- `regenerate_human {era?, groups?, totalPop?, seed?, keepManual?}`：按记着的参数重新生成，写了的几项换掉；拖过的发源地留着（换了组时不在新组里的去掉）；`keepManual` 省略为 true（手改过的格不动）。“重新生成人文”。
- `move_hearth {group | culture, index?, cell | null, keepManual?}`：挪一个发源地（文化组的写 `group`，同组有几个时 `index` 是第几个；组里文化的写 `culture`），挪过的锁定，`cell: null` 是恢复自动；之后照 `regenerate_human` 重新生成。“挪动发源地“西方””“发源地“西方”恢复自动”。
- `remove_human {}`：去掉人文（人口清零，数组留着，小数据里的去掉）。“删除人文”。`set_worldgen` 的新世界也去掉。
- `set_pop_total {total}`：总人口按比例改（每格 × 同一个倍数）。“总人口 · 2.0 亿”。
- `paint_pop {cells, t?, mode, ...}`：人口笔刷，只画干的陆地，`t` 是画笔的权重（0–1，与 cells 对齐，省略为 1）。改过的格记 `popManual`。
  - `mode: 'share', group: {culture, values}, amount`：这个群体的占比升高 a = amount × t（每个群体 × (1 − a)，这个群体 + a），人数不变；没人的格不画。“人口“阿拉伯 · 月轮教” · 36 格”。
  - `mode: 'count', factor`：人数 × factor^t（0.01–100；Shift 反过来由界面给 1/factor）；没人的格在 factor > 1 时按最近的有人的格的成分补上一些人（世界的平均密度 × 宜居度 × (factor^t − 1)）；不到半个人的清零。“人数 ×1.5 · 36 格”。
  - `mode: 'value', dimension, value, amount`：每个群体里 a 的人这一维换成 value（传教、改宗），文化与别的维不变。“宗教改为“月轮教” · 36 格”。
- `paint_culture {cells, t?, culture, amount, typical?}`：文化笔刷：每个群体里 a 的人换成这个文化（别的维不变）；`typical` 时换成这个文化最典型的群体（`typicalTuple`：每一维取倾向里权重最大的）。“文化“法兰克” · 36 格”。
- `set_cell_pop {cell, total?, groups?: [{culture, values, share}]}`：档案里改一格（只能是陆地）：总人数、各群体的占比（0–1，不到 1 的是“其他”，超过时按比例缩）。“人口改为 5000”“修改人口”。
- 群体里的文化、取值要在世界里，维度要是这个时代的，不然报错。历史里几格是真改了的格数（已经是这个文化的格不算）。

**改地形以后的修补**（`population.ts` 的 `populationFix`，`Engine.fixPopulation`）：一步改了陆海、湖之后（推导算好之后，与湖省的整理同一个地方）：变成水面（海、湖）的格去掉人口；这一步之前是水面、现在是干的陆地、还没有人的格，按宜居度补上人（km² × (宜居度 × 最近的文化的偏好)^sparsity × `small.human.perWeight`，低于 `minHabitability` 再 × `nomads`），成分照最近的有人的格。别处的人数不动（宜居度变了也不动，要整体重来时重新生成），手改过的格只在变成水面时清掉。结果记进这一步的命令 `popFix {cells, total, groups, shares}`（重放、重做照用）与撤销记录，再重算一次人文的几层与名字。

**地名跟着文化**（`name-styles.ts` 的 `styleFor`，数据在 `human/culture-style.ts`）：一处地方用哪种风格：自己选的 → 当地占多数的文化的风格 → 世界默认 → 内置中文。“当地”：地物是它的格，省份是它的格（`{province, cells?}`），一格是它自己（格所在的省份选了风格时按省份）。占多数按人数（`popCulture × popTotal`）；一个人都没有的地方（海、荒地）按格数取 `cultureNear`。文化的风格不在世界里时跳过。按 `popCulture`、`popDensity` 两个数组（内容不变时沿用同一个）与地物的格列表缓存，只在文化变了时重新判断。没有人文的世界什么都不变。省份的名字只在新起名时按当地的文化（已有的省名不动；要换时用界面的“重起省名”）。为了让起名看得到人口的几层，第二十二轮把人文的几层挪到了认地物之前（`computeHuman` 不看地物）。

**给界面的**（都从 `core/human` 导出）：
- 内容：`worldEras / worldEra / worldDimensions / worldPopValues / dimensionValues / worldCultureGroups / worldCultures / cultureById / cultureGroupById / popValueById`、`BUILTIN_ERAS / BUILTIN_POP_VALUES / BUILTIN_CULTURE_GROUPS / BUILTIN_CULTURES`（`core/packs/eras`）、`weightedList`（带权重的一组 → `[id, 权重][]`）、`defaultTotalPop(world, d, era)`（向导的总人口滑块的默认值）、`dryLandKm2`。
- 图层：`humanLayers(world)`（底图列表：没有人文时只有 `habitability`；有时是 `culture`、`cultureGroup`、每一维的 id、`popDensity`、`habitability`，带中文名）；`humanColors(world, layer)`（`culture | cultureGroup | 维度 id`：编号 → RGB，0 为 null，按 `derived.popCulture / popCultureGroup / valueLayer(world, k)` 的编号着色）；人口密度按 `derived.popDensity`（建议对数色阶，同导出的 population.png）；宜居度按 `derived.habitability`（0–1）。
- 图例：`humanLegend(world, layer)`：`[{code, id, name, color, pop, cells}]`，只列有人的、按人数从多到少。`populationSummary(world)`：总人数、时代名、各文化。
- 格的档案：`cellArchive(world, cell)` 多了 `habitability` 与 `population?: {total, density, manual, groups: [{code, culture, group, values: [{dimension, label, id, name, color}], label: “大和 · 祖灵信仰”, share, people}], other, culture?, cultureGroup?}`（`cellPopulation`）。`groupInfo(world, code, tuple?)` 是一个群体的说明（笔刷的选择、图例用）。
- 吸取：一格的 `readComp(world.causes, i)` 第一个群体（`small.popGroups[code]`）就是“这里最多的人”，文化笔刷吸 `derived.popCulture`。
- 生成的步骤：`registerHumanStage`、`unregisterHumanStage`、`humanStages`；`GenContext`、`HumanStage` 类型。

**界面**（第二十二轮 UI）：
- **向导的“人文”**（`Wizard.tsx`，地形之后一步）：`HumanChoice {on, era, groups: [{id, weight}], pop: number | null}`（`ui/human.ts`）。时代、文化组的列表是 `eraChoices` / `groupChoices`（内置的每次从 `core/packs/eras` 读，加了新的自动出现；有世界时世界里同 id 的换上、另加的排后面）。默认 `defaultChoice`：第一个时代与它的 `eraGroups`（`defaultGroups` 里认得的；没写时是 `cultureGroups` 各 1；再没有时前三个组），已有人文时照 `small.human`。时代的 `defaultGroups`、`cultureGroups` 之外的组收在“更多文化组”里（`suggestedGroups`）。组的权重滑块 0.1–10（对数）。总人口滑块是默认的 1/10 到 10 倍（对数，两位有效数字，`popAt` / `popPos`）；向导里还没有世界，默认按时代的 `popDensity` × `estimateLandKm2`（星球的表面积或地图的宽 × 高，× 陆地多少）估，`pop` 为 null 时命令里不写 `totalPop`（建好后按真的陆地面积）。`generateCommand` 给出 `generate_human`，`newWorldCommands(gen, name, seed, before, human)` 把它排在 `generate_provinces` 之前（省名按当地文化起）。缩略图不画人文。
