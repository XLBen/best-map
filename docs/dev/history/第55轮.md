# 第五十五轮的设计

这一轮改了什么见 [更新记录](../../更新记录.md)；现在的文件见 [开发说明](../../开发说明.md) 与 docs/dev/ 下的各篇。

用户定的：**生态跟高度走**。生态加高度范围（奇幻生态也加），新增高山草甸、高山苔原，沼泽只在低而平的地方。这是全计划里第一次**有意改生成结果**：同一个种子的世界和以前不一样，人口、文化、国家跟着变。

## 高度范围是什么

`species.height = { low, high }`（`core/species.ts`），可以不写。

- **绝对的海拔，米**。和检查器里“海拔 1234 m”、山峰标注、“这一格为什么”写的是同一个数，用户点一下地图就能和滑块对上。“最高的山”只是缩放高程，范围不跟着它缩放。
- 没选相对（“最高的山的七成”）的理由：
  - 相对的基准要么是滑块，要么是这个世界实际最高的格。后者堆一座山会让全世界的高山带挪窝，结果没法预料；前者把滑块拉高时，同样海拔的地方反而不算高山了。
  - 气温已经按米降（`lapse`，每千米 6.5 °C），森林线、雪线本来就是绝对的。相对的高度和气温各说各的。
  - 星球和地区的高程都是米，同一张表两边都对（一格 100 km 的星球山峰矮一些，高山带窄一些，符合看到的）。
- **“最高的山”很低时**（比如 1500 m）高山带自然很少。这是预期：不够高就没有高山带，测试查着（越高越多，下限不变）。
- **两端**：`low` 为 0 不限下限，`high` 到 `HEIGHT_MAX`（9000）不限上限。范围外 `HEIGHT_MARGIN`（300 m）内从 1 线性降到 0，和气候矩形外面留的 ±3 °C 同一个量级（±3 °C 约 460 m）。

## 怎么和气温、湿度结合

**打分，不是硬条件**：`heightTolerance(h)` 换成一条场是 `elevation` 的耐受曲线，排在写着的曲线后面乘进适宜度（`speciesTolerances`）。别的都不用另写：竞争、份额、解释这一格（“地势太低（海拔 500 m，它要 1000 m 以上）”）、“没涂成”的原因、求解器都照常。

成片靠这三样，没有另外平滑高程：

- 边界是渐变的，交界处份额混色，地图上看不到一格一变（图见下）。
- **森林线、雪线跟气温走，不靠高度上限**。高山草甸（年均 −9～−1 °C）的强势程度 3.5 比针叶林（3）高，所以它俩的交界在年均约 −0.6 °C。中纬度（海平面 12 °C）约 2000 m，赤道（海平面 27 °C）约 4200 m，高纬度根本到不了山上，这才合常识。气温在格之间是连续的，所以线也连续。
- 量到的碎片：一块地区（4 万格）陆地里孤零零一格的片从 0.86% 到 1.07%（多了两种生态，片自然多一点），另一块 1.52% → 1.55%，星球 1.51% → 1.58%。高山带里孤零零的格不到 5%（测试查着）。

## 沼泽的低而平

- **高**：`height: { low: 0, high: 300 }`，到 600 m 为 0。高的低洼平地不再有沼泽（测试查着适宜度是 0）。
- **平**：用现有的 `d.slope`（m/km）和已有的条件“只长在平地上”（`CONDITIONS.flat`：2 以下最合适，5 为 0），沼泽本来就勾着它和“低洼积水处”（`wetness`）。坡度不用改。

## 兜底：没有生态的陆地格

**以前就有这种格**（`dominant` 是 −2）：地图上量到一块地区 18、62 格，星球 39 格，出在两道缝里：湿润程度 0.21–0.214（荒漠的上限和稀树草原的下限之间）和又冷又干（年均 −14～−9 °C、湿润程度 < 0.086）。高山苔原不看湿度，补上了山上的后一道缝。

写了高度范围的世界（`species.some(height)`）：这种格取最近的长着生态的格的那一种，份额 1（`vegetation.ts` 的 `fillBare`）。

- 一圈一圈往里填，每格看邻居（按邻接的先后）里第一个长着生态的，一圈填完再填下一圈，结果只取决于这一遍的 `dominant`。所以颜色连着周围，不会冒出一种不相干的生态。
- 只从哪里都能长的生态传出去：只长在某处、不自然生成的不传。
- 四周没有能传的（小岛上全是这种格）：再从全世界找过来（`fillFar`，隔着海）。世界里没有哪里都能长的生态时留着 −2。
- 一种高度范围都没写的世界不走这里，和以前逐值相同（包括那些 −2）。

## 编辑

- `FieldDesc` 多一种类型 `range`（`core/content/registry.ts`，引用表 `noLinks`）：两个滑块，到两头写“不限”。资源库的编辑页（`ContentEditor`）和生态抽屉（`ClimateChart`）都用 `components/RangeSliders.tsx`。
- 两头都不限时不写这个字段（`update_species` 的 `height: null`），和没写过一样。
- 滑块不交叉：拖过另一个时它跟着走（`moveRange`）。
- 改高度范围从求解重算（`speciesChange` 默认那一支）。

## 世界文件

`DOC_VERSION` **没有加**，还是原来的。命令的格式没变，`add_species` 带着整个生态，多的只是一个可选字段。旧文件重放出来的生态没有高度范围，结果和以前逐值相同，是用户自己的存档该有的样子。要新生态的话从库里导入。

## 变了什么，没变什么

`digestWorld` 六十几项里，**没有“自然融入”、没有带影响的生态的世界只有这几项不同**（地区、星球，测试查着）：`derived.share`、`suit`、`reach`、`dominant`、`features`、`small`。

网格、原因、高程、风、洋流、气候、水面、流向、汇水、径流一个数不变。人文的几层（宜居度、人口、文化、国家、城市、道路、地标、地名、资源）在生成人文时跟着生态变。

陆地格里主导生态变了的比例（包括高山生态占掉的）：北纬 20–60° 的地区 6.1%，赤道附近的地区 3.8%，类地星球 7.0%。

**生态影响水文、气候的只有这两条路，以前就有**，世界里用到时跟着变：

- **“自然融入”**：求解器反推修正场（`corrT`、`corrP`），要让涂的生态长成，竞争的对手变了，修正也变，气候、径流跟着变。`golden`、`golden-full`、`r31` 的气候项变就是这个。高程不变。
- **带影响的生态**（奇幻的死亡森林、神圣之地）：`computeEffects` 按生态的位置改气温、降水。一块地区里，奇幻生态都加上时气候、径流、`effT`、`effP` 不同，星球上这个种子没变。

河的类型（`typeRivers`）按生态限制时走 `baseBiomes`，类型会跟着生态变；只挖河床的类型会改高程。内置的世界默认没有河的类型，第 57 轮带上时再量。

## 提速

每次都走的一步变重了：生态从 13 种到 15 种（`S` 进每格的循环），每种多一条曲线，还有兜底。这几处压回去，都比以前快：

- **`suitability`**（`narrow`）：一条曲线一遍，下一条只看上一条留下的格。多数格被年均温、湿度卡掉，算都不用算；是 0 的格不写。梯形写在循环里。4 万格一遍 ≈ 5.5 → 2.4 ms。
- **`vegShares`**：一格里平均只有 2.1 种适宜度不是 0，只碰这几种，先把份额整个清成 0。
- **`comp` 换成 `Float64Array`**：以前 `number[]` 的元素种类不定，`vegShares` 优化后会被打回去。
- **几块地方留着接着用**（`scratchFor`）：场的值、留下的格，每遍省下约 2 MB，垃圾回收也少。
- **`fillBare` 只碰这种格和邻居**。第一版从全世界一圈一圈传，只要有一个这样的格（几乎总有）每遍多 5–8 ms，这是早期加工变慢的主要原因。

**逐位相同**：`biome-legacy.test.ts` 里 f2c6f77 的 `suitability`、`vegShares` 原样拷贝，随机的曲线（硬边、负的脚本系数、竞争力 0、可达、侵占）对照 60 轮；加上面的旧摘要。

计算植被这一步（一遍，引擎里量的，类地星球前 15 遍）：

| | 第 1 遍 | 第 2 遍 | 第 3 遍 | 之后 |
