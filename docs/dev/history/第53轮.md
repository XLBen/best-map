# 第五十三轮的设计

这一轮改了什么见 [更新记录](../../更新记录.md)；现在的文件见 [开发说明](../../开发说明.md) 与 docs/dev/ 下的各篇。

用户定的：**派系融入政体。** 政体只列有哪些派系，没有比重；派系的定义共用，改一处全处生效；比重在具体国家里调。默认按派系的基础分量加这个国家的人口算，档案里的滑块可以覆盖，也可以恢复自动。各政体不再都一样。

## 数据

- `government.factions`：派系 id 的列表（可选，最多 16 个）。没写的政体没有派系。
- `faction.amount`：基础分量，0–10。代替按政体类别的 `base`，`base` 和编辑器里那张按类别的表都去掉了。
- `countryFactions`：政体列的、世界里有的派系，按政体列的先后。`基础分量 + Σ 来源的权重 × 那部分人的比例`，负的算 0，归一，三位小数。
- 比重**不存在世界里**，打开档案、导出时才算。`CountryMeta.factions` 只在用户拖过滑块后才有，所以生成出来的国家和以前逐值相同，r29 的 `countries` 没动。

## 名单怎么推出来的

`tools/rewrite-factions.mjs`，一次性，跑完留着。输入总是 bcf2c05 的 JSON（`git show`），所以跑几遍都一样；`--check` 比较算出来的和仓库里的逐字节相同，`--table` 打印名单。规则：

- **点名**：`base` 里写了这个政体的某个类别，比 `default` 大，并且 ≥ 0.4 或 ≥ `default` 的 3 倍。只看“写了”不够：`liberals` 写了 `dictatorship: 0.1`，比它的 `default` 还小，那是在说它在独裁里没分量；`tribes` 写了 `monarchy: 0.3`（`default` 0.2），基础太小，不该让封建君主制有部落这一派。
- **靠人口驱动**：`base` 里只有 `default`，有 `drivers`。内置的只有**异教臣民**一个。
- 点名的不到两个时，按旧的基础影响力从大到小补。靠人口驱动的不算在这两个里，它们在没有异教徒的国家接近 0。
- `amount` = 列着它的政体上，旧的基础影响力的平均，两位小数。这样数字最接近旧的。

### 和字面上不一样的两处

**“靠人口驱动”取得窄。** 几乎每个派系都写了 `drivers`。按“有 drivers”算，或者按“来源的权重比基础大很多”算，现代和科幻的每个派系都算（意识形态的权重是 3–4），每个政体的名单又都一样了，这正是用户不要的。所以只算没有点名任何类别的。现代的“绿色派”在军政府里就没有了：军政府没给它位置。

**政体在几个库里时，名单只有一份，库要多带几个派系。** 11 个政体在好几个库（专制君主制在青铜、中世纪、近现代；技术官僚制在现代、科幻），而那些库的派系可能完全不重叠。门槛要求每个库都没有找不到的引用。试过的另一条路是每个库一份名单（拼树时按库筛），但同一个 id 在不同库内容不同，判断“同一项”、撞名、“改过”、换库都要再加一层例外（第五十一轮的 `weight` 已经是一层）。所以名单只有一份，规则是：

- 先从这几个库都有的派系里选；都有的不到两个时从最早的库选（技术官僚制例外，写在 `HOME` 里：现代没有点名寡头的派系，科幻的财团、科学院才是它的人），选中的加进别的库。
- 靠人口驱动的，这几个库里有一个带着就列。这样中世纪的每种政体都有异教臣民（以前绝对君主制里能占 25%）。

结果：

| 库 | 多带的派系 |
| --- | --- |
| 青铜与古典 | 异教臣民 |
| 近现代 | 贵族、部落、异教臣民、教士、市民 |
| 现代 | 贵族、教士、市民、异教臣民、联邦主义者、财团、科学院 |
| 中世纪、奇幻、科幻 | 没有 |

现代世界的资源库里因此多了几个旧派系，只有绝对君主制、技术官僚制用。它们写的来源指向现代没有的取值（`faction→popValue` 5 条、`faction→dimension` 1 条，`strip` 类，记在 `modern:strip`），算出来是 0，只剩基础分量。

## 引用

`government.factions` 写在字段表上：`{ type: 'tags', ref: 'faction', dep: 'auto' }`。

选 **`auto`，不选 `hard`**：没有派系的政体也成立（`hard` 的意思是“没有它这一项不成立”），导入时默认跟着带，取消的话 `stripLinks` 把引用去掉，不留找不到的。第六十一轮的导入窗口正好用这个。写在字段表上，`renameLinks`、`stripLinks`、`linkTable` 都不用改，编辑器也直接是 `TagRefs`（小块加“加一个”）。

`links.test` 的撞名表（第四十九轮）多一条：60 条引用，旧的写法 41 条没跟着改；旧写法的拷贝没动。

### 在用

`factionUsage`：**政体列着它**就算在用，再写上用这些政体的国家（“2 个政体列着它、5 个国家有它”）。以前是“有时代就都算在用”。

- 没有国家的政体列着的派系也移不出去，因为移出就留下找不到的引用。要先改名单。
- 整理（`unusedContent`）：派系按移出没用到的政体之后的世界查，一步走完，不用整理两遍。
- 小包移出（`onlyCandidates`）本来就一层层算，政体在派系之前（`TIDY_KINDS`），不用改。
- 删国家（`dropUnusedGov`）：留下的政体列着的才算在用。

### 换库

`librarySwitchPlan` 没改。`SWITCH_KINDS` 里政体在派系之前，`view` 一步步去掉，`usageOf` 查到“留下的政体列着它”就留下。所以锁定国家的旧政体留下时，它列的派系也留下，写进 `kept`。测试：四对库走一遍，政体没有悬空，世界里的派系正好是新库带的；锁定的国家留下全部派系，别的旧派系走了。

### 换政体时从库里加

`addFromLibrary`（`governmentCommand` 用）：政体带上它列的、世界里没有的派系，先找同一个库。

**没做的：** 旧资源库面板单独“添加到本世界”一个政体不带派系，档案里少几个，不出错（`governmentFactions` 跳过找不到的）。依赖闭包是第六十一轮的事，这一轮不动旧面板。

## 档案

- 拖滑块还是 `set_country` 的 `patch.factions`（已经在 `baseCommands` 里），一次松手一条命令；“恢复自动”是 `factions: null`。**没有加新命令。** 撤销、重做、重放都走现成的，测试查了逐值相同。
- `patch.government` 真的换了时去掉覆盖：覆盖是给原来那份名单的。撤销连覆盖一起回来。
- **名单后来改了**（改政体、移出派系）：覆盖里键和名单正好对上就照用；否则名单外的不看，没写的按自动，再归一。不留灰色的“未知派系”了。
- 政体只列一个派系时滑块灰着（拖了也只有它）；没列派系时写一句“这种政体没有派系，可以在资源库里选”。
- 文件：`FactionSection`、`StackBar` 搬到 `src/ui/CountryFactions.tsx`（`CountryArchive.tsx` 照旧导出 `StackBar`）。`CountryArchive.tsx` 914 → 860 行，还是超过 800，这一轮没再拆。

## 编辑器

政体多了“有哪些派系”，派系的“基础”换成“基础分量”一个数。`WeightTable` 里按类别那条分支、`links.ts` 里 `keyRef === 'govCategory'` 两处没人用了，去掉。`ref: 'govCategory'`（政体的类别、地标的政体类别）还在。

## 大小与速度

打包：主线程 2,621.91 → 2,624.60 kB（gzip 798.00 → 798.34），计算 Worker 848.08 → 848.27 kB。`worker-imports` 照旧查内置数据不进计算 Worker。

编辑走的路只多了 `setCountry` 里一个判断（`usage`、`unused` 只在移出、整理时走）。

**island 连着标了两次，按规矩要查。** 查了：这一步是地形，世界里没有人文（`--library` 不生成人文），派系的代码一行都不走。`--all` 看各阶段，第三次 `island.features`、`island.apply` 各 +4 ms，九次时这两项 +0%、`island.climate` +3%（气候也没碰）。多量几次回到 +4% 以内。所以当作这台机器的宽度，没有改代码；数都写在这里。

星球没有量（没有碰地形和推导）。`overlay-ab`、`compose-ab` 没有跑：没碰渲染和叠加层。
