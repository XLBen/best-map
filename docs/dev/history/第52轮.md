# 第五十二轮的设计

这一轮改了什么见 [更新记录](../../更新记录.md)；现在的文件见 [开发说明](../../开发说明.md) 与 docs/dev/ 下的各篇。

用户定的：**新建世界、生成人文只选一个库，没有勾选的树。** 时代有自己的库，想要别的自己加进世界：比如奇幻世界里做社会主义国家，就把意识形态这个变量和政体加进来。所以从别的库加来的东西要一直参与生成。

## 选一个库

`HumanChoice` 的 `packs` 换成 `library`（资源库里的键）。命令里还是 `packs: [[键]]`，世界文件没变，`DOC_VERSION` 没加（第五十一轮说“改命令时再加”，这一轮命令只多一个可选的字段，旧文件照样重放）。`genStamp` 也还是 `{ packs }`。

- `LibraryPick`（`src/ui/components/`）：向导里一排卡片，弹出面板里一个下拉。最后的面板在第五十九轮，这里不多做。
- 能选的（`libraryOptions`、`isLibrary`）：内置六个；我的、装上的包里有时代、有带文化的文化组的。新建世界还要有 `base`、`nature` 两个小包，不然地形类别、生态都是空的。
- `packChoice.ts` 从 313 行减到 271 行：去掉勾选（`togglePack`、`packState`、`makeRule`）、分时代包和别的包（`splitPacks`）、`inUse`、补一遍的名单（`REFILLED`）、`LIBRARY_BASE_PACKS` 的判断（只留在 `import.ts`）、`worldDefaultPacks` 和那句“资源库里还有 N 个文化组”。
- 已有的世界加内容都是 `onlyMissing`：世界里有的 id 不动。以前第一次生成时不是，改过的项会多一份 `x-2`。
- 第一次生成人文的默认库是世界的底子来自的库，不再总是中世纪。向导选奇幻、不生成人文，之后默认还是奇幻。

**文化组的列表**：库默认带的带滑块；“还有 N 个文化组（这个库默认不带）”收着，勾上才参与（`reviveGroups`）。另有一段“本世界加的”（`beyondGroups`）：世界里有、这个库不列的组，比重不是 0 的默认勾上。用户加进来就是要它参与。“重新生成”按钮也带上它们（`regenerateCommand`），世界里没有这样的组时命令和以前一样。

**`findGroup`**：选的库有这一组就用它的小包，来源记选的库。中世纪世界点名刚果，来源从 `industrial/cultures/kongo` 变成 `medieval/cultures/kongo`。选的库没有时照旧（奇幻点名日耳曼：比重不是 0 的第一个）。r29 没变。

## 换库

选的库和世界现在用的不一样（`worldLibrary`：有人文时看规则的时代的来源，没有时看世界的底子的来源）就是换库。一步，可以撤销：

1. 加进来：新库带的、世界里没有的 id（`onlyMissing`），和新世界一样分两步（世界的底子里生成要用的几种、库里的），先后也排成新世界的。
2. 移出来自旧库、新库不带的。“来自旧库”看 `small.origin` 和 `originSourceId`。
3. 两边都有的留着，**来源改写到新库**（`rehome`）。不改写的话，连着换第二次就认不出它来自旧库了。世界的底子（生态、地形类别……）也改写，不移不加。
4. 我的库里同一个 id 内容不同：世界里和旧库一样的换成新库的，世界里改过的不动。
5. 重新生成。国家重新长，手改的格不留，总人口按新时代的默认。

生成里没有加筛选，`eraGovernments`、`eraFactions`、`dimensionValues` 没动。第五十一轮说按来源筛不够（两个库都有的项来源还是旧库），现在来源改写了，也不用筛：世界里只剩该有的。

### 和计划不一样的地方

**“新库有”不能按库的整棵树算。** 四个历史库都带全部 71 个 EU4 文化组（比重 0），每个库的 `names` 下面都有全部地名风格，按树算的话中世纪换现代一个文化都移不掉，世界里的文化选择器全是没人的组。所以按“一个新世界用这个库、这几个文化组会带什么”算（`broughtBy`）。这也意味着：从旧库单独加的项（比如勾过的比重 0 的组、从“地名”加的一种风格），新库不带就移出。第三个库来的不动。

**移出不能是单独的命令。** 生成之前这些项还在用（国家的政体、人口的文化、人文的时代），`set_content` 不让移。先生成再移不行，生成会用到它们。所以名单放进生成的命令（`generate_human`、`regenerate_human` 的 `switchLibrary`），`commands/switch.ts` 的 `leaveLibrary` 在算好推导之后、生成之前照着做，不查“还在用”。放在同一条命令里，中间不会重算推导。计算 Worker 只照名单做，不碰内置的数据。

**生成之后还会在的东西用到的不移**（`survivors`）：把世界改成生成之后的样子（只留锁定的国家、在新选的组里的锁定发源地、自己放的和锁定的城市地标、自定义点，没有人口），问现有的 `usageOf`，再加别的项 `hard` 引用着的。这些写进 `kept`，结果里写“N 项还在用，留下”。文化在文化组之前查，组在风格之前，一个没人的组和它的文化、风格一起走。

**只管生成要用的十二种**（`GEN_KEYS`）。生态、河、湖、地形类别、岛、画风、国家等级不加不移：它们改的是地图本身，换库不该让河变样。奇幻可选的生态、河、湖因此不跟着来去，手动加过的换走时也留着。

**生成之前的底子要和新世界一样**（`freshStart`）。不然结果不同：群体的编号从头给（共用的群体留着旧编号时，人口几格的排法不同，中世纪换现代差出国家的首都）；自动的城市、地标删掉，没有留下的时编号从头给。

### 门槛：换库 = 新建

`core/packs/switch.test.ts`。三十对库都量过（6000 格，比直接用新库新建，r29 的十四项）：

| 目标 | 不同的项 |
| --- | --- |
| 中世纪、奇幻 | 只有 `provinces` |
| 青铜与古典 | `provinces`，加一条河的名字（`features`） |
| 近现代、现代、科幻 | `provinces`，加 `pop`、`human`、`country`，多数还有 `countries`、`cities`、`roads`、`landmarks` |

**省份换不回去，这一条做不到逐值相同。** 所有世界一开始都有省份，旧国家切出来的省留着（“只切不并”，第二十三轮），已有的省名不变（有“重起省名”）。这是用户的东西，可能改过，也不是库的内容，所以不动：

- `provinces` 总是不同。中世纪换现代：773 个省，直接新建 696 个。
- **有联邦的时代**，联邦分邦时看省份（`blocs.ts` “整省归格数最多的那一邦”），所以差一点。同一个库重新生成也一样，和换库无关。
- 青铜与古典那条河差在新建的一边：它生成人文前后起名的办法没变，新建的世界留着生成之前的名字（`keptNames`）。

差多少（6000 格）：

| | 陆地格归属不同 | 国家档案不同 | 人口差 |
| --- | --- | --- | --- |
| 中世纪 → 奇幻 | 0 / 2846 | 0 / 22 | 0 |
| 中世纪 → 近现代 | 2 / 2846 | 0 / 34 | 0.01% |
| 中世纪 → 现代 | 23 / 2846 | 3 / 68 | 0.05% |
| 现代 → 科幻 | 20 / 2846 | 1 / 47 | 0.15% |

**证明差别只来自省份**：测试让直接新建的世界先有和旧世界一样的省份，再生成。这样比，省份的划分和别的十三项全部逐值相同（中世纪 → 现代、奇幻、近现代，现代 → 科幻）。切出来的新省的名字看生成前的推导（旧文化还在里面），所以省名那一项还是不同。世界里生成要用的十二种内容（含先后）在所有情况下都和新建的逐值相同。

要逐值相同只能把省份重新划分，自己改过的省就没了，这一轮没有这样做。

## 大小与速度

打包：主线程 2,617.75 → 2,621.91 kB（gzip 796.68 → 798.00），计算 Worker 846.96 → 848.08 kB。

算一次计划 6–34 ms（面板每画一次都问，按世界和选择记着，拖滑块时只算一遍）。执行 140–320 ms（6000 格，整个生成）。

`bench-median 5 --against 877d990`（负载 2–4，一次一个任务）：

| 对照 | 标出来的 | 再量一次 |
| --- | --- | --- |
| 区域 | tempBrush +6%、island +7%、humidity +7% | +2%、-2%、-5%，没有标 |
| `--kept` | island +11% | +1%，没有标 |
| `--kept`，HEAD 对照自己 | humidity +7%、hotRelief +5% | 没改代码，这是这台机器的宽度 |

**没有一步两次都慢**，所以星球没有量。`--kept` 两次（旧 → 新）：`libEdit` 2.15 → 2.13、2.17 → 2.13 ms，`libUndo` 3.18 → 3.15、3.19 → 3.18 ms，`libContent` 2.17 → 2.17、2.16 → 2.16 ms，`libHuman` 9.9 → 10.46、10.28 → 9.98 ms，`libCountry` 6.36 → 6.34、6.33 → 6.32 ms，`libSaveDoc` 3.27 → 3.25、3.28 → 3.3 ms，`genHuman` 720 → 729、723 → 719 ms。

编辑走的路只多了 `touchedArrays` 里生成的那一行和 `setContent` 的一个参数。`overlay-ab`、`compose-ab` 没有跑：没碰渲染和叠加层。

## 坑

- 算 `broughtBy` 时世界的底子在前，同一项取第一次出现的：地标在基础和 `landmarks` 里都有。先后不能按它排，地标的先后要用第二步的 `order_content`（和新世界一样）。
- 批里的 `ensureDerived` 不算前面几条的改动，推导是这一步之前的。`generateHuman` 只读地形、生态这些，所以和新建相同。切出来的新省的名字读的是旧的文化，见上。
- 画过的奇幻资源换走时格恢复自动（资源有 `afterSet`，和移出一样），写进了 `limits.md`。
- 移出的项里改过的、自己的库来的，`keepRemoved` 照旧存进资源库“来自《世界名》”，撤销不会把它们从资源库拿掉。
