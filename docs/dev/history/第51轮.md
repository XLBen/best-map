# 第五十一轮的设计

这一轮改了什么见 [更新记录](../../更新记录.md)；现在的文件见 [开发说明](../../开发说明.md) 与 docs/dev/ 下的各篇。

用户定的：**每个时代一个完整的库，“通用”拆进各库**。内置六个：青铜与古典、中世纪与近世、近现代、现代、奇幻、科幻。四个历史库带全部 EU4 文化组，新世界只用默认的（别的比重是 0，靠导入）；奇幻、科幻不带 EU4 文化。选库的界面在第五十二轮，这一轮旧界面照样能用。

## 树

```
<库>（antiquity、medieval、industrial、modern、fantasy、scifi）
  era、<维度>…、governments、factions、[resources]、landmarks
  cultures ▸ <组>…      时代默认带的在前（小包写权重），历史库再加别的 EU4 组（小包和组的比重都是 0）
  [biomes、rivers、lakes]   只有奇幻
  base、nature、names ▸ zh / <地区>…、forms、styles、tiers   世界的底子，每个库都有
```

- **不复制数据**：`build()` 里世界的底子只拼一次，六个库放同一个对象（奇幻的 `forms` 多几种，是一份新的小包，项还是同一份）。比重 0 的小包（`sparePack`）四个历史库共用一份，组是 `{ ...g, weight: 0 }` 的浅拷贝。
- **打包只大了 1.4 KB**（主线程 2,616.39 → 2,617.75 kB，gzip 795.94 → 796.68；计算 Worker 846.84 → 846.96，多的是生成里的几行；导出 Worker 2,026.20 → 2,026.48）。`worker-imports` 照旧查内置数据不进计算 Worker。
- **运行时**：`JSON.stringify(builtinPacks())` 从 2976 KB 变成 8833 KB，这是展开的大小，内存里是共用的。拼树 4.6 → 5.0 ms，建索引 4.4 → 6.6 ms（都只一次）。把一个内置库导出成文件时是展开的（约 1.5 MB）。
- **上限**：`PACK_MAX_SUBPACKS` 64 → 128（“文化”下面 71 组，还要能加）。`PACK_DEPTH = 2` 够用：库 ▸ 文化 ▸ 组。地区（欧洲、中东……）放不进第三层，不再是树里的一层；`CULTURE_REGIONS` 还在，历史库的组按它的先后排，第五十九轮的页面要分段可以用它。
- **比重 0 不算内容**：`sameIgnore: ['weight']`（第五十轮）。`builtinItem('cultureGroup', id).item` 总给没写比重的那一份，不管树里先碰到哪个库，否则“恢复内置”会写进一个 0。
- `builtinOrigin` 没写优先的库时取默认的库（中世纪与近世）。以前的 `paths[0]` 现在会是最前面的“青铜与古典”，基础、自然这些都落到它上面。

## 从库里加内容

`packImportPlan`（`core/packs/import.ts`）：

- **时代包整个加进世界时跳过世界的底子**（`LIBRARY_BASE_PACKS`）。不跳的话 `names` 下面全部地名风格都会进世界，自己移出的城市等级、地形类别也会在重新生成时回来。小包 id 相同就跳过，所以“复制成我的库”（第五十九轮）以后照样对；自己写的时代包里叫 `base`、`names` 的小包也跳过，要的话单独勾。
- **新建世界时世界的底子单独加**：`worldPartsOf(key)`（基础、自然、中文地名、画风、国家等级），`packChoice.worldContentPacks` 把勾着的库展开成它们，放在新建的第一步（生成之前）。已有的世界不加：`worldDefaultPacks` 以前也只勾在用的，而它们本来就在世界里。
- **比重 0 的小包点名才带**：走下面的小包时跳过 `n.weight === 0`，点名的组走原来“勾选的包里没有的组”那条路（`findGroup`）。所以文化组的先后和以前一样，这是 r29 不变的关键之一。
- **`findGroup` 先找比重不是 0 的**（计划里的坑）：同一组在几个库里。比如中世纪世界点名刚果，来源是 `industrial/cultures/kongo`，和以前（第一个列它的时代包）一样。这个顺序是为了 r29 逐值相同；第五十二轮只选一个库时，可能想改成优先这个库，那时再看。
- **点名的组带进世界时去掉这个 0**（用户就是要它参与）。没点名的（整个小包加进来，将来导入依赖带来的）带着 0，不参与生成，和不在世界里逐项相同（测试）。
- **`GEN_KEYS` 加 `resources`**：奇幻自带 5 种资源。奇幻的生态、河、湖照旧要单独勾：它们带上会改结果，用户只提了资源；第五十二轮、第五十七轮再定。
- `ORDERED` 不用改：地标的先后来自 `landmarks` 小包，基础被跳过，和以前一样。`packChoice` 的 `REFILLED` 也不用改：世界的底子在库下面，勾着库时走不到这里；单独勾着的小包照旧。

## 去掉 human.packs

`human.packs` 有两种读者：一种要“规则用哪个时代”（`ruleEra`），一种是界面要记“上次用什么生成的”（向导默认勾选、政体的选择、“用的包”）。

现在 `small.genStamp = { packs }`，在 `human` 外面，生成时写，`clearPop` 时去掉，撤销跟着小数据走。命令的 `packs` 不动：`ruleEra(small, packs)` 的算法一个字没改，重新生成时没写 `packs` 就用 `stampedPacks(small)`。

**r29 摘要怎么算的**：`humanDigest` 以前就把 `packs` 从 `human` 里删掉再算（第三十轮加的那行）。所以去掉这个键不碰 `r29-digests.json`，文件一字没改。`population.test` 也一样，那行删掉了。

**第五十二轮只选一个库时**：`genStamp` 换成库的键，命令的 `packs` 换掉，`DOC_VERSION` 那时再加一。

## 换时代时旧内容也参与生成

**这一轮行为没变**：同一个世界换时代，旧时代的政体、派系、取值照旧留着并参与生成（政体 8 → 30、取值 32 → 52，`limits.md`）。

给第五十二轮留的路：生成读内容只走三处，`eraGovernments(small, era)`、`eraFactions(small, era)`、`dimensionValues(small, dim, era)`，它们带时代的参数现在都没用。改这三处就够了，别的（国家、人口、派系）都从这里拿。

按来源筛（`small.origin[kind][id][0]` 是不是这个库）**不够**：两个库都有的政体，加进来时跳过，来源还是旧库。计算 Worker 里又没有内置的树。所以筛的名单要由界面算好放进命令（比如 `generate_human.only`）、记进 `genStamp`。它不在 `human` 里，r29 不受影响。

## 界面（第五十二轮之前）

- **向导默认只勾一个库**：`defaultPacks` 给 `[['medieval']]`。勾选框的树原样能用。库下面的小包是“整个包在”，变灰；要不带基础，就不勾库，单独勾小包（测试改成了这样）。
- **文化组**：库里比重是 0 的组收在 `<details>`“还有 N 个文化组（这个库默认不带）”里，勾上后才列在上面（`culture.tsx`）。权重用 `o.weight || 1`，不然勾上时是 0。
- **世界里已有比重 0 的组、用户勾上它**：`reviveGroups` 先去掉这个 0。不然从资源库整包加进来的组勾了也不生成，还看不出为什么。上一次就选着、后来才改成 0 的不动。
- **星球形态**：同一种每个库都有，`formChoices` 只列一次，键按默认的库（`medieval:continents`），`paths` 记着都在哪；`formsInPacks` 列在勾着的库下面。
- **资源库两栏**（旧面板，第五十九轮换掉）：行数 1963 → 3804。`statusIn` 让同一个对象的状态只算一遍，`packTree` 15.6 → 11.3 ms，比以前还快。本世界改过的内置项，每个库的那一行都写“改过”（以前只有来源那个包）。

## 新的摘要和引用

`core/packs/libraries.test.ts`，摘要在 `libraries-digests.json`（`LIB_RECORD=1`）：

- 每个库新世界走得通、只带默认的组、世界的底子来源是这个库，十四项摘要加内容、来源的摘要。
- **每个库单独看，`hard`、`auto` 的引用都找得到**（第四十九轮记的 6 条 `swarm_zone` 没有了）。`linkProblems()` 是空的。

**`strip` 类的引用不是都找得到**，这是有意的，数记在文件里：

| 库 | 找不到的 `strip` |
| --- | --- |
| 青铜与古典 | 2907 |
| 中世纪与近世 | 1973 |
| 近现代 | 1820 |
| 现代 | 1194 |
| 奇幻 | 14 |
| 科幻 | 0 |

绝大多数是文化、文化组写的倾向指向别的时代（`eraTendencies` 的键、别的时代的政体和取值），少数是政体的换说法、派系的来源指向这个库没有的取值，奇幻那 14 条是地标的名字写法指向 EU4 文化。`strip` 的意思就是“缺了就去掉这条引用”（第四十九轮），导入时去掉。要全部找得到，就得在每个库里把这些写法删掉，同一个文化组在几个库里就不一样了（撞名），也会改结果（奇幻场景里的日耳曼用着这些写法）。

世界里只查 `hard`：新世界只带默认的组，政体的 `only` 这类 `auto` 引用指向没带的组，这和第五十轮一样，条件对不上而已。

## 世界文件

`DOC_VERSION` **没有加**，还是 12。文件是 `{ format, version, settings, commands }`，命令的格式没变，`human.packs`、`genStamp` 都是重放算出来的。旧文件里 `from`、`packs` 写着 `common`，照样重放，地图和内容的摘要相同（测试），来源指向不存在的包，和用户删掉了那个包一样。第五十二轮改命令时再加。

## 坑

- **worktree 里 `bench-median` 跑不起来**：它要 `<根>/node_modules/tsx`，worktree 里的 `node_modules` 只有缓存（依赖是从上层目录找到的）。量的时候临时换成指向主仓库的符号链接，量完换回来。工具没改。
- **旧面板的“整包添加”会把比重 0 的组也加进世界**：它们留在世界里不参与生成，勾上时才去掉 0（`reviveGroups`）。
