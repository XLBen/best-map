# 第二十一轮的设计

从开发说明里搬来（第四十一轮）。这一轮改了什么见 [更新记录](../../更新记录.md)；现在的文件见 [开发说明](../../开发说明.md) 与 docs/dev/ 下的各篇。

## 地形类别、资源、格的档案（第二十一轮）

人文的第一批：每格一种地形类别、最多一种资源、一份档案（小地名、备注），山峰。都只读自然的推导，不反向改地形（`core/human/`）。

**地形类别**（`human/terrain-class.ts`，内容种类 `terrainClass`，资源包的段 `terrainClasses`）：
- 一项：`{id, name, color, exportColor?, terrain?（导出给游戏的地形名，plains 或不写时按生态）, description?, priority, rules: 按格的条件[], fallback?, ore?（档案里写“无矿”）, peaks?（这一类里算山峰）, movement?（起伏的通行难度，平原 1）, habitability?}`。
- **只管起伏**（第二十七轮）：内置 5 种——平原（兜底，没有规则）、丘陵、高原、山地、山峰，规则里只有高度、坡度。森林、林地、丛林、沼泽、沙漠、冻原、冰川、草原、干草原 9 种删掉了：植被是生态的事，以前一格的森林既是生态又是类别，宜居度、通行难度、资源都算了两遍。阈值按生成的世界标定：陆地坡度的中位数约 1.3 m/km、九成以下约 9；丘陵是坡度 ≥ 4.5（或海拔 ≥ 700 且坡度 ≥ 2.5），高原是海拔 ≥ 1100 且坡度 ≤ 4，山地是海拔 ≥ 1900（或 ≥ 1100 且坡度 ≥ 7），山峰是海拔 ≥ 3000 且坡度 ≥ 8（或 ≥ 4200 且坡度 ≥ 3），优先级山峰 > 山地 > 高原 > 丘陵。新建的类地星球上约是平原 58%、山地 17%、高原 9%、山峰 9%、丘陵 7%（一块温带地区：平原 70%、丘陵 13%、山地 11%）。
- 旧命令里画成删掉的那几种（`RETIRED_CLASSES`）的 `set_cell_class`：世界里没有同 id 的类别时恢复自动，不报错。世界里改过的同 id 的一项（`small.content.terrainClass.forest`）成了新加的类别，排在 5 种后面。
- **世界里有哪些**（`worldTerrainClasses(small)`）：内置的 5 种总在（不用启用、不能停用，像内置中文风格）；`small.content.terrainClass` 里同 id 的一项换掉内置的那一种（`set_content` 改颜色、规则……，停用它就换回内置的），别的 id 是新加的，排在内置的后面（按启用的先后，最多 64 项）。编号 = 列表里的下标 + 1。
- **自动分类**（`classifyTerrain`）：每格取规则满足的类别里 `priority` 最大的（一样大时排在前面的），一条都不满足时取写了 `fallback` 的那一类；只给干的陆地（陆地、不是湖面）分，水面为 0。地形类别的规则里不能写 `classes`（`check` 拒绝）。
- **按格的条件**（`human/rules.ts` 的 `cellRuleSchema`，资源共用）：`elevMin/Max`（m）、`slopeMin/Max`（m/km）、`tempMin/Max`（年均温）、`moistMin/Max`（P/PET）、`wetMin/Max`（地形湿度）、`latMin/Max`（纬度绝对值）、`terrain`（生态的地形）、`biomes`（生态 id）、`classes`（地形类别 id，资源与人口的偏好用）、`coast`、`river`（流量够画成河）、`lake`；写了的几项都满足才算，一项有几条规则时满足任何一条就算。编辑器里每一项是一个可以不写的字段（`RULE_FIELDS`、`RESOURCE_RULE_FIELDS`）。

**资源**（`human/resources.ts`，内容种类 `resource`，段 `resources`）：
- 一项：`{id（不能是 none）, name, color, icon?（界面按它画）, category: farm | wood | herd | fish | ore | luxury | magic（农、林、牧、渔、矿、奢侈、奇幻，CATEGORY_LABEL）, description?, rules, rarity（能长的格里约多少比例有它）, weight（几种都能长时谁占上）, cluster（成片的大小，km）, seedKey?}`。
- 内置的通用 18 种总在：粮食、牲畜、鱼、木材、盐、石料、铁、铜、锡、金、银、煤、宝石、香料、毛皮、葡萄酒、丝、茶。奇幻 5 种（秘银、魔晶、龙骨、灵木、星陨铁）是内置的但默认不在，在资源库里启用（`set_content`）。列表、编号同地形类别（`worldResources`）。第二十二轮由时代包选用。
- **分布**（`distributeResources`）：每格在规则满足的资源里取 `weight × (取值 − 门槛)` 最大的那种，都不到门槛时没有。取值是按地图上的位置（km）的两层噪声（成片的 + 四分之一的细噪声，星球上按单位球面 × 半径取三维噪声），种子是世界种子 + `resource:` + seedKey（省略时 id）；门槛是这种取值的 1 − rarity 分位（固定种子标定一次）。所以与格数无关、同一个世界同样的结果。每种资源每格的取值按网格记下（`fieldOf`，单精度，最多 48 份），只画资源、改规则时只查表。山地、山峰上能长的只有矿（石料、铁、铜……）与宝石（奇幻的除外），所以山地上是矿或者没有（“无矿”）；新建的类地星球上约四成的陆地没有资源。
- **规则怎么写**（第二十七轮）：起伏写 `classes`，植被写生态的地形 `terrain`（forest、jungle、steppe、savanna、desert、arctic、marsh、hills——地中海灌木）或 `biomes`。原来的植被类别只出现在平地上（丘陵以上的起伏优先），所以改写后的规则多半带着 `classes: ['plains']`（木材是平地的 forest、jungle 与灌木，粮食是平地的草原、灌木与不太湿的林地……）；矿的规则加了 `tempMin: −18`（原来的“冰川”类别上不出矿）。改写前后同一个世界的资源只有约 2% 的格不同。

**推导与原因**（`world.ts`）：
- `derived.terrainClassAuto` / `terrainClass`（生效的：画过的用画的）、`resourceAuto` / `resource`、`peak`（1 是山峰）都是每格一个 Uint8，空白世界里全是 0。没画过时生效的与自动的是同一个数组。`computeHuman`（`human/index.ts`）每次都换上新的数组、不就地改：撤销缓存与发给主线程的上一份照旧共用。只重算人文的几层时（`computeHuman(w, d, false)`）自动的类别在规则、生态没变时照用上一份（按数组记下当时的规则），自动的资源在规则、生效的类别都没变时照用上一份。
- `causes.terrainClass`（0 自动，否则编号）、`causes.resource`（0 自动、255 明确没有 `RESOURCE_NONE`、否则编号）：可选，第一次画时才建，撤销到那之前时去掉（`UndoRecord.dropArrays`），新世界（`set_worldgen` 的 reset）清零。只画陆地格；变成海的格留着画过的值（水面不分类别），又变回陆地时照旧。
- `small.cells`：格的编号 → `{name?, orig?, salt?, note?}`，第一次写之前没有这一项，空了就去掉。
- 没用到这些的世界：原因、小数据里一项都不多。人文的推导数组（`HUMAN_DERIVED`）不进金标准的 `digestWorld`（金标准记下时还没有它们），它们自己的金标准在 `human/human.test.ts`（地区与星球各一组）。

**命令**：
- `set_cell_class {cells, class: id | null}`：这些格（只算陆地）画成这一类，null 恢复自动。历史“地形类别“山地” · 36 格”“地形类别恢复自动 · 36 格”。`Dirty.Human`。
- `set_cell_resource {cells, resource: id | 'none' | null}`：'none' 是明确没有，null 恢复自动。“资源“铁” · 12 格”“去掉资源 · 12 格”“资源恢复自动 · 12 格”。`Dirty.Human`。
- `set_cell {cell, name?: string | null, orig?: string | null, salt?, reroll?: true, note?: string | null}`：小地名（null 恢复自动；原文跟着名字，只改中文名时去掉）、换一个（reroll 盐加一，或直接写 salt，自己起的名字去掉）、备注（null 去掉）。`Dirty.None`。
- `set_content {kind: 'terrainClass' | 'resource', ...}`：改、加、停用；`Dirty.Human`。停用新加的一种时画成它的格恢复自动、后面的编号往前挪（`remapCodes`，资源的 255 不动），都记进撤销。

**山峰**（`human/peaks.ts`）：干的陆地上比相邻的格都高（一样高时编号小的算）、海拔 ≥ `PEAK_MIN`（1000 m）、生效的地形类别写了 `peaks`（内置的山地、山峰）的格。山脉的主峰（地物 `peak`，海拔 ≥ 2600 m）一般就在里面。

**格的小地名**（`human/cells.ts` 的 `cellName`）：自己起的（`small.cells`）；否则按 `styleFor(world, {cell})`（第二十一轮加的目标：这一格所在省份的风格，没有时按世界默认；第二十二轮起省份没选风格时按这一格的文化，见“时代、文化、人口”）起：山峰用风格的 `peak` 模板，别的用 `spot`（情境标签 coastal、river、mountain、cold、sea），种子“世界种子:cell:格:盐”（风格不是世界默认时加风格 id）。不上地图、不进 taken（可以与地物重名）。没有加新的地物类型，内置的 27 种风格都写了 `peak` 与 `spot`。

**给界面的**（都从 `core/human` 导出）：
- `cellArchive(world, cell)`：`{cell, surface: land | lake | sea, name, orig?, custom, feature?（山脉的主峰：名字是地物的，改名用这个键 rename_feature）, style, note?, elevation, lat, lon, province, provinceName?, biome?, terrainClass?: {id, name, color, auto, autoId?}, terrainLabel?（第二十七轮：“丘陵 · 温带阔叶林”，`terrainLabel(world, cell)`，城市档案、画类别时的悬停也用它）, resource?: {id, name, color, icon?, category, categoryLabel}, resourceAuto, resourceNone?（“无矿”/“无”）, peak?: {name, orig?, elevation, feature?}}`。主峰在格自己起了名字时用格的。
- `peakCells(world)`（按海拔从高到低，按 `derived.peak` 缓存）、`peakMarks(world, limit?)`（地图上画全部山峰：格、位置、名字、海拔、主峰的地物键）。
- `worldTerrainClasses(small)`、`worldResources(small)`、`classCode` / `classAt`、`resourceCode` / `resourceAt`、`classColors(world)` / `resourceColors(world)`（编号 → RGB，0 为 null）、`BUILTIN_CLASSES`、`GENERAL_RESOURCES`、`FANTASY_RESOURCES`、`CATEGORY_LABEL`、`RESOURCE_NONE`、`provinceHuman(world, d)`（每省格数最多的类别、资源）。
- 图层：按 `derived.terrainClass` / `derived.resource` 的编号取 `classColors` / `resourceColors`，0 不着色。

**界面**（第二十一轮 UI）：
- 底图 `terrainClass`、`resource`（`render/colors.ts` 的 `humanFlat`：地貌上按格平涂，资源底图里没有资源的陆地是 `NO_RESOURCE` 灰；不画生态的花纹）；`colorSignature` 在改过、加过类别或资源时带上它们的颜色。
- 山峰图层（`overlays.peaks`，默认关）：`render/overlay.ts` 的 `peakLabels(world)` 把 `peakMarks` 变成键带 `PEAK_KEY` 的假地物，排在别的地名之后（地名里已有的主峰不重复），放大到 `PEAK_NAME_ZOOM` 才标名字，之前画小三角（相隔 `PEAK_GAP` 像素以上，按海拔先后）；点击命中不给它们。导出整张地图时同样画。
- 画笔：`tools/human.ts`（`dryLand` 只涂干的陆地，`options.terrainClass` / `options.resource`：'' 恢复自动、'none' 无），底部条的选择在 `panels/human.tsx`（`TYPE_PANELS` 的 `classpick`、`resourcepick`）。
- 格的档案：`ArchiveBox.tsx` 画在 `Inspector` 里，命令在 `archive.ts`（`renameCommand`、`rerollCommand`、`autoNameCommand`、`cellClassCommand`、`cellResourceCommand`、`noteCommand`；`archive.feature` 有值时走 `rename_feature` / `reroll_feature`）。右键点地图（不拖，`map/input.ts`）调 `state.ts` 的 `pinCell(cell, part)`：`pinnedCell` 钉住、`pinnedPart` 记下钉住的是陆还是水（第三十七轮：`tools/api.ts` 的 `pinTarget` 取鼠标处的描格的格 `DisplayCell.focus`；没有描格的格时钉 `here`、`part` 为 null 不描）、`hereOpen` 展开卡片；钉住时 `lastHoverCell()` 给钉住的格，档案可以改，地图上描出这一格画成陆地或水面那一部分的边（`MapView` 每帧把它交给 `renderer.setFocus`，任何工具下都画，见“描格（第三十七轮）”）；收起卡片、新建或打开世界时不再钉住（`pinCell(-1)` 一起清掉 `pinnedPart`）。没钉住时档案只读。
- 资源库：`repo.ts` 的 `RepoStatus` 多了 `always`（登记表里的内置项、`alwaysOn` 给了原因：没有开关，写“内置·常开”）和 `modified`（世界里同 id 的那一份改过）；`restoreRowCommand`（一步的 `set_content null`）、`editStart`（编辑从世界里的那一份开始，用到世界是修改同 id 的那一项）。
- 通用编辑器：一组全是可以不写、至少 `SPARSE_MIN` 个的字段（规则的条件）只列写了的，其余从“添加”里选（`fields.ts` 的 `isSparse`、`sparseSplit`、`addedValue`：开关加上时是打开的）。

**导出**（`export.ts` 的 `humanFiles`）：`terrain_class.bmp`（类别的 `exportColor ?? color`；海、湖用 terrain.bmp 的颜色；画成陆地的碎岛落在海格里时按兜底的那一类）、`resources.bmp`（资源的颜色，没有资源的陆地是白色）、`terrain_classes.csv`（code, id, name, red, green, blue, terrain, cells；terrain 是 `paradoxTerrain(类别)`：丘陵 hills、高原 highlands、山地与山峰 mountains、平原 plains）、`resources.csv`（code, id, name, category, red, green, blue, cells）；`provinces_summary.csv` 最后加两列 `terrain_class, resource`。别的文件逐位不变。

**导出的地形**（第二十七轮，`terrain-class.ts` 的 `paradoxTerrain(起伏的类别, 生态的 terrain, 海拔, 坡度)`）：类别写了地形且不是 plains 时就是它，否则是生态的 terrain（没有生态时 plains）；没有类别时按海拔、坡度用内置的阈值判起伏。`cellParadoxTerrain(world)` 给每格（海 ocean、湖 lake，没有类别的陆地按兜底的那一类）；`terrain.bmp` 逐像素按格取它的颜色（`TERRAIN_COLORS` 多了 highlands、glacier；画成陆地的海格按兜底的类别），`summarizeProvinces(world, d, cellTerrain)` 的 terrain 是省里各格的多数（一样多时字母在前的），`terrain_classes.csv` 的 terrain 一列也是它。以前三处各写一份（terrain.bmp 按像素的海拔判山地丘陵、省份按平均海拔与坡度、表按类别），现在只有这一个函数；`human/human.test.ts` 逐像素核对三处一致。

**通行难度**（第二十七轮，`cellMovement(small, x, cls)`）：每格 = 类别的 `movement`（平原 1、丘陵 1.5、高原 1.3、山地 2.5、山峰 4）× 生态的倍数（`biomeMovement`：生态写了 `movement`——`speciesSchema` 新加的可选项，只改它时重算到 `human`——就用它，内置的 13 种按 `BIOME_MOVEMENT`：冰盖 3、苔原 1.3、针叶林 1.4、温带阔叶林 1.3、草原 1、灌木 1.25、亚热带常绿林 1.4、稀树草原 1、热带干燥林 1.25、季雨林 1.8、雨林 2、沼泽 2、荒漠 1.5；别的按生态的地形 `TERRAIN_MOVEMENT`）。平地上与以前植被类别的通行难度差不多；起伏上的林、沼泽比以前难走（以前丘陵的林只算丘陵）。文化圈、国家的 `edgeCosts`、道路的 `roadCosts` 都用它，A* 的估计用 `minMovement`。
