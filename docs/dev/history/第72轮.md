# 第七十二轮的设计

这一轮改了什么见 [更新记录](../../更新记录.md)；文件见 [ui.md](../ui.md)、[core.md](../core.md)。主题是生态的界面只在一处：以前编辑一种生态有两个地方——右边的生态抽屉（`ClimateChart.tsx` 575 行 + `SpeciesAdvanced.tsx` 444 行）和资源库里按字段表画的通用表单，两边叫法不一样、能改的不一样。现在只有一个生态编辑器，就是资源库里一种生态的页面。

**生成的世界逐值不变**：金标准、摘要、着色器的哈希、`tool-replay.json` 一个都没重录。

## 一个编辑器

- `src/ui/ecology/`：`BiomeEditor.tsx`（气候图下面：名字颜色、强势程度、高度范围、只长在……、雨季、长在哪里、水系、人文、按钮）、`BiomeChart.tsx`（气候图）、`BiomeAdvanced.tsx`（“高级”）；逻辑都在 `.ts`：`biome-edit.ts`（每处改动的补丁、新建复制的命令、导出）、`biome-target.ts`（存到哪里）、`advanced.ts`（高级里的补丁，从 `SpeciesAdvanced.tsx` 原样搬来）、`chart.ts`（气候图的几何、陆地分布、占比）、`base-map.ts`（在地图上看）、`open.ts`（别处打开）、`species-scripts.ts`（从 `ui/` 根下搬来）。最大的文件 363 行。
- `PageItem.tsx` 遇到生态时画 `BiomeEditor`，不再按字段表分段画（`page-segments.ts` 里生态的分段留着：测试查着每个字段都有归处）。生态在嵌进上级页面时也是它。
- 字段的叫法照生态抽屉的：“竞争力”→“强势程度”、“耐受条件”→“更精细的条件”、“样子”→“图案”、“地名设定”→“地名”（字段表 `core/content/kinds.ts` 的 `label` 跟着改，“和库不同：……”里写的也是这些）。
- **入口**：“自然 ⋯ → 编辑生态类型…”、没涂成的“编辑生态”、脚本出错的“编辑”、选好岛 / 圈好范围以后，都开到资源库的本世界 → 生态与水系 → 生态 → 那一种（`ecology/open.ts` 的 `openBiomeEditor`，`panel-store.ts` 新加的 `openLibraryAt`：栈里不在了的一层截掉）。右边的抽屉里只剩国家、城市、集团三种档案（`SHEET_KINDS`、`sheet` 的类型去掉 `species`）。选范围时（“只在一个岛上”“只在圈的范围里”）资源库面板关上，选好再开回来（以前是抽屉收起）。

### 同样的命令、同样的撤销

`biome-target.ts` 把“存到哪里”收成三样：`edit`（立即的补丁）、`queue`（排队，轮到时按最新的样子做补丁）、`replace`（整项换掉）。

| | 本世界 | 我的库 | 内置的、导入的库 |
| --- | --- | --- | --- |
| edit | `exec(update_species)`，和抽屉同一条、同一个“正在计算…” | 补丁落到那一项上（`applyPatch`：null 去掉字段），`commitItem` 换掉一项（这个库自己的撤销） | 不存 |
| queue | `queueSpeciesEdit`（和抽屉的“高级”一样） | 同 edit（库是同步的，用面板现在的那一份） | 不存 |
| replace | `commitItem` → `batch{update_species}`，带“改生态“X””（以前表单的那条路） | `commitItem` | 不存 |

抽屉改过的字段在本世界走抽屉的命令；只有表单才改的两项（宜居度、通行难度）走表单的路。水系一段两边本来就是同一个（`BiomeWaterSegment` → `commitWaterCell`，命令和抽屉的 `setWaterAllowed` 相同）。

`src/ui/ecology/biome-edit.test.ts` 把抽屉的写法原样抄进测试（拖色块、勾条件、雨季、高度范围、更精细的条件、新建、复制），和新的补丁逐个比；再换掉 `exec`、`queueSpeciesEdit`、`commitItem` 查本世界、我的库、只读的库各发了什么。

### 不一样的几处（有意的）

- 本世界里按钮是抽屉的那一排：用它涂、复制（副本不自然生成，叫“（副本）”）、新建生态、导出、删除（问一句，在用的也能删，长它的地方换成别的生态）。页面底下通用的“复制”“移出本世界”对生态不出（和这排重了，而且“移出本世界”在用时不让移）；“详细编辑”去掉（`DEDICATED` 里去掉生态：页面本身就是）。我的库里照旧是页面底下的复制、删除。
- 气候图上点别的色块是换到那一种的页面（页面换了，要拖再按一下）。抽屉里是同一个面板里换选中，点了就能接着拖。
- 库里看时气候图画这个库的全部生态，底下的灰点是本世界的陆地（没有世界时没有）；拖色块松手才存（没有预览：库里的生态不在世界上）。“现在占陆地”只在本世界写。
- “示例生态…”“导入…”两个按钮去掉：列表上有“从别的库加”，读文件在标题下拉的“读文件…”。
- “更精细的条件”的“添加条件”以前默认加一条海拔（0–2000–3000 m），海拔不在这里设了，改成年降水（同样的四个数）。

## 高度只在一处设

- 界面上只有高度范围的滑块。“只长在高山上”（命名条件 `mountain`：海拔 1000 / 1500 / 9000 / 9000）不再是“只长在……”里的勾，成了滑块旁边的按钮：把下限设到 `ALPINE_LOW` = 1500 m（上限不动；已经是 1500 时再点回到不限）。“更精细的条件”的下拉里没有海拔，列表也不列海拔的条件。
- **读进来的海拔条件**（`core/species.ts` 的 `elevationAsHeight`，资源包的 `biomes` 读的时候用，见 `kinds.ts` 的 `pack.read`）：换成高度范围后算出来逐值相同时换掉，否则原样留着。逐值相同要三条都成立——没写高度范围；海拔的这一条是最后一条，也是唯一的一条；四个数和 `heightTolerance` 给的一样。理由：算适宜度时用的是 `speciesTolerances`（写着的条件，加上高度范围排在最后），三条都成立时这两种写法给出的曲线数组一模一样（同样的数、同样的先后，乘的先后也不变），所有用到条件的地方（植被、约束求解、没涂成的原因）都走它。
- **用测试查，不靠推**（`core/species-height.test.ts`）：两种内置的高山生态把高度范围写成最后一条海拔条件，换回来就是原来的写法；在一块高山多的地区上，换前换后整个世界的推导（`digestWorld` 除了 `small`）逐个相同。
- **换不了、原样留着的**：以前的“只长在高山上”。高度范围的过渡只有 `HEIGHT_MARGIN` = 300 m（下限 1500 时从 1200 m 起），它从 1000 m 起，曲线不同。测试里硬换成 `{low: 1500, high: 9000}`：`derived.suit`、`derived.share` 变了（这块地区上主导的生态恰好没变，但适宜度变了，别的世界上就可能变）。还有：不是最后一条、写了高度范围又有海拔条件、两条海拔条件，都留着。编辑器里这些写一行“另有海拔条件 1000–9000 m（1000 m 起、9000 m 止）”，旁边“换成高度范围”：用户点了才换（悬停写着地图可能变），是一步，能撤销。内置的生态都写的是高度范围，没有海拔条件，所以内置的库、金标准都不受影响。

## 允许的水系只在两处改

河湖类型能出现在哪些生态里（`biomes`）只在生态编辑器的“允许的水系”和总表（`WaterTablePage`）里改。河湖类型的编辑器（“水系 ⋯”的 `panels/waterTypes.tsx`、资源库里河湖的页面 `WaterBiomesSegment`）只写一行“出现在：针叶林、阔叶林、草原 等 9 种”（全部、没有、前三种，`domain/water-biomes.ts`），旁边“去总表改”（世界里开到本世界的总表，库里的页面到这个库的总表）。

## 底图

- “图层”里和生态有关的只留地貌、生态分区。湿润程度、地形湿度、离海远近、涂生态时的温度调整、涂生态时的降水调整、某种生态的适宜程度挪进生态编辑器的“在地图上看”（`ecology/base-map.ts`）。渲染器里的这几种模式不动，只是换的地方变了。图层里的“更多底图”剩抬升和自定义场。
- **临时换、关上换回**：选一张就把 `mode` 换上，记下换之前的那张；编辑器关上（关面板、返回、换到别的页）时，地图上还是编辑器换上的那张就换回去。这期间在“图层”里换过底图就不动（和工具换底图的规矩一样）。换着看别的生态（`PageItem` 按种类和 id 做键，换一页是先卸下再挂上）不换回去：开着几个编辑器记一个数，挂上用 `useLayoutEffect`（和卸下在同一轮里），卸下后等一个微任务再看数是不是 0。适宜程度看的是编辑器里的那一种（`focusSpecies` 跟着换）；只有在本世界的生态才有这一项。图层里以前适宜程度下面的“看哪一种”下拉（`SuitabilityPick`、`suitabilityFocus`）去掉。
- **地貌的图例**：地貌的陆地按生态着色（加起伏、雪），图例列的和生态分区一样（按格数从多到少），标题写“地貌”。默认的底图就是地貌，所以打开世界左下角就有一张图例（可以收起）。
- **叫法**：生态条件的字段表（`BUILTIN_FIELDS`）里“湿润指数 P/PET”→“湿润程度”、“地形湿度指数”→“地形湿度”、“大陆度”→“离海远近”，和底图、“这里”的叫法一样；地形类别、资源的规则里“湿润指数”→“湿润程度”。界面上“没涂成”的原因按 `Inspector.tsx` 的 `reasonText` 写（本来就叫湿润程度）。
- **没改的字**：`core/constraints.ts` 写进推导的“建议”（`derived.conflicts` 的 `suggestions`，界面上不显示）用的也是这张表。第一次全量测试时 `golden-full`、`biome-legacy`、`solver-identity` 的 `derived.conflicts` 摘要因此变了（6 个测试）；金标准不能重录，所以那里另放一张小表（`CONFLICT_WORDS`）照旧写湿润指数 P/PET、地形湿度指数、大陆度，摘要回到原来的值。

## 导出是资源包

编辑器的“导出”以前写一个裸的生态数组（`species.json`），所以 `readPack` 一直留着 `legacy: 'biomes'` 这一条（第七十一轮记着）。现在写资源包（`biomesPack`：本世界的按导出的样子、写明自然生成，带上用到的自定义场；文件名 `本世界的生态.map2pack.json`），和资源库导出的一样。`readPack` 去掉读生态数组的那一段（也去掉了只给它用的 `name` 参数），读到数组时写“旧版的生态文件不再能读：请用新版导出的资源包”；`packs/store.ts` 的 `importBiomeFile`、`fileLabel` 去掉。测试：导出的包读回来就是导出的那些生态（`biome-edit.test.ts`）。

- `node tools/compose-ab.mjs --against main`：714 组，不同 0 组。
- 测速（`node tools/bench-median.mjs 5 …`，中位数，毫秒）。计算 Worker 里这一轮只多了读资源包时每种生态一次 `elevationAsHeight`、约束模块加载时多建一张三项的小表，加工的各步不碰它们。机器同时在跑别的工作树（负载 2–4.5）：

| 测法 | 标出 +5% 以上的步（旧 → 新） | 别的几次 |
| --- | --- | --- |
| 地区 `--against main` 第一次 | erod 203 → 225（+11%）、tempBrush 57 → 60（+5%） | 和自己（`--against HEAD`，代码一样）：erod 197 → 214（+9%）、tempBrush 55 → 59（+7%） |
| 地区 `--against main` 第二次（负载跳到 4 以上） | 十一步：relief、rivers、erod 204 → 228、tempBrush 53 → 73…… | 同上：同一份代码也标出这两步，第二次是整台机器忙 |
| 星球 `-- --globe --against main` | undo1 9 → 13（+44%） | undo2 8 → 5（−38%）：两步加起来 17 → 18；别的步都在 ±1% 里，erod +1%、tempBrush −1% |

erod、tempBrush 在“和自己比”里一样被标出（先跑旧的、后跑新的，后跑的这两步常常慢一点；第七十一轮也是这两步），星球上同样两步在 ±1% 里，所以是噪音，没有要压回去的步。
