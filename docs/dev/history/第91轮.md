# 第九十一轮的设计：资源库（二）国名与称号跟着库变；旧存档不再无声消失

这一轮改了什么见 [更新记录](../../更新记录.md)。两件事：

- **A**：用户头号的抱怨“改资源库看不到效果”里最扎眼的一条——把政体的称号“国王”改成“大汗”，地图上什么都不变，要重新生成国家（国界全重画）才看得到。用户定的：改了就自动跟着变。
- **B**：这一轮自己把世界文件的版本升到 22。以前别的版本的自动保存“当作没有”，启动直接进向导，新建以后旧的被盖掉：不修就会亲手弄丢用户上次的世界。这里只做最小的修（留下来、说清楚、能导出）；两个标签页互斥、关页面丢最后几步留给第九十四轮。

生成的结果逐值不变：金标准、摘要、着色器的哈希、界面的快照、地名排版的摘要一个都没有重录。世界文件的格式变了（见“世界格式变了什么”），`DOC_VERSION` 21 → 22。

## A. 国名、称号跟着库变

### 读代码查到的

- 国名 = 词根 `base` + 政体给这个国家的称号（`government.ts` 的 `govTitles`：按等级、换说法 `names` 挑），`records.ts` 的 `nameCountry` 在生成时算一次，存进 `CountryMeta.name / orig`。
  统治者的称号在 `rulers.ts` 的 `generateLore` 里按同一个 `govTitles` 取，名单上每一位都写同一个词（`RulerMeta.title`，在 `small.archive`）。
- “最典型的取值”（`records.ts` 的 `typical`）**不读地图上的人口**：它走的是资源库里这个文化（没写时文化组）写的倾向（`cultureTendency`），取权重最大的那个取值。任务书里担心的“人口后来被涂过，别的国家跟着改名”不会发生——称号只取决于内容和国家的三样（政体、主流文化、等级）。
- “这是手改的”已经有：`CountryMeta.nameLocked`（`set_country` 改名字时记，名字改成空的时去掉）。但联邦的成员邦、殖民地、公司领地的名字是格局起的，也记着 `nameLocked`（“名字不随政体自动改”）。统治者的称号没有这样的记号。
- 称号会读的内容：政体的 `titles / rulers / names`；国家等级的 `order`（称号按等级的 id 写，没写这一级时取最近的一级）；文化的 `group / tendencies / eraTendencies`；文化组的 `tendencies / eraTendencies`；取值的 `dimension / group`；时代的 `dimensions`；世界用的是哪个时代。
- 集团（帝国、联邦、同盟）的名字和联邦成员邦的名字不走政体：用的是时代的 `relations.titles`（`blocs.ts` 的 `titleFor`，按集团的编号挑一种）。时代的 `relations` 里只有这几种称号。

### 选了乙：名字照旧存着，命令之后重算

两条路：甲显示时现算，乙名字仍存在 `small.countries` 里、命令之后引擎重算。选乙：

- 读国名的地方有几十处（叠加层的排版与它的缓存键、档案、列表、图例、搜索、导出的几种文件、维基、历史的句子、撤销条上的字），甲要一处处换成函数，漏一处就是“这里没跟着变”；乙一处都不用动。
- 金标准、快照、摘要里记着的就是存着的名字，乙不改它们的来源，最容易保证一个都不重录。
- 甲每次读都要走一遍文化的倾向（一次几十微秒），排国名、图例是按帧读的；乙只在称号会读的内容真的换了的那一条命令里算一次。
- 撤销本来就是整份小数据退回，乙不用另记什么。

### 规则（`core/human/retitle.ts`）

每条命令执行完（`commands.ts` 的 `applyCommand`，在 `run` 之后、同一个 try 里：出错时整步退回）：

1. **要不要算**（`titleInputsChanged`）：世界的时代换了；或者上面那六种内容里，称号会读的那几项（`TITLE_FIELDS`）有哪一项变了。内容是不可变的、按引用共用，所以绝大多数命令（画笔、改别的内容）只是比几个引用；同一种里换了对象的项再比那几项的字（政体改“国土”、文化改颜色不算）。
2. **对每个国家**，拿“改之前的内容给它的称号”和“现在的”比（同一组（政体、主流文化、等级）只算一次）：
   - 国家称号不一样、没有 `nameLocked`、而且**现在的国名正是按改之前的称号起的**（`titled(base, 旧称号)`）：换成按现在的称号起的。
   - 统治者称号不一样：这一国里没有 `titleLocked`、称号正是改之前那个词的统治者（在位的、以前的都算）换成现在的词。
   - 世界里没有它的政体（换库时留下来的锁定国家）：不动——没法推。
3. **集团**（`retitleBlocs`，只在世界的时代的 `relations` 变了时）：没手改过名字的集团，找到“名字正是它的地名 + 改之前的称号”的那个成员（多半是盟主），地名不换、只换称号；联邦的成员邦名字正是“自己的地名 + 改之前的成员称号”的换成新的。
4. 国名变了时这一步至少重算到 `Dirty.Human`（和手改国名一样）。国家等级的内容本来是 `Dirty.None`。

给一个国家换政体、主流文化（`set_country`）时国名照旧由它自己重起；新加的是 `followRuler`：**在位的**统治者（名单最后一位）没手改过称号、称号正是换之前政体给的那个词时换成现在的，以前的统治者不动。

为什么是“正是按改之前的称号起的才换”，而不是“把没锁的都按现在的重算一遍”：

- 这样**只有适用的称号真的变了的国家才改名**，是能对新手讲清楚的一句话。全部重算的话，哪个国家的名字因为别的原因和“现算的”不一样（下面“注意到但没处理的”里拆分出来的国家就是），改任何一个不相干的词它都会被顺带改掉。
- 以前的统治者也用同一条：在库里把“国王”改成“大汗”是改这个词，名单上的“国王某某”都该变；给一个国家换政体是这个国家的一件事，以前的国王还是国王。两种情况用“改之前的词是什么”就分开了，不用另加规则。

### 第 5 条：用现在的人口还是生成时的

都不用。最典型的取值按资源库里文化写的倾向算（上面查到的），和人口无关。所以规则是：**只有适用的称号真的变了的国家才改名；涂人口、改国界、挪首都都不会让谁改名**。写进了使用说明（“国名、称号跟着资源库变”）。测试：把一国涂成别的文化的人、划走几格以后改一个词，改名的国家和没涂时一模一样；改一条没有国家满足的换说法，谁也不改名；`typical` 只给内容也算得出同样的结果。

要知道的一点：改文化的倾向（比如把“最多的宗教”换了）会让这个文化的国家换称号——如果政体有按宗教的换说法。这是“跟着库变”的本意，但那一段仍标“要重新生成”（人口要重新生成才按新的倾向分）。

### 第 6 条：已故的统治者、历史里的字

- 在资源库里改称号：名单上还用着原来那个词的都换（在位的、以前的）。给一个国家换政体、主流文化：只有在位的换。
- 国家档案“历史”那一段（`CountryMeta.history`）、大事年表的句子（`HistoryEvent.title`，“某某王国与某某结盟”）、备注是写下的字，**不跟着改**。历史没有“手改过”的记号，句子里的国名也可能是用户自己写的，替换字串会改到不该改的。以前手改国名时也不改它们（`limits.md` 早就写着）。重新生成国家时生成的那几句会重写，手写的照旧留着。
  所以“改完”和“改完再重新生成国家”相比：国名、外文名、每一位统治者的称号一样（测试查着），历史那一段和生成的大事的句子还是旧名字。

### 手改过的怎么记、世界格式变了什么

- 国名：照旧是 `CountryMeta.nameLocked`（`set_country` 写了名字时记，名字改成空的去掉并恢复自动；`new_country` 给了名字时也记）。没有加新的。
- 统治者的称号：新加 `RulerMeta.titleLocked?: true`。`set_ruler` 的 `patch.title` 写了字就记；**改成空的是恢复自动**（去掉记号，称号换成政体现在给的；以前是去掉称号）——和国名“改成空的恢复自动”一个做法。`add_ruler` 写的称号和政体现在给的不一样才记（界面的“加统治者”照抄上一位的称号：上一位是自动的，新的一位也跟着变；上一位是手改的，新的一位也算手改的）。
- 命令的格式没有变（没有加字段、没有加命令）；变的是命令的含义：改内容的命令之后国名、称号会重算，`set_ruler` 的空称号是恢复自动。旧文件重放出来的国名可能不一样，所以 `DOC_VERSION` 22，代码里不留旧的写法。

### `timing.ts`：哪些改成了“即时”

| 种类 | 字段 | 这一轮 | 依据 |
| --- | --- | --- | --- |
| 政体 | 国家称号、统治者称号、换说法（“称号”一整段） | 要重新生成 → 即时 | `retitle.ts`；测试：改了不算“改了 N 项”，国名马上变，和“改完再重新生成国家”起出来的一样 |
| 时代 | 集团的称号（`relations`，一整段） | 要重新生成 → 即时 | `retitleBlocs`；`regen.ts` 的 `ERA_COUNTRY_KEYS` 里也去掉了它 |
| 时代、取值、取值组、文化组、文化、政体、国家等级、国家格局、城市等级、地标、点 | 名字 | 没能确认 → 即时 | 生成不读：每一种里把名字都改掉再重新生成，`humanDigest` 逐项相同（文化除外，见下）。存着的字串里没有它们（国家、集团、档案、省名、城市里存的都是 id 或自己的名字），界面只能现读 |
| 取值、取值组、文化组、文化 | 外文名 | 没能确认 → 即时 | 同上 |
| 国家等级 | 简称 | 没能确认 → 即时 | 同上 |

- 文化的名字有一处例外：生成国家时写进了档案“历史”那一段（“某年，某某人建立某某王国”）。那是写下的字（第 6 条），改名不跟着改；测试里文化这一种比的是“除了历史那一段都一样”。
- 一段里还有要重新生成的字段时，这一段仍标“要重新生成”，那一句里写“名字、外文名、颜色、说明马上变”。所以页面上整段换成“即时”的只有政体的“称号”和时代的“集团的称号”，各写一句“自己改过的国名、称号不动”“自己改过名字的集团不动”。
- 国家等级的“高低”、文化的文化组和倾向、取值的组也会让国名马上跟着变，但它们生成时也要读，仍标“要重新生成”。
- 仍然没分清、留在 `limits.md` 的：文化、文化组的**地名风格**（国名的词根、省名是生成时定的，城市名现算）；时代的城市化率；城市等级“多大算这一级”；自定义点的“当作城市”。

### 称号编辑器（`title-help.ts`、`editors.tsx` 的 `TitleEditor`、`ItemPreviews.tsx` 的 `TitleReplace`）

- **示例**：每一行称号下面一行，国名（“青岚王国　Kingdom of Qinglan”）或统治者的称呼（“国王安澜”）。本世界里用地图上真的国家的词根（先找用这个政体、又是这一级的，再找用这个政体的，再是随便一个；没改过名字的优先），库里用固定的例子。拼法就是引擎的 `titled`。`Draft` 加了 `onDraft`：正在打的字马上就是示例（存还是离开框才存）。
- **谁盖过它**：政体默认的那两张表里，一行下面写哪几条换说法会盖过它（“换说法盖过：阿尔泰、鞑靼写“汗国”；…… 等 5 条”）。判断和引擎一样：换说法的表里写了这一级、写了“其余”、或只写了一种的那几条。几样条件都写了的写“甲 且 乙”。只说“满足时会盖过”，不逐国算谁满足。
- **把一个称号都换掉**：两个框和“替换”，写着词的时候下面先说“会改 12 处（5 个政体）”。只换整个就是这个词的写法（“部落王国”里的“王国”不算：换半个词结果难料），外文的写法不动。本世界是一条批量命令（一步，能撤销；执行时按那一刻的世界再算一遍）；我的库走 `library-edit.ts` 新加的 `setItems`（一步，撤销一次全回去，有一项不合格就都不改）。
- 用上下文（`TitleHelpCtx`）把这些交给 `TitleEditor`，只有 `PageItem` 在政体的“称号”一段外面给；别处的称号框（地标名字的写法……）照旧。

## B. 旧存档不再无声消失

### 做法（`src/backups.ts`、`src/state/backups.ts`）

- `core/doc-version.ts`：`docAge(doc)` 分四种——这一版、旧版本、比这一版新、不是世界文件。`checkDoc` 对“比这一版新”报另一句（“这个世界是更新的版本做的，请先更新程序”），以前也说成“旧版本”。调用方：`engine.ts` 的 `fromDoc / fromCheckpoint`、`state/open.ts` 的 `loadDoc`（提示条写的就是这句话）、`state/autosave.ts`（`isCurrentDoc`）都看过，不用另改。
- `src/idb.ts`：库第 7 版，只多一张表 `backups`（升级照旧只补缺的表）。
- 启动时读自动保存之前（`readAutosave` 的第一句；写自动保存之前也等同一个 Promise，哪个先到都行，一次打开页面只做一次）：`keepStaleAutosaves` 看 IndexedDB 里的和 localStorage 后备里的自动保存，这一版打不开的（旧的、更新的都算）原样做成一条 `WorldBackup`（整个世界文件连命令、它最后一次自动保存的时间、留下来的时间、它自己的版本号、几步、安全模式的原因、连着哪张地图）。
  - IndexedDB 里的：一个事务里放进 `backups`、删掉 kv 的 `autosave`、清空 `autosave` 表——要么都做，要么都不做。
  - localStorage 里的：IndexedDB 能用就放进 `backups` 再删原来的键；用不了（隐私模式，本来就是因为这个才有后备）就在 localStorage 里换一个键（`map2.backup.<编号>`）。localStorage 放不下两份，所以先拿掉原来的再写（同步的两句）；写不进去就放回原处，`autosave.ts` 写后备之前再看一眼（`staleLocalAutosave`），不盖它。
  - 之后 `readAutosave` 照旧返回 null（进向导）。自动保存的位置空了，新世界怎么存都碰不到它。
- 存取经 `BackupIo`：规则都在纯函数里，测试换成内存里的（`memoryBackupIo`，能装“IndexedDB 用不了”“localStorage 满了”）；浏览器那一层（`browserBackupIo`）只有几行，另有一个用假 IndexedDB 走 `readAutosave` 整条路的测试。

### 界面

- 一直在的一条（`shell/BackupBanner.tsx`）：“上次的世界是旧版本做的，这一版打不开。它还留着”（更新的版本做的是另一句），“导出文件”，× 关闭。启动时向导盖着地图，所以这一条在向导最上面的一块里（多一句“以后在‘世界 → 留着的旧世界’里找”）；进了地图以后在顶上的横幅里。要用户自己关；关过了记在那一份上（`seen`），下次启动不再提示。
- “世界”菜单里一行“留着的旧世界…”（有才出现，写着几个），打开列表（`maps/BackupsDialog.tsx`）：一行一份（时间、第几版、几步、为什么打不开），导出文件、删除（先问，删了找不回来）。程序更新以后这一版能打开的那一份（原来“更新的版本做的”）多一个“打开”。
- 导出的文件就是那份世界文件本身（`JSON.stringify(doc)`），里面写着它自己的版本号；文件名“旧世界 2026-11-09 第21版.json”。
- 文字都在 `ui/copy.ts` 的 `BACKUP_TEXT`。按 `ui-design.md` 的叫法用“关闭”“导出文件”，没有用“知道了”。

- 当前版本、但命令条数对不上的自动保存（写到一半）照旧当作没有。

## 注意到但没处理的

- **拆分出来的国家**（`country-edit.ts` 的 `splitCountry`）：先按“没有等级”起名（称号取正中的一级），再把原来国家的等级抄给它，所以它的名字、统治者称号和“按它的等级现算的”可能不一样（以前就是这样）。这一轮的规则对它是安全的（名字不是按旧称号起的就不动，不会被不相干的改动顺带改掉），但改它那一级的称号时它不一定跟着变。要改就得动拆分时起的名字，会改到已有的行为，没有动。
- 殖民地、公司领地的名字（“某某属某某”“某某殖民地”）用的是代码里写死的几个词（`patterns/colonies.ts`、`outposts.ts`），不在资源库里，不跟着变。
- 文化的地名风格改了，国名的词根不跟着重起（词根是国家的身份，重起等于所有国家换名字）；要换就重新生成国家。
- 国名跟着变以后，“历史”那一段、生成的大事还是旧名字（第 6 条）。
- 换库重新生成人文时留下来的锁定国家：它的政体还在新库里、称号不一样时，名字会跟着新库变（按同一条规则）；政体不在了的不动。
