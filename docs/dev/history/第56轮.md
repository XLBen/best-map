# 第五十六轮的设计

这一轮改了什么见 [更新记录](../../更新记录.md)；现在的文件见 [开发说明](../../开发说明.md) 与 docs/dev/ 下的各篇。

用户定的：**有些地形（生态）允许出现什么水系，有些不允许**。条件是声明式的，普通河、普通湖也是允许表里的一行，河按段定类型，不允许时按生态设置换类型或断流。这一轮不加新的河湖内容（第 57 轮），不做总表和新面板（第 59 轮）。

## 数据放哪里

**允许表的一格只存一处，没有放在生态的 `allowedWater` 上**（计划建议过）：

| 表里的行 | 存在哪里 | 省略时 |
| --- | --- | --- |
| 普通河、普通湖 | 生态：`species.plainRiver`、`plainLake`（`false` 不允许） | 允许 |
| 别的河、湖 | 这种水：`type.biomes`（已有的字段） | 全部生态；空的列表哪里都不行 |
| 不允许时怎么办 | 生态：`species.waterBlock`（`'stop'` 断流） | 换类型 |

理由：

- **`biomes` 本来就在**，引用表、导入改名、依赖（`dep: 'auto'`）都有。放在生态上就要生态反过来引用河湖：导入一种生态会拖来一堆河（第 61 轮的“还会带上”），河和生态还互相引用。
- **河湖的包是自足的**：第 57 轮的冰川河自己写“在哪些生态里”，不用去改每一种生态（也改不到用户自己做的生态）。
- **新加一种河不用改生态**：`allowedWater` 是白名单时，新河在有名单的生态里全都不允许，要一种一种去勾。
- **普通的河湖没有自己的记录**，只能在生态上。
- 一格只在一处，不用两边同步。`core/water-table.ts`（`waterAllowed`、`setWaterAllowed`、`setWaterBlock`）是唯一的读写入口，生态抽屉和河湖编辑都用，第 59 轮的总表直接用。

代价：总表改一格时要看是哪一行，发不同的命令（`update_species` 或 `set_*_type`），都在 `setWaterAllowed` 里。没列生态的一行取消一格时写成列出别的所有生态，全勾回来就去掉列表；所以之后新加的生态不在列表里，默认不允许这一种（普通河不受影响）。这和“这种河我专门挑过地方”的意思相符，写在这里。

**`biomes` 的意思变了**（只影响写了它的世界，内置的内容都没写）：以前是“流经的格至少一半”，整条河一种；现在河按每一格的生态，再分段。湖还是湖岸一圈至少一半。`core/biome-range.test.ts` 那一条跟着改写，脚本 `biome()` 还是整条河算一次，所以那条测试不再说两种写法逐值相同。

## 条件

`type.when = { height?, slope?, temp?, flow? }`，每项 `{ low, high }`，到 `WHEN_RANGE` 的两头是不限（全是不限不算写了条件，`hasWhen`）。

- 高度：`max(0, d.elevation)`，米；坡度：`d.slope`，m/km；气温：`d.tMean`，年均 °C；流量：`d.discharge`，m³/s。都是检查器里写的数。
- **硬边**：类型是分类，不像生态要混色。不碎靠分段。
- 河按每一格，湖按整个湖（高度、坡度、气温取平均，流量取最大，和脚本读到的汇总相同）。算类型时湖底还没修（`shapeLakeBeds` 在最后），和脚本读到的一样。
- 流量的滑块按对数走（`flowScale`），`RangeSliders` 多一个可选的 `scale`。

## 一格是哪一种（`river-types.ts` 的 `labelRivers`）

1. 选了类型的河道（和以前一样，最优先，不受任何规则限制）。
2. **按类型的先后**，前面的说了算：
   - 只写了 `match` 脚本的：整条河一种（和以前逐值相同，脚本还是每条河算一次）；
   - 写了条件或列了生态的：按每一格看。同时写了脚本的，脚本说“是”的河才看（脚本是整条河的门槛）；
   - 只写了条件的类型也看“有一格是河道定下的河”上别的格（脚本的类型照旧不看这种河）。
3. 往下游传：只从第 1、2 步**整条定下的、河道定下的**格传。按格定的不传，不然冰川河会一路染到海。
4. 允许表：这一格的类型这里不允许时：
   - 带类型的河道传下来的，这里允许普通河：普通河；
   - 断流的生态：断流（只有水文那一遍，`stopCells`）；
   - 否则换成**这一列从上往下第一种允许、开着自然生成的**（条件不看：“这一段换成这里允许的类型”），一种都没有时照旧是普通河。
5. 短段并进相邻的段（`river-segments.ts`）。

没有规则的世界（`waterRules` 返回 null：没有列生态、写条件的类型，也没有不允许普通河的生态）不走第 4、5 步，和以前逐值相同。只有脚本的奇幻世界就是这样，`r29` 查着。

**断流的生态里也可以有河**：这里允许的类型条件满足时照常流。断流只在“这一格没有允许的类型”时发生；普通河允许时不会断流。所以生态抽屉选“断流”时同一步取消普通河（不然什么都不会发生），再勾上普通河时写一句“普通河允许时不断流”。

## 分段

- 一段至少 `RIVER_SEGMENT_MIN` = **4 格**。按格不按 km：地区和星球的格大小差很多，按格看起来都不碎。4 万格的地区里 753 条河一共 2371 格，平均三格多（长的几十格），门槛再高就很难有分段了；短的河整条一种。
- 只看一条河（`stems`，源头到汇入更大的河）从上往下的先后：取最短的段（一样短取上游的），并进较长的邻居（一样长取上游的），相同的连起来，直到没有太短的段。和格的编号无关（测试打乱编号对照）；唯一和编号有关的是 `riverNet` 里流量**完全相等**时取编号小的上游，这是以前就有的。
- 选了类型的河道所在的段不会被并走，别的段可以并进它。
- 并进去的几格可以是这里不允许的类型：这是“不一格一变”的代价。断流也一样：一小片（不到 4 格）不断流，不然路过一格荒漠的大河就没了。

## 断流

一遍里（`engine.ts` 的 `pass`）：

```
水文 → 不计水体类型的生态（baseBiomes）→ 哪些格断流（stopCells）→ 再算一遍水文（cut）→ 植被、河湖类型
```

- **单向，不迭代**：断流的格只按第一遍的水定。结果只取决于原因，撤销、重放都一样（测试查着）。
- `computeHydrology(..., cut)`：这些格的流量是 0，水不往下游流（`accumulateFlow`；分流 `splitFlows` 到这里停）。汇流有缓存（`routeMemo`），第二遍不重新填洼。
- **高程、流向、汇水面积、湿度指数都不变**（河道没改，只是水没了）；变的是流量和跟着流量走的内流湖涨落、读流量的生态。
- 湖的出口算蒸发在前、断流在后：湖的蓄水不因为出口断流算错。
- **画的河、锁定的河不断流**：`hydrology.ts` 有“画出来的线一路都在”这一条，用户画的说了算。没选类型的画的河照样按这一格的规则换类型。这是替用户定的。
- 断流之后还留在这种生态里的河（水少了、条件变了、断流那一遍并进相邻段的）在定类型那一遍按换类型算，不再断。
- 不用断流的世界不走这里。用断流的世界每遍多一次 `baseBiomes` 和一次水文（汇流命中缓存），量到的见“量到的”。

## 湖

- 条件、列的生态（湖岸一圈至少一半）都要满足，整个湖一种。
- **湖没有断流**：湖是积出来的水面，水文已经算完，不能只去掉一块；断流的生态对湖也是换类型。写在生态抽屉的小标题上（“河不允许时”）。
- 不允许普通湖按湖岸最多的那种生态看（一样多取先列的），换成这一列第一种允许、自然生成的；**一种都没有时照旧是普通湖**。放的湖、选了类型的湖不受限制。

## 提速：不多算一遍植被

以前类型按生态限制时每遍算两次植被（`baseBiomes` 一次、真的一次）。第 57 轮新世界默认带类型，这就是每一笔的代价。

两次只差河岸、湖岸（`baseBiomes` 把 `riverType`、`lakeType` 当作没有）。**生态不读河岸、湖岸时两次逐值相同**，算一次就够，算完再定类型（`computeVegetation` 的 `after`，问题的先后不变）。读不读（`water-types.ts` 的 `readsBanks`）：条件里的 `river:`、`lake:`，“长在哪里”脚本里的 `river`、`hasRiver`、`nearLake`、`hasLake`（`codeOnly` 之后找名字，保守：写了就算读）。颜色脚本不决定长什么，不算。

`match` 脚本读不到植被的结果（`worldInputs` 里没有），所以挪到植被后面值不变。

**新旧逐位相同**（`core/water-rules.test.ts`）：`waterPlanDebug.baseFirst` 打开时照旧的走法，同一串命令整个世界的摘要和 `scriptIssues`（含先后）相同：按生态的类型、条件、允许表；脚本里用了生态、脚本出错；带“长在哪里”脚本和影响的奇幻生态。`vegetationStats.base` 查着新的走法一次都不多算、读河岸的世界照旧先算。

另两处，也都有逐位相同的测试：

- **河网**（`riverNet`）：哪些格是河、每格最大的上游和上一次相同时，一条条河不重新走（第五十五轮的算法原样拷在测试里对照；留着的结果不会被下一次改掉）。
- **河线的类型**（`rivers.ts` 的 `doubledTags`）：平滑时不再每一遍跟着加，算完一次展开，一条线一种类型时直接填。和 `cells` 同样的规则，测试把同一份数传给两边对照。

## 看图

真的渲染器加叠加层，无头 Chrome（脚本不进仓库），4 万格地区，五种河（青：冰川，蓝：山溪，橙：季节河，黑：黑水河，红：泥沙）：

- 荒漠里的河一段黑水（经过沼泽湿地的那几段）、一段普通的蓝、进稀树草原变橙，颜色在段的交界处干净地换，没有一格一变。

## 坑

- **第 57 轮**：内容里的 `natural: true` 要写明（包里没写的加进世界时是关着的，`naturalOff`）。类型的先后有意义，“第一种允许的”也按它。`biomes` 不写就是全部，写了以后新生态不在里面。
- **第 57 轮**：资源的规则、起名都没动。一条河上几种类型时按多数起名（`majorityType`，超过一半才算），没有多数时用普通河的名字。
- **第 59 轮**：总表读写用 `water-table.ts`。一行全取消是空的列表（`biomes: []`），不是省略。
- **第 58 轮**：涂地形类别改高度以后，按高度、坡度的条件跟着变，是预期。
- 改一条按段定类型的河的走向时不再把整条河定成一种（`ruleTypeOf`，这条河上不止一种时不记）。只有一种时照旧记下。
- 底部条上“类型：X”写的是多数（`riverTypeOfRiver`）；没有多数时写普通河。一格一格的看检查器。第 59 轮可以改。
