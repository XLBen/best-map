# 第九十轮的设计：资源库（一）改了就看得到

这一轮改了什么见 [更新记录](../../更新记录.md)。用户（不懂技术的新手作者）头号的抱怨是“编辑资源库太难用”，其中一条是“改了看不到效果”。
这一轮只解决这一条；国名称号现算、搜索与地图直达与“只改这张地图”、表单简化与做法统一留给第九十一到九十三轮。

生成的结果逐值不变：金标准、摘要、着色器的哈希一个都没有重录，世界文件的格式没变（`DOC_VERSION` 不动），已有世界重放出来和以前一样。

## 为什么看不到效果

1. **不知道这一项用上了没有**：页面最下面收着的“谁用到它”才写“长在 261 格”；没用上时什么都不写，不知道是哪里不对。
2. **新建的默认不生效**：新建的生态、河、湖“自然生成”关着；复制生态时还悄悄把它关掉。两处新建的默认值又不一样（列表上新建强弱 1、没有气候范围，生态页上新建强弱 3、有范围）。
   从“全部文化”新建的文化放进 `chinese` 组——世界里常常没有这一组。
3. **不知道什么时候生效**：只手标了两处“即时”（本世界的生态、省份划分的“湖”）。别的不标，看上去都像要重新生成；
   其实地形类别、资源、地名风格、河湖、画风改了引擎自己就重算了。反过来国家等级里首都图标的大小、浓淡是画的时候现读的，却被算进“改了 N 项 · 重新生成国家”。
4. **“改了 N 项 · 重新生成”藏着**：只在面板开着、看本世界时出现；只记在内存里，刷新页面、重新打开世界就忘了（使用说明自己写着“之后从那时候的内容算起”）。
5. 地标名字的写法（“{city}神庙”）、政体的旗（纹章、样式）填的是字，看不到会是什么样。

## 1. 每一项顶上一行“在地图上”（`on-map.ts`、`OnMapLine.tsx`）

只在看本世界、不是在上级页面里展开着时。用上了写用在哪里（能定位），没用上写原因，能一下子解决的旁边一个按钮。
原因按每一种实际的生效条件写，每一条都有测试（`on-map.test.ts`），给了命令的解法在测试里真的执行一遍。

| 种类 | 用上了 | 没用上的原因 · 解法 |
| --- | --- | --- |
| 生态 | 长在 N 格（主导生态是它的格） | 自然生成关着（也没涂它 / 涂的地方没长成）· 打开；选的范围里、起源地附近没有适合的地方；没有适合它、又争得过别的生态的地方 |
| 河、湖 | 河道 / 湖面 N 格 | 自然生成关着 · 打开；还没选生态、写条件 · 去选（展开那一段）；没有符合条件的河（湖）· 看条件 |
| 地形类别、资源 | 占 N 格 | 没有符合自动规则（条件）的地方 · 看规则 |
| 岛、自定义点 | N 格是这种岛 / N 个点 | 还没放 |
| 地名风格 | 世界默认的；N 个文化、地名、省份 | 没有地名、文化用它 · 设为默认 |
| 画风 | 地图正用这种画风 | 没在用 · 用它 |
| 省份划分 | N 个省份按它划分 | 还没有划分省份 · 划分省份 |
| 时代 | 这张地图的时代：N 个国家、N 座城市 | 还没有生成人文 · 去生成；这张地图用的是“X” |
| 文化组 | N 格有这一组的人、N 个国家 | （多少是 0，）没参与生成 · 加进来；重新生成后才出现 · 重新生成；这次生成没分到地方 |
| 文化 | N 格有这种文化的人、N 个国家的主流文化 | 所在的文化组“X”没参与生成 · 加进来；重新生成后才出现；这次生成没分到地方 |
| 取值、取值组 | N 格有这样的人；N 个取值属于它 | 时代没有这个变量 · 去加；重新生成后才出现；这次生成没分到人 |
| 政体 | N 个国家 | 还没有国家 · 生成国家；重新生成后才出现；多少是 0 · 去改；没有国家满足“限谁用”· 看条件；这次生成没有国家选它 |
| 派系 | N 个国家有它 | 没有政体列着它 · 去政体里加；列着它的政体这次没有国家 |
| 国家等级 | N 个国家 | 时代里这一级的比例是 0 · 去调（生成设置）；这次生成没有这一级的国家 |
| 国家格局 | 这张地图的时代列着它 | 时代没列这种格局 · 加进时代 |
| 城市等级 | N 座城市（按现算的等级数） | 还没有城市 · 生成城市；没有城市够得上这一级 · 看条件 |
| 地标 | N 个地标 | 不自动放；还没有生成城市和地标 · 生成；生成城市时没放地标 · 放地标；没有国家是限定的文化组 · 看条件；这次生成没放它 |

取舍：

- “参与生成”和 `regen.ts` 算的是同一份（`joiningGroups`：上次生成选了的组，加上重新生成时会加进来的——本世界自己加的、多少不是 0 的组）。
  所以本世界自己新建的组、它里面的文化，底下有“改了 N 项”时写“重新生成后才出现 · 重新生成”（按钮就是底下那一步）；库里默认不带的组（多少是 0、上次没选）才写“没参与生成 · 加进来”，
  按钮发的是“文化 ⋯”里勾上这个组再重新生成的同一条命令（`regenerateWith`）。
- 生成人文要选库、选文化组，没法一键：按钮打开“文化 ⋯”。生成国家、城市、划分省份是一条命令，直接做（能撤销）。
- 数的办法复用现成的：有人的格是 `core/content/usage.ts` 里删除前查的那一套（新导出 `peopleCells`），生态、河湖、地形类别、资源按推导数（和“谁用到它”一样），城市等级按现算的城市表 `cityList`
  （以前“谁用到它”只数自己定了等级的城市）。
- 页面底下的“定位”按钮在有这一行时不再放一个（这一行上有，格更全：生态是长着它的格，不只是涂的）；没用上、但有手动指定它的地方（涂了没长成）时照样能定位。
- 生态页上以前就有“现在占陆地 X%”和“看底图”，照旧。

## 2. 新建就生效、复制保持原样

**默认值是在哪一步写进去的**：界面发命令时。`ContentKind.blank()` 只有界面的“新建”读（`src/ui/packs/fields.ts` 的 `blankItem`，`page-actions.ts` 的 `newItemIn`、`newChildIn`），
引擎执行、重放都不读；命令里带着整项（`add_species {species}`、`set_river_type {type}`、`set_content {item}`），格式里也没有补默认值的地方（“自然生成”没写就是没写，
引擎按“没写是开着”读，不往世界里补）。资源包里没写的关掉（`naturalOff`）也是界面做计划时写进命令的（`core/packs.ts` 的 `planPack`）。
所以改登记表里的 `blank()` 不影响任何已有世界的重放（测试：命令里写着关着的，执行、重放出来还是关着；没写的不补）。

- **生态**：`core/species.ts` 新的 `freshSpecies(id, name, color)`：自然生成开着，强弱 3，最适合 5–18 °C、湿润 0.6–1.6（以前生态页上新建的那个范围）。
  登记表的 `blank()` 和 `ecology/biome-edit.ts` 的 `newSpeciesCommand` 都用它，两处只差 id、名字的编号、颜色。强弱取 3：内置的生态在 1.5–4.5 之间，取 1 时几乎哪里都争不过，建了等于没建。
- **河、湖**：`blank()` 和底部条“新建类型…”（`panels/water-types.ts` 的 `newWaterType`）都改成自然生成开着。只开着、没选生态、没写条件和规则时照旧不会自己出现
  （`core/water-types.ts` 的 `matchesNaturally`），“在地图上”写“还没选生态、写条件 · 去选”。例外：有生态不允许普通河、又没有别的河可换的世界里，新建的这一种会被选成“换成哪一种”（它在每种生态里都允许、又开着自然生成），这时那一行写河道几格。
- **复制**：`copySpeciesCommand` 不再写 `natural: false`，原来是什么就是什么（原来没写的不写）。通用的复制（`copyItem`）本来就原样。
- **文化**：在某个文化组里新建照旧跟这个组（`newChildIn`、列表的 `defaults.group`）。从“全部文化”新建时列表上面出来一栏“放进哪个文化组”（`new-in.ts` 的 `newChoiceOf`、`PageList.tsx`）：
  本世界里只列参与生成的组，库里列这个库的全部组，还没生成人文的世界列多少不是 0 的。没选组时 `newItemIn` 不建。登记表里 `blank()` 的 `group: 'chinese'` 没动（它得是一项合格的文化，`pages.test.ts` 查着），界面不再用到这个默认。
- 新建一种会自然生成的生态后地图马上变：页面最上面那一行立刻写“长在 N 格”，是一步，能撤销（测试查着）。

## 3. 改之前就知道何时生效（`timing.ts`、`TimingMark.tsx`）

一张表，页面上的标记和“改了 N 项”都从它推（以前两处各管各的）：

- 看我的库：每一段“只影响新地图”。只读的库、本世界的星球形态不标；没有可改的（地名风格的示例）不标。
- 本世界，不在“要重新生成”的种类里的：即时。它们的命令执行完引擎自己从该重算的那一层重算，或者只在画、用的时候现读。
- 本世界，生成时才读的种类（`core/regen-base.ts` 的 `SCOPE_KINDS`）：要重新生成；其中画、用的时候现读的字段（`INSTANT_KEYS`）即时。
- 一段里几个字段不一样时按最慢的标，段里写一句哪几个马上变（“改完点底下的“重新生成”；颜色、说明马上变”）。

每一种读过的代码和最后标成什么：

| 种类 | 标成 | 依据 |
| --- | --- | --- |
| 生态 | 即时 | `update_species` 按改了什么从植被或更深重算（以前就标着） |
| 河、湖 | 即时 | `set_river_type` / `set_lake_type` 按改了什么重画、重新起名或从植被重算 |
| 岛 | 即时；形状、高低、岩石只影响以后放的岛（段里写着） | `islandTypeDirty` 的注释：形状、高低、岩石只影响以后放的岛 |
| 地形类别、资源 | 即时 | 登记的 `dirty` 是 `human`：改了引擎重算人文的几层与名字 |
| 地名风格 | 即时 | `dirty`：在用时重新起名，没在用时不用算 |
| 画风 | 即时 | `dirty` 是 `none`，只是画法 |
| 派系 | 即时（以前算“重新生成国家”） | 生成国家的各步不读派系；影响力是 `countryFactions` 用到时按政体列的派系、“多少”和人口现算的 |
| 省份划分 | “湖”即时，名字说明即时，大小、省界要重新生成 | 以前就是（`PROVINCE_KEYS`） |
| 时代 | 都要重新生成；“变量”那一段即时（本世界里是加变量的单子，一条命令，现有的人原地分开） | 颜色、说明马上变 |
| 取值组、取值、文化组、文化 | 要重新生成 | 颜色、说明马上变 |
| 政体 | 要重新生成；“有哪些派系”、颜色、说明马上变 | `governmentFactions` 只有 `countryFactions` 用；旗是生成时按政体的纹章、样式定的 |
| 国家等级 | “首都”一段即时（以前算“重新生成国家”）；别的要重新生成 | `capitalLook` 只有画城市、排国名时调 |
| 国家格局 | 要重新生成 | 只在生成国家时读 |
| 城市等级 | “样子”一段即时；“基本”要重新生成（名字、图标、颜色、说明马上变）；“多大算这一级”要重新生成 | 城市的表现算；道路读“连大道”、重要、首都用，地标读重要 |
| 地标 | “基本”“名字的写法”即时；谁有、放在哪要重新生成 | 地标只记类型和格，名字每次按写法现起 |
| 自定义点 | “基本”即时；“当作城市”要重新生成 | 点是自己放的，列表现读类型 |

测试（`lib-seen.test.ts`）：整张表钉住；标“即时”的字段改了不算“改了 N 项”，而且**改了以后重新生成、和没改重新生成的结果一样**（`humanDigest` 逐项相同：这几个字段生成时确实不读）；同一种里生成要读的一项改了就算。

没能确认、保持原样（要重新生成）的：

- 文化、文化组、取值、时代、政体、国家等级的**名字、外文名、简称**：图例、档案里多半是现读的，但没有逐处查生成的字串里有没有用到，仍算要重新生成。
- 文化、文化组的**地名风格**：改了引擎会重算人文的几层与名字（`dirty` 是 `human`），城市名是现算的，但省名、国名是生成时定的，没有逐项分清，仍算要重新生成。
- 时代的**城市化率**：城市的人口是现算的（`computeCityTable` 读它），生成时也读，仍算要重新生成。
- 城市等级的“占本国人口”“人数下限”：城市定哪一级马上变（现算的），但道路按等级连，要重新生成才跟上，标要重新生成。
- 自定义点的“当作城市”：进城市的表（现算），道路、地标按表放，标要重新生成。

顺带的变化：新加一种自定义点（只有名字、图标、颜色）不再算“改了 N 项”；从别的库添加派系、点的类型时清单底下不再写“重新生成后才用上”（`pick-other.ts`）。

## 4. “改了 N 项”不再藏着

### 顶栏的小标记（`shell/TopBar.tsx`、`panel-store.ts` 的 `pendingBadge`、`regen-now.ts`）

面板关着、或者看的是别的库时，“资源库”按钮旁边一个“改了 N 项”（窄窗口只留数）；看本世界时不写（那一条就在面板底下）。点它回到本世界（面板关着就打开）。
顶栏一直在，世界每换一份（画一笔也是）都会问一次有没有：`regenNow` 按用到的几样（内容、人文、城市的规则、省份、上一次生成时的那一份、资源库）记着，都没换就不算；
`regenNeed` 自己也加了一句“内容还是那时候的那一份就不比”。画一笔时这几样都是手上同一个对象（`content-post.ts`），所以是六次比较。

### 刷新、重新打开以后还在（`core/regen-base.ts`）

要知道的是“每一样上一次生成时世界里的内容”。以前只在主线程上跟着这一次打开页面的每一步记。其实不用另存：引擎的历史里每一步都留着它之前的内容
（撤销记录的 `content`，按引用共用，见 `small-copy.ts`），所以“最后一次生成这一样的那一步之后的内容”就是它后面那一步的撤销记录里的那一份（它是最后一步时就是现在的内容）。
打开世界时历史是从命令记录来的（重放，或者从检查点恢复——检查点里带着历史），所以从命令记录里就能算出来，世界文件、检查点的格式都不用动。

- `regenBaseOf(done, now)`：从后往前走一遍历史，四样都找到就停。哪条命令重新生成哪一样、哪条是手改，从 `src/regen-track.ts` 搬到 core，两边用同一份。
- 引擎只在**新建、打开、撤销、重做**的回复里带上（`Response.regen`）；执行的回复不带，主线程照旧自己跟着记（`RegenTrack`）——编辑一点都不多做事。
  撤销到这一次打开页面之前的步骤时，主线程没记过那个位置，用引擎给的（以前是“从现在的内容算起”，就忘了）。
- 只发和现在不一样的项（`postRegenBase`）：每一样只比它生成时读的那几种，换过的项带上那时候的样子，那时候没有的只带 id。刚生成完是 `{ diff: {} }`。
  主线程在手上的内容上拼回去（`unpostRegenBase`）：没换的种类、项还是同一个对象，`regenNeed` 按对象一比就过。
- 取舍：也可以让引擎每一份快照都带、主线程不再跟着记（只有一处真相）。没这样做：每次编辑多走一遍历史、多比几十个对象虽然只有几十微秒，但规矩是编辑不能变慢，而且主线程的那一份和内容对象是同一批引用，比起来最省。
  两处的规则是同一份函数，测试里一串操作（改、手改、重新生成、撤销、重做）每一步都比过两边一样。
- 从来没有生成过的那一样按现在的内容算（没有要重新生成的）。向导新建的世界里省份是最后一步划分的，所以新建完是空的。
