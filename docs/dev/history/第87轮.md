# 第八十七轮的设计：手绘画风

这一轮改了什么见 [更新记录](../../更新记录.md)。目标：第三种内置画风“手绘”，像老式的手绘奇幻地图——纸、水彩、墨线的海岸与水纹、
画成小符号的山与森林、楷体的地名，导出时加罗盘、标题、边框、图例。写实、地图册一个像素都不变；推导一个值都不变。

## 画风的几项（`core/map-style.ts`）

手绘多了十项，都是**可以不写、没有默认值**的（`.optional()`）：

| 项 | 意思 | 不写时（`HAND_OFF`） |
| --- | --- | --- |
| `paper`、`paperColor` | 纸的纹理与四周暗角的浓淡、纸的颜色 | 0（不画） |
| `wash` | 陆地上水彩的晕染 | 0 |
| `ripples`、`rippleColor` | 岸外几道水纹（0–4）、颜色 | 0 |
| `mountains`、`forests` | 山与丘陵、森林画成符号 | 关 |
| `ink` | 符号的墨色 | |
| `labelFont` | 地名、城市名、国名的字体（CSS 的 font-family） | 照旧（`system-ui…`、国名宋体） |
| `exportDecor` | 导出整张地图时默认加装饰 | 关 |

为什么不给默认值：画风是世界里的内容。写实、地图册在每个库里、每个新世界里都有，格式一补默认值，库里、世界里的这两项就多了十个键，
`core/packs/libraries-digests.json` 里六个库的 `content` 摘要都要重录。不写默认值时写实、地图册的对象与以前逐字节相同（`hand-style.test.ts` 查），
读的时候 `handLook(style)` 按 `HAND_OFF` 补（按画风对象记住）。签名 `mapStyleKey` 后面多了这十项（没写的是 null）：只是缓存的键。

**手绘放在哪个包**：每个库新的小包“手绘画风”（`builtin-tree.ts` 的 `drawn`，在“画风”后面，算世界的底子 `LIBRARY_BASE_PACKS`，换库、加时代包时不带）。
它不在 `worldPartsOf` 里：新建世界不带它，新世界与以前逐字节相同（库的摘要、金标准一个不重录）。
“图层 → 画风”（`LayersPanel.tsx`，逻辑在 `ui/domain/map-styles.ts`）列出世界里的画风，再加上世界用的库里“手绘画风”里世界还没有的；
点它时走从资源库加一项的闭包（`addFromLibrary`）再 `set_map_style`，一个 batch，撤销一次全撤。

手绘的颜色：陆地底色混 0.6、着色的山影（暗色、亮色都很淡），海按水深分四层浅的蓝绿、等深线很淡（0.12），海岸线深墨色、浓 0.9，
线条、道路、国名偏红褐，河湖的种类用另一种颜色（同地图册）。

## 合成着色器里的一段（`src/render/shaders/hand.ts`）

只加不改：`compose.ts` 里多了四个 uniform（`uHand`、`uPaper`、`uWash`、`uRipple`）、几个函数和海岸线之后的一行
`if (uHand == 1) col = handLook(...)`。`styleUniforms` 里 `hand` 只在纸、水彩、水纹有一样开着时是 1：写实、地图册是 0，整段不走。
星球、投影的几份照旧由 `sphere.ts` 替换出来（新代码里不用 `vUv`、`uSceneXf`，替换的次数不变）。第八十六轮（在别的分支）改的是合成着色器里
浅水那一行，与这里不碰同一处。

- **纸**：乘上纸的颜色（`mix(col, col · 纸色 · 1.08, paper)`），加两样明暗：纤维（一个方向拉长的值噪声叠一层圆的，波长按 2 的幂取最近的两档、
  约 3–6 个屏幕像素，按小数部分混合：平移时跟着地图走，缩放时不游动、不闪），几格大小的旧痕（三层噪声）。四周的暗角画在叠加层上
  （`overlay-symbols.ts` 的 `drawVignette`）：合成按块导出，着色器里的画面坐标是每一块的，叠加层的画框才是整张图。
- **水彩**：陆地去掉三成饱和度（按 `wash`），乘上几格大小的一片片深浅，靠岸一圈深一点。
- **离岸多远**：先试的是海岸值（高度纹理的 g）除以它的 `fwidth`——海上到处是点。量了一下种子 3 的 4 万格：岸上一圈的海岸值中位数 97、
  离岸一格的海 −108、两格以外饱和在 −250，而格以下的海岸噪声的幅度是 180，比岸边的落差还大，`fwidth` 主要是噪声，没法当距离用。
  改成**按 mipmap 模糊地形层画好的海岸线**：手绘时渲染器给场景颜色生成 mipmap（`renderer-draw.ts` 的 `compose`：过滤换成
  `LINEAR_MIPMAP_LINEAR`、`generateMipmap`；换回别的画风时放回 `LINEAR`，写实、地图册从来不碰）。海岸线约 1.3 个像素宽，模糊到
  B 个场景像素的方块时，离岸 d 处约是 1.3 / B · (1 − d / B)；乘回 B / 1.3 就是岸上 1、离岸 B 处 0 的一个量（`handNear`）。
  第 k 道水纹取 B = 2 · (4.5、9.5、15、21 个像素)，画在 0.5 那一条线上（抗锯齿按这个量的 `fwidth`：它是平滑的，不再是噪声），
  越往外越淡；岸边的水色按 B = 18 的那一份深一点；粗一点的墨线是海岸线模糊一级再加浓。导数都在 `uHand` 这个一致的分支里、
  分陆海之前算。（地图册那一段在陆海分开的分支里算 `fwidth`，见下面“对照”。）
- **导出的接缝**：导出按块画，每块自己生成 mipmap。手绘时块四周多留一圈（边距加 48 像素，取 64 的倍数），块的大小也取 64 的倍数：
  每块的 mipmap 方格与整张图对齐，拼起来没有接缝（`ui/map/export.ts`）。

## 符号（`symbol-place.ts`、`overlay-symbols.ts`）

**每格的编码**（`cellCodes`，只看这一格自己和邻格的高程，与先后无关）：
山：海拔 ≥ 1000 m，并且比最低的邻格高 150 m 以上或海拔 ≥ 2000 m，大小 = (海拔 − 1000) / 3500；
丘陵：海拔 ≥ 250 m 且起伏 ≥ 80 m，或海拔 ≥ 600 m，大小 = 起伏 / 300；
森林：主导的生态是森林一类（`group: forest`，或地表 `forest` / `jungle`），年均温 < 3 °C 是针叶，雨林一类是圆的一丛，别的是阔叶。

**候选与放法**：第 k 档每格 4^k 个候选（2^k × 2^k 的抖动格点），每个候选一个足迹的圆（山 0.85–2.05 格距、丘陵 0.6–0.9、森林 0.7，
第 k 档除以 2^k）；森林只留约 55% 的候选。两轮“比周围都大就留下”（Luby 的 MIS 前两轮）：和它相交、还没定的同一类候选里它的优先级
最高就留下，挨着留下的去掉。优先级：山 2 + 大小、丘陵 1 + 0.5 · 大小，加 0.35 的随机（按世界种子、格号、第几个、第几档）。森林在山、丘陵之后：
挨着留下的山、丘陵的去掉，再按同样的规则留一轮。留下的两两不相交（每个符号画在自己的圆里），结果只看附近、与镜头和先后无关。

**按块缓存**：第 k 档的块边长 16 / 2^k 格距。一块的结果只取决于四周 `HALO` 以内的候选（两轮 + 森林一轮：8 个最大半径 + 2 个森林半径 + 0.75 格，
约 18.6 格距）。键是这一片里第 0 档的块的编码哈希合起来（每个世界先把 4 万格的编码、每块的哈希算一遍，约 1 ms）；键没变的块原样给回同一个对象，
改了高程只有那一片的块重算（最多留 6000 块）。第 0 档一块约 0.9 ms（Node），看全图 153 块约 130–160 ms，只在第一次（或换了种子、网格）。

**画法**：画在叠加层最底下那一层（`overlay.ts` 的 `drawBack`：和河、标记一起，停稳时进离屏画布，移动中挪用低分辨率的那一张）。
第一版每块建几条 Path2D、按块描：主线程只要 1–2 ms，但几千个小路径在软件画的画布上光栅化要 500–600 ms（无头 Chrome）。
改成**每个符号贴一张小图**：按种类、大小的档（山 5 档）、样子的档（3 档）、屏幕上的半径（对数取整，每档约 3%）、每 CSS 像素几个像素记住，
一帧里几十张就够（最多留 800 张）。山：偏一点的尖顶，左亮右暗，墨线只描两坡，暗面两三道排线，大的山顶有雪；丘陵：圆的小土包；
森林：三棵一丛（针叶是三角）。一格在屏幕上不到 2.5 像素不画；第 0 档到 14 像素，第 1 档到 30 像素，再往上第 2 档；树冠足迹不到 3 像素不画森林。
只画一块地区：整个星球（展平的、等面积、球形）都不画符号（纸、水彩、水纹照样有）。

## 字体

霞鹜文楷：npm 的 `lxgw-wenkai-webfont@1.7.0`（字体是 SIL OFL 1.1，包里有 `OFL.txt`；包装的仓库是 MIT），`lxgwwenkai-regular.css`
按 unicode-range 切成 97 个 woff2（共 4.6 MB），`font-display: swap`。`main.tsx` 引它的 CSS：只是 @font-face 的声明（约 105 KB 的 CSS），
没用到时一个字体文件都不下载；画布上画到哪些字，浏览器只下载那几个小文件。屏幕上排地名时按字请浏览器先载入（`label-font.ts` 的
`askGlyphs`，载入好了 `loadingdone` 让静态那一层重画）；导出前等要写的字载入（`loadGlyphs`，最多 8 秒，载不到时用后备的字体）。
不从 CDN 取。字体栈 `"LXGW WenKai", "Kaiti SC", "STKaiti", KaiTi, serif`：没载入时 Mac 用系统的楷体。打包后 dist 多了 97 个字体文件
（见下面“打包”）。写实、地图册不写 `labelFont`，地名照旧 `system-ui, "PingFang SC", sans-serif`、国名照旧宋体（`hand-style.test.ts` 查）。

## 导出的装饰（`export-decor.ts`）

罗盘（右上角，八个尖、刻度、写“北”）、标题（上面一条带燕尾的飘带，写我的地图里的名字；没保存的世界没有名字不画）、边框（纸色的边、
一道粗墨线、一道细线、四角的小方块）、图例（右下角：现在的底图的图例前 8 行，色块混上画风的陆地底色；再加画了的符号：山脉、丘陵、森林、
城市、道路）。画在地图和叠加层都画好之后的整张图上，大小按图的短边（每 900 像素一个单位）。导出面板“地名字号”下面四个开关
（`components/Toggle`），按画风记着：手绘默认全开，别的画风默认全关。“当前画面”不加。

## 对照（写实、地图册逐像素不变）

- `node tools/compose-ab.mjs --against aa73c93`：写实（默认的画法）714 组，**不同 0 组**（一块地区、星球；七种模式、四种缩放、描格、移动中、
  导出的一块、等面积与球形投影）。这一轮加了地图册的 32 组（地貌、国家，三种缩放、移动中、导出的一块、两种投影），每组另画一个旧的渲染器：
  旧↔新不同 18 组（共 2006 字节），**旧↔旧（同一份 aa73c93 的两个渲染器）也不同 17 组（共 1866 字节）**，每次跑都不一样。
  原因是地图册分层的海那一段（第三十八轮）在陆海分开的分支里算 `fwidth(depth)`：导数在不一致的分支里没有定义，SwiftShader 的 2×2 小块里
  没走这条分支的那几个像素的值是随手的。核对过：把手绘的三段换成空串（着色器源码与 aa73c93 逐字节相同，哈希测试通过）时地图册照样差这么多。
  这几组只写出来、不算进“不同”。想要地图册能逐字节对照，得把那一段的导数挪到一致的分支里——那会改合成着色器的老代码，这一轮不动
  （第八十六轮在别的分支上也改合成着色器）。
- `node tools/overlay-ab.mjs --against aa73c93`：一块地区与类地星球、地貌与国家、看全图与一格约 8 像素，直接画、一串帧（按显卡画、按软件画）
  都是 **0 字节**；这一轮加的地图册（叠加层里画河、直接画）四组也是 **0 字节**。
- 着色器：只有合成的六份（平面、星球、投影各带不带花纹）的哈希变了（多了手绘那一段），`RECORD_SHADERS=1 npx vitest run src/render/shader-sources.test.ts`
  重记；别的程序（地形、编号、切线、极地……）的哈希不变。
- 金标准（`golden*.json`）、摘要（`*digests*.json`，含六个库的 `libraries-digests.json`）一个没重录；CPU 的那几份（`subcell.ts`、`display.ts`）没动，
  着色器照字面换成 JS 的对照测试照常通过。
- 测试里改的：`core/pack-tree.test.ts`（每个库的底子多了 `drawn`）、`core/content/links.test.ts`（手绘的 `mountains`、`forests` 是开关，
  碰巧有地形类别也叫这个名字，写进“不是引用”的表）。

主线程上手绘一帧 1.6–3.9 ms（目标 8 ms 以内）。软件画的那一行是 CPU 上的 Skia 连光栅化一起量（几项之间的差有十几毫秒的噪音），
真正的浏览器里画布在显卡上画；而且停稳时叠加层什么都没变就一笔不画，移动中符号在低分辨率的那一张里挪用，只有停下后的第一帧整张重画。
第一版每块描 Path2D 时同样的“看全图、软件画”是 711 ms（符号一项约 580 ms），换成贴小图后符号约 45 ms。
第一次画符号（算看得见的块、建小图）：一格约 8 像素 125 ms，看全图 49 ms；之后只有改到的块重算（第 0 档一块约 0.9 ms）。

合成着色器手绘那一段只在手绘时走；写实、地图册多传四个 uniform（`uHand` 为 0），合成的速度不变（compose-ab 的 `--time` 没另跑：
写实走的指令与以前相同，只多了一个一致分支的判断）。

## 打包

`npm run build`：`dist/assets` 多了 97 个 woff2（共 4.6 MB），CSS 从约 55 KB 到 147 KB（多了 92 KB 的 @font-face 与 unicode-range，gzip 后小得多），
dist 共 11 MB。只下载画到的字所在的小文件（一张地图的地名通常几十个小文件、几百 KB），不挡第一次画（`font-display: swap`）。
依赖多了 `lxgw-wenkai-webfont`（精确到 1.7.0）：合并后一键开启会因为 `package-lock.json` 变了先装依赖；开发服务器那边要 `npm install` 一次。

## 没做的

- 整个星球上不画符号（展平的、等面积、球形都不画）：符号的块按平面的格子分，星球要按经纬或球面另分块、跨分界线。纸、水彩、水纹照样有。
- 山的符号只是一个山头，没有连成山脉的那种排法（一排互相挡着的山）：要求不重叠。
- 地图册在 compose-ab 里不能逐字节对照（见上）。
