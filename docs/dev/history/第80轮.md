# 第八十轮的设计

这一轮改了什么见 [更新记录](../../更新记录.md)。用户要国家界面整体快一些。都是主线程上的事：地图上的画面逐像素不变
（`overlay-ab`、`compose-ab` 0 字节不同），金标准、摘要、快照、着色器的哈希一个都没有重录。

## 慢在哪里

先写了测速（`tools/bench-country-ui.mjs`，见下面“怎么量”），再用 CDP 的 Profiler 剖析新的一边（网址带 `#rename` 等，开发时用）。
一块地区（4 万格、268 国）上改一次国名，主线程约 70 ms：

- **每份快照的原因数组都是新的副本**（`src/worker.ts` 的 `snapshot` 整份复制 `causes.*`）。按数组认的缓存全都作废：
  着色（底子、模式的一层整个重算、整个重新上传，约 13 ms，类地星球上 SwiftShader 里上传要几百毫秒）、省界的大小、省名的位置……
- **国家的统计每次重算**：`statsOf` 的键里有 `causes.country`（每份快照都是新的），还有 `small.countries`（改名、换颜色也变）；
  统计里要城市表，城市表的键里也有原因数组，于是城市的管辖、名字整个重算（图例 → `countryRows` → `statsOf` → `allCountryStats` + `cityTable`，约 21 ms）。
- **城市、地标的列表每次重算**（`settleLists` 的键里有小数据的各段、原因数组，每份快照都是新的对象）：地标的名字一个个起（约 8 ms），
  地图上的点换了一批，地名的版面整个重排。
- 河：Worker 每份快照都发一份描好的河，主线程每次拆开（约 2.5 ms），河的那一层重画（约 3.5 ms）。
- 别的零碎：“改了什么”逐格比一遍（约 1 ms）、省名的位置每次重数、底部条每次重画都把国家排一遍（`largestCountry` → `countryRows`）。

档案、领土笔刷：

- 档案“关系”“概览”里选国家的下拉框带着全部国家（星球上 512 个）：按下标比，选另一国时后面的选项一个个改字，整个下拉框重新排版。
  换到“关系”一页要建上千个选项。
- 领土笔刷动一下：叠加层整张重画（笔刷的圈在工具的图形里，图形变了就照原样直接画）。首都的星每帧重建（每国三个图形），
  比较图形时每个图形建一个 Set；画图形时每个都重设颜色、线宽、虚线。
- 高亮的贴图：量下来笔刷每动一下不到 0.3 ms（星球上），没有改。

## 改了什么（结果都逐值不变）

### 快照只发变了的（`src/worker-snapshot.ts`、`src/content-post.ts`、`src/state/snapshot-merge.ts`）

- 快照从 `worker.ts` 搬到 `worker-snapshot.ts`（`SnapshotSender`）。**原因数组**也像推导数组一样：与上一次发的内容逐字节相同的不发
  （`same.causes`、`same.fields`），主线程沿用手上的同一个对象。引擎会就地改原因数组（笔画、撤销），所以 Worker 记的是发出去时的副本；
  变了的数组复制两份（一份转交、一份留着下次比）。轻快照换了省份、岛的种类时，记的副本跟着换。
- **地物**（`derived.features`）：与上一次发的逐值相同（每个地物逐项比，格的数组按字节）时不发（`same.objects`）。
- **河**：`core/river-pack.ts` 的 `riversId` 是 Worker 那一份河的编号（描河读的东西没变时相同，预览世界描过也会变）；
  和上一次发的相同时快照不带河，主线程 `reseedRivers` 用手上拆好的那一份（编号对得上才用，对不上时画的时候自己描，与以前一样）。
- **小数据的各段**（城市、地标、省份、集团、生态……）：按 JSON 与上一次发的比，相同的写占位 0、列进 `sameSmall`；
  **国家一国一国比**，没变的国家写 0（`sameCountries`）。主线程补上手上的同一个对象：只改了一国的名字时，别的国家、它们的旗都是原来的对象
  （列表的行、旗的字符串照样命中）。这几样要主线程用上了上一份（`secBase` 与手上的 `secRev` 相同）才拼得起来，对不上时和以前一样要一份完整的。
  换了引擎（新建、打开）后的第一份是完整的。
- 主线程拼快照的几步搬到 `state/snapshot-merge.ts`（`mergeSnapshot`、`lightWorld`），测试直接调。
- Worker 这一头：改名一步（地区）“快照 + 结构化克隆”11.5 → 5.4 ms，星球 18.8 → 8.6 ms；抬山一笔 30 → 25 ms（描河那一份另算，两边一样）。
  按 JSON 比各段每份约 1.7 ms，比整份克隆小数据省。

改国名、颜色、旗、锁定、政体、外交（`set_country`）照旧是 `Dirty.Human` 的一步、走完整的快照：
快照里已经只有变了的那一国，主线程拿到的和轻快照一样（数组、地物、别的段都是原来的对象），不必另开一条路。
没有改成 `Dirty.Names`（走轻快照）：那要动引擎的重算层次——名字一层“留着的名字”不走人文一层的捷径（`carryNames` 的 `onlyRestyled`）、
还要整理一遍湖的省份，记进命令的东西可能不同；Worker 里改名一步本来只要约 10 ms（地区）。

### 缓存的键（第八十轮以前每份快照的原因数组都是新的，键里漏掉的数组也会重算；现在没变的数组是同一个对象，键要写全）

- `core/world-token.ts` 的 `arraysToken`：一个世界全部数组（原因、推导、修正场、自定义场）的“这一批”编号，两个世界的数组一个不差是同一批对象时相同。
  读的数组多、一个个列容易漏的缓存用它当键里的一项：只改了国名、颜色（数组都没变）时命中，别的编辑（总有数组变了）照旧重算，和以前一样。
- **国家的统计** `statsOf`：数组按 `arraysToken`，小数据按统计、城市表读的几样（各段在快照里没变时是同一个对象），国家只看统计用到的
  （编号、主流文化、兼容的文化组、首都、政体，按国家的对象缓存成一个字）。**列表** `countryRows` 按统计、国家、内容缓存（领土笔刷每动一下、底部条每次重画都要最大的一国）。
- **城市表** `cityTable`（core，Worker 里也用）：键里加 `arraysToken`、河流门槛（`planet`）、种子（`terrain`）、时代（`human`）；原来的 JSON 签名照旧。
  Worker 里世界是同一个对象、数组就地改，`arraysToken` 一直相同——和以前按数组对象认一样，没有变得更松。
- **城市、地标的列表** `settleLists`：数组按 `arraysToken`，再加地物、各段，国家只看名字与城市表用到的（首都、政体、主流文化、名字的词根）。
- **图例**：国家、集团的字按对象缓存（以前每次重画图例拼一遍），键里加统计（`statsOf` 的结果）。
- 一国的格 `cellsOf`、选中与悬停的国家的高亮：领土没变、陆海变了也重数（以前靠领土数组每次都是新的）。
- 片区名：国家的编号、集团的成员连成的字按对象缓存（以前每帧排一遍、拼一遍）。
- “改了什么”（`describeChange`）：读的数组都是同一个对象、门槛与生态的先后也一样时直接是“没变”（逐格比下来也是这样）。
- 地图（`MapView.tsx`）：省份数组、各省的档案、网格都没变时省名的位置不重数。

### 档案

- 选一国的下拉框 `CountrySelect`（`archives/fields.tsx`）：平时只有第一项（“无”“加一国”“并入…”）与选着的那一国，按下、得到焦点、按键时才放进全部国家
  （Preact 在微任务里重画，下拉框打开之前就放好了）；档案换了一国又只放两项。宗主、同盟、敌对、并入都用它。
  以前换到“关系”一页要建上千个选项，选另一国时按下标比，后面的选项一个个改字、整个下拉框重新排版。
- 政体：资源库里能加进来的政体（导入的检查）按小数据、资源库缓存，档案每次重画不再重查。

### 领土笔刷、国家一类的工具

- 首都的星按国家的对象、网格、缩放、选中的国家缓存同一个数组；叠加层比较图形时同一批对象一比就过。
- `sameShape` 不再把两边的键并成 Set：先看 a 的键，再看 b 有没有 a 没有、不是 undefined 的键（与并起来比相同）。
- 画图形（`overlay-shapes.ts`）：一遍图形里颜色、线宽和上一个图形相同时不再设，虚线只在虚线的图形前后设（设成一样的值画布的状态不变）；
  一遍开始时 `resetPen()`，第一个图形全部设一遍；河的图形自己改状态，画完当作不知道。
- 新建国家点省份：每个省的陆地格按省份、陆海数组一次分好（以前鼠标每换一个省扫一遍所有的格）。
- 橡皮擦：能不能擦（改过的格的掩码）按同一个世界对象直接给上一次的，不再每格建一次键的数组。

### 没做的

- **笔刷的圈画在单独的一层**：做不到逐像素相同。现在的叠加层是一张画布，圈画在地名、城市的下面；单独一层要么在地名上面（画面变了），
  要么画进离屏画布再贴回来（第四十轮量过，贴回来的与直接画的读回来不逐字节相同）。笔刷每动一下照旧整张重画叠加层（星球上约 3 ms 是首都的星、约 2.5 ms 是地名），
  只省下了重建星、比较图形、重设画笔的时间。
- **高亮的贴图只更新笔刷那几格**：量下来整张重建加上传不到 0.3 ms，没有改。
- 改名后的那一帧里叠加层照旧整张重画、地名重排（国名变了，版面本来就要重排）。
- “人口与城市”一页本来约 1 ms（建那一页的元素），没有可省的。

## 怎么量

`tools/bench-country-ui.mjs`：同 `overlay-ab` 的做法（`git archive` 解出旧的提交，esbuild 打成 file:// 页面，无头 Chrome 打开），
两边各挂一份地图（`MapView`，WebGL 照常画）、底部条、图例、“这里”、右边的抽屉（国家的档案），世界相同。默认用这台机器的显卡（Metal）：
SwiftShader 里贴图上传要几百毫秒、抖得厉害，量不出主线程上的事（`--soft` 照旧可以用）。
计算 Worker 的那一半在页面里：引擎（现在的 core）执行命令，按 `src/worker-snapshot.ts` 做快照、结构化克隆后交给那一边的 `handle`；
第八十轮以前的一边按那时的样子给（原因数组、地物、小数据都是新的副本）。Preact 的重画、`requestAnimationFrame` 接过来当场跑，
量从收到回复（或写信号、发鼠标事件）起到没有要画的为止的主线程时间（WebGL 的命令发出去为止，不等显卡）。
世界：种子 3，中世纪，时代的国家大小 ÷ 8（第七十七轮的“很分裂”），城市。两边交替、每轮换一边先，11 次的中位数，毫秒。
