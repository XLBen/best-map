# 第九十二轮的设计：资源库（三）找得到、分得清

这一轮改了什么见 [更新记录](../../更新记录.md)。用户（不懂技术的新手作者）头号的抱怨是“编辑资源库太难用”。第九十轮解决“改了看不到”，
第九十一轮解决“国名称号不跟着变”，这一轮解决另外两条：**找不到要改的**、**分不清改的是哪一份**。用户定的：
入口两个都要（地图上点到什么就改什么 + 面板做简单）；平时只改这张地图；“存到我的库”合成一个动作、一个去向，新建地图时选得到；
直接改我的库收进不显眼的地方。

生成的结果逐值不变：金标准、摘要、着色器的哈希、界面的快照一个都没有重录；世界文件的格式没变（`DOC_VERSION` 还是 22）；
没有加命令、没有改命令的格式。core 里只改了几句给人看的字（见“术语”）。

## 为什么找不到、分不清

1. 这张地图的首页没有搜索（`PageHome.tsx` 写着 `src.t === 'lib'` 才有）；文化融入在文化组里，首页没有“文化”这张卡片，要先想起它在哪个组。
2. 在地图上看到一个国家、一种生态，想改它的政体、颜色，得自己去资源库里一层层找——档案里没有过去的路。
   反过来，库里一项顶上的“在地图上”只有一部分种类能定位。
3. 面板的标题是个下拉，本世界、六个内置的库、我的库、导入的库并排列着。看的不是本世界时只有一行小灰字“改这里不影响当前世界”；
   看本世界时什么都不写。新手分不清现在改的会不会动地图。
4. 三个“存到我的库”去向各不一样：和库不同的一项“存回”来源的库（内置的先复制）；自己新建的一项存进“我的资源”——它没有时代，
   新建世界的向导里选不到，存进去就再也用不上，首页上还写着“没有时代，新建世界时选不到这个库”；“⋯”里的是挑几样另做一个包（默认也叫“我的资源”）。
5. 界面上同一样东西有四个词：资源库、库、资源包、小包，还有“我的资源”。
6. 从别的库添加时，勾一项会连带什么只有清单里看得出；已经有了的行、这一种加不了的行只是不能勾，不写为什么。

## 1. 找得到

### 这张地图的首页能搜（`page-search.ts`、`PageHome.tsx`）

- 去掉 `src.t === 'lib'` 的限制。本世界的行本来就走同一个 `rowsOf`，所以 `searchSource` 不用分两种。
- 多搜一样：外文名（文化、文化组、取值、取值组的 `orig`）。按什么找到的分三档（`matchOf`：名字 0、外文名 1、id 2），名字对得上的排在前面。
  列表上的搜索（`pages.ts` 的 `listPage`）也跟着搜外文名。
- 每一行灰字写清楚是哪一种、在哪一组（`kindLine`）：“文化 · 汉组”“政体”“宗教 · 取值”；按外文名、id 找到的把找到的那个字写在后面
  （“文化 · 日耳曼 · Bavarian”），不然看不出为什么这一行在结果里。
- 取舍：仍然按种类分段（每段最多 40 行，多的写“还有 N 个”）。不分段、全部混排的话“汉”会把汉组、汉文化、汉字风格的地名风格搅在一起，
  段的小标题本身就是“这是哪一种”的第一层回答。
- 点一行就是 `openRoute`：本世界里直接点进那一项。

### 文化有自己的卡片（`page-layout.ts` 的 `WORLD_OWN_CARDS`、`pages.ts` 的 `homePage`）

内置的库的安排里文化融入文化组（`core/content/arrange.ts` 的 `PRESET_ARRANGE`），所以首页只有“文化组（含文化、地名风格、地标）”。
这张地图的首页上现在留着“文化”这张卡片（点进去是全部文化，按文化组分段——这个列表本来就有），文化组照旧写“含文化”。

- 没有动登记的先后（`core/content/kinds.ts`）、没有动 `PRESET_ARRANGE`、没有动任何库的安排：只是 `homePage` 在看本世界时不把这一张藏起来。
  库的首页不变（库的安排是库自己的，我的库里还能拖着拆出来）。
- 只放了文化一种。地名风格、地标、派系也融入在上级里，但它们不是“最常找的”；都放出来首页就又满了。要加就往 `WORLD_OWN_CARDS` 里添。

## 2. 地图上点到什么就改什么

### 先读清楚的：指针点到的东西现在各自显示什么

| 点到 | 显示在哪 | 以前有什么 |
| --- | --- | --- |
| 国家（国家模式） | 右边抽屉的国家档案（`CountryArchive.tsx`，五页） | “政治”页的政体列表下面一行“从资源库添加…”（开到库里还没加的政体），文化下面同样一行 |
| 一格 | 右下角“这里”（`HereCard.tsx` → `Inspector.tsx` → `ArchiveBox.tsx`） | 生态的名字和为什么；档案里国家、省份、城市能点过去；地形、资源是下拉 |
| 城市、地标、点 | 右边抽屉（`SettleArchive.tsx`） | 等级、类型是下拉，没有去库里的路 |
| 文化笔刷的“⋯” | `panels/culture.tsx` 的 `PopTupleMenu` | “从资源库添加…” |

都没有“这一项在资源库里是哪一页”。

### 做法（`packs/open-item.ts`、`shell/LibItemLine.tsx`、`panel-store.ts` 的 `openWorldItem`）

- `open-item.ts`（纯函数）：`countryTargets`（政体、等级、主流文化）、`cellTargets`（生态、占多数的文化、地形类别、资源）、
  `settleTargets`（城市 → 现算的那一级；地标、点 → 它的类型）、`libTarget`（任意一项）。世界里没有的不列。
  `worldItemStack`：那一项的页面，下面垫着它那一种的列表（生态垫着“生态与水系”），所以返回是回到列表、再回首页，不是直接关掉。
- `LibItemLine`：档案的一行（`.arch-line`）——色块、名字、“在资源库里打开”。放在：国家档案“政治”页最上面一段、“这里”的档案最下面一段、
  城市 / 地标 / 点档案的等级、类型下面、文化笔刷“⋯”里选着的文化下面。
- **直接改名字、颜色**：国家、城市的档案里和钉住一格时，那一行的色块是取色框、名字是框。`quickNext` 做出改了以后的这一项，
  交给 `page-actions.ts` 的 `commitItem`（面板里改一项走的就是它：世界里是一条命令，排在前面的编辑后面，能撤销）。没有另写一套。
  只有名字、颜色两样；`quickFields` 按字段表看这一种有没有这两样、世界里能不能改。别的去面板里改。
- 取舍：
  - 没钉住的“这里”只给链接、不给框：卡片跟着鼠标，框里的字会被下一格换掉。
  - 改的是“这一种”，不是这一国、这一格：框的悬停写“改的是这一种，用到它的都变”。国家自己的名字、颜色在“概览”页，没有动。
  - 没有把整个表单搬过去（任务里说的）；也没有在“这里”卡片里放生态的气候图之类。
  - `Inspector.tsx` 里生态的标题旁没有另放一个按钮：同一张卡片的档案里已经有“生态”这一行。

### 反过来：“在地图上”都能定位（`on-map.ts`）

第九十轮只有一部分种类给了定位用的格。这一轮补上能补的：

| 种类 | 定位到 |
| --- | --- |
| 时代 | 全部国家的领土（没有国家时不给） |
| 省份划分 | 划了省份的格 |
| 取值组 | 组里各取值的人所在的格（一格只算一次，最多两万格） |
| 国家格局 | 按这种格局生成的国家（国家上记着的角色 `role`：格局的模块，或“模块:角色”）；这时那一行多写“：N 个国家” |

画风、星球形态、世界默认但没有地名在用的地名风格没有可定位的东西：不给格，按钮不出现（“定位不了的不显示”）。没用上的照旧只有原因和解法。

## 3. 只改这张地图、一个“存到我的库”

### 顶上一直在的一句（`source-view.ts` 的 `editingLine`、`LibPanel.tsx` 的 `EditingBar`）

| 看的是 | 写 | 样子 |
| --- | --- | --- |
| 这张地图 | 改的是：这张地图 | 强调色的底、地图的图标 |
| 我的库 | 改的是：我的库“X”（新地图会用，这张地图不变） | 警告色的底、书的图标 |
| 内置的、加进来的库，读进来的文件 | 只能看：X | 灰、锁 |
| 挑选时 | 挑了加到：这张地图 / 我的库“X” | 跟着加到的那一份 |

以前的两种横条（只读的“这是“X”，只能看”、我的库的一行小灰字）并进了它；右边的按钮照旧（一项的页面上“在这张地图里打开 / 添加到这张地图…”，
别的“回到这张地图”——以前我的库没有这个按钮）。看本世界时以前什么都不写，现在也写：分得清靠的是“总有这一句、颜色不一样”，不是“不对劲时才提醒”。

### 来源下拉（`source-view.ts` 的 `sourceMenuView`、`lib-prefs.ts` 的 `showAllSources`）

- 平时只有“这张地图”和“从别的库添加…”（和右上角的按钮是同一件事）。别的收在“更多”下面：我的库（直接改）、内置的库（看）、加进来的库、
  读进来的文件，和“新建一个库”“读文件…”。
- 正在看的那一份在“更多”里时它一打开就展开着（不然找不到自己在哪）。
- 挑选时下拉选的是“从哪个库挑”：库都列着，内置的在前，不收。没有世界时只能看库，也都列着。
- **留给第九十九轮的一个判断函数**：`showAllSources()`（`lib-prefs.ts`，读本机的一个偏好 `map2.lib.allSources`，默认 false；`setShowAllSources` 写它）。
  它是 true 时没有“更多”这一层，几组直接列着（和以前一样）。全局的“完整界面”开关接在这一个函数上，界面不用再改。这一轮没有放开它的入口。

### 一个“存到我的库”（`save-mine.ts` 算、`save-mine-run.ts` 做）

**去向**（`myLibraryOf`）是“我的库”：一个新建地图的向导里选得到的库——`domain/packChoice.ts` 的 `isLibrary(pack, true)`（有时代、有带文化的文化组、有世界的底子），
向导本来就把这样的我的库列在“我的库”那一排卡片里（`libraryOptions`），所以向导没有改，测试钉着“存进去的库在向导的选项里”。

1. 这张地图用的库就是我的库时：它；
2. 不然上次存进去的那个（本机记着，`map2.lib.mine`）；
3. 不然第一个向导里选得到的我的库；
4. 一个都没有：把这张地图用的库复制一份叫“我的库”（`copyBaseOf`；那个库不在了、不够新建地图用时复制默认的库）。第一次先问一句，说清楚会发生什么。

为什么是“复制一整个库”而不是一个只装自己东西的小库：小库没有时代和世界的底子，向导里选不到——“我的资源”就是这样成了死路。
复制出来的库里内置的内容和原来的库共用同一批对象（`copiedPack`），改的时候才换；存进浏览器是一份完整的（中世纪约 1.5 MB）。

**怎么存**（`savePlan`，纯函数，一项一项落到同一个包上）：

1. 这一项是从库里来的（世界记着来源）：和我的库里的那一份比——id、引用换回库里的写法，比重留库的（`core/packs/source-diff.ts` 的 `savedBackItem`，
   以前“存回”用的就是它，这里把“来源的库”换成我的库）。不一样就换掉库里的；一样的算“已经是这样”。
2. 库里有同 id 的一项（以前存过的自己做的）：换成现在的样子。
3. 库里没有：新加，**它写到的、库里没有的内容一起带上**（导入的闭包 `importToPack`，来源是这张地图当作一个包 `worldAsPack`）。
   和“从别的库添加…”是同一套规则（变量写进时代、放不下的写原因），所以新文化组里的新文化存进去，组也在。
   以前存进“我的资源”时什么都不带，存进去的文化指着一个不存在的组。

几项一起（“⋯ → 存到我的库…”，`saveableRefs`：自己做的、和我的库里那一份不一样的）是同一个 `savePlan`、一次 `setPack`：一步，撤销一次全回去。
写下去之前 `setPack` 把整个库按格式查一遍（读不回来的不写）。

**存完**：顶上“已把“X”等 N 项存到“我的库”：新建地图时选“我的库”就带上”，带“去看看”和撤销（`noteAction`，撤销的是库里的这一步）。
存过的项在世界里的来源记成我的库（`repointAll`：一条 batch，内容不变，只记来源；以前“存回”来自内置的库时也这样做）——之后“和库不同”的标记、再存一次都和我的库比。
取舍：这一步在世界的撤销栈里多一条“来源记成“我的库””。不记的话存完以后那一项还标着“和库不同”、按钮还在，再点一次只会说“已经是这样”，更让人糊涂。

**去掉的**：`page-actions.ts` 的 `saveBackToLibrary`、`row-actions.ts` 的 `saveRow`；`itemActions` 里的 `saveBack`（并进 `saveToMine`：改过的、自己做的都是这一个按钮）；
`PackDialog.tsx` 的导出弹窗里的“存到我的库”（那个弹窗只剩“导出文件”，入口叫“⋯ → 导出文件…”）。

### “我的资源”里已有的内容

不丢，不自动搬：

- 那个包的键没变（`library.ts` 的 `MY_PACK_KEY`），照旧从存储里读出来，是一个我的库。它还叫旧名字时显示成“以前存的内容”
  （`shownPack`：读出来时换名字，内容是同一批对象；下次写这个库时名字就存成新的）。自己改过名字的不动。
- 它在标题下拉的“更多 → 我的库”里；“从别的库添加…”也能从它挑（和任何库一样）。
- 它的首页以前写“没有时代，新建世界时选不到这个库”——一条死路。现在这一句旁边有“并进我的库”（`mergePlan`：里面的全部内容走导入的闭包并进我的库，
  同 id、内容不同的并存，不盖掉库里的；一步，能撤销）。原来的库留着，要删自己删。删除、打开世界文件时留下的“来自《世界名》”是同一种库，同样有这个按钮。
- 没有自动迁移的原因：并进去要先有“我的库”（要复制哪个库得看用户在做哪张地图），而且同 id 的东西并存还是盖掉，替用户决定不了。
- 星球形态编辑器的“存”照旧存进这个包（新建时叫“我的星球形态”）：形态是在向导、调整里从任何库里列出来选的，不靠时代，不是死路。
  没有把它也改成存进我的库：编辑器在没有世界的向导里也用，“编辑自己存的形态改的是它本身”认的是这个包（`domain/forms.ts`），动它要连着改一串。

## 4. 术语

对用户只说“资源库”和“库”。先 grep 出全部出现的地方（界面的字 30 来处），改完再 grep：`src/`、`core/` 里引号、JSX 里的字已经没有“资源包”“小包”“我的资源”
（`library.ts` 里留着一个不显示的常量 `LEGACY_PACK_NAME`，只用来认出以前存的那个包的键）。代码里的标识符、注释没有动。

| 以前 | 现在 |
| --- | --- |
| “资源包…”（面板“⋯”） | “管理库…”；弹窗的标题“管理库” |
| “导入资源包”（弹窗标题）、“读资源包文件” | “读文件”、“读一个库的文件” |
| 读进来的文件的“存到我的库…”“装进资源库…” | “加进资源库…”（整个文件成为一个库，不是存进我的库）；“导入的库”叫“加进来的库” |
| “我的资源”（管理库里的分段、导出时默认的名字） | “我的库”、“我的内容” |
| “不在同一个小包里”（拖动换先后） | “只能在同一组里换先后” |
| core 的报错：“资源包格式是第 N 版”“资源包的 id / 名字”“小包“X”里的”“不是资源包”“不在资源包里” | “文件格式是第 N 版”“库的 id / 名字”“分组“X”里的”“不是库的文件”“不在这个文件里” |
| 撤销条：“用上资源包“X”” | “用上“X”” |
| 本世界（面板、帮助、使用说明里 60 来处） | 这张地图 |

最后一行不在任务列的三个词里，但顶上那一句写的是“这张地图”，下拉里也是；别处还叫“本世界”的话同一样东西又是两个词，所以一起换了
（界面的字 24 处、撤销条的“整理这张地图”、帮助、使用说明）。“世界”这个词本身没有动（世界菜单、新建世界）。

## 5. 从别的库添加：每一步一句人话（`pick-help.ts`）

规则都是导入的闭包算好的，这里只把它们说成话：

- 挑选时顶上：“挑了加到：这张地图”，下面一句“勾要的，再点右边的‘添加’。灰的行写着为什么不能选”。
- 勾着的一行：“勾了它，它用到的 3 样会一起带上”（`bringsOf`：清单里因为它才来的几项——它用到的、它下面的；按清单记着，列表每一行问一次不重算）。
- 清单最上面：“勾了 2 项，它们用到的 5 项一起带上。下面这些会一起加进来；点 × 去掉”（`basketLine`）。
- 不能勾的每一行都写原因。读代码查到：灰的行（缺东西、放不下）本来就写着原因（`rowLook` 的 `note`，列表、子项、“从别的库加”都画）；
  只是灰着、不写的有两种——已经有了的（✓，原因只在悬停里）现在写“这张地图已经有了”，这一种加不了的（加到世界时的星球形态，以前只是没有勾）现在写“这一种不能加到这张地图”。
