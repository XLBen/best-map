# 第九十六轮的设计：不白屏、不卡死

这一轮改了什么见 [更新记录](../../更新记录.md)。前提和前两轮一样：用户是不懂系统的新手，作品只存在浏览器里。出了任何事，页面都要用人话说清**发生了什么、作品还在不在、现在能点什么**。

生成的结果逐值不变：金标准、摘要、着色器的哈希、界面的快照、`raster-identity` 一个都没有重录。世界文件的格式没变（`DOC_VERSION` 还是 22），IndexedDB 的库还是第 8 版。`core/` 一个文件没动。写法照前两轮：规则是纯函数、碰外面的东西经一层可换的 io、有测试；界面只调一层薄的函数；文字都从 `src/ui/copy.ts` 出（这一轮的几组写在 `src/crash-text.ts`、由 `copy.ts` 照旧导出，原因见第 1 节）。

## 以前的毛病（动手前核对过的）

- 没有任何全局的兜底：`main.tsx` 只有一句 `render(<App />)`，没有错误边界、没有 `window` 的 `error` / `unhandledrejection`。画界面时抛错，Preact 把整棵树卸掉，页面是白的；Promise 里没接住的错只进控制台。
- 计算程序（Worker）卡住时只有脚本能停（看门狗只在脚本运行期间计时）。别的请求没应答，“正在计算…”一直转；这时导出世界文件（`getDoc` 问计算程序）、⌘S（同一条路）、自动保存（`docTail` 问计算程序，而且一次接一次排着）、回到以前的版本（先等排着的编辑算完）都在等它——存不了也导不出。
- WebGL 的上下文丢了没人管：画布是黑的，`gl.createTexture()!` 之类返回 null，回不来。不支持 WebGL2 时 `renderer-base.ts` 抛一句“浏览器不支持 WebGL2”，`MapView` 把它在顶上闪 6 秒，之后是一张空白的页面和照常转的“正在打开世界…”。
- 报错是引擎的原话。命令的格式是“几种里的一种”（zod 的 union），格式不对时几乎总是 `命令参数无效：(根)：Invalid input`（`src/error-text.test.ts` 里用真的 `commandSchema` 核对过就是这一句）；重放出错是 `第 7 条命令失败：…` 后面接原话；JS 的异常是 `Cannot read properties of undefined…`。
- 计算 Worker 没有 `onmessageerror`：消息解不出来时那个请求永远不回。

## 1. 全局兜底与自救页

### 分三种（`src/mishap.ts` 的 `classify`，纯函数）

| | 是什么 | 怎么办 |
| --- | --- | --- |
| 不管 | 不是这个程序的、无害的：别的网站的脚本（只有一句 `Script error.`，没有文件、没有错误对象）、浏览器扩展（文件或调用栈里全是 `chrome-extension://` 之类）、别的来源的脚本、`ResizeObserver loop…` 的警告、用户自己取消（`AbortError`）、计算程序自查隔离时的探针（话里带 `data:text/plain,x`）、界面起来以后才要的程序文件没读到 | 什么都不说 |
| 不致命 | 点击、定时器里抛的错，没接住的 Promise，某一块（面板、弹窗）画不出来 | 顶上一条：“刚才那一步可能没做成。世界还在，可以接着用”/“‘资源库’出了问题，已经关闭。世界还在，可以接着用”，带“原因”（展开是翻成的人话 + 原话 + 调用栈，能复制）、×。不打断；不展开时 12 秒后自己消失 |
| 致命 | 根上的错误边界接到的（整个界面画不出来）、界面还没画出来过就出的错（页面是白的）、界面没出来时程序的脚本或样式没读到 | 整页的自救页 |

- 页面是从文件直接打开的（来源是 `null`，`compose-ab` 就是这样）时分不出同源不同源：不是扩展的都算自己的。
- **同一个错不反复刷屏**（`MishapLog`）：记号是名字 + 原话 + 调用栈的第一处。正显示着的再来只把次数加一（“原因”里写“出了 5 次”）；关掉、自己消失、被别的顶掉以后一分钟内再来不说；过了才再说一次。每一帧都抛的同一个错，一千次只说一次（测试里是这个数）。
- **地图的一帧画不出来**另有一条规矩（`DrawHealth`）：`MapView` 的 `draw` 包了一层，一帧出错报成不致命的（上面那一条），连着三帧都画不出来才算地图坏了——盖上“地图画不出来了……”的一层（第 4 节），不再重画。偶尔一帧出错（某个预览的毛病）不算。

### 接线

- `src/crash-host.ts`：`installCrashHandlers` 接 `window` 的 `error`、`unhandledrejection`（冒泡阶段）和程序自己的 `<script>` / 样式表没读到（捕获阶段才收得到）；`report(来源, 错)` 分一分，不致命的交给 `crashHooks.minor`，致命的交给 `crashHooks.fatal`，并从此不再处理后面的错（自救页只出一次）。
- `src/boot.ts`：页面最先载入的一小段（`index.html` 里排在 `main.tsx` 前面），只做两件事：`crashHooks.fatal = showRescue`、`installCrashHandlers()`。它只引用 `crash-host.ts`、`rescue.ts` 和它们用的几个纯文件——不引用界面、状态、资源库、渲染器。
  - 打包以后 Vite 把两个入口并进了同一个文件，但模块照 `index.html` 里的先后执行：`boot.ts` 和它引用的先跑完，才轮到 `main.tsx` 引用的那一大串。所以主体在载入、运行的任何一步抛错，兜底都已经接上了（冒烟第 11 段最后一项验证的就是这个：让主体第一次找 `#app` 时拿不到，它一运行就抛错、界面一次都没画出来——页面是自救页，不是白的）。
  - **整个文件没读到、读得很慢**时脚本一行都没跑，什么兜底都没有。这一种在 `index.html` 里留了一句不靠脚本的话：`#app` 里一个 `p.boot-wait`，CSS 动画让它十秒后才显出来（“页面还没打开：程序的文件没读到，或者读得很慢。请重新载入。已有的世界还存在这个浏览器里，不会丢”）；程序一起来第一件事就是把它拿掉。
- `src/ui/shell/Guard.tsx`：`RootGuard` 包着 `<App />`，接到就 `report('boundary', …)`；`Guard` 包着一块——图例、“这里”卡片、档案抽屉、资源库面板、弹出面板、管理库 / 我的地图 / 留着的旧世界 / 以前的版本 / 帮助几个弹窗——接到就把那一块关上（`onFail`）、报成不致命的。`watch` 变了（那一块关上、换了一页）就重新画，一直挂着的那几块下次打开时再试，不会一直空着。顶栏、底部条、地图、向导、问话框没有单独包：它们画不出来就是整个界面用不了，交给根上的那一个。
- `src/state/mishap.ts`：顶上那一条的信号（`mishap`）、多久消失、展开；`src/ui/shell/MishapBanner.tsx` 画它。

### 自救页（`src/rescue.ts`）

写明“页面出了问题”，下面一行说世界在哪（见下），按钮：**导出文件**、**重新载入**（主要的），“原因”折叠着、里面是原话、能复制（没有剪贴板的权限时把那一段选中）。

- **它不依赖出错的那部分**：不用 Preact、不用信号、不用 `src/ui/components/` 的控件（“控件只用 components/”的规矩在这里有意不守——出问题的可能正是它们），只用 DOM；样式写在元素上、颜色取 token 并带后备的值（`styles.css` 没读到也看得清）。文字在 `src/crash-text.ts`：一个不引用任何东西的文件（`ui/copy.ts` 引用了 `trust.ts`、连着存储，自救页不能靠它），`copy.ts` 照旧把这几组导出去，界面别处还是从 `copy.ts` 取。
- 出来以后下面的界面加 `inert`（不收鼠标键盘）；`boot.ts` 在 `window` 的捕获阶段登记的 `keydown` 比程序的任何一个都早，自救页开着时把键盘拦下（撤销、保存的快捷键不再到下面的程序），不拦默认行为（Tab、回车照样在按钮上起作用）。
- **导出从哪里拿世界**（`src/rescue-doc.ts`，有测试）：
  1. 页面里现在的世界——主线程手上的命令记录（`main.tsx` 接上 `crashHooks.liveDoc`：`mirror.doc()` 转成字）。不问计算程序；最新，连没来得及自动保存的最后几步都在。
  2. 拿不到（程序没起来、还没打开世界、取的时候抛错、给的不是世界文件）时用浏览器里存着的那一份：`readSavedWorld` 自己读 IndexedDB 的自动保存（`kv` 的 `autosave` 是头，`autosave` 表里是每一条命令）和 localStorage 的后备，取较新的。它不引用 `autosave-io.ts` / `backups.ts`（那两个连着信号和锁），只认存储里那几样东西的形状；测试拿真的写入（`AutosaveWriter` 经浏览器那一层写进假的 IndexedDB）写下的东西来读，形状变了这里没跟上测试就不过。打开库时不升级、不新建（没有这个库时中止那一次新建，不留下一个空的）。
  3. 没存完整的（头里的条数对不上）照样给出存下的那一部分，页面上写“是存下的那一部分”。
  - 文件名“世界 2026-11-11 1405.json”。哪一步出错都不抛（这是最后一条路）：没能导出时写“没能导出。请不要关这个页面……”。
- **“世界还在不在”那一行**（`crash-text.ts` 的 `rescueWorldLine`）：出自救页之前先把没写的尾巴同步写进自动保存（第九十四轮的 `flushNow`）。页面里的世界拿得到、也写下了：“你的世界还在浏览器里，重新载入后接着做”；拿得到但写不了、又有没存的改动：“……最后几步没来得及存进浏览器。请先导出文件”；页面里的拿不到：先写“正在看浏览器里存着的世界…”，读到了写“是今天 14:05 存的”，不完整的写不完整，都没有时写“浏览器里没有存着的世界，没有东西会丢”（导出文件灰着）。
- “重新载入”之前叫一声 `skipLeaveWarning`：这个页面已经坏了，浏览器不用再问“要离开吗”。

## 2. 计算程序不应答时也能导出、能保存

主线程手上有一份完整的命令记录（`sandbox.ts` 的 `Mirror`：每一条改动世界的回复都带着变了的命令）。它的内容就是计算程序里“已经应答的最后一步为止”的世界文件（`src/sandbox-stop.test.ts` 拿真的引擎核对：执行、撤销、重做、换一个之后，`mirror.doc()` 和 `engine.toDoc()` 逐值相同，新加的 `Mirror.tail(base)` 和 `engine.docTail(base)` 逐值相同）。

查了一遍哪些路还在死等：

| 哪条路 | 以前 | 现在 |
| --- | --- | --- |
| 导出世界文件（“世界 → 导出 → 世界文件”、各处的“导出文件”） | `getDoc()` 问计算程序 | `docNow()` |
| ⌘S、另存为 | 同上 | 同上 |
| 自动保存要“变了的命令” | `call({kind:'docTail'})`，等不到就一直等，后面的自动保存都排着 | `docTailNow(base)`：照旧先问（它的回复顺带写检查点），3 秒没回就用 `mirror.tail(base)` 算同一份 |
| 自动保存跟着写连着的“我的地图”、退回 localStorage 的那一份 | `getDoc()` | `docNow()` |
| 导出游戏文件包、单独导出的一项 | `getDoc()` | `docNow()` |
| 留一份以前的版本（回去之前、换世界之前、重新载入之前） | 先 `whenEditsIdle()`（一直等） | `idleWithin()`（最多等 3 秒），字照旧从命令记录来（第九十五轮就是） |
| 存到电脑上的文件 | 命令记录（第九十五轮就是） | 没动 |
| 关页面那一下 | 命令记录（第九十四轮就是） | 没动 |

`docNow()`（`state/worker-host.ts`）：
- 没有改动世界的请求在等：命令记录就是现在的世界，直接用，**不问计算程序**（比以前还少一次来回）；
- 有在等的：最多等 `DOC_WAIT_MS` = 3 秒。等到了（那一步在里面）照常；等不到也给，并标上 `behind`——**还在算的那一步不在里面**。
- 为什么是 3 秒：比几乎所有编辑的一步都长（平常点了导出，前一笔还在算，等得到），又短到点了“导出文件”不像没反应。

`behind` 时界面说一句：“已导出。还在算的那一步不在里面”“已保存‘X’。还在算的那一步不在里面”。这时也不整理世界文件（整理要在导出 Worker 里把世界从头重放两遍；计算程序正卡着的时候不再添一件久的事），原样写出去——打得开，只是没去掉“加了又删”的命令。

卡着的时候“正在计算…”一直占着顶上那一条，以前一般的提示被它挡住。现在出现了“停止”以后（第 3 节），这期间说的话排在它下面，不被挡。

## 3. 什么请求都能停

### 多久出现“停止”（`src/stall.ts` 的 `Stall`，纯规则，时钟可换）

有带提示的请求在等（执行、撤销、新建、打开……），而计算程序已经连着 **5 秒**（`STOP_AFTER_MS`）没有回过任何一条——“正在计算…”旁出现“停止”。不自动停：算得久不等于卡住，由用户决定。

- 为什么是 5 秒：平常的一步是几十到几百毫秒，量到的最慢的几步在半秒上下（第九十五轮 `bench-median` 的数：一块地区描河 560–640 毫秒、整个星球 hotRelief 340–450 毫秒），5 秒是它的八倍以上，编辑时碰不到。5 秒以上的只有新建、打开很大的世界和真的卡住了：前一种多一个“停止”正好能取消，后一种这是唯一的出路。再短，慢机器上的一步会让按钮一闪；再长，卡住的人要盯着转圈等更久才知道能做什么。
- 按“多久没有回过一条”算，不按“忙了多久”：连着画十秒、每一笔都按时算完的，不出现；后台的回复（预览、自动保存要的）也算它还活着；回复到了、还在等网格和换快照的那一段不算（不是计算程序的事）；电脑睡过、页面在后台被节流（看的那一下晚了 2 秒以上）重新计时，和看门狗一样。
- 脚本的“停止”照旧（看门狗管，1.5 秒就出现、4 秒没动静自己停），排在前面。

### 停下做什么（`sandbox.ts` 的 `EngineHost.stopAny`）

照脚本的“停止”推广的：结束这个 Worker，在等的请求都回 `{ok:false, stopped:true}`，用命令记录另开一个打开同一个世界（Worker 会先试检查点），世界回到这一步之前，说一句“已停止，回到了这一步之前”（撤销过几步、重做记录因此没了时添“。重做记录已清空”）。和脚本那条路不一样的三处：

- 说的话不当成报错（不是红的），`handle()` 也不再把“被停下了”当出错弹一次；
- **正在新建、打开的被停下时不换安全模式再开**（脚本卡住时是换安全模式：再正常打开还会卡；用户停下的不是脚本的事，是不要它了）。原来开着一个世界（命令记录里还是它）就回到原来的世界；
- 原来没有世界（启动时打开上次的世界）：只是不打开了，不恢复、不另开 Worker。

`stopped` 这个记号只有主线程自己替 Worker 回的出错才带（`readWorkerMessage` 把 Worker 发来的出错重写成只有 `id`、`ok`、`error`），Worker 里的脚本伪造不了。

### 界面

- 有世界时：“正在计算…”旁的“停止”（`shell/Notice.tsx`）；
- 启动时正在打开上次的世界（还没有世界）：中间“正在打开世界…”那一块上的“停止”（`App.tsx`）；
- 新建向导里正在生成、正在打开：向导底下的“停止”（`Wizard.tsx`）。

### 启动时停下、连着两次没打开成

- `open()` 的结果多一种 `stopped`。`resumeLast()` 遇到它照第九十四轮“用户取消”那样走：`noteNotResumed('cancelled')`，进向导，那一份自动保存留在原处（向导上面“继续上次的世界”还在；新建以后它在“留着的旧世界”里，原因是 `cancelled`）；顶上说“已停止。上次的世界还留在浏览器里”。
- **连着两次没打开成，下次先问**（`src/open-guard.ts`，纯函数 + 一个可换的存储）：每次动手打开上次的世界之前在 localStorage 的 `map2.opening` 里记一笔（同步写：页面随后就崩也已经记下了；记的是哪一份自动保存、连着第几次）。打开成了、并且之后 5 秒（`OPEN_SETTLE_MS`）界面没有坏才擦掉——世界一画出来整个界面就坏的，也算没打开成。有原因的没打开（马上就问了）、用户取消了也擦掉。页面出了问题、卡住被关掉、被停下，这一笔留着。
  下次启动看到连着两笔：不直接打开，先问——**就是第九十四轮“上次的世界没能打开”的那一个问话**（`askResumeFailed`，没有另写一套），标题换成“上次的世界前两次都没打开成”，没有原因那一行，按钮一样：再试一次 / 用安全模式打开（有脚本时）/ 导出文件 / 新建。选了新建，那一份照旧在被新世界盖掉之前挪进“留着的旧世界”，原因写“连着两次没打开成”。
  认的是哪一份自动保存（它保存的时间）：换了一份就从头数。原来给脚本用的那一个标记（`trust.ts` 的 `markLoading`：带脚本的世界打开到一半页面没了，下次先问要不要安全模式）没动，两样都在。

### 消息解不出来

计算 Worker 那边 `onmessageerror`（主线程发来的解不出来）抛出去——不知道是哪个请求、回不了它，让主线程那边按 Worker 出错处理；主线程这边 `EngineHost` 给每个 Worker 接上 `onmessageerror`（`engine-spawn.ts` 的那一层也传上来：打过招呼之前的和报错一样换普通的 Worker），都走“崩了”那条路：停掉、在等的回出错、用命令记录恢复。

## 4. WebGL 的上下文丢了能恢复

规则在 `src/render/gl-recover.ts` 的 `GlRecovery`（纯的，计时可换），接在 `ui/MapView.tsx`；盖在地图上的那一层是 `ui/shell/GlNote.tsx`，写什么是纯函数 `gl-note.ts`。

- `webglcontextlost`：`preventDefault`（不拦，浏览器之后不会再还上下文），状态变成 `lost`，地图中间盖一块“画面暂时不可用，正在恢复…”，这期间不画（丢了的上下文上画什么都是空的）。叠加层是另一块 2D 画布，不受影响（地名、图例照常在）。
- `webglcontextrestored`：重建、重画，回到 `ok`。刚说恢复又丢了（`isContextLost`）就接着等，不去重建。
- 等了 **8 秒**（`GL_RESTORE_MS`）还没恢复：`stuck`——“画面没能恢复。这张地图已存在浏览器里，重新载入后接着做”+“重新载入”。Chrome 里显卡进程重启后一两秒内就还上下文；8 秒还没有，多半这一次不会有了。说早了没有坏处：之后浏览器还了照样恢复，那一层自己消失。
- 重建时出错、或者连着三帧画不出来（第 1 节）：`broken`——“地图画不出来了。……”。
- **“世界已经存好”是照实说的**：进 `stuck` / `broken` 时先存一次；那一句跟着 `unsaved` 变——都存好了说“已存在浏览器里，重新载入后接着做”，只有“重新载入”；还有没存的说“还有改动没存好，请先导出文件，再重新载入”，多一个“导出文件”。

### 怎么重建（`Renderer.revive`）

渲染器里“传过没有、画过没有”的记号有几十个（每张纹理传的是哪几个数组、各层画的是哪个键、幽灵海岸改过哪几行……），GPU 上的东西一没，这些全是错的。没有一个个去清：**在同一个对象上从头来一遍**——`new Renderer(同一块画布)`（拿到的就是恢复了的上下文，构造时把程序、纹理、渲染目标都建好），把它的全部状态 `Object.assign` 进原来的对象；镜头、画风、晕渲倍数这些设置照旧。外面拿着这个对象的（导出、`window.__map2`、工具）不用换。然后 `MapView` 把自己这边“给过没有”的记号也清掉（着色的缓存、幽灵海岸、省份预览、高亮、花纹、湖色的键），下一帧照平常的路把网格、图层、高亮、预览重新给一遍。

画法没有动：之后每一帧走的还是原来那几个函数，输入和丢之前一样，所以结果一样。冒烟里验证了（见“量到的数”）：丢、恢复，画布的 PNG 逐字节相同；丢了 8 秒以上再恢复也相同。

### 不支持 WebGL2

`MapView` 建渲染器失败（拿不到 WebGL2、没有浮点渲染目标、着色器编不过）不再是顶上闪一句：`reportNoWebgl` → 自救页的另一种——“这个浏览器画不了地图 / 地图用 WebGL2 来画，这里用不了。请换新版的 Chrome、Edge、Firefox 或 Safari 打开；已经是新版时，在浏览器的设置里打开‘硬件加速’，再重新载入”，下面同样有世界在哪的一行、“导出文件”“重新载入”、原因。已有的世界在这一页上导得出（浏览器里存着的那一份）。

## 5. 报错改人话（`src/error-text.ts` 的 `humanError`）

只在显示的那一层翻：`core/` 里的原话不动（`formatIssues`、`CommandError` 的话进了测试的断言，“留着的旧世界”里存的原因也是原话）。翻出来是 `{text, detail}`：`text` 给用户看，`detail` 是原话（和 `text` 不一样时才有）。

- **本来就是中文的原样**，不带 `detail`。怎么认“带英文”：去掉引号、书名号、全角括号里的（地图名、文件名可以是英文；程序自己附在后面的原话在全角括号里）以后，还有连着两个以上的英文词、或者一个 `XxxError`。单个的词（WebGL2、JSON、km）不算。
- **脚本出的错原样**（话里有“脚本”）：`core/script.ts` 已经写成中文、后面带着解析器和运行时的原话，写脚本的人要看原话。
- `命令参数无效：…` → “这一步的内容格式不对”；zod 说得出更细的（期望什么类型、太大太小、不在可选的几种里、有不认识的项）时写“这一步的内容不对：应该是数，给的是文字”这样的一句，字段的英文路径不给用户看。
- `第 7 条命令失败：…` → “第 7 步做不出来：…”（后半句接着翻）。
- 前半句是中文、后半句带英文（“世界没能恢复：TypeError: …”）：前半句留着。
- 浏览器、运行时的原话按一张小表：内存不够、浏览器存储满了、没能读到程序的文件请重新载入、没能读到要用的文件、浏览器不让这样做、浏览器没有允许、要用的东西找不到了、已取消、显卡没能画出来；都对不上的是“程序内部出错”。

用在三处：
- 顶上的出错提示（`state/notes.ts` 的 `showToast(…, true)`）：所有出错的提示都经过它。原话不一样时提示条上多一个“原因”，点了换成第 1 节那一条（展开着，原话能复制）。
- “上次的世界没能打开”的问话：原因那一行写人话，原话在下面折叠着的“原话”里（`Ask.note.detail`）。
- 第 1 节顶上那一条的“原因”：第一行是翻成的人话，下面是原话和调用栈。

渲染器的“浏览器不支持 WebGL2”不再直接给用户看（第 4 节）；`sandbox.ts` 的几句（“计算程序没有响应”“……超过 4 秒没算完，已停止”）本来就是中文，没动。

## 6. 冒烟

`tools/smoke.mjs` 接着前七段多了四段（写在 `tools/smoke-safety.mjs`，原来的文件再加就过 800 行了）。做法都是从外面做，不用程序配合：

- **让计算程序卡住**：经调试协议挂到页面的 Worker 上（`Target.setAutoAttach`），在计算 Worker 里 `Runtime.evaluate` 一段忙等十分钟的循环。程序里没有为它留任何东西，普通用户碰不到。
- **启动时打开卡住**：冒烟在页面载入前注入一小段，把 `Worker` 包一层，吞掉发给它的“打开世界”。
- **WebGL**：页面里拿画布的上下文，用 `WEBGL_lose_context` 丢、还。
- **没有 WebGL2**：载入前注入，把 `getContext('webgl2')` 换成拿不到。
- **程序的主体一运行就出错**：载入前注入，让第一次 `getElementById('app')` 说没有。
- **下载都拦住**：载入前注入，把 `<a download>` 的 `click` 换成记下文件名和那个 Blob（冒烟再读它的字核对），不真的下载；浏览器那边另设成不许下载（`Browser.setDownloadBehavior: deny`）。
- **只有“画界面时抛一个错”从外面做不到**，留了一个钩子（`src/smoke-hooks.ts`）：只在打开页面时网址的 `#` 后面正是 `#map2-smoke-96` 才在 `window` 上装一个 `__map2Smoke.crashRender('root' | 'part')`；界面上没有任何地方通向它，装了不调用也什么都不发生；没装时界面里那个空部件永远什么都不画。“点击里抛错”不用它（冒烟自己在定时器里抛）。

## 取舍

- **自救页用 DOM 手写**，和别处的界面是两套写法。换来的是它在 Preact、信号、样式表坏了的时候也出得来。它只有一个标题、两段字、两个按钮。
- **不致命的错一律说“可能没做成”**：没接住的错不知道是哪一步、做没做成，不替它编。真的因为它没做成的那一步，多半另有自己的提示。
- **“停止”要等 5 秒才有**，不是一开始就有：一开始就有的话每画一笔都闪一下按钮。
- **停下不是暂停**：没算完的那一步丢掉（世界回到它之前），不能接着算。
- **计算程序卡着时导出的文件不含那一步**，说明了；没有去等。
- **连着两次没打开成才先问**，不是一次：关掉一个还在打开的页面太平常了，下次就拦一道只会烦人。
- **上下文恢复用“整个重来”**，不逐项修：多花的是一次全量上传（几十毫秒），省下的是几十个记号一个个对的风险。
- 自救页、画不了地图的那一页上没有“新建”：页面已经不能用了，重新载入以后再说。

## 没做的、要知道的

- **程序的文件整个没读到**（断网、文件换了）时没有自救页、没有导出按钮，只有 `index.html` 里十秒后显出来的那一句。兜底和主体打包后在同一个文件里：文件读到了但浏览器太旧、语法都不认时也是这样。离线可用是后面的轮次。
- **不致命的那一条可能多说**：界面起来以后任何没接住的 Promise、定时器里的错都会出一条“刚才那一步可能没做成”。冒烟的前七段里一条都没有；隐私模式、存储被禁用、选文件的窗口这些环境里以前悄悄没接住的错现在会不会冒出来，没有逐个试（用户取消的 `AbortError` 挡掉了）。它不打断、12 秒后自己消失、同一个错一分钟内不重复。
- **没单独包错误边界的**：顶栏、底部条、地图、向导、问话框。它们画不出来就是自救页。
- **恢复世界本身卡住**（“正在恢复世界…”）时没有“停止”——那时再停只会再恢复一次。“世界 → 导出”照样导得出。
- **新建到一半停下、原来没有世界**：回到向导，只说“已停止”。
- **卡着的时候**：⌘S 存进“我的地图”的是没有那一步的（说了）；自动保存用命令记录写下去的那一次不写检查点（计算程序活过来以后的下一次照常写）；存到电脑上的文件、以前的版本照第九十五轮的路（本来就用命令记录）。
- **等 3 秒是固定的**：点了导出，计算程序正算一个 4 秒的步骤，拿到的是没有那一步的文件（说了“不在里面”），不会多等一秒。
- **“停止”不是暂停**：没算完的那一步丢掉。重新生成整个世界这样的大步骤停下以后要重来。
- **WebGL**：只在无头 Chrome（SwiftShader）里用 `WEBGL_lose_context` 验证过。真的显卡驱动重置、电脑睡眠唤醒、别的浏览器、手机没有试。上下文丢着的时候不截缩略图（这期间留的版本、存的地图没有缩略图）；导出整张地图（.png）画到一半上下文丢了，那一次导出没有专门处理。网址带 `?perf` 测速时，恢复以后 GPU 计时的扩展没有重新取（只影响开发时的测速）。
- **重建以后“离边界远的格”（第三十九轮的提速）重新在空闲时算**：恢复后头一两秒合成走的是没有它的那条路（结果一样，只是慢一点）。
- **报错的表是按见过的写的**：没见过的英文一律“程序内部出错”，原话在“原因”里。命令这里 zod 几乎只给 `Invalid input`（格式是“几种里的一种”），更细的几种说法（类型不对、太大太小）是给别处的校验留的，哪些地方会把那样的原话送到提示条没有逐个查。资源库里“不是 JSON：…”后面的解析器原话没翻（那是给会写 JSON 的人看的输入框）。“留着的旧世界”里存的原因还是原话（列表里不显示它）。
- **连着两次没打开成**记在 localStorage：写不了（隐私模式）就不记，每次照常直接打开。两个页面同时在打开同一份时会各记一笔。
- **5 秒、3 秒、8 秒**是按上面写的理由定的，没有在慢机器、很大的世界上量过“打开要多久”“一步最慢多久”。
- **没有用眼睛看过的界面**：新建向导里的“停止”；出错的红色提示条上的“原因”按钮（和点了以后换成的那一条）；计算卡着时两条提示叠着的样子（冒烟里读到了两条的字，没截）；“画面没能恢复”在还有没存的改动时（多一个“导出文件”）；“地图画不出来了”（连着三帧画不出来的那一种）；自救页的另外几种说法（“最后几步没来得及存进浏览器”“存着的世界不完整”“浏览器里没有存着的世界”、没能导出的那一句）、“原因”展开和“复制”；问话里“原话”展开的样子；`index.html` 里十秒后那一句；900 px 以下的窄窗口；Firefox、Safari。这些的字和判断在纯函数的测试里（自救页的版面除外：它只有冒烟看得到），排版没看。
