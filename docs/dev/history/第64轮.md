# 第六十四轮的设计

这一轮改了什么见 [更新记录](../../更新记录.md)；现在的文件见 [开发说明](../../开发说明.md) 与 docs/dev/ 下的各篇。第六十五轮（两栏窗口、各入口的界面）照这里的接口做。

## 为什么重写

用户觉得导入反直觉：有一项不行就整次导入不了；只想要一个宗教却带来一堆。第六十一轮的闭包是“默认都带，可以取消”：

- 往科幻世界导入天主教写入 35 项（28 种宗教 + 7 个组），变量不能取消，按钮却写“导入 1 项”。
- 社会主义共和国写“4 项”，实际写入 18 项。
- 任何一项放不下，确认按钮整个灰掉。

用户定的规则是反过来的：**不能进来的一开始就灰着并写明原因，勾什么进什么。**

## 规则怎么落到代码

`core/packs/import-gates.ts`（新）判断能不能选、走到哪些；`core/packs/closure.ts` 算写入。closure.ts 原来 763 行，拆开后约 500 行和约 720 行。

### 每一项的状态

| 状态 | 什么时候 |
| --- | --- |
| `free` | 能选。`differs`：目的地有同 id、内容不同的，导入后并存（清单写 `to`） |
| `have` | 一模一样；或者是来源去掉几条引用后的样子，而这些目标现在也没有 |
| `fixable` | 是来源去掉几条引用后的样子，有的目标现在有了；或者比重写了 0、来源不是 0 |
| `gated` | 少了东西：派系主要靠的变量、政体列的派系有一个灰、“限谁用”全部落空、去不掉的引用哪里都没有 |
| `full` | 这一种满了、变量满了、有问题的地名风格 |

### 灰不灰：最小不动点

“勾上的算目的地已有”。走一遍勾选，灰的不往下走；把走到的算上再走一遍，到不再变为止（`walkClosure`）。所以：

- 同一窗口勾意识形态，社会主义共和国马上能选；只勾一个取值也行（取值会加变量）。
- 互相限定、都没勾的两项还是灰的，不会靠自己解开自己。
- 没有被拒绝的项时只走一遍。

### 哪些引用跟着来

只有**去不掉的**（`link.drop` 没有）：`culture.group`、`popValue.dimension`、`valueGroup.dimension`、脚本。带这一项本身，组比重写 0；取值要的变量只加变量，不带别的取值。脚本互相写到（奇幻的 8 项）可以成环：走过的不再走，算灰不灰时走到自己算不灰。

hard 但写了 drop 的（取值的组、生态写到的河）和 strip、auto 一样：目的地没有就去掉这一条。设计文档说“只跟 hard 且去不掉”，代码只看 `drop`：内置的字段里，没有 drop 的都是 hard，将来有别的类别也不能去掉，只能跟着。

### 子项

用库的 `arrange` 和融入表 `RELATIONS`，和面板上看到的结构一样（第六十轮）。内置的库是预设：文化组 ▸ 文化、地名风格、地标；政体 ▸ 派系；取值组 ▸ 取值；时代 ▸ 变量；等级 ▸ 格局。变量 ▸ 取值和取值组不在表里（变量不是一项内容），写死在 `requireDim`。

跟着来的上级不带下级：一个文化不会把组里 28 个文化都带来。库把“派系”从政体拆开了（`arrange` 没写）时，勾政体不带派系，写到的引用去掉；灰不灰还看列的派系，因为规则说的是“政体列的派系”。

### 字段表的 `dep: 'gate'`

`LinkClass` 加一类。缺的目标去掉；还剩就只留剩下的；**一条不剩就灰**，不然限制没了谁都能用。只写在最外层的列表字段上（`linkProblems` 查着，写在里面看不出落空）：`government.only`、`landmarkType.cultureGroups`、`terrainClass.rules`、`resource.rules`。判断用 `stripLinks` 真的去一遍看字段还在不在，只有真的缺目标时才算（内置的约 25 项）。`dependencyClosure`（只是查引用表，导入不走它）把 `gate` 当 `auto` 走。

写入时也查一遍（`finalsOf`）：“限谁用”写到的目标放不下被跳过时，这一项也跳过，不写成不限。

### 项数

`count = rows.length`：写入的内容（新的、改名的、补回的）+ 新的自定义场 + 加到时代里的变量。变量的取值算在里面（第六十一轮不算，所以才对不上）；清单里收成一行是第六十五轮的显示。目的地没有时代时变量写在带来的时代里，不单独算一项。门槛：世界里 `count === command.commands.length`；库里 `added + fixes + dims + 新的场 === count`。

### 放不下

先走到的（勾的）留着，多出来的记进 `c.over`，再走一遍：写到它们的引用去掉，去不掉的连要它的一起跳过。写进 `dropped`。取值都放不下的变量也不加（世界里 `add_dimension` 不接受没有取值的变量）。“放不下的派系”不让政体灰：和用户去掉一个派系一样，名单少这一个；灰政体的规则只说变量。

### 补回

`relationOf` 认“目的地这一份是来源去掉某些引用后的样子”：看目的地写到哪些目标（`a-2` 也算写到 `a`），把来源里没写到的去掉，再把引用目标都抹掉比（`linksBlanked`）。按对象记着。

- 现在目标有了、去掉后还写着、目的地没写的（`restoredLinks`）才补回。一条来源写了变量和取值、只有变量有了时整条还是去掉，不算（第一版漏了这个，再导入不是 0 项，随机测试查出来的）。
- 跟着来的项不补回（只是要它在），勾的和子项才补。
- 比重：不比的键（`sameIgnore`）留目的地的。例外：目的地比重是 0、来源不是、勾了这个组时比重回来。**这一条设计里没明写**，它让“勾整组才参与”对已经跟着文化来的组也成立。
- 世界 `enableCommand`（没写 from，来源留着），库 `replaced`。
- 引用改过名（撞名导入过 `a-2`）的不补回，只算已经有了。写的时候要知道 `a` 对应 `a-2`，这一轮不做。**所以撞过名的 `catholic-2` 后来再勾组，还是会多一份 `catholic-3`。**

## 接口（第六十五轮用）

```ts
// core/packs/import-gates.ts，closure.ts 照旧导出
type ImportGate =
  | { t: 'free'; differs?: boolean }
  | { t: 'have' }
  | { t: 'fixable'; restores: string[] }
  | { t: 'gated'; needs: ImportNeed[]; any: boolean; reason: string } // reason：“需要意识形态”“需要戌或亥”
  | { t: 'full'; reason: string };
interface ImportGates { of(ref: ContentRef): ImportGate; all(): Map<string, ImportGate> }
function importGates(source, target, picks?, off?): ImportGates;

// core/packs/closure.ts
interface ImportAsk { source; target; picks; off? } // 没有 on 了
interface ImportRow { kind; id; name; kindLabel; role: 'pick' | 'child' | 'follow'; state: 'new' | 'rename' | 'fix'; because: string[]; to?; under?; count?; children: ImportRow[] }
interface ImportPreview { list: ImportRow[]; rows: ImportRow[]; count; stripCount; stripped; dropped: ImportDropped[]; dims; gates: ImportGates; plan }
```

`preview.gates` 和 `importGates` 算的一样，已经走过一遍，窗口直接用它。`of` 用到时才算，按这次勾选记着。

和设计文档不一样的字段：多了 `rows`（一列，算项数、`regenLine` 用）、`gates`、`stripped`（`source-diff` 的测试用；窗口只用 `stripCount`）。`list` 里每行的 `because` 是数组（一项可能几处要它）。

## 量到的数

内置库两两，只看目的地自己（没有勾选）灰了多少（政体 / 派系 / 文化）：

| 来源 → 目的地 | 政体 | 派系 | 文化 |
| --- | --- | --- | --- |
| 现代 → 奇幻 | 11 / 12 | 10 / 14 | 0 / 410 |
| 现代 → 中世纪 | 11 / 12 | 10 / 14 | 0 / 410 |
| 现代 → 工业 | 9 / 12 | 8 / 14 | 0 / 410 |
| 中世纪 → 奇幻 | 7 / 19 | 0 / 5 | 0 / 404 |
| 中世纪 → 科幻 | 19 / 19 | 2 / 5 | 0 / 404 |
| 奇幻 → 中世纪 | 11 / 14 | 3 / 5 | 0 / 52 |
| 科幻 → 现代 | 5 / 13 | 0 / 7 | 0 / 35 |
| 科幻 → 中世纪 | 13 / 13 | 7 / 7 | 0 / 35 |

- 全部两两里灰的：政体 232 项，派系 112 项，地标 6 项。地形类别、资源、河、生态一项都没有灰（设计也说只有前两种会碰到）。
- **科幻的派系写到意识形态，科幻的时代没有这个变量**：写“需要变量 ideology”，这个库解不开，要先从现代库导入。没有 label 可用，只好写 id。
- 中世纪 → 科幻：勾天主教 2 项（去掉 1 条：宗教组）；勾直隶人 2 项（文化 + 组，去掉 47 条）；勾伊克塔灰“需要宗教”。
- 现代 → 奇幻：社会主义共和国灰；加上意识形态 19 项（政体、2 个派系、变量、15 个取值和组，去掉 2 条）。

速度（中世纪勾全部 727 项导入科幻）：`importPreview` 约 20 ms，`gates.all()` 约 4 ms；勾 3 项时不到 1 ms。随机 1440 次导入最慢 14 ms。

## 取舍

- **变量跟着来取消了**（第六十一轮的行为）：奇幻世界要社会主义共和国，勾意识形态再勾政体。这是用户定的。
- **“放不下”只算走到的**：灰不灰用的 `full` 按没认出撞名的算（`x-2` 其实可能已经有了），`importPreview` 走完 `settleIds` 才是准的。差别只在种类刚好满、又撞过名时，勾上后结果里没有多写。
- **档案里换政体**：灰的 `id: null`，`governmentCommand` 返回 `null`，点了不做。还列着，第六十五轮不再列。
- **列表上的“添加”**：要加变量、有灰的还是打开窗口；第六十五轮改成不弹窗。
- **目的地没有时代时变量算都有**（勾一个取值带来时代后，时代写的别的变量也算有）：这样政体能解开，但取值没带时派系的来源去掉了。只有空的库碰得到。
- **窗口**：能勾、灰的写原因、下面列清单和 ×，别的是第六十五轮的。

## 测试

- `closure.test.ts`、`closure-gates.test.ts` 按新规则改写。门槛一（两两、固定种子）现在查：项数等于命令数、灰的写明原因、灰的进不来、再导入 0 项、一步撤销；抽样里加了变量。这一轮另外跑过 40 个种子 × 6 × 6（一次性的，没有留下）。
- 改了断言的（是被用户推翻的行为）：`pack-tree-ui` 的全部添加（伊克塔这些灰的不进来）、`countries-ui` 换政体（要先导入变量，灰的返回 null）、`page-import`（去掉可选的变量、窗口里算的项）、`page-world`、`source-diff`（导入社会主义时勾上意识形态）、`links.test`（`only`、地标的组类别是 `gate`）。
- 新增：变量一种取值（人全归它、文化比例逐值不变、撤销重放）；世界和库里的补回；放不下；目的地没有时代；`dep: 'gate'` 写错地方时 `linkProblems` 报。

金标准（`core/golden*.json`、`*digests*.json`、`shader-hashes.json`）一个都没重录。
