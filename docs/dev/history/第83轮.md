# 第八十三轮的设计

这一轮改了什么见 [更新记录](../../更新记录.md)。纯结构：之后几轮要改人文的生成、自然（侵蚀、河、气候）、新的手绘画风（渲染器、叠加层）和地名排版，
先把它们要碰的大文件按职责拆小，以后的改动只落在小文件里。规矩：代码原样搬、不改一行逻辑；原来的文件照旧导出原来的那些（别处的 import 一个不改）；
金标准、摘要、快照、着色器的哈希一个都没有重录，世界文件的格式没变（`DOC_VERSION` 不动）。

## 怎么搬

- 顶层的声明（函数、常数、类型）：用 oxc 的语法树（rolldown 带的 `parseAst`）认出每条顶层语句和它前面的注释，按名字整条搬到新文件，
  新文件的 import 按搬过去的代码实际用到的补上；原文件去掉搬走的、补上 `import`，原来导出的名字用 `export { … } from` 照旧导出。
  搬走的东西之间只许单向引用（新文件不引用原文件），所以没有循环引用，模块求值的先后和以前一样。
  每拆一个文件都核对过：原来的每一行（去掉 import 与行首的 `export`）在拆出来的几个文件里一行不多、一行不少。
- 原来没导出、拆开后别的文件要用的，加上 `export`（只在新的小文件里；原文件不转出它们，对外的接口不变）。
- 文件开头说明整个文件的注释留在原文件；每段前面的分节注释（“---------- 河口 ----------”）跟着那一段走。
  着色器的 CPU 版本（`subcell-*.ts`）每个函数前面“与 GLSL 逐位一致”的注释原样跟着。
- 类（两处）：
  - `Renderer`：方法按职责搬进一串基类，一层继承一层（`RendererBase` → `RendererLayers` → `RendererDraw` → `RendererExport` → `Renderer`），
    方法体一字不改（`this.x` 照旧），只把成员前的 `private` 换成 `protected`（子类要用；对外照旧看不到）。全部字段和构造函数在最底下一层，
    字段的先后、初始值不变；下层的方法从不调用上层的，所以不用抽象声明。`new Renderer(canvas)`、公开的方法与字段都和以前一样。
    每帧不多分配东西，方法查找沿原型链（内联缓存照样单态）。
  - `Engine` 的 `recompute`（流水线，约 160 行）搬成 `engine-recompute.ts` 的 `recomputeDerived(e)`：`this.` 换成 `e.`，别的一字不改；
    `Engine.recompute` 只剩 `return yield* recomputeDerived(this as unknown as RecomputeState)`。`sharedDerived` 去掉了 `private`
    （引擎自己只写不读，tsc 会报“没读过”）。`passStats` 跟着搬过去，`engine.ts` 照旧导出。
- 只转发的旧文件：`src/ui/countries.ts` 是冻结的参照（`src/testing/frozen/political-r39.ts`）要用的，留着；
  其余只转出的文件（`core/human/countries.ts`、`src/ui/tools.ts`、`src/ui/river/index.ts`、`src/ui/tools/public.ts`）都是正式代码在用的入口，不是历史遗留，也留着。

- 画面：`node tools/compose-ab.mjs --against 6a1e0d9` 714 组不同 0 组；`node tools/overlay-ab.mjs --against 6a1e0d9` 直接画、一串帧（软件画、显卡画）都是 0 字节不同。
- 金标准、摘要、快照、着色器的哈希都没重录（和 6a1e0d9 比，`*.json` 一个没改），全部测试照旧通过（221 个文件、2534 个，个数没变），`npx tsc --noEmit`、`npm run build` 通过；`src/worker-imports.test.ts`、`src/ui/layering.test.ts` 照旧过。

  标出来的几项查过：
  - 噪音的宽度：同一个提交对照自己（`--head 6a1e0d9 --against 6a1e0d9`）erod 就差 +17%；island、rerollFjord 第二次跑反过来快了。
  - 地区的 latShift 两次都慢约 8%、`openCheckpoint`（不算加工）10 → 17–22 ms：分到各阶段的都是一两毫秒，像是一次垃圾回收落在了这一步里。
    拿 tools/bench.ts 的一份临时副本（每一步之前 `gc()`，检查点先复制好再计时；`NODE_OPTIONS=--expose-gc`，用 `--script` 两边跑同一份，没有提交）再对照：
    latShift 139 → 142（+2%）、openCheckpoint 2 → 2，别的加工都在 ±4% 以内，“加工都没有比旧的慢 5% 以上”。
    所以变的是回收落在哪一步（多了几十个模块，堆的样子变了），不是代码变慢。
  - 星球的 undo2 5 → 9 ms：undo1 同时 13 → 9，两步加起来一样（18 ms），也是回收换了一步。
