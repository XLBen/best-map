# 第四十六轮的设计

这一轮改了什么见 [更新记录](../../更新记录.md)；现在的文件见 [开发说明](../../开发说明.md) 与 docs/dev/ 下的各篇。

用户要的：“复活风向和洋流相关的内容”，又补了一句：“感觉有点太吃性能了，你保证一下性能开销，区域地图也有洋流，单独的地图模式”。
风向、洋流以前一直在（图层里两个默认关着的开关），只在等距圆柱里画，一块地区没有洋流，没有图例。批准的做法：

1. 地图模式“风与洋流”：褪了色的地貌上画风的流线与洋流（暖流橙、寒流蓝），图例写风的几档与冷暖，能换季节；图层里的两个开关并进来；三种投影都画。
2. 一块地区的洋流：在地区的海上跑简化的风生环流（西边界流、近岸上涌），按地区的纬度与风带；像星球上一样改海温、沿海的气候。
3. 性能：不在这个模式时一点不花；模式里按镜头、季节把流线缓存成位图，平移、转动用缓存，主线程每帧 ≤ 4 ms；地区的洋流放在气候一步里，加工各步不慢过 5%，新建不过 1.3 倍；只在陆海变了时、在粗的格上重算。做不到就退成只在空闲时算、只画不进气候（这一轮没有退，见下面量到的数）。

## 一块地区的洋流（`core/ocean-plane.ts`）

和星球的 `ocean.ts` 同一个道理、同一组系数（Sverdrup 平衡的流函数、西边界流宽 400 km、大洋宽度的饱和 8000 km、梯度换成海流的 0.08、顺风偏转约 30° 的风吹流、近岸上涌、赤道东部的冷水舌、海温沿海流输送约 1500 km 回到平衡、去掉纬度带的平均偏离），只是全在一张粗的栅格上算：

- **栅格**（`planeGrid`，按网格缓存）：像素约 3 格宽、长边最多 128 个像素（4 万格、2:1 的地区 86 × 43，一个像素约 210 km）；每个像素中心在哪一格查一次（蛇形走，`findCell` 带提示），每格双线性取值的像素与比例也记下（`k0/tx/ty`）。
- **挡海流的陆地**：面积 ≥ min(15 万 km², 地图的 1%) 的陆块（四邻连通），再填掉一像素宽的海峡。小岛不挡。
- **图边**：没有绕星球一圈。“地图外面是海”开着时，每一行到东、西海岸的距离从图边起再加 `EXT_KM` = 3000 km（图外还有一段海）；关着时图边就是海岸。所以地图只占大洋一小段时，西边界流可能落在图外。
- **流函数**：每一行按纬度的 G（风带对纬度的导数 / cos 纬度，65°–80° 渐弱），挡流的陆地上为 0；南北平滑约 1.5°，再在海上与四邻平均两遍。海流 = ψ 的旋转梯度 + 风吹流；东西走向的海岸旁 ψ 在一个像素里从 0 跳到大洋里的值，海流限在 4 以内（星球上的范围，“约 0–4”）。
- **上涌**：离挡流的陆地 300 km 以内（两遍的倒角距离），风把表层水推离海岸（Ekman 输送在风向右侧 90°，北半球）时近岸变冷，按 exp(−距离 / 120 km)；赤道 12° 以内信风让大洋东部变冷。
- **海温**：平衡温度（按纬度的辐射平衡 + 上涌）沿海流半拉格朗日地输送：每步约 150 km，取上游一步处的值（双线性，出了图取那里的平衡温度），往平衡回一点（λ = 1500 km × √(流速 / 0.5)，限在 0.5–2 倍），正反交替扫约 2500 km（4 万格的地区 13 遍）。每遍取的都是同一处，先把要更新的像素排成一列、记下取值处的像素与比例（`stencil`），每遍只做加权平均。
- **纬度带的平均偏离**：星球上按纬度的平衡温度是照地球拟合的，已经含着洋流的平均作用，所以去掉每条纬度带的平均。地区里一行只是大洋的一段：图外是海时按“这一行的海 + 补足到 2 万 km 宽的偏离为 0 的假想海”平均（只扣一部分），图外不是海时整行扣掉。限在 ±10 °C。
- **缓存**（第四十六轮续）：栅格上的那份按**像素上取到的输入**认——每个像素中心那一格的陆海、平衡温度、两季的背景风，各行的纬度，倾角、自转、图外是不是海、比例尺——留两份。改海陆没改到任何像素中心时（小岛、在一个像素里画几笔）整份照用；只改高程、冷暖、干湿、湿度时也是同一份。
- **带上陆地**（`carryAnomaly`）：海上像素的偏离（强弱 × dSST1，限 ±14 °C）顺着这一季偏转前的背景风吹上陆地，每步约 150 km，按 exp(−步长 / 1200 km) 衰减，走约 1500 km；离海约 150 km 内的陆地再与四邻平均几遍（海风）。像素上的两季偏离按洋流强弱记在栅格那份上。
  - 与星球不同：不按高度衰减（星球上 800 m 高处衰减快一倍、山会挡住），不跟着山挡风拐。第一版照星球的做法按高程与偏转后的风算，抬山、改岩性每次要重算两季（加工各步 +9–16%，见下），改成只取决于海陆。
- **回到格上**（`seaOut`，一遍）：海格按四个像素里海上的那几个双线性取海流与偏离（重新归一），陆格按四个像素取两季带上来的偏离；每格只记海流与两季的偏离 x（海格两季都是海温的增减）。温度的增减（陆上八成）、降水的倍数、写进推导的偏离在气候里按 x 现算（算式与先算好放着的逐值相同）。这一份按（栅格那份、强弱、格的陆海）认、留两份，挤掉的那份的数组拿来装新的；海面的饱和水汽量也记在它上面（按日照那一份认）。
- **进气候**（`climate.ts` 的 `computeClimate`，与星球相同的算式）：海上两季温度加偏离、陆上加两季带上来的偏离的八成（先写进 Float32 再加）；海面的饱和水汽量按改过的海温；降落的比例乘 clamp(1 + 0.06 × 偏离, 0.5, 1.25)（冷水海岸少雨、暖流上空多雨）；`currentX/Y`、`sstAnom` 写进推导（陆上是两季的平均的八成）。
- **强弱为 0 时整段跳过**，与第四十五轮逐值相同（`core/ocean-plane.test.ts` 比第四十五轮代码上同一个世界的哈希）。“调整 → 洋流强弱”一块地区也有了（以前藏着）；“这里”一块地区也写洋流。
- 偏转前的背景风记在 `PlaneTerrain.baseWinds` 上（气候的地形部分命中时也有），不再每次取陆地占比、风的缓存；两季平均按像素现取。
- 只取决于像素陆海的几样（挡流的陆地、到东西海岸的距离、到挡流陆地的距离与平滑后的样子、近海的陆地）按像素的陆海另记两份（`landParts`）：挪纬度、改轴倾角、日照时照用。
- 取输入用按栅格留着的一份草稿：命中时一个数组都不新开，没命中才复制出来进缓存。
- 洋流那一份的字段一开始就是最终的类型（饱和水汽量是空数组、空的 Float64Array，不是 null）：字段从 null 变成数组会让读这个对象的、已经编译好的函数作废，下一次改海陆时回到格上的那一遍要从头编译（量到一次 8–16 ms）。
- **预热代码**：这个进程里第一次算（新建、打开）时再空算三遍（结果扔掉，不进缓存；后两遍走“拿挤掉的那份的数组来装”的路，最后一份留作下一次新开时用的数组），海面饱和水汽量那一遍也空算三遍；之后改海陆的每一笔不冷。新建因此慢一点（允许）。
- 没有做“只重算变了的那几行”：海温输送是整片的，一处改了处处有细小的差；改成按像素的输入认缓存以后，改不到像素中心的编辑整份照用。

## 地图模式“风与洋流”## 地图模式“风与洋流”

- `MapKind` 多了 `wind`、`ViewMode` 多了 `wind`（`kindOfView('wind') = 'wind'`）；`modeDef('wind')` 是 `{ wind: true, 省界 / 国界不画, 城市照地理图的规则, 不画地标, 只标大洋、海, 没有片区名 }`。`mapModes` 没有人文时也给“地理”“风与洋流”两个按钮（以前没有人文时这一排不出现），有人文时“风与洋流”排在“地理”后面。偏好里存的 `wind` 读回来照旧。
- **底子**（`colors.ts` 的 `windBase`）：按全年的地貌着色（`baseLayers` 的 terrain、annual），再褪色：陆地去掉七成的颜色、压暗到 64%，水面往暗的蓝灰 (30, 46, 66) 拉七成；晕渲 0.75、不画露岩与岛的样子。对岸的颜色按格自己是陆是水反着褪。底子的键就是 `wind`（不随季节）。
- **画什么**：MapView 与导出的 `OverlayState.wind` / `currents` 只在这个模式里为 true（再按图例里的“风与洋流 / 只看风 / 只看洋流”，`state.flowShow`，只记在这次打开的页面里）。季节就是原来的 `season`（全年、北半球夏、北半球冬：风有两季的数据，“全年”取平均；洋流是全年平均的）。
- **图例**（`shell/MapLegend.tsx`、`legend.ts` 的 `WIND_LEGEND`）：上面两排分段按钮（画什么、季节），下面风的三档（弱 < 0.35 ≤ 中 < 0.75 ≤ 强，与画的浓淡一样）、暖流、寒流、不冷不暖的洋流，色块画成暗底上的一小段线（`LegendItem.line`）；洋流强弱为 0 时写一句。
- 图层面板里“风向”“洋流”两个开关去掉了（`OverlayKey` 少了两个，`overlays` 里也没有了）；投影的提示只说参考图只在等距圆柱里显示。
- 洋流画得比风粗（`FlowStyle.width` 1.7），不冷不暖的洋流换成青灰 (170, 225, 215)，和白色的风分得开。

## 流线：算法不变，场是参数（`src/render/wind.ts`）

- 一块地区的块（`computeTile`）以前只认风，改成和星球的一样按场（`Field`：缓存的身份、每格的向量、碰到哪格停），风的场不停、洋流碰到陆地就停。风的块的随机数、步长、档与以前相同。
- `windLines` / `currentLines` 给看得见的线（地区、星球各一套块的选法，与以前的 `drawWind` / `visibleLines` 相同，包括缺块时先画上一次画全的那一档）；洋流的颜色按线中间那一点的海温偏离，按（偏离的数组、线）记下。
- `strokeFlows` 一处描线：尾细头粗、末端小箭头、深色的边；投影时按线给出每一点画到哪里（`FlowProject`，看不见的点断开、相邻两点跳了 80 像素以上也断开），移动中可以不描边（`light`）。

## 画进叠加层（`src/render/wind-layer.ts`）

- **只在这个模式里**：`drawFlows` 一进来看 `st.wind || st.currents`，别的模式里什么都不调（不取块、不排队、不建位图），`wind-layer.test` 查过几种镜头、停稳与移动中都一块不算、一笔不画。
- **投影**：等面积、球形时，先按画面上 15 × 15 个点反算出看得见的经纬范围（看得见极点、跨了大半圈时取整圈），给一个盖住这一片、缩放等于画面中心比例（`effectiveZoom`）的等距圆柱镜头去取线（同一套块的缓存、同样的疏密档），再逐点投影。每一点只取决于自己的几个数（经度、cos / sin 经度、sin / cos 纬度、等面积的 cos t / (M·Y′(t)) 与 Y(t)，`projection.ts` 的 `pointCoefs`）按线的点数组记下，每帧只做乘加，球形的背面按 cos c < 0 断开（与 `forward` 同一个式子）。
- **停稳**：画进一张与叠加层一样大的位图，键是（网格、风与洋流的数组、陆海、开关、季节、`windEpoch`、镜头、投影的朝向、画布大小）；都没变时只 `drawImage`（鼠标移动、画笔拖动时不重描几千条线）。缺块时排进空闲队列，算好以后 `windEpoch` 变了、叠加层的静态键也变了，重画一次。
- **移动中**：四周多出 `MOTION_LAYER_MARGIN`（35%）、半分辨率的位图，镜头还在边距之内、缩放没变过 1.3 倍、投影的朝向没变时挪一挪、缩一缩贴上（等距圆柱与地区的平移缩放、投影里的缩放）；挪出边距重画一次。转球、转等面积的中央经线时朝向每帧都变，按移动中的画法（不描边）直接画。
- 导出整张地图、测试里没有画布时直接画。
