## state.ts 怎样拆而不绕成圈

界面的 130 个文件照旧从 `'./state'` 引用：测试里 `vi.mock('../state')` 换掉 `exec`、`askUser` 等（15 个测试文件），界面若直接引用 `state/edits.ts`，就换不掉了。所以 `state.ts` 按名字逐个导出（不用 `export *`，不把 `call`、`hostHooks` 这些内部的露给界面）。用测试读了改之前、改之后 `state.ts` 导出的全部值的名字和类型，逐个相同（141 个）；类型由 `tsc` 查。

`state/` 下彼此只往下引用：`world`、`notes`、`options`、`prefs`、`cost-gate`、`mesh` 在最下面，`worker-host` 在它们上面，`edits`、`exact-preview`、`open`、`autosave`、`tidy`、`export-host`、`script-trust` 在 `worker-host` 上面，`state.ts` 在最上面。原来写在一起时有四处是下面调上面：

- 换上快照（`applySnapshot`）时清掉调整面板正在预览的命令（`adjustKey = ''`），最后排一次自动保存；
- Worker 卡住、恢复时（`engineReset`、`engineRestored`）丢掉排着的预览、自动保存从头写。

这四处改成 `worker-host.ts` 的 `hostHooks` 上的四个空函数，`exact-preview.ts`、`autosave.ts` 在模块里填上；调用还在原来的那一行，先后不变。成本闸门（`noteTimings`、`noteCost`）换上快照、执行时都要记，分成最下面的 `cost-gate.ts`。`prebuildMesh` 原来读 `hostOpts.build`，改成调用的地方传进去（同一个时刻读，同一个值）；`retryScripts` 读 `host?.mirror` 改成 `currentHost()?.mirror`；`stopRunningPreview` 看排着的请求改成 `isPending('previewWorld')`。`state.ts` 里的 IndexedDB 小函数 `idb` 搬进 `src/idb.ts`，叫 `kvRequest`。三个 Worker 的地址（`new URL('../storage-worker.ts', import.meta.url)` 等）跟着改了相对路径。

## 先后不变

模块里在顶层做事的（`effect`、`registerPanels`、`pushEscape`、`registerToolSwitch`、`bindTools`、`addEventListener`）按求值的先后（深度优先、后序，与 ES 模块相同）排出来，与 `main` 比：只多了 `state/` 下的两处 `hostHooks` 登记和四种档案的 `registerArchive`，其余的先后逐个相同（第六十九轮在意的 `map/modes.ts`、`panels/lakes.tsx`、`panels/rivers.tsx`、`provincePanel.tsx` 的 effect 仍是这个先后）。页面隐藏时写检查点的 `visibilitychange` 只有这一处，在 `worker-host.ts` 求值时挂上（以前在 `state.ts` 的最后），只有它一个，先后无关。为了这一条，`MapView.tsx` 引用新文件时放在原来 `packs/panel-store`（有 `pushEscape`）那一行；`defs/tools/index.ts` 先引用原来那几个模块，各类的文件放在最后。

工具表按类分开后，`TOOL_DEFS` 的键按类排（以前 `biome`、`grow` 夹在地形的 `reroll` 与 `terrainClass` 之间，`range`、`resource` 夹在气候的 `moist` 与 `field` 之间）；每一类里的先后、类别表、`ToolId` 都不变。只按全表走的是 `watchTools`（在一个 effect 里读一遍，读的先后不影响什么时候重画）和测试。

`MapView.tsx` 里带状态的（着色的缓存、最醒目的点的记忆、先不标的地名的记忆、比例尺的抬高）做成每个地图视图一份的工厂，在原来的地方建；本来就在模块里的 `mergeProvinces`、`mergeGhosts` 的记忆照旧在模块里。参考图的样式把画布传进去，照旧在原来的时刻量它的大小。

## 没能完全一样的

- 工具表全表的键的先后（见上），每一类里的不变。
- 冻结的参照 `src/testing/frozen/political-r39.ts` 引用现在的 `ui/countries.ts`（`countryLabelLines`），文件搬了，只把这一行引用的路径改成 `ui/domain/countries`，代码一个字没动。
- 抽屉的标题由档案登记：集团的标题读世界与选中的集团，以前写在 `Sheet.tsx` 里，读的时机、读的信号相同。

## 测试与量到的数

- 全部测试（`npx vitest run --maxWorkers=2`）：206 个文件、2410 个全过（上一轮 206 个文件、2405 个；`layering.test.ts` 多了 5 个）。搬走的测试断言一条没改。
- `npx tsc --noEmit`、`npm run build` 通过（三个 Worker 的地址改了相对路径，打包出来照旧是 `storage-worker`、`mesh-worker`、`export-worker` 三个文件）。
- `node tools/overlay-ab.mjs --against main`：地区与星球、地貌与国家、看全图与一格约 8 像素，直接画与一串帧都与旧的不同 0 字节，时间相同；“选国家”（档案 + 列表）照旧画得出来，0.8–0.9 毫秒。`node tools/compose-ab.mjs --against main`：共 714 组，不同 0 组。
- `core/`、`tools/` 一行没动，`tools/bench-median.mjs` 测的是同一份 core：地区 `-- ` 加工各步都没有比旧的慢 5% 以上（最大 `island` +5%、`humidity` +4%，`erod` −7%：同一份代码的噪音；不算加工的 `openCheckpoint` 9 → 21 毫秒，读浏览器存储的抖动）。星球 `-- --globe`：只有 `undo1` 9 → 13 毫秒（+44%）超过 5%，同一次里 `undo2` 9 → 5（−44%），别的都在 ±4% 以内。`tools/bench.ts` 只引用 `core/` 与 `tools/hash.ts`，两边逐字节相同，所以这一次就是同一份代码自己比自己：几毫秒的撤销一次差几毫秒是噪音的宽度，不是变慢。
- 运行时引用：`panels/` → 工具内部 8 → 0，`shell/` → 档案 4 → 0；最大的几个文件：`state.ts` 2212 → 249，`MapView.tsx` 883 → 650，`river/tool.ts` 900 → 652，`defs/tools.ts` 752 → 247（`index.ts`），`CountryArchive.tsx` 779 → 97。
