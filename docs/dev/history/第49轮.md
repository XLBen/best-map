# 第四十九轮的设计

这一轮改了什么见 [更新记录](../../更新记录.md)；现在的文件见 [开发说明](../../开发说明.md) 与 docs/dev/ 下的各篇。

用户要的：内容之间的关系看得懂（引用能点过去、“谁用到它”、导入时依赖跟着来、不留下找不到的引用）。界面在后面几轮做（59–62），这一轮只做数据这一层：`core/content/links.ts`，一张通用的引用表。

## 表从哪里来

字段表 `FieldDesc` 已经写着引用（第四十五轮的 `ref`、`keyRef`），`linksOf(kind, item)` 照字段表走一遍这一项的数据：

| 字段 | 引用在哪里 |
| --- | --- |
| `text`、`tags`、`weighted` 带 `ref` | 值。`ref: 'tolerance'` 再拆前缀：`river:x`、`lake:x`、`field:x`，内置变量不算 |
| `map`、`title` 带 `keyRef` | 键（`default` 不算；称号的键可以是文化或文化组，先文化） |
| `list`、`json`、`tuple`、`tuples` | 往下走 |
| `tendencies` | 键是维度，值是取值；`government` 那一维的值是政体；`byEra` 的外面一层键是时代 |
| `script` | `field('x')`、`river`、`hasRiver`、`nearLake`、`hasLake`、`biome`，和 `dominantBiome() === 'x'` 这样比的字面量 |

字段表说不清的写在 `core/content/link-rules.ts` 的 `KIND_LINKS`，每种内容一条：`note`（哪些看着像引用其实不是）、`provides`（时代提供维度）、`extra`（派系的来源写了“与国教”、没写维度时隐含宗教这一维）。

**不进表的**：政体的类别（`govCategory`，是标签，没有“这一项”可以点过去）；生态的地形标签（`terrain`）；起名模板的 `{词表}`（不属于哪一项，由 `packProblems` 查）；世界里用到内容的地方（国家、城市、画的格，在 `usage.ts`，第六十二轮把两边合起来显示）。

维度不是单独的一项，表里算一个节点（`kind: 'dimension'`，`owners` 是提供它的时代）。时代改了名维度的 id 不变，所以改名不碰它。

## 依赖类别

写在字段表的 `dep` 上（`LinkClass`，省略时跟着上一层，最外层是 `hard`）：

| 类别 | 意思 | 哪些 |
| --- | --- | --- |
| `hard` | 没有它这一项不成立 | 文化的组、取值与取值组的维度、取值的组、生态的条件、脚本里写的、侵占的目标 |
| `auto` | 默认跟着带，取消也行 | 政体的“限谁用”、河湖的“只在这些生态里”、地形类别和资源的规则、文化和文化组的地名风格、地标的文化组、点的等级、格局的等级 |
| `strip` | 缺了就去掉这条引用，不把目标拖进来 | 换说法、称号的键、倾向、按时代的倾向、喜欢的地方、派系的来源、时代里的等级比例、地标名字写法的键 |

取舍：

- **侵占的目标算 `hard`**：一种生态的“侵占”就是它的作用，目标也只有几个。以前这里就跟着改名，有测试查着（第三批）。
- **地名风格算 `auto`**：缺了会退回世界默认，能用，所以不算 `hard`；但每个组只一种，带上很便宜，默认带。
- **喜欢的地方算 `strip`**：一个文化不该把生态拖进来。资源的“长在哪里”同样的写法却算 `auto`，因为去掉规则就是放开限制。所以类别写在字段上（`{ key: 'prefs', of: PREF_FIELDS, dep: 'strip' }`），不写在共用的规则字段里。

## 查询

- `linksOf(kind, item)`：这一项里的引用，不看目标在不在。`linkIds`、`itemFields` 是它的两个小用法。
- `linkTable(scope)`：一个世界（`worldScope`）或几个包（`packScope`）的表；`referencesOf`、`referrersOf`、`danglingLinks`、`resolveLink`。
- `dependencyClosure(table, seeds)`：`{ hard, auto, strip, missing }`。两条路的算 `hard`；经过 `auto` 的算 `auto`；`strip` 只列出来不走。不反着走：文化组不带它的文化（那是第六十轮的 `childrenOf`），维度不带时代（只给 `owners`，加变量见第五十四轮）。
- `renameLinks(kind, item, renames, only?)`：值、键（先后不变）、条件的前缀后面、脚本的字面量都换。没改时给回原来的对象。
- `stripLinks(kind, item, pick)`：第六十一轮用。列表里去掉一个；**规则里的条件没了时整条规则去掉**（`{ cultureGroups: ['a'], values: ['b'] }` 去掉 a 后只留 b，这条规则就放宽了）；可选的字段空了去掉字段；称号的表键都没了时换成第一种写法。脚本和必须有的字段去不掉。内置的每一项去掉全部 `auto`、`strip` 后都还通过格式检查（测试查）。

## 导入改名

以前每种内容自己写 `pack.rewrite`（生态、取值、文化）或塞在 `finalize` 里（河湖）。现在 `packs.ts` 只调 `renameLinks`，`rewrite`、`fieldsOf` 从 `PackSpec` 去掉，`finalize` 不再收改名表。

**和以前对照**（`core/content/links.test.ts` 的撞名测试，每种有引用的内容都写满引用，世界里全是同 id、不同内容的项，手写的旧规则原样拷在测试里）：

| 种类 | 没跟着改的引用 |
| --- | --- |
| 政体 | 12 |
| 文化组 | 6 |
| 文化 | 5 |
| 派系 | 3 |
| 地标 | 3 |
| 取值、时代、格局、资源 | 各 2 |
| 河、地形类别、点 | 各 1 |
| 合计 | **59 条里 40 条** |

以前这些引用**不是找不到，而是指错了**：`germanic` 改名成 `germanic-2` 以后，新加的政体还写着 `germanic`，世界里正好有原来的那个 `germanic`。所以门槛不只查“找不到的是 0”，还逐条查每条引用都指到改名后的那一项。现在 0 条。导入另一个包以前没有这条路（`addToPack` 整个换掉同 id 的项，目的地原来的内容就没了），新的 `importIntoPack` 撞名改名，目的地原来的项不动。

### 只差 `auto`、`strip` 的目标改了名不算不一样

世界里改过一个文化组，再用同一个时代包：包里的那个组撞名，加进来叫 `germanic-2`。写到它的政体、派系、地标如果都算“不一样了”，就全复制一份。一个撞名的等级能把全部政体复制一遍。所以判断“世界里已有一模一样的”时，两种样子对上一种就算：全部引用改过名的，或者只改 `hard` 类的。世界里那份接着引用世界里的目标，仍然找得到。`hard` 类改了名才算不一样：文化的组换了就是另一个文化。

代价：新加进来的 `germanic-2` 没有政体写到它。这是有意的，真要对应上要靠第六十一轮的导入窗口。

### 互相引用的项

有了键和倾向以后引用成环（文化组的倾向写政体，政体的换说法写文化组）。同一个包用第二次时谁都等着对方先认出来，都算不一样，全部多一份 `-3`。所以 `settleIds` 第一遍先猜：目的地有只差引用目标的 `id-k`（`linksBlanked` 抹掉目标后比较）就当它是，猜错了下一遍对不上，换回新的 id。迭代的上限从 6 放宽到 32（到不再变就停，实际只有几遍）。

### 坑

- **`small.origin` 要记住改名前的 id**：来源只记包的路径，改名以后按 `culture-2` 在库里找不到。多了 `small.originId`（种类 → 世界里的 id → 来源里的 id，只有改过名的才有）和命令的 `fromId`，`originSourceId(small, kind, id)` 查，第六十二轮的比较和“用库里的版本”用它。没改名的世界里没有这一项，金标准不变。可选字段，旧存档照样打得开，所以这一轮没有升 `DOC_VERSION`（第五十轮升）。
- **判断同一项要能忽略 `weight`**：`pack.sameIgnore` 与 `sameContent`。`weight` 第五十轮才加，现在没有一种写了 `sameIgnore`，`pop-kinds.ts` 的文化组那里留了注释；测试用 `updateKind` 试过这条路（只忽略文化组的，文化的 `weight` 照旧比）。
- **`packImportPlan` 的 `era`、`groups`** 以前给包里的 id，改名后对不上世界。现在给世界里的 id，路径不变。

## 别的文件

- `refs.ts`：只留底层（脚本字面量的位置、`sameItem`、`sameContent`、模板的词表）。`fieldRefs`、`biomeRivers`、`biomeLakes`、`rewriteRiverRefs` 去掉，`scriptRefs` 多认 `biome()` 和比较的字面量。
- `unused.ts`：自定义场有没有内容写到，以前对内容的 JSON 搜 `field:x`（说明里写到也算），现在走表。
- `usage.ts`：文化组有几个文化、取值组有几个取值走表；别的都是地图上的用处，照旧。地名风格那一段仍然按“文化没写时用组的”算，这是实际生效的风格，不是直接引用。
- `missing.ts`：没动。它说的是“一种内容一项都没有时跳过哪一步”，和表说的“这一条引用找不到”不是一件事。
- `kinds.ts` 的问题检查（`fieldProblems`、河湖）用 `linkIds`，消息不变。去掉 `rewriteBiome`、`waterFinalize` 后反而短了（676 → 647 行）。
- `packs.ts` 的包的树搬到 `content/pack-tree.ts`（原样，照旧导出）：`links.ts` 在 Worker 这边，不能引用带内置地名风格的 `packs.ts`。`worker-imports.test` 加了一句确认 `links.ts` 在 Worker 的引用图里。
- 资源规则的 `classes` 以前没写 `ref`，补上后编辑器里也变成带搜索的下拉。
- **顺手修的**：编辑器“条件”下拉里选自定义场时写的是 `x`，应该是 `field:x`，以前选了之后那一条条件永远是 0（`fieldGetter` 的默认分支）。

## 覆盖

- `linkProblems()`：每种内容都要在 `KIND_LINKS` 里（没有引用也要写一句），字段表里的 `ref`、`keyRef` 要认得，字段类型要有走法（`FIELD_WALKERS` 是 `Record<FieldType, …>`，少一种 tsc 不过），`ref` 写在走不到的字段类型上也报。测试登记一种假的内容确认报得出来。
- **内置数据**：整个资源库一起看，节点 1017 个（含维度），引用 8308 条：`hard` 690、`auto` 280、`strip` 7338，**找不到的 0 条**。每个大包单独看，找不到的 `hard` 只有奇幻的 `swarm_zone` 侵占“通用 ▸ 自然”的 6 种生态（第五十一轮各库完整以后就没有了），测试写明了这 6 条。
- **有没有写漏**：内置数据里每个字（值和键）碰巧等于某一项的 id、又不在表里的，都要写明为什么不算（`NOT_REFS`，28 处：`natural` 碰巧是一个取值组的 id、`empire` 既是等级又是政体类别……）。新的引用写漏了这里会报。

## 速度

这张表不在编辑的路径上：`renameLinks` 在没有真的改名时直接返回，`linksOf` 只在导入、整理、移出内容时走。`core/commands.ts` 只多了读 `fromId` 一处，`tidyOrigins` 只在有 `originId` 时多走一步。

量到的（负载 3 上下，`bench-median 5 --against 760668f --`）：第一次标出 tempBrush +7%、island +7%、warmRelief +5%；同一提交对照自己标出 erod、lake（coast +22%，9 ms 上的 2 ms），所以这个宽度里的不算数；再对照一次这三步是 -11%、-1%、-2%，改标 rerollFjord（第一次 +0%）。没有一步两次都慢。带库的世界（`-- --library`，三次）：`libEdit` 1.16 → 1.15 ms、`libUndo` 2.53 → 2.55 ms、`libContent` 1.23 → 1.22 ms，加一个时代库 51 → 53 ms。星球没有量（只碰到命令的一处，与地图大小无关）。
