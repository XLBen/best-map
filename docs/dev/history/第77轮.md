# 第七十七轮的设计

这一轮改了什么见 [更新记录](../../更新记录.md)。用户定的：**生成的参数只在资源包（资源库的内容）里**，
生成人文、国家的面板上不再有每个世界自己调的滑块。用同样的规则生成的世界逐值不变。

## 去掉了什么

| 以前（面板上、命令里） | 现在（资源库里） |
| --- | --- |
| “分裂 ↔ 统一” `fragmentation`（0–1，正中 0.5）：平均的国家面积 = 时代的 `countryKm2` × 8^(1−2f) | 时代的“国家大小” `countryKm2`。f = 0.5 时因子正好是 1，`averageCountryKm2(era)` 就是 `era.countryKm2 ?? COUNTRY_KM2` |
| 格局下拉 `layout`（按时代 / 混合 / 诸侯林立 / 大一统 / 列强并立）：盖掉时代的 `tiers` | 时代的“国家等级的比例” `tiers`。格局这种内容（`countryLayout`）整个去掉了 |
| 总人口滑块 `totalPop` | 时代的人口密度 `popDensity` × 陆地面积。生成后改总人口（`set_pop_total`，“文化 ⋯”里的滑块）照旧 |
| 每个文化组的“占”（权重滑块），命令里 `groups: [{id, weight}]` | 文化组的“比重” `cultureGroup.weight`（省略为 1；0 照旧是不参与）。命令里 `groups` 只写 id |

- 命令：`generate_human`、`regenerate_human` 去掉 `totalPop`，`groups` 是 id 的数组；`countries` 只剩 `seed`；`generate_countries`、`regenerate_countries` 去掉 `fragmentation`、`layout` 和没人用的 `packs`、`groups`。四条命令改成严格的格式（`.strict()`）：旧的写法报错，不会悄悄丢掉字段换了结果。
- 世界：`small.human.countryRules` 只有 `seed`；`small.human.groups` 只记 id（重新生成时按那时世界里的比重）；文化组的 `cultures`（只用组里的几个文化，只有测试用过）去掉了。世界文件的版本 16 → 17。
- 代码里跟着去掉的：`sizeFactor`、`estimateCountryCount`（只给滑块估“约几个国家”）、`eraUsesModule`（只给滑块的说明）、`choicePattern`、`fragPos / fragAt / fragText / fragTitle / estimateCountries`、`layoutOf / layoutChoices / LayoutPick / FragSlider`、`groupShares / setGroupWeight / WEIGHT_RANGE / roundWeight`、`estimateLandKm2`、`HumanChoices` 的 `defaultPop`、`estimate`；`core/human/tiers.ts` 的 `countryLayoutSchema / worldLayouts / layoutById / ERA_LAYOUT*`，`tierWeights` 只收时代；登记表、引用表（`link-rules.ts`）、融入（`arrange.ts` 的 countryLayout → countryTier）、首页的卡片、分段、图标、`regen.ts`、`pick-other.ts` 里的格局。测试的 `humanExec` 不再认 `era` 的写法（写 `packs: [[era]]`）。

## 格局这种内容为什么整个去掉

格局只做一件事：生成国家时盖掉时代的 `tiers`。去掉每个世界的选择以后，世界里、库里都没有东西指向它（时代写的就是各等级的比例本身，不引用格局），
留着只会在资源库里多一张改了也不起作用的卡片。想要“大一统”那样的比例，把它写进时代的“国家等级的比例”（时代页面“国家”一段）——生效的比例逐值相同
（`tierWeights` 两边都是 `tiers.map((t) => w[t.id] ?? 0)`，测试里 `OLD_LAYOUTS` 写进时代后与以前选格局的结果逐值相同）。
内置的四种格局从 `core/packs/countries/tiers.json` 删掉；“国家等级”小包只剩五级。

## 各组占多少：放在文化组的比重上

以前界面按库里小包的 `weight`（时代 JSON 的 `pack.cultures`：中世纪汉 4、黎凡特 3、日耳曼 3……）发命令，世界里的组本身没写比重。
核心在计算 Worker 里，读不到资源库，所以比重要在世界的内容里。可选的有两处：时代上加一个“各文化组的比例”，或文化组自己的“比重”。选了后者：

- 比重这一项早就有（第五十轮，0 是不参与），同一组在不同的库里只差比重时本来就算同一项（`sameIgnore: ['weight']`），导入、和库的差异、“内置的原样”都不用改；
- 时代上加一个引用文化组的表，导入时代时会把这些组拉成依赖、换库时要剥掉写不到的组，牵动的地方多。

做法：`core/packs/builtin-tree.ts` 的 `groupPack` 把这个时代的权重写在组上（和比重 0 的 `sparePack` 一样是浅拷贝；权重是 1 时不写）。
新世界从库里带进来的组就带着这个时代的比重，生成时 `generateHuman` 用 `group.weight ?? 1`——与以前界面按小包发的权重是同一个数。
换库（`core/packs/switch.ts`）：两个库都有、世界里没改过的项以前按 `sameContent` 比（不看比重），现在逐字比，比重不同的组换成新库的那一项；
以前界面发的是新库小包的权重，结果相同。“本世界加的”组、勾上的比重 0 的组以前界面给 1，现在组上没写比重，也是 1。
资源库面板顶上的“重新生成”（`regen.ts`）以前只看比重是不是 0，现在比重变了也算要重新生成。
已知的不同：比重只差的改动在“存进我的库”时照旧不算改过（`sameIgnore`），和第五十轮的比重 0 一样。

## 面板

“文化 ⋯ → 生成”“换库、文化组…”、新建向导的“人文”、“国家 ⋯”的生成与重新生成：只选库、文化组、生不生成国家与城市、锁定的不动。
下面一句“国家大小、人口、各组占多少在资源库里改”（`copy.ts` 的 `GEN_RULES_NOTE`），旁边“时代”按钮打开时代的页面（`shell/EraRulesNote.tsx`、`packs/open-era.ts`）：
世界里有这个库的时代时开本世界的那一份（改了重新生成就用上），换库时开库里的；生成人文时展开“国家”一段，“换库、文化组…”里展开“人口”一段。
新建向导里只有这一句、没有按钮（资源库面板在向导下面）。

## 核对：结果逐值不变

三个临时测试（不提交）在第七十六轮的代码（a704f10，另检出的 git worktree）和这一轮上各跑一遍，逐项比较。

**1. 同样的世界，旧的命令与新的写法**（`proof/r77-proof.test.ts`，65 个世界）。导出所有类型数组（网格、原因、自定义场、全部推导数组连同人文的、修正场）的摘要、地物，和整个小数据（JSON，类型数组转成数组）。

- 界面的流程（两边调同一份 `src/ui/domain/human.ts` 的函数，旧的发带权重的命令，新的只发 id）：六个库各新建人文（国家、城市）、“重新生成”（连国家）、生成国家、重新生成国家（不留锁定的）；中世纪 → 古典 → 奇幻 → 现代换库；整个星球（5000 格）上奇幻的生成与重新生成。
- 以前的参数换成库里的规则：分裂 1、0.2、0（旧的写 `fragmentation`，新的把时代的 `countryKm2` 写成 × 8^(1−2f)）、格局大一统（旧的写 `layout`，新的把它的比例写进时代的 `tiers`）、自己定的权重（旧的命令写 1 / 5 / 0.3，新的写进组的比重），各再“重新生成人文”“重新生成国家”；星球上分裂 0.2。
- `r29` 的七种设置（`era-packs.test` 的 SCENES：古典到科幻，权重和库里的不同，带国家、城市），各再“重新生成人文”和 `regenerate_countries seed 9`。

结果：**类型数组不同 0 项**。小数据不同的只有这几类（1194 处）：

| 路径 | 处数 | 是什么 |
| --- | --- | --- |
| `content.countryLayout`、`origin.countryLayout` | 各 65 | 去掉的格局 |
| `content.cultureGroup.*.weight` | 436 | 组上的比重（旧的世界里没写）；另一个脚本核对过全部 537 个组：新的比重（省略为 1）都等于旧的 `human.groups` 里命令写的权重 |
| `human.groups.#` | 537 | `{id, weight}` → id |
| `human.countryRules.fragmentation` / `.layout` | 63 / 3 | 去掉的字段 |
| `content.era.*.countryKm2`、`content.era.*.tiers.*` | 10、15 | 只在“以前的参数”那几个世界：换成库里的规则写进时代 |

**2. 金标准那组操作**（`proof/r77-golden.test.ts`）：旧的提交上把新世界内容里的格局去掉，`extendedHashes('region' / 'planet')` 与 `referenceHashes` 和这一轮的逐项相同（`cmp` 两份输出一字不差）。

**3. 重录的世界摘要**：在旧的提交上只改“存下来的样子”、算法不动（去掉内置的格局；版本 17；内置的组带这个时代的比重；`human.groups` 只记 id、`countryRules` 只记种子，读的地方按世界里组的比重换回去），
把这一轮重录的 `golden-full.json`、`r31-digests.json`、`class-only-digests.json`、`biome-legacy-digests.json`、`libraries-digests.json` 和 `solver-identity`、`ocean-plane`、`raster-identity` 的新值拷过去，旧的测试文件全部通过（69 个）。
`r29-digests.json` 的 13 项只有 `human` 一键变了（人口、群体、国家、城市、地名……13 个键一个没变），由第 1 项的 r29 设置核对。
