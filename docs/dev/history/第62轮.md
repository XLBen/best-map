# 第六十二轮的设计

这一轮改了什么见 [更新记录](../../更新记录.md)；现在的文件见 [开发说明](../../开发说明.md) 与 docs/dev/ 下的各篇。

用户定的：世界里的内容是独立的一份，改库不影响世界。和来源不同的项带标记，可以“用库里的版本”或“存回我的库”。世界保留全部内容，生成后没用到的变淡，有“清理没用到的”。编辑页底部“谁用到它”。要重新生成才影响地图时顶部出现“重新生成”。不做关系图，不做缺引用标红。

## 和来源的差异（`core/packs/source-diff.ts`）

`sourceDiff(kind, id, item, world, libs)` 四种结果：

| 结果 | 什么时候 | 界面 |
| --- | --- | --- |
| `none` | 没有来源（自己做的）、来源的库不在了、库里已经没有这一项 | 不标，不报错 |
| `same` | 一样 | 不标 |
| `trimmed` | 只差导入时去掉的引用 | 不标，页面上灰字写“这个世界没有的没带：X” |
| `changed` | 不一样：世界改过，或者库后来改了 | 列表写“和库不同”，页面写哪几个字段不同，能用库里的版本、存回 |

**比什么**：世界里的项和“来源里那一项加进这个世界时该有的样子”（`finalItem`：自然生成关掉、撞过名的 id 和引用跟着换）。所以比较是往前算来源，不是把世界的项往回算：`withId` 改名时名字也带编号，往回算不出来。`small.originId` 反过来就是改名表。来源的库是 `small.origin` 的第一段，不看内置表。

**不比的**：`pack.sameIgnore`（文化组的 `weight`）。

**导入时去掉的引用**（第 61 轮的坑）：替用户定的讲法是单独一种，不算改过。规则和导入一样：来源里写到、这个世界找不到目标、能去掉的引用全部去掉之后和世界一样，就是 `trimmed`。代价：导入之后目标又来了（后来导入了那个变量），这一项就算“和库不同”。这时用库里的版本确实能多带上东西，讲得通。

`same` 也包括“来源和世界都写着找不到的目标”：从中世纪库建的世界，文化写着别的时代的倾向，两边都有，原样相同。

**时代**：不比“有哪些变量”。世界的变量只能走加变量（第五十四轮），直接换变量表人口就对不上了（第 60 轮写过）。世界加的（`added`）、库后来加的、删的都不算不同；两边都有的变量才比，不看 `added`。

**按字记**：`contentKey`（closure.ts 导出）按对象记比较用的字，包和世界里的项不能就地改（没有改）。第一次打开 404 个文化约 1 ms 比较（这张表每改一次内容，主线程收到的是新对象，就重算一次）。

## 用库里的版本、存回我的库

都放在 `itemActions`（`useSource`、`saveBack`），只有 `changed` 时才有。第 45 轮的“恢复内置”不再出现在新面板上（它和内置表比；`restoreCommand` 留给旧的 `RepoDetail`，第 63 轮一起删）。

**用库里的版本**（`usedSourceItem`，一步，世界的撤销）：
- 比重留世界的。
- 时代留世界的变量表，两边都有的变量按库里的写法，`added` 留着。
- 世界没有的目标：只有 `strip` 类时原样（新世界也这样，本来就允许缺），有 `hard`、`auto` 类时全部去掉（不留下找不到的）。只有这两种样子，换完之后才认得出是 `same` 或 `trimmed`：去一半的话就永远是 `changed` 了。
- 生态走 `update_species`，按字段写，和页面上改字段同一条。

**存回我的库**（`savedBackItem`）：
- id、引用换回库里的。改名时带的编号不写回去。
- 比重留库的；加进世界时才关掉的“自然生成”不写回去。
- 时代的变量表留库的：世界加的变量的取值不在库里，写回去新世界就坏了。两边都有的变量按世界的写法。
- 写到的、这个库里没有的：照样存，提示里写“这个库里没有：X”。
- 来源是我的库：`libEdits.setItem`，这个库的撤销。顶上的提示带“撤销”：看本世界时 ⌘Z 撤销的是世界，所以要有这个按钮。
- 来源是内置的、导入的库：先问“复制成我的库并存回”。复制一份（不换面板上看的来源），写进去，世界里这一项的来源换到副本上（一条只记来源的命令，世界的撤销）。同一个来源只复制一次（这次打开页面期间），下一项问“存进副本”。别的项的来源不动：还是内置的，还是一样，不标。

## 变淡和清理共用一个函数（`core/content/cleanable.ts`）

`cleanableContent(world)`：判断是 `unusedPeople`（第五十轮的规则，这一轮从 `unusedContent` 里分出来，先后不变），这里只定范围：

- 种类：时代、取值、取值组、文化、文化组、地名风格；有国家时还有政体、派系。
- **还没生成的不算**：没有人文时什么都不算（导入了还没生成的不该变淡），没有国家时政体、派系不算。
- **生态、河、湖不算**（第 57 轮的坑）：按种类排除，不是默认不勾。一格都没有的现实水系（这个世界没有火山口湖）清掉之后改一笔出现了符合条件的河，也不会有这种类型了；这和生态的“改了气候不会自己长出来”是同一个问题。要拿掉到那一项的页面上“移出本世界”。
- **画风不算**：不是生成用到的，是“图层”里的选项。第五十轮的整理算它：清掉之后选项少了一个，讲不通。自定义场跟着生态，也不算。

列表上每一行问 `cleanableSet`（一个世界算一遍）。面板上的“清理”走 `planTidy(cleanableContent(w))`，所以看到淡的就是清理会清的；移出后地图会变的（`kept`）留着并写明，测试的几种世界里一项都没有。

**“⋯”里的“整理本世界”合并成“清理没用到的”**，首页和有变淡的项的列表上也有这个按钮，数都是全世界的。问话里一种一行（种类、个数、前 12 个名字）。第五十轮以来的 `unusedContent`（生态、河湖都算）还在：`tidy_content` 没写 `items` 的旧命令、旧面板一个包的“移出没用到的”用它，结果不变。

**快**：`unusedPeople` 每一项都要扫一遍人口。4 万格、404 个文化，`unusedContent` 约 630 ms。列表每次渲染都要用，所以 `compactPeople` 先扫一遍人口，压成一个文化一条、一个取值一条，判断的代码一行没换（测试拿没压的 `unusedContent` 逐项对照）。`groupUsage` 每组走一遍全部文化的引用表，改成按这一份文化记一张表（`culturesOf`）。

## 明确删除不再带走内容（`dropBroughtContent` 去掉）

第五十轮留的问题：`remove_human`、`remove_countries` 带走内容，“要不要也改成留着，等用户定”；这一轮的简报说讲不通就改。

**讲不通的地方**：
- 问话写“全部国家都删除，人口不变”，实际所有政体、派系都从世界里没了，包括用户导入的（奇幻世界导入社会主义共和国，删除国家，社会主义就不见了）和改过的。
- 再生成国家时 `withPackImports` 只从世界用的库加回来，所以导入的回不来，改过的变回库里的样子。改过的那份在“来自《世界》”这个包里，用户不会知道。
- 和“世界保留全部内容”“世界里的内容是独立的一份”冲突。

**改成**：两条命令只去掉人口、国家，内容都留着。`core/human/prune.ts` 删了。

**换来的**：
- 删除人文之后再生成，人口、国家和第一次逐值相同（测试）。城市、道路、地标不同，这不是内容造成的：内容一样（`set_content` 一条都没变）。没有查下去，留作坑。
- 想换一个库：`generateCommand` 走 `switchPlanOf`（第五十二轮的换库），旧库带来的移出，和有人文时一样。
- 没有人文时清理不算这些内容（上面写了）：删除人文之后想清干净，要到那一项的页面上移出，或者再生成一次之后清理。替用户定的，这样新世界导入的内容不会被清掉。

**变了的**：旧的世界文件重放时，这两条命令之后内容多了；之后再生成时命令里写的 `set_content`（当时是新加）照样执行，内容相同就不变。旧存档不必兼容，`DOC_VERSION` 没加。金标准一个都没动，它们没有走这两条命令。计算 Worker 因此变了（见“不能变慢”）。

## 谁用到它（`src/ui/packs/page-used-by.ts`）

`usedByOf`：

- **引用它的内容**：`linkTable` + `referrersOf`（core/content/links.ts），没有另写。按种类一组，能点过去，每组先写 12 个。
- **在**：第 60 轮的 `partOf`（“在 X、Y”）合进来，写在这一段，不再写在页面最上面。上级本来就引用它（政体写着派系）时算在引用里，不写两遍；上级是它引用的（文化的组）时写“在”。
- **地图**：放在 `small.content` 的种类用 `usageOf`（引擎查的同一份）；生态、河、湖、地形类别、资源是按规则长的，`usage.ts` 只数手动指定的，这里看推导数格；国家等级数国家。只有本世界有。

默认收着，标题旁写一句（“政体 19 · 19 个政体列着它、40 个国家有它”）。就地展开的项也有。表按世界、库记着。

## 重新生成的按钮（`src/ui/packs/regen.ts`、`src/regen-track.ts`）

`regenNote` 那一句话去掉，面板顶上一条（看本世界时，在哪一页都有）：“改了 2 项。重算国家、人口、城市，锁定的不动”和按钮“重新生成国家”。

**怎么知道确实需要**：和上一次生成时的内容比。世界不记这个（`small` 在金标准里），所以 `RegenTrack` 在主线程跟着撤销的先后记：历史里的每个位置对应三份内容的引用（人文、国家、城市各自上一次生成时的 `small.content`）。撤销、重做回到那个位置的那一份：撤销掉改动按钮就没了，撤销掉重新生成按钮就回来了。`engine.stateId` 撤销时也换新的，不能当键，所以用“做过的步数”。内容对象不改动，很多步共用一份，不占地方。

比的是世界，不是这一页，所以就地展开改的项、档案里改的都算。

| 算 | 不算 |
| --- | --- |
| 新加的、改过的 | 移出的（在用的移不出，没用到的移出之后地图不变；清理不该让按钮出现） |
| 文化组比重 0 ↔ 不是 0 | 比重别的数（和没写一样） |
| 文化、时代、取值 | 说明、颜色（地图按现在的颜色画） |
| 用着的那个时代 | 别的时代 |
| 这个时代的取值 | 后加的变量和它的取值（只算新变量，文化、国家都不变，第五十四轮） |
| 参与生成的组和文化 | 比重 0、没选的组和它的文化（依赖带来的） |
| 有人文才算文化，有国家才算政体、派系、等级，有城市才算城市等级、地标、点 | |

颜色：国家的颜色、旗子是生成时从文化取的，不跟着变。为这个重算一遍地图不值得，所以不算（测试：改了之后重新生成，只差国家的颜色、旗子）。

| 改了 | 按钮 | 命令 |
| --- | --- | --- |
| 文化、时代、取值 | 重新生成人文 | `regenerateCommand`，和“文化 ⋯”的同一条（国家的领土不动） |
| 政体、派系、等级、格局 | 重新生成国家 | `withPackImports(regenerate_countries)`，锁定的不动 |
| 两样都改了 | 重新生成人文和国家 | `regenerate_human` 带 `countries`，一步 |
| 只有城市等级、地标、点 | 重新生成城市 | `regenerate_settlements` |

人文、国家重新生成时城市跟着重算，所以一个按钮就够。不问确认：按钮写着重算什么，能撤销。

**做不到的**：刷新页面、打开世界文件之后不知道以前改过什么，从那时候的内容算起，按钮不出现。要知道的话得写进世界，`small` 在金标准里；或者打开时走一遍命令历史，这一轮没有做。

## 替用户定的

- 去掉了引用的项是单独一种（`trimmed`），不标，页面上写一句。
- 列表上的字是“和库不同”，不是“改过”：库后来改了也算，世界没动。
- 时代的变量增减不算不同，用库里的版本不动变量表。
- 清理按种类排除生态、河、湖、画风，不是列出来默认不勾。
- 没有人文时不变淡、不清；没有国家时政体、派系不变淡、不清。
- 明确删除不再带走内容（上面写了）。
- 存回内置的库：复制一份，只有这一项的来源换到副本上。
- 存回时写到的、库里没有的照样存，提示里写。
- 只改颜色不出现重新生成。
- “谁用到它”默认收着。

## 坑

- **第 63 轮**：`restoreCommand`、`builtinOriginal` 和 `status.modified` 只有旧面板和库里那一行“本世界改过”在用，删 `Repo*` 时看要不要留；`tidyWorld` 旧面板也调。旧面板的 `removeUnused`（`packRemoveRefs`）算上生态、河湖，删旧面板时一起没了。
- **第 63 轮**：`unusedContent` 只剩 `tidy_content` 没写 `items` 的路和测试在用。
- **看本世界时 ⌘Z 撤销的是世界**：存回我的库之后按 ⌘Z 不会撤销这一步，要点顶上的“撤销”，或者切到那个库。
- **按钮只知道这次打开页面以后的事**（上面写了）。
- **删除人文之后再生成，城市、道路、地标的摘要和第一次不同**：内容相同，原因没查（第五十轮的 `keep-content` 没走过这条路）。
- **`faction` 的“地图”一行**写“19 个政体列着它、40 个国家有它”：来自 `factionUsage`，前半句和引用重复，没有改（引擎的报错也用这一句）。
