# 第九十四轮的设计：自动保存不再丢

这一轮改了什么见 [更新记录](../../更新记录.md)。前提：用户是不懂系统的新手，作品只存在浏览器里。原则：旧存档不必兼容，但**绝不静默丢**——留着、明说、能导出。

生成的结果逐值不变：金标准、摘要、着色器的哈希、界面的快照、`raster-identity` 一个都没有重录。世界文件的格式没变（`DOC_VERSION` 还是 22）；IndexedDB 的库还是第 7 版（没有加表：留下来的都放进第九十一轮的 `backups`）。自动保存的头里多了两项（`writer`、`gen`），旧的头没有这两项时当“别人写的”，整份重写一次。

## 1. 两个页面把自动保存写坏（F2）

### 复现

第九十三轮的 `state/autosave.ts`：每个页面各自记 `savedIds`（写过哪几步）、`savedCount`（表里有几条，只在第一次写时读一次），只把“和 `savedIds` 不同的那一段命令”按下标写进 `autosave` 表，头（kv 的 `autosave`）整个换成自己的。没有任何东西认“表里现在是不是我的”。

把那一段“写什么”原样搬到假的存储上（`src/autosave-io.test.ts` 的 `OldPage`，引擎用一个只有 `docTail` 的替身，`docTail` 是 `core/engine.ts` 那四行原样），两页交替写，三种都复现了：

- **两个不同的世界，后开的那个步数多**（甲 5 步、乙 8 步）：甲写、乙写、甲再画一笔写——读出来 6 条：`乙乙乙乙乙甲`，头是甲的（种子 1）。条数对得上，读的时候看不出来，**照样会被打开**：甲的设置重放乙的命令。
- **后开的那个步数少**（甲 8 步、乙 3 步）：乙写的时候删掉了第 3–7 条，甲再写第 8 条——头写着 9 条，读出来 4 条。条数对不上，以前**当作没有**，启动进向导，新建以后两边都没了。
- **同一个世界在两个页面里各自接着做**（都从 4 步的自动保存打开；甲画两笔、乙画一笔、甲再画一笔）：读出来 `原原原原乙甲甲`——甲的世界是 `原原原原甲甲甲`，乙的是 `原原原原乙`，存着的谁的都不是。

所以不是推断，是会发生的。（在真的浏览器里没有另跑旧代码复现：冒烟只跑现在的代码。）

### 修法

**写什么**（`src/autosave-io.ts` 的 `AutosaveWriter`，规则只经 `AutosaveIo` 碰存储）：

- 头里记 `writer`（这一次打开页面的随机 id）和 `gen`（每写一次加一）。
- 每次写都在**同一个事务**里先读头（`AutosaveIo.write(plan)`：读头 → `plan(头)` → 照着写）：
  - 头是自己上一次写的那一代（`writer` 是我、`gen` 是我记着的）：中间没有别人写过，照旧按下标只写变了的（`inc`）；
  - 不是，而我有写的权利：**整份重写**（清空表、从第 0 条起写、头换成我的）；手上只有尾巴时回 `again`，调用方向 Worker 重新要整份；
  - 不是，我也没有写的权利：不写（`other`）。
- **整份重写会盖掉别人写的那一份**。盖之前（`vet`）：它就是我打开的那一份（`opened`：`readAutosave` 记下的头的记号，不用再读一遍）——直接盖；不是的话读出来比一下，是我的世界的开头（`continues`：设置相同、它的每一条命令和我的同一条逐字相同）——盖掉什么都不丢，直接盖；都不是——**先原样挪进“留着的旧世界”**（`backups`，一个事务里放进去、位置空出来），写上为什么（`BackupWhy`），再写我的。挪不进去（满了）就不写，原来的还在。
- 测试：三页随机交替画、撤销、存、接过去 400 步，每一步之后存着的都是某一页完整的世界（命令都是同一页的、头的种子是那一页的、条数对得上）。

**谁写**（`src/autosave-lock.ts` 的 `SaveRole`）：

- `navigator.locks` 的一把锁 `map2-autosave`。打开页面时 `ifAvailable` 试着拿：拿到的写；拿不到的不写，`saveRole` 是 `other`，顶上一直有一条“这个世界已在另一个页面打开，这个页面里的改动不会自动保存”（`shell/SaveBanner.tsx`），带“在这里接着做”“导出文件”。
- “在这里接着做”（`takeOverSaving`）：`steal` 把锁抢过来，在 `BroadcastChannel`（同名）上说一声 `taken`；原来写的那一页（锁被抢走的回调、或者收到这句话，哪个先到都行）变成不写的那一方，显示同一条。接过来的页面 `claim()`：忘掉下标、从头写整份——那一页存的和这里不一样时先留着（上面的 `vet`，原因是 `other-page`）。
- **写的那一页关了**：不写的页面排着队，这时拿到锁。但只在“存着的那一份是我的世界的开头”时才不问就接着写（`canPromote`）；不是（那一页后来又做过）就**放开锁、照旧不写**，等用户点“在这里接着做”。
  为什么不直接接：新手最容易做的是不小心多开了一个页面、回原来的页面做了一小时、把原来的关了。后开的那个页面还停在一小时前，它一接着写，就把那一小时无声地盖了。反过来，多开以后关掉旧的、在新的里接着做，这一条让它不用点任何东西就接着存。
- **没有 `navigator.locks` 的环境**（旧浏览器、测试）：`lock` 为 null，都当自己能写，靠头里的核对：后开的页面第一次写时头是别人的——整份重写（接过去，先 `vet`）；先开的那一页下一次写时发现头不是自己的、而自己写过——`lost`：不写，变成不写的那一方，显示那一条。有锁时这一层核对也在（双保险）。频道有就照样用（让出得更快）。
- 让出的时候（`AutosaveWriter.yield`）连“上一次写的那一代”也忘掉：以后再轮到这个页面写时，第一次一定在事务里读头、整份重写；关页面那一下的同步写（第 3 节）在这之前不做。
- 留着的旧世界启动时那一次挪（第九十一轮的 `keepStaleOnce`）只由写的那一方做（`keepGate`）：不写的页面不动别的页面的自动保存。

**读**：头里写的条数和读出来的对不上、或者有哪一条不是命令——不再当没有。`backups.ts` 判断“打不开”的地方加了这一种（`staleWhy` → `{age: 'current', why: 'damaged'}`），启动时和旧版本的一样原样挪进 `backups`，界面说“上次的世界没存完整，打不开。存下的部分还留着”，能导出（就是读出来的那几条），列表里有“打开”（少的是末尾几步时打得开，是更早的样子）。

### “我的地图”“我的库”在两个页面里

读代码看的，没有改：

- **我的地图**：`maps` 和 `mapDocs` 总在同一个事务里整份写，两个页面各存各的只会是“后写的那一份”，不会写混；别的页面里删掉了的那一张，这里存的时候发现它不在就不再连着（原来就有）。现在不写的那一页不自动保存，也就不自动更新连着的那一张。**没修的**：不写的那一页按 ⌘S 存进连着的那一张以后，写的那一页之后的自动保存会把它盖成自己的世界（没有提示）。要修得让每一次写都认“这一张上次是不是我写的”，牵到 `ui/maps/store.ts` 的五六处，这一轮没动。
- **我的库**：整个库是一条记录、带版本 `rev`，写是整条换，不会写坏。但两个页面同时改同一个库时后写的盖掉先写的；读存储时发现存着的版本更新，这一页没写的改动、撤销栈、日志一起作废（`adopt`，第五十九轮的规矩）。日志（localStorage 的 `map2.libWal.<键>`）两个页面共用一个键，也是后写的算。**没修**：要么合并、要么也用锁，都不是小改。

## 2. 打不开的存档先问（F3）

以前：`App.tsx` 启动时 `resumeLast()` 失败就 `wizardOpen = true`，原因在顶上闪 6 秒；用户在向导里一新建，1.5 秒后新世界的自动保存把原来那份盖了。

现在（`state/open.ts`）：

- `open()` 给出三种结果（`OpenResult`）：打开了、取消了、没能打开（原因）。`loadDoc` / `newWorld` 照旧回布尔。
- `resumeLast()` 没能打开时停在一个问话上（现有的 `askUser`；问话框只多了一种原样的一行 `Ask.note`——整句写出来、能选中复制）：“上次的世界没能打开 / 它还存在这个浏览器里，没有丢……/ 原因：……”，按钮“再试一次”（主要的）“用安全模式打开”（世界里有脚本、这次不是安全模式时）“导出文件”（下载那份世界文件，一字不差，然后接着问）“新建”。关掉问话等于“新建”：进向导，向导上面“继续上次的世界”还在（再点一次就是再试）。
- **那一份自动保存原样留在原处**，没有先复制一份：没有世界就没有自动保存，没人会盖它。用户新建以后，新世界**第一次自动保存之前**它被原样挪进 `backups`（第 1 节的 `vet`：头不是我打开的那一份、也不是我世界的开头），原因写 `failed` 和那一行出错的话；顶上一条“上次的世界没能打开。它还留着”。
  为什么不在失败的那一刻就挪走：多数失败是一时的（Worker 没开起来），挪走以后下次启动就不会自己接着打开了；复制一份又要占两份的地方。留在原处、盖之前才挪，两头都顾到；再试成功时什么都不用收拾。
- **用户自己取消**（不信任脚本时点了取消）不算打不开：不问那一句，照旧进向导。那一份同样在被新世界盖掉之前挪进 `backups`（原因 `cancelled`，“上次的世界没有打开。它还留着”）。选这个做法是因为它不多问一句：新手刚点了一次取消，再弹一个“要不要留着”只会更慌；留着、事后说一声、能导出就够了。
- 向导里“继续上次的世界”走的是同一个 `resumeLast`。

冒烟里真的走了一遍：把存着的最后一步改成引擎不认识的命令 → 刷新 → 出来这个问话（原因“第 7 条命令失败：命令参数无效……”）→ 新建 → 在向导里建一个新世界 → `backups` 里有那一份（`failed`、7 步、带原因），顶上有那一条。

## 3. 关页面不丢最后几秒（F5）

以前：改动 1.5 秒后才写；页面隐藏时只让 Worker 写检查点。关页面、切走时最后 1.5 秒的改动没写。

- 自动保存要的命令以前只能问 Worker（`docTail`），是异步的；页面要没了的时候等不到。主线程其实有一份完整的命令记录（`sandbox.ts` 的 `Mirror`，卡住后恢复用的，每条改动的回复都带着变了的命令）。加了 `Mirror.full()`（整份世界 + 每一步的编号 + 认引擎的 key）和 `keyFor`。
- `flushNow()`（`AutosaveWriter.blind`）：**同步地**从命令记录算出没写的尾巴，开事务、发出去、`tx.commit()`，不读头、不等回调。只在拿着锁、而且已经写成过一次（头确实是自己的那一代）时这样做——不读头就写，得确定没有别人。平常那一次写成之后留着一个开着的连接（`browserAutosaveIo` 的 `keepOpen`），因为开连接也是异步的。
  - 编号还是不是同一个引擎的（换了世界、换了 Worker）靠 key 认：不是就整份发，不接在旧世界的下标后面。
  - 平常那一次正写到一半时发了这一下：平常那一次按的是旧的 `savedIds`，它据此（`base !== savedIds`）知道自己过时了，不写，再来一次。
  - 这一下发出去却没提交（满了）：记着的那一代和头对不上，下一次写时整份重写。
- `visibilitychange → hidden` 和 `pagehide`：先 `flushNow()`，再照平常的路 `autosaveNow()` 一次（页面还在时把 Worker 里排着的也写上、核对）。不是写的那一方、还没写成过、没有锁可用时同步写不了，只走平常那条路。
- **有没存的改动时 `beforeunload` 提醒**：`unsaved`（`state/save-status.ts` 的 `hasUnsaved`）= 有世界，并且（计算程序里有没应答的编辑，或者世界不是写下的那个状态）。“改了还没到写的时候、正在写、没写成、这个页面不写”都是“世界不是写下的那个状态”，不用分开记。只在它为真时挂着监听（`effect` 里加、去），不是每次关页面都问。
  刚打开上次的世界、还没改时不算（`noteResumed` 把写下的状态记成现在的）：不然打开后 1.5 秒内关页面也会被问。
- **Worker 里还没应答的笔画不在这一下里**：命令还没算完，没有结果、可能失败，不能当“做了的一步”写下去。那时 `unsaved` 是真的，浏览器会问。

冒烟里：画一笔，世界一变（约 0.4 秒后）就刷新，那时存着的还是旧的步数；刷新后那一笔在。马上关页再开也在。都存好了的时候刷新浏览器没有问，有没存的时候问了。

## 4. 存储会不会被清掉、存不下时说清楚

- 第一次自动保存成功之后申请一次 `navigator.storage.persist()`（`src/storage-health.ts`）：结果记在 localStorage 的 `map2.persist`，给了就再也不申请；没给的过 30 天再申请一次（Chrome 自己按用得多不多决定、不弹窗，以后可能就给了；Firefox 会问用户一次）。没有这个接口就跳过。
- `navigator.storage.estimate()` 写成之后看一眼（最多十分钟一次），用掉九成以上时这一次打开页面提醒一次：“浏览器给的存储快满了。请导出世界文件，或删除几张旧地图”。
- 以前自动保存失败只弹一次（`autosaveWarned`），之后再也不说。现在原因一直在 `saveFail` 里，下一次写成了才清：
  - `quota` 存储满了（IndexedDB 那一次是“满了”的错；或者后备的位置上压着没能挪走的旧世界）；
  - `unavailable` 浏览器存储不可用（IndexedDB 用不了，退回 localStorage 也不让写）；
  - `too-big` 世界太大（IndexedDB 用不了，退回的 localStorage 放不下）；
  - 加上 `other-page`（不是写的那一方，从 `saveRole` 来）。
  IndexedDB 写不进、退回 localStorage 写成了，照旧算存成了。
- 界面（`shell/save-note.ts` 的 `saveNote`：保存状态 → 写什么）：顶栏“世界”旁一个“没保存”的小标记（`button.tb-badge.warn`，900 px 以下只留“!”），悬停写原因；点它打开“世界”菜单，第一行（`.save-problem`）写原因、现在能做什么、“导出文件”（开在另一个页面里时还有“在这里接着做”）。刚没存成时顶上说一次（原因换了再说一次）。存成了都自己消失。
- 文字在 `ui/copy.ts` 的 `SAVE_TEXT`、`BACKUP_TEXT.why`。照 `ui-design.md`：说“这张地图”“世界文件”“页面”，不说“标签页”“IndexedDB”；每一句说清发生了什么、现在能做什么（测试查着）。

## 5. 我的库

`library-edit.ts` 的 `flush` 以前不看 `put` 的返回值：没写进去也清掉日志和“没写”的记号——之后刷新，那几项就没了，没有任何提示。现在没写进去（返回 false 或抛错）时：记号留着、日志留着（刷新后还能从日志补上）、说一次（`onStoreFail` → `libStoreFail.notify` → 顶上“‘X’的改动没能存进浏览器……请导出库的文件”），过 30 秒（`FLUSH_RETRY_MS`）再试；写成了以后再失败才再说。库删掉了就不再试。

马上写的那几种（加、删、换先后、改库名）在写之前就清了日志（记不成“这一项换成这样”），这一点没动：它们没写进去时记号留着、会再试、关页面时再试一次，但刷新以后那一步没有日志可补。

## 6. 冒烟（`tools/smoke.mjs`，`npm run smoke`）

无头 Chrome 里把 `dist/` 走一遍，不进 vitest。自己起一个只绑 `127.0.0.1`、系统挑端口的静态服务器（`file://` 不行，没有去试：打包出来的 `index.html` 引的是 `/assets/…` 这样从根起的地址，`file://` 下直接找不到；起一个服务器几行就够），跑完就关；Chrome 用临时的用户目录，经 `--remote-debugging-port=0` 的调试端口用 Node 自带的 `WebSocket` 操作，没有加依赖。七步：新建；画一笔、等自动保存、刷新后还在（陆地的数组逐字节相同）；世界一变马上刷新；马上关页再开；第二个页面和“在这里接着做”；上次的世界打不开；没存完整。`--shots <目录>` 把几处界面截成图。

## 取舍

- **平常那条路照旧问 Worker**（`docTail`），没有换成全用命令记录：`docTail` 的回复顺带让 Worker 写检查点，下标的算法和以前逐字相同，这条路上只是把“直接写”换成了“事务里先读头再写”。命令记录只在关页面那一下用。
- **写的权利不自动接**（那一页关了也要“是我的开头”才接），宁可多显示一条提示，不冒拿旧的盖新的险。
- **留下来的不自动清**：每次盖掉不一样的世界都留一份，可能攒下几份（来回点“在这里接着做”、`#demo`）。自动清就是另一种静默丢；列表里能删。
- **不写的页面不问 Worker、不写检查点**（`docTail` 不发）。页面隐藏时那一次检查点照旧（检查点打开时要和世界的命令对得上才用，别的世界的检查点只是用不上）。

## 没做的、要知道的

- 关页面那一下不含 Worker 里还在算的笔画；新建 / 打开后还没写成过一次（1.5 秒内）就关页面，同步写不了。
- 没有 `navigator.locks` 的浏览器：先开的那一页要到下一次写才知道自己不写了（有 `BroadcastChannel` 时马上知道）；关页面那一下走平常那条路，不保证写成。
- “我的地图”：不写的那一页 ⌘S 存进连着的那一张会被写的那一页之后的自动保存盖掉。“我的库”：两个页面同时改同一个库，后写的盖掉先写的。见第 1 节。
- localStorage 后备里的那一份是一整段 JSON，没有条数可对；不是 JSON 时照旧当没有。
- `continues` 按命令逐字比。引擎重放时如果给某条命令补了东西（比如 `provinceFix`），同一个世界也会被当成“不一样”多留一份——只多一条留着的，不丢东西；没有量过发生得多不多。
- 这一版的世界留进 `backups` 以后，“我的地图”的连着关系（`mapId`）带着，但从“留着的旧世界”里“打开”时不接着连。
- 没存成时的那一句只在原因换了时再说；一直是同一个原因就只有记号。
- Firefox 申请持久存储会弹一次浏览器自己的问话，这里没有先解释。
- 出错的原因是引擎给的原话（里面可能有英文，比如“Invalid input”），没有翻。
- 拿着锁的页面浏览器不放进“后退 / 前进”的缓存（bfcache）：后退回来是重新打开一次，照常接着上次的世界。
- **没有用眼睛看过的界面**：顶栏“没保存”在存储满了、存储不可用、世界太大三种原因下的样子（和“开在另一个页面里”是同一个标记，只是字不同）和那时顶上说一次的提示条；900 px 以下标记只剩“!”的样子；存储快满了的提示；“我的库没能存进浏览器”的提示；“留着的旧世界”列表里新几种原因的一行；有脚本时问话里多一个“用安全模式打开”；导出文件之后那句“已导出……”。这些的字和判断在纯函数的测试里，排版没看。
