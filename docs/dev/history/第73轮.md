## 格局模块（`countries/patterns.ts`）

```ts
interface PatternModule {
  id: string; name: string; description: string; amountHint: string;
  params?: readonly PatternParam[];   // {key, label, min, max, step, default, hint}：资源库里的滑块
  fallback?: number;                  // 时代没列这个模块时的多少（附庸 1，别的 0）
  reserve?(g: CountryRun, use: PatternUse): void;    // 数完几个国家、挑普通起点之前
  grow?(g, use): void;                                // 往外长之前
  after?(g, use): void;                               // 长完、整理完、建档案之前
  diplomacy?(g, use): void;                           // 建好档案、同盟与敌对之前
  relate?(g, use): void;                              // 领土补齐之后的集团一步
}
interface PatternUse { amount: number; params: Record<string, number>; patterns: string[] }
```

比计划多了一个钩子：附庸在外交里（建好档案之后、同盟与敌对之前，同盟要跳过宗主与附庸），帝国、联邦、同盟在领土补齐之后（按补齐之后的面积挑），是两个时刻，所以 `relate` 之外另有 `diplomacy`。

- **调法**：`runPatterns(g, hook)` 按模块登记的先后调，每个有这个钩子的模块都调——时代没列的模块用法的多少是它的 `fallback`（通常 0）。内置的四个在多少是 0 时和以前一样什么都不做，但照旧取数：以前 `countOf(rel?.federation, rand())`、`countOf(rel?.alliances, rand())` 不管时代写没写都从 `'blocs'` 流里取一个数，同盟“拉不拉进来”也从这条流取，所以联邦、同盟两个模块共用一条流（`g.shared('blocs')`），先后不能换。新的模块在 0 时应当什么都不做，也不取共用流里的数。
- **同一个模块被列了几次**：多少加起来，参数用第一个。世界里没有的格局、不认得的模块不算。
- **`CountryRun`**（`g`）：一次生成共用的东西：世界、计划、国家的种子、`mix(name, …k)` / `stream(name, …k)`（`mixSeed(seed, hashString(name), …k)` 和它的 mulberry32）、`shared(name)`（按名字共用的一条流）、各步的结果（几个国家、等级、起点 `seeds`、预留的地方 `region` / `regions`、`owner`、`dist`、编号 `ids`、档案 `metas`、面积 `areaOf`、邻国 `neighbors`、宗主 `overlord`）、模块自己的东西 `state`，集团一步的 `bloc`（`'blocs'` 流、补齐之后的面积、这一次的集团、`nid`、`inUnion`、`inAlliance`、`split`、按这一次的时代起名）。放在 `ctx.countryRun`，集团一步接着用（以前邦联靠 `ctx.confederations` 传过去，这一项去掉了）。
- **给格局用的两处小口子**（内置的四种都不用，结果不变）：`g.stepCost`（走一条边的代价再乘点什么，`grow.ts` 在文化、海岸的倍数之后调；没有时一个分支都不进）；`Seed.overseas`（长完以后“隔海的一块能住人的分量不到本国 5% 就放掉”不管它）。预留的地方从邦联推广成 `Region { pattern, group, seeds }`：只有它的成员进、成员不出去占能住人的地方、它的成员不当别国的附庸，这几条以前就是邦联的规则。

## 国家格局（内容 `countryPattern`）

- **格式**（`patterns/index.ts` 的 `countryPatternSchema`）：`id`、`name`、`description`、`module`（模块的 id）、`amount`（多少，0–20），各模块的参数平铺在项里（`vassal`、`protectorate`……，按模块登记时的范围；几个模块用同一个键时范围要一样，登记时查）。参数平铺而不是放进 `params` 对象，是为了通用的表单：字段表里每个参数写 `when: {key: 'module', is: 模块}`，换模块时别的模块的参数自动去掉（`fields.ts` 的 `setField` 本来就这样做，地名风格的模板式 / 音译式也是这样）。
- **登记**（`human/pattern-kinds.ts`，`human/kinds.ts` 在国家等级、格局之后调）：`store: 'content'`、`dirty: 'none'`（只在生成国家时读）、`order: 44.5`、一个世界最多 64 种、包里的段 `countryPatterns`；不认得的模块挡启用（`check`），资源包的问题里写明。模块是下拉（`enum`，选项从登记的模块来），多少是滑块，参数只显示选着的模块的。
- **时代**：`patterns: [{pattern, amount?}]`（最多 16 条，多少省略时用格局自己的）、`nationalism`（0–1，这一轮只记着、带着走，生成不读）。`relations` 只剩 `titles`（帝国、联邦、同盟、成员邦的称号）。内置的民族主义：古代、中世纪、奇幻 0.2，近现代 0.6，现代 0.85，科幻 0.5（计划里没给奇幻、科幻，照中世纪、近现代之间取的）。
- **内置的九种**（`core/packs/countries/patterns.json`，只在主线程）：神圣帝国、联邦、军事同盟（几个库共用，多少写在时代里）和六种附庸（每个时代以前的从属比例一种：朝贡与附庸、封建附庸、封臣与朝贡、保护国与自治领、保护国、星区保护国）。放在每个库的“时代”小包里（这个时代用的那几种，按时代列的先后），时代加进世界时一起来；`DEFAULT_WORLD_PACKS` 不变，所以新建世界（金标准）的小数据不变。

### 接到哪里

- **引用表**：时代的 `patterns.pattern` 是 `ref: 'countryPattern'`、`dep: 'auto'`（缺了去掉那一条：时代少一种格局），依赖的闭包（`dependencyClosure`）带上它。`link-rules.ts` 加了一条（格局没有引用：`module` 是代码里的模块）。
- **导入**：导入的闭包（`import-gates.ts` 的 `walkOnce`）以前只跟着带去不掉的引用；字段表多了 `follow`（只写在 ref 的字段上，`linkProblems` 查着），写了的引用去得掉也跟着带：勾一个时代（或为了变量跟着来的时代）带上它用的格局，清单里去掉一种格局时只去掉时代里那一条。
- **生成人文**：`import.ts` 的 `GEN_KEYS` 加 `countryPatterns`（时代包里带进世界）；换库（`switch.ts` 的 `SWITCH_KINDS`）在时代之后加 `countryPattern`。
- **资源库**：首页“政治”一段在格局后面多一张“国家格局”卡片（图标 Handshake）；一项的页面分“基本”（名字、说明、模块、多少）、“参数”两段；时代的“国家关系”一段是格局、民族主义、称号。改了它算“重新生成国家后才用上”（`regen.ts`、`pick-other.ts`）。通用的表单，时代页面上的滑块是第七十五轮的事。
- **界面的一处**：“分裂 ↔ 统一”的说明写“联邦的成员邦另算”以前看 `relations.federation`，现在看时代列没列多少大于 0 的联邦模块（`eraUsesModule`；在生成向导里按选的库找格局，`choicePattern`）。

## 重录了什么
