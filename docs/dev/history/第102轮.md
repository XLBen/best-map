# 第一百零二轮的设计：存了再开，世界文件一字不差

十二轮计划之后的一处小修补。第九十七轮发现、第九十八轮查清（见 [第98轮](第98轮.md) 第 4 节）、一直留着没修的那一件：一份世界文件用 `Engine.fromDoc` 重放以后再 `toDoc()`，新建那一条命令里记的省名（`provinceNames`）会少几个。世界本身不变；只是第一次存的文件和重新打开后存的文件不一样。当时没修，是因为要重录 `core/raster-identity.test.ts` 的两个摘要；这一轮用户点了头才动。

生成的结果逐值不变。世界文件的格式没变（`DOC_VERSION` 还是 22）：`provinceNames` 本来就是可选的，旧文件里多记的那几个名字照旧读得进来（重放时写上去、随省一起删掉，和以前一样）。

## 原因

新建时划出来的陆地省里，有的整个落在推导算好以后才知道的湖面上。湖省整理（`core/engine-fixes.ts` 的 `fixLakeProvinces`）把这些格并进湖省，把空了的省删掉（`provinceFix.drop`）。

- 第一次执行：先记这一步新起的省名（`Engine.noteApplied`），推导算好以后才整理——记下的名字里有后来被删的省。
- 重放、重做：命令里带着 `provinceFix`，整理在收尾之前就做了（`commands.ts` 的 `settleApply`），记省名时那些省已经不在。

## 改法

`fixLakeProvinces` 把整理的结果记进这一步的命令时，顺手把 `drop` 里的省从这一步的 `provinceNames`、`provinceOrig` 里去掉（`withoutDropped`，十几行）。这样第一次记的就等于重放记的。

- 一个名字都不剩时原样留着：重放时这一步没有新起的省名，`noteApplied` 照原样记命令，两边还是一样。
- 没有 `provinceNames`、`drop` 里没有这一步新起的省时，命令对象原样返回（不新建对象）。
- 只在这一步真的有湖省整理时多做一次过滤，不在任何热路径上；没有跑测速。

## 核对

- 新测试（`core/replay-names.test.ts` 的“存了再开，世界文件一字不差”，2000 格、种子 4）：新建那一条命令的 `provinceFix.drop` 不空；被删的省没有名字记着；留着的省个个在世界里；文件走一遍 JSON 再 `fromDoc`、`toDoc`，逐字相同；世界的摘要相同；撤销再重做也是同样的字。把修补拿掉，这个测试不过（省 136 的名字还记着）。
- **重录的摘要**：`core/raster-identity.test.ts` 里星球的 `world.json` 两项（`0ef6aeae… → e30d0d6a…`）。`RECORD_RASTER=1` 跑出来 84 项里只有这两项变。另把那个测试用的两个世界在修补前后各写一份世界文件来比：地区的逐字相同；星球的只差新建那一条命令的 `provinceNames` 少了 256、265、1351 三个，正好是那一步 `provinceFix.drop` 的三个，别的键、别的命令都相同。
- 别的金标准、摘要、快照一个没动。

## 没做的

- 第九十八轮说的三处“按命令的字逐条比”的地方（`checkpointFits`、`Engine.fromCheckpoint`、自动保存的 `continues`）没有另外去浏览器里走：它们的后果本来就是读代码推的，现在两边的字相同了，那条路走不到。
- 修补之前存的世界文件里还带着多记的名字：打开时照旧（世界相同），再存一次以后文件里就没有了。

## 量到的数

- 测试 292 个文件、3350 个（多 1 个）。`npx tsc --noEmit` 通过。整套一起跑：4 个文件没过，都是机器忙时的超时——`core/sizing.test.ts`、`src/ui/speed-r80.test.ts`、`tools/realism.test.ts`，和 `core/human/keep-content.test.ts`（整个文件准备世界时超时，里面 11 个没跑到）；四个文件单独重跑都过。
- 没有动界面、渲染、打包的东西：没有重跑冒烟和逐字节对照。
