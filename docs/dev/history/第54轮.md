# 第五十四轮的设计

这一轮改了什么见 [更新记录](../../更新记录.md)；现在的文件见 [开发说明](../../开发说明.md) 与 docs/dev/ 下的各篇。

用户定的：**给已有的世界加一个变量，只算新变量。** 文化、国家、城市都不动；点“重新生成国家”才会出现社会主义国家。文化没写倾向时按平均。原地填入：现有群体的人口按新变量分开，各文化比例不变。放宽每个时代 3 个变量的上限。

## 3 个变量的上限是什么

只是 `eraSchema` 的 `.max(3)`，代码里没有别的地方依赖 3：`popValue` 是 n × D，`TupleCodes.values` 按维数建。真正的限制是**每格只记 4 个群体**（`SLOTS`，`popGroup` / `popShare` 是 n × 4，/255）。生成时每个文化的各维取值排列组合（每维最多 3 种、每个文化最多留 8 种），取人最多的 4 个，剩下的算“其他”。**“其他”不属于任何文化。** 量的（6000 格，6 种取值的维度，没有倾向）：

| 库（原来几维） | 原来“其他” | +1 维 | +2 维 | +3 维 | +5 维 |
| --- | --- | --- | --- | --- | --- |
| 中世纪（1） | 0.40% | 15.9% | 41.6% | 47.5% | 51.7% |
| 奇幻（2） | 2.48% | 21.4% | 39.1% | 44.8% | 49.2% |
| 现代（3） | 31.81% | 42.5% | 47.4% | 49.9% | 52.5% |

所以照生成的写法加一维，文化比例就变了，排列组合用到的编号还会翻几倍（现代 +5 维，一次生成中途要 19137 个编号，留下 6107 个）。`SLOTS` 改了就是世界的布局变了，r29、`libraries-digests`、golden-full 都要重录，不行。

## 原地分开

`core/human/add-dimension.ts`。一格里每个群体的人只在“这个群体 + 新维度的某个取值”之间分，整数的占比加起来和原来一样，所以**每个文化、每个旧群体的占比逐值不变，“其他”也不变**。

1. 想要的份额：这一格、这个文化按新维度的分布。用生成同一个式子（`valueDist`：倾向 × 偏好 × 成片的噪声，取 2.5 次方，不到 4% 的去掉，最多 3 种），种子是 `value:维度:取值`，所以和生成时同一片地方是同一种。
2. 群体从大到小，每个先整个归给这个文化缺得最多的取值。
3. 还有空位时，把多出来的人分给缺的取值，每次挑能挪最多的，少于 3/255（约 1.2%）的不分。

一个群体占满一格（255）、份额 0.6 / 0.3 / 0.1：153、77、25。四个格位都满时不能再分，只能第 2 步。所以**格位满的格，新维度的比例只能精确到一个群体**。和“每个群体按份额分”的理想值比（只看人数差多少，1 是全错）：

| 世界（6000 格） | 全世界，按文化 + 取值 | 按格 |
| --- | --- | --- |
| 中世纪 +1（民族认同） | 8.5% | 12.3% |
| 中世纪 +2（意识形态） | 12.4% | 22.0% |
| 奇幻 +2（意识形态） | 13.1% | 29.2% |
| 现代 +1（种族） | 3.8% | 7.1% |

现代低是因为它的群体本来就碎。**“按平均”不是每格都平均。** 字面上每格一样的话，一样多时全世界都是第一个取值占多数，图层上只有一种颜色。用噪声成片，全世界的份额接近平均（奇幻加意识形态 15 种，每种都在 1/60–1/6 之间，有测试）。这是我定的，和重新生成时的样子一致。

**命令**：`add_dimension { dimension: {id, label}, era? }`，在 `baseCommands` 末尾。

- 这一维的取值要已经在世界里。计算 Worker 不碰内置的数据，界面用 `core/packs/add-dimension.ts` 的 `addDimensionCommand` 发一个批量：先加取值、取值组（`planPack`：一模一样的跳过，同 id 不同内容的改名，记来源），再 `add_dimension`。第六十一轮直接用它和 `dimensionOptions`。
- 时代的这一维写 `required: true`（文化没写倾向时按平均，不写的话这些人没有这一维）和 `added: true`。
- `era` 写了别的时代时只改那个时代，不分人（换库用）。没有人文时只改时代。
- 文化、国家、城市、地名都不是这条命令的事，人数和手改的记号也不动。`touchedArrays`：`popGroup`、`popShare`、`popAutoGroup`、`popAutoShare`。自动的快照也分开，橡皮擦恢复后还是分开的样子。
- 已有的群体都带了新取值，旧群体没人用，所以编号另起一份、从头排（`compactGroups`）。`human.nextGroup` 跟着变，别的不变。
- `DOC_VERSION` **没加**：多一条命令、多一个可选的字段，旧文件照样重放，`raster-identity` 也没动。

## 重新生成

“重新生成国家”走 `regenerateHuman`，人口也重算。如果后加的维度和别的维一起排列组合，上面那张表又回来了：中世纪重新生成一次“其他”从 0.4% 到 16%，文化圈的边上也会变。所以 **`added` 的维度生成时也原地分开**（`fillAddedDims`，几个生成步骤之后）：

- `composedDims`：不是 `added` 的前 3 维，照旧排列组合。`filledDims`：别的（`added` 的和超过 3 维的）。
- 人口、国家的移民都只用 `composedDims`，所以到分开之前和没有这一维的世界逐值相同。测试：中世纪加意识形态、不加新政体，重新生成国家后，国家、城市、地名、文化比例、宗教比例都和没加的世界重新生成的相同（只差新维度）。
- 自己的时代写了超过 3 维（没有 `added`）时，第 4 维起也这样，所以排列组合的编号不会比以前的世界更多。
- 内置的时代都不超过 3 维、都没有 `added`，`filledDims` 是空的，这条路不走（有测试）。

| 奇幻 6000 格 | 197 → 973 → 4121 → 6863 → 8246 → 9001 |
| 现代 6000 格 | 1097 → 3808 → 6779 → 8555 → 9468 → 9929 |
| 中世纪 4 万格 | 232 → 632 → 2022 → 8385 → 18250 → 26635 |

（前几个是内置的变量，没有内置的可加时是 6 种取值的假变量。群体多不过“有人的格数 × 4”。）

**内存**：

| | 每多一维 |
| --- | --- |
| `derived.popValue` | n × 2 字节（20 万格 400 KB） |
| `TupleCodes` | 群体个数 × 2 字节 |
| `small.popGroups` | 每个群体一个对象。4 万格现代 +5：JSON 8.6 MB，这一项是主要的 |

世界文件存的是命令，不存群体，这一轮世界文件只多取值的定义。

**定 8**：现代（3 维）能再加 5 个，文化比例不变，分开的精度不随维数变差（下表），时间是线性的。再多也不会坏，只是几乎每个格位都是不同的群体，档案里读不出什么。写在 `MAX_DIMENSIONS`。

**群体太多时**（`MAX_POP_GROUPS` = 60000，编号是 Uint16，留 5535 个给之后的笔刷）：全世界按人数从多到少留，每个旧群体至少留一种，别的并进同一个旧群体里留下的人最多的那一种。**并只发生在同一个旧群体里，文化比例不变。** 这要先算完全部的格才知道谁留下（`Splitter` 先在对象上分，最后才给编号），不是先到先得：先到先得的话编号用完后地图的南边整片都分不开。

现代 20 万格 +4、+5 碰到了，精度（全世界 / 按格）：2.2% / 6.3%（+3，没碰到）→ 2.7% / 9.3%（+4）→ 4.1% / 12.3%（+5）。

编号表满了之后笔刷新建的群体到 65535 个时命令报错（第二十二轮就有这条），世界不变。

## 换库

`librarySwitchPlan`：世界自己加的变量（`added`）和“自己做的”一样跟着世界走。

- **新库的时代也有这一维**（奇幻加意识形态 → 现代）：用新库的定义，不是 `added`，生成时和那个库一样排列组合。新库带的取值加进来，世界里已有的（来自第三个库的、自己做的）留着，一起参与。
- **新库没有**（奇幻加意识形态 → 中世纪）：`imports` 末尾多一条 `add_dimension { era: 新时代 }`，只改时代，生成时分开。它的取值、取值组不移出，**哪怕来源是旧库**。换回去也一样。测试：这样换的文化圈、领土和没加变量换过去的相同；没有悬空的引用；撤销、重放一致。
- 没加过变量的世界：计划和以前逐字相同（`switch.test` 全部通过）。

## 世界加的政体不打折（替用户定的）

门槛要“奇幻世界加意识形态、加社会主义政体，确实能长出这种国家”。一量：**长不出来**。奇幻的 11 个文化组都写了 `government` 的倾向，没写到的政体 × 0.15，三个种子 57 个国家一个社会主义的都没有，和变量无关。

改了 `govWeights`：**世界自己加的政体（自己做的、来源不是规则时代所在的库）不打这个折。** 库里文化的倾向写的时候不知道有它，第五十二轮说的“从别的库加来的要一直参与生成”也是这个意思。结果（6000 格，社会主义国家 / 全部国家）：

| 种子 | 奇幻 | 中世纪 |
| --- | --- | --- |
| 2 | 1 / 22 | 1 / 19 |
| 3 | 1 / 16 | 2 / 13 |
| 4 | 3 / 19 | 2 / 17 |

六个库的默认世界里政体都来自那个库，折扣照旧，摘要没变。**不走这条路的世界结果不变；世界里已经有别的库的政体的（第五十三轮“换政体时从库里加”）重新生成时它们会多一些。** 这一条可以单独撤。

社会主义共和国没有写 `only`，所以和意识形态的取值没有硬的关系：加政体不加变量也长得出来，只是派系的来源是 0。硬的关系（“只有信 X 的”）要政体写 `only`，第六十一轮的导入窗口把它要的变量带来。

## 共用人口群体（这一轮的提速）

世界有上万个群体后，**每条命令都慢**（不只是人口的命令）：撤销记录要把 `popGroups` 序列化一遍，撤销要解析，发快照要结构化克隆。量到（奇幻 6000 格 +5）：写个备注 1.6 → 14.9 ms，撤销 1.5 → 11 ms，笔刷 5.7 → 34 ms。所以和第四十七轮的内容一样：

- `small-copy.ts`：`popGroups` 是整个换掉的（`GroupTable.commit`、`compactGroups`），副本里按引用共用，JSON 里留占位，键的先后不变。`add-dimension.test` 把它冻住跑一遍，和不冻的逐值相同。
- `content-post.ts`：没换时不发，主线程补上手上那一份（`groupsRev`、`sameGroups`）。预览（`postedPatch`）还带着，没动。
- `GroupTable`：“键 → 编号”按群体对象记着，第一次给新编号时才拷贝。

这三处都不改结果，没加变量的世界也少一点（见下）。

`tools` 里没有留这段脚本：同一个世界（`generate_human` 之后）一维一维加，每一档量五次中位数。笔刷是 1/64 的有人的格改一个维度。

## 界面

“文化 ⋯”里时代下面多一段“加一个变量”：列资源库里有、这个时代还没有的（意识形态、民族认同、种族、物种……，写着几种，悬停写前几个取值），点一下就加，可以撤销。下面一句话：文化、国家、城市都不会变。想让国家用上它，点“重新生成国家”。

- 控件是 `TypePicker`。新面板在第五十九轮。
- 图层、地图模式、图例、格和国家的档案、人口笔刷的选择都是按 `worldDimensions` 列的，不用改。
- 人口笔刷“改一个维度”：超过 3 维时选维度从 `Seg` 换成下拉，8 个放不下。

**没有做的**：

- 这里只能从资源库选，不能现写一个变量。要自己的取值，先在“我的库”的时代写这一维和取值。
- 还没有“去掉一个变量”。在资源库改时代的维度可以去掉，人的元组里留着旧取值，重新生成后没了。
- 导入政体时变量跟着来是第六十一轮。

## 坑

- 两个世界的 `popCulture` 相同不等于 `small.human` 相同：`nextGroup` 会变，比摘要时要去掉（`untouched`）。
- 分开之后 0 号格位不一定是占多数的文化（`[A:100, B:90]` 分成 `[B:90, A:60, A:40]`）。读 0 号格位的只有补新陆地的成分（`populationFix`，取偏好）和国家的移民（生成时，人口是新算的、分开在它之后），生成的世界本来也不保证。
- `fillAddedDims` 先整理一次编号：上一次生成和排列组合没选上的编号不算数，不然 60000 的上限早早就满了。手改的格留着时，自动的快照要留这几格的（别的格马上被 `snapshotPop` 换掉，先清零）。
- `dimensionOptions` 每次都走一遍库的树，面板里按库和时代记着。
