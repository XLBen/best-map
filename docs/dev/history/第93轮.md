# 第九十三轮的设计：资源库（四）表单变简单、做法一致

这一轮改了什么见 [更新记录](../../更新记录.md)。用户（不懂技术的新手作者）头号的抱怨是“编辑资源库太难用”。第九十轮解决“改了看不到”，
第九十一轮解决“国名称号不跟着变”，第九十二轮解决“找不到、分不清”，这一轮解决最后两条：**表单看不懂**、**做法不一致**。

生成的结果逐值不变：金标准、摘要、着色器的哈希、界面的快照一个都没有重录；世界文件的格式没变（`DOC_VERSION` 还是 22）；
没有加命令、没有改命令的格式、没有改任何 schema。core 里只动了登记表的字段表（给人看的那一层：哪些收起来、滑块的范围、选项的中文名、说明的字）
和一个新文件 `core/effect-ranges.ts`（滑块的范围，不参与计算）。

## 为什么看不懂、不一致

1. 一项的页面把字段表里的每一个字段都摊着：政体 20 个、画风“基本”一段 13 个（没写到哪一段的都落在第一段）。规则、脚本、换说法和名字、颜色并排。
2. 要手打英文：政体的类别提示写着“monarchy、republic……”，规则里“生态的地形”要打 `forest desert marsh`，旗的纹章、样式要打 `crown lion`、`bicolor-h`，
   岛的颜色要打 `#rrggbb、coral、marsh`；岛的形状、高低、地标放在哪的选项照写 `rugged`、`big-city`；键 → 值的表新加一项先叫 `new`；下拉里每一行都带着英文的 id。
3. 同一个数两处范围不同：生态“对周围的影响”在生态编辑器里变暖变冷 ±5 °C、变湿变干 −50%～+100%、范围 50–1500“千米”，
   在字段表里是 ±10、指数 ±1.5（说明写“降水乘以 e 的这么多次方”）、20–3000“km”；河的两岸又是第三套（按对数的范围、带“自动”）。
4. 滑块只能拖：两千格的滑块拖不到一个确切的数。
5. 四套做法：通用页的一排按钮（删除在中间，在用的不能删、原因只在悬停里）；生态页自己一排（用它涂、复制、新建生态、导出、删除——删除不管用没用都问一句）；
   河湖岛另有“详细编辑”，打开“水系 ⋯”“地形 ⋯”里的另一个编辑器（那里的删除直接删）；我的库里的删除每次都问。新建的 id 四种起法：`my-river`、`custom_3`、`river-type-2`、`island-type-1`。
6. 来源下拉开着时按 Esc，整个面板关了。
7. 倾向的表怎么读只写在悬停里。

## 1. 常用 / 更多设置（`core/content/registry.ts` 的 `FieldDesc.more`、`more-settings.ts`）

- 登记表的字段多一项 `more?: true`：不是新手第一次打开最想改的。只管显示在哪，不影响格式、导入、引用。
- 一项的页面（`PageItem.tsx`）：
  - 一段里有常用的、也有 `more` 的：`more` 的几个在这一段最下面折叠着（“更多设置”，收着时旁边写里面是什么：“换说法”“偏海岸、城市化、紧凑 等 5 项”）。
  - 一段的字段全是 `more`（规则、脚本、限谁用、倾向……）：整段收进页面底下的“更多设置”，和 **id** 放在一起（id 以前页面上不写；现在在这里看得到，只给看：别的内容按它找到这一项，建好后不改）。
    是不是整段从字段推（`segmentIsMore`），自己画的段可以在 `page-segments.ts` 写 `more`。
  - 里面有要改的错时那一处直接展开着；从别处直达“更多设置”里的一段（“在地图上”的“看规则”、时代的“变量”卡片、脚本出错的“编辑”）时那一层跟着展开（`moreOpen` 看里面的段）。
- **展开过的记着**：照用 `panel-store.ts` 的 `openSegments` / `rememberSegments`（按种类、这次打开页面期间），多两种键：`@more`（页面底下那一层）、`@more:段`（一段里的那一层）。
- **要不要都摊开只问一个函数**：`lib-prefs.ts` 的 `showAllSettings()`。它和第九十二轮的 `showAllSources()` 是**同一个偏好**（同一个键 `map2.lib.allSources`、同一个信号）——都是“要不要完整的界面”，
  第九十九轮的全局“完整界面”开关只写这一个。界面上分两个函数问，以后要分开时只改 `lib-prefs.ts`。它是 true 时：没有折叠、没有页面底下那一层（id 写在最下面），
  下拉里每行带 id、能照写一个列表里没有的 id（见第 2 节）。这一轮没有放开它的入口。
- **生态的页面**是自己的编辑器：以前收着的“高级”改叫“更多设置”，水系、人文从外面挪进去，id 写在最后；展开过记在同一个键上。
- **画风的“基本”分开**：以前 13 个字段（名字、说明、河湖的种类用，加没写到的手绘十项）。现在“基本”只有名字、说明；手绘的八项成一段“手绘”，字体进“字”，很少动的两项成一段“导出与河湖”（整段是更多设置）。
- 没有动登记的先后（`kinds.ts`）、没有改 schema、没有改世界文件格式。段的 id 和每个字段在哪一段除了画风都没变，所以“即时 / 要重新生成”的表（`timing.ts`）只多了画风的两段。

## 2. 不再手填 id 和记号

| 以前 | 现在 |
| --- | --- |
| 规则里“生态的地形”手打 `forest desert marsh` | 从表里选（森林、荒漠、沼泽……，`refs.ts` 的 `biomeTerrain`：那张导出用的地形表，库里的生态写了表外的也列） |
| 资源规则“地形类别”的说明“plains、hills…” | “平原、丘陵、山地……”（它本来就是从内容里选的） |

| 旗上的纹章、旗的样式手打 `crown lion tower`、`bicolor-h` | 一格一个带小图的选择（`FlagPick`、`previews.ts` 的 `flagChoices`：样式是那种样式的一面旗，纹章是纯色底上的那个纹章；中文名用国家档案里的那两张表，搬到了 `domain/flag-names.ts`）。以前手打错的照旧列着，能点掉 |

| 引用的下拉每一行“名字 + 灰色的 id”，能照写一个没有的 id（“用 xxx”） | 平时只写名字；带 id、照写 id 只在 `showAllSettings()` 时 |

| 地标名字的写法下面“能写的词：{city} {country}…” | 每个词后面写它换成什么（“{city} 城市、{river} 河……”） |
| “权重”（起名模板、音节数里的） | “多少”（第八十一轮定的叫法） |
| 倾向的说明里“维度”“那几维” | “变量” |

**政体的类别新加的那个为什么不用起 id**：类别不是一项内容，政体里存的就是这几个字（格式收 16 个字以内的任何字，`categoryName` 不认识的照写）。
所以“给它中文名、id 自动起”在这里就是存这个名字本身；内置的十四种存的是英文（`monarchy`），显示时换成中文，照旧。

**`pick` / `keyPick`，不是 `ref` / `keyRef`**：字段表里“从现成的表里选”的两处（生态的地形、地物的类别）写的是新的 `pick`、`keyPick`。它们和 `ref` 一样画成下拉，
但**引用表（`core/content/links.ts`）不看**——那两张表不是内容，写成 `ref` 的话导入的闭包会把“forest”当成一项缺的内容，规则那一条（`dep: 'gate'`）就被去掉了。
测试钉着：带这两处的地形类别、地名风格的引用是空的，`linkProblems()` 没有问题。

**新建一项的 id**（“看现在怎么起的，统一”）：

- 以前四种起法：资源库列表上的“新建”是登记表里的底子加编号（`my-river`、`my-river-2`）；生态页的“新建生态”`custom_3`，复制 `taiga_copy`；
  底部条上河湖的“新建类型…”`river-type-2`；岛 `island-type-1`。
- 现在只有一种：都走 `packs/fields.ts` 的 `blankItem`（生态页自己的新建、复制去掉了；`panels/water-types.ts` 的 `newWaterType`、`island-types.ts` 的 `newIslandType` 改成调它，只是颜色轮着取）。
  第二个起名字也带编号（“新的河 2”），列表里分得清。
- **id 没有从名字起**：名字是中文（“新的河”），id 只能是字母、数字、下划线、连字符（`ITEM_ID`，别的内容、脚本按它引用），新建时名字又是默认的那个，起不出有意义的 id。
  没有引入拼音。id 在“更多设置”里看得到、不能改（以前页面上根本不写）。

**改完 grep 过**：`lib-form.test.ts` 把这一条写成了测试——每种内容平时露的字段，名字、说明、选项里没有三个字母以上的英文（花括号里的词、单位除外）；
`tags` 都写了 `ref` / `pick` 或者界面另画；手打的 `text` 框只剩名字、说明（图标是下拉、图片是上传、岛的颜色是几个里选一个）。
平时露着、还带英文的只剩起名模板里花括号的词（“{city}神庙”）：它是写法本身，下面有示例和每个词的中文。

## 3. 同一个数一套范围和单位（`core/effect-ranges.ts`）

先 grep 了滑块的范围（`linear(`、`min: … max:`、`Knob`、`RangeSliders`）和字段表，同一个数写了两处以上的都在这里：

| 这个数 | 以前 | 现在（一处定义，几处引用） |
| --- | --- | --- |
| 变暖变冷（生态对周围的影响、河湖岸边） | 生态编辑器 ±5 °C；字段表 ±10；“水系 ⋯”的编辑器 ±10 | `EFFECT_DT`：±10，步子 0.5，°C（格式收的就是 ±10） |
| 变湿变干（同上） | 生态编辑器 −50%～+100%，步子 5%；字段表是指数 ±1.5，说明“降水乘以 e 的这么多次方”；“水系 ⋯”按指数等间距、写“雨水 +20%” | `EFFECT_DP` + `RAIN_SCALE` + `rainText`：存的还是指数；滑块按指数等间距（正中是不变），停在 5% 的整数倍上，写“降水 +20%”；字段表上 `show: 'expPercent'` |
| 生态影响的范围 | 生态编辑器 50–1500“千米”；字段表 20–3000“km” | `BIOME_RADIUS`：20–3000，步子 10，km |
| 岸边的范围 | “水系 ⋯”10–1000 按对数、没设时写“自动”；字段表 10–1000 | `BANK_RADIUS`：10–1000，步子 10，km；第一次“添加”时是 100（`BANK_RADIUS_DEFAULT`） |
| 生态的强弱 | 生态编辑器 0.5–10，步子 0.1；字段表 0–100，步子 0.5 | `COMPETITION`：0.5–10，步子 0.1 |
| 侵占的力度 | 生态编辑器 0–5；字段表 0–10 | `INVADE_STRENGTH`：0–10 |
| 花纹大小 | 生态编辑器步子 0.05、“格”；字段表步子 0.1、说明“以格为单位” | `VISUAL_SIZE`：0.1–4，步子 0.05，格 |
| 明显、发光 | 两处都是 0–1 步子 0.05，一处写百分比、一处写小数 | `VISUAL_AMOUNT`、`VISUAL_GLOW`：单位 `%` |
| 高度范围 | 两处各写一遍 0–9000、步子 100 | `core/species.ts` 的 `HEIGHT_RANGE` |
| 河的粗细（河的种类） | “水系 ⋯”0.3–3 按对数、写百分比；字段表 0.3–3 步子 0.1、写小数 | `RIVER_WIDTH`：0.3–3，步子 0.05，写百分比 |
| 岛的岩石 | “地形 ⋯”0.3–5 按对数；字段表没有范围 | 字段表 0.3–5（`ISLAND_ROCK_RANGE`），那个编辑器去掉了 |
| 条件里的流量 | “水系 ⋯”按对数（`flowScale`）；字段表等间距 | 字段表 `show: 'flow'`，用同一条刻度（搬到 `domain/flow-scale.ts`） |
| 陆地多少（星球形态） | 向导、星球形态编辑器 3%–70%；字段表 0–0.85 | `LAND_FRACTION`：3%–70%，三处引用 |
| 岛多少、山带宽窄 | 步子一处 0.01、一处 0.05 | `ISLAND_AMOUNT`、`BELT_WIDTH` |

- **已有的值含义不变**：存的数不换算，默认值没动。库里超出新范围的值（强弱 20、陆地 0.8）照旧留着，滑块停在最右，不拖就不改。
- 两种“范围”是两个数（格式收的不同：生态 20–3000，岸边 10–1000），没有硬并成一个，步子和单位一样。
- 测试（`core/effect-ranges.test.ts`）：字段表里那几个字段的范围就是这里的对象；滑块的两头都在格式收的范围里；百分比和指数互换、滑块停得到的数原样回来；以前生态编辑器范围以外的值（降水 −78%）照样写得出来。
- 没有并的：个别河的“粗细”（`guide.width`，0.4–3）和河的种类的粗细是两个数；“调整”里的星球参数只有一处。

## 4. 滑块能打字（`components/slider-entry.ts`、`Slider.tsx`）

- 点滑块右边的数出来一个框（先写着现在的数、选中）：回车、离开框生效，Esc 取消（只取消这个框，不往外传），超出范围停在那一头并浮出一句“最大 10 °C”。
- **怎么把打的数换成位置**：滑块只认识位置（0–1）和写出来的字。给它一个 `textAt(位置)`（这个位置写什么字），打的数就在“每个位置写的数”里找最接近的那一个
  （先粗看 65 个位置，再在最近的一格两边细看两遍，最多 195 次）。所以直径、力度、百分比、带单位、按对数的、取整成好读的数的都能用，不用每个滑块另写反过来的换算；
  写的字里没有数的位置（“不限”“自动”）不算。生效时和在滑轨上点一下一样：`onDraft` 一次、`onCommit` 一次——用的地方不用另写一条路。
- 打的数停在**滑块停得到的最近的一格**（写 0.33、步子 0.05 → 0.35），和拖到那里是同一个数：显示的和存的不会不一样。
- **不变慢**：`textAt` 只在回车、离开框时调；拖动的路上（`onPointerMove`）一行没多。每次画多两个状态钩子。
- 整个应用的滑块都加了（18 处，没有漏的）：底部条上工具的滑块（`OptionSlider`）、调整、图层、向导、星球形态编辑器、资源库的数字字段、范围的两个滑块、生态编辑器、倾向的表、河的大小 / 粗细 / 分水、湖的直径、碎岛、派系、总人口。
  写的字带“万”“亿”、分东西经、不是值本身的三处另给框里先写的数（`entry`）：总人口（打确切的人数）、导出的接缝经度（西经写成负数，悬停里说了）、河流多少（打门槛的流量；`AdjustmentDef.typed`）。
- 测试 `slider-entry.test.ts`（11 个）：字里的数、打的字认不认、等间距 / 两千格 / 对数 / 从大到小 / 左边是“不限”的滑块都停得准、超出范围、一次不超过两百次。没有 DOM 的测试环境，框本身（焦点、回车、Esc）没有自动测试。

## 5. 做法一致

### 同一排按钮（`pages.ts` 的 `itemActions`、`PageItem.tsx` 的 `Actions`）

每一种内容（生态也是）最下面同一排、同一种先后：先是“用它”的几个（用它涂——只有生态、设为默认、定位、用库里的版本），然后 **复制 → 存到我的库 → 导出文件 → 删除**（总在最后）。
新建只在列表上。生态页自己的一排（用它涂、复制、新建生态、导出、删除）去掉了；“详细编辑”去掉了（见下）。

### 删除同一套规矩（`item-delete.ts`）

| 情形 | 做什么 |
| --- | --- |
| 没人用到 | 直接删，不问（一步，能撤销；我的库里删完顶上“已删除‘X’”带“撤销”） |
| 别的内容写到了它 | 问一次：“政体‘封建君主制’写到了它，删了以后那几处不会跟着改。可以撤销。” |
| 地图上有它、删得掉（生态、河、湖、岛——涂的、选了它的、自己长出来的都算） | 问一次：“地图上长在 261 格。删了以后长它的地方会换成别的生态。可以撤销。” |
| 地图上用着、引擎不让删（放在 `small.content` 里的种类） | 不能删：按钮变淡，点一下把原因写在下面（“地图上有 3 处用到它（……），先把用到它的地方改掉”），悬停里也有 |

以前：通用页在用的一律不能删（包括生态、河湖——其实引擎让删），原因只在悬停里；生态页不管用没用都问；“详细编辑”里直接删；我的库每次都问。

### 河、湖、岛只有一个编辑器

- “水系 ⋯ → 水体类型”“地形 ⋯ → 岛的种类”里以前各有一个展开的编辑器（`waterTypes.tsx` 的 `TypeEditor`、`islandTypes.tsx` 的 `IslandTypeEditor`），和资源库里那一项的页面改的是同一样东西。
  现在那两处**只留选择用的列表**：点一种、“新建”“新建类型…”都直达资源库里这张地图的那一项（`openWorldItem`）。
- 那两个编辑器有、通用表单以前没有的，补进了通用表单：
  - 规则的脚本框（停一下就用到地图上、出错写在框下面、能点过去看是哪一格）：这张地图里河、湖的“规则”一段就是它（`WaterScript.tsx`，逻辑还是 `panels/water-types.ts` 的 `applyMatch`）；我的库里照旧是普通的框。
  - 条件里流量按对数、变湿变干写百分比、岛的颜色几个里选一个、形状高低写中文、岩石有范围（见第 2、3 节）。
- 脚本出错提示条上的“编辑”：以前换到画河工具、打开“水系 ⋯”；现在打开资源库里那种河的页面、展开“规则”（`state.ts` 的 `waterTypeEditor.open`，`connect.ts` 接上，和生态的一样）。
- 没有了的：岛的编辑器按形状把用不上的几项藏起来（环礁不显示高低……）——字段表的 `when` 只会“等于某个值时显示”，现在是说明里写一句；
  岸边的范围没设时写“自动 · 约 N km”的那个滑块——现在“岸边的影响”没写时是一个“添加”，添加时范围是 100 km。

### Esc 先关下拉（`shell/escape.ts` 的 `libMenu`、`lib-keys.ts` 的 `useLibMenu`）

面板标题的来源下拉、右上角的“⋯”开着时，Esc 先关它，面板不动。它在栈里排在“弹出面板”下面、“正在框里写”上面（105）；
面板自己的键盘（`panelKeys`：先清搜索、收右栏）这时不接 Esc，让它传到栈里。

## 6. 时代与生成规则

- 时代的页面：平时露名字颜色说明、人口密度、城市化率、国家大小、国家等级的比例、国家格局与按文化分国；年份、聚居、无主地、领海折叠着，变量、集团的称号整段在页面底下。
- 生成设置那一页（`PageGen.tsx`、`gen-settings.ts` 的 `genNotes`）每一项下面写现在是什么样：国家大小“现在 12 个国家；调小，国家更多”，
  人口密度“按这个密度一共约 3.2 亿 人”（和“文化 ⋯”的总人口同一个算法 `defaultTotalPop`），城市化率“城里约 4800.0 万 人”，
  国家等级的比例下面“帝国、王国占得多，大国就多；小国占得多，更分裂”。最上面一句“这几项改完要点底下的‘重新生成’”。别的在“时代‘X’的更多设置”“省份划分的更多设置”。
- **“统一 ↔ 分裂”没有对应的量了**：那个滑块第七十七轮去掉了（它在正中时就是时代的国家大小）。现在调的是国家大小和国家等级的比例，所以那句话写在比例下面。
