# 第七十九轮的设计

这一轮改了什么见 [更新记录](../../更新记录.md)。用户说“优化又变差了”：以前每一轮只和上一轮比，小的变慢一轮轮攒下来没看出来
（第七十二到七十五轮生成人文 719 → 745 ms；岩性一笔在第七十一到七十四轮都标过、当成噪音放过；第六十九、七十六轮没测；工业、奇幻、科幻的人文从来没测过）。
这一轮**直接和第六十八轮的提交 3d22942 比**，把生成和加工压回不比它慢；结果逐值不变，金标准、摘要、快照、着色器的哈希一个都没有重录。

## 怎么量

- 机器空着的时候一样一样地跑（vitest 用 `--maxWorkers=2`）；每种七次（复查的十一次），旧、新交替，每轮换一边先跑。
- `tools/bench.ts` 加了 `--era <id>`：`--library`、`--kept` 用这个时代的库（六个时代），`--kept` 另计重新生成国家（`regenCountries`：三个种子各一次再撤销，取中位数）。
  3d22942 已经有六个时代（第六十八轮），但没有第七十三到七十五轮的国家格局（集权帝国、汗国、殖民地、民族主义……种族王国、殖民据点）：
  那里的国家少走几步，所以下面每个时代都另和第七十八轮（8facf5e）比——两个都不慢才算。
- `tools/bench-median.mjs` 加了 `--head <提交>`：新的一边也检出（量“改之前”时可以接着改代码），`--script <文件>` 跑别的测速脚本。
  旧的提交上的命令格式：`bench.ts` 早已按第七十七、七十八轮回退（先试新的写法，不认时用旧的），在 3d22942 上照样能跑；`bench-layers.ts` 没跟上，这一轮补上。
- 主线程的图例另有 `tools/bench-legend.vitest.ts`（在 vitest 里跑：界面的状态模块要 Vite）。
- 这一次的对照存在 `tools/bench-baseline/r79-ab-*.json`（`base` 3d22942，`head` 这一轮）：**以后加工、生成人文都另和 3d22942 比**，不只和上一轮比。

## 量出来的（改之前）

和 3d22942 比，第七十八轮（8facf5e）比它慢 5% 以上的：

- 生成人文：工业 +6%、科幻 +6%、奇幻 +5%（中世纪 +3%、古代 +2%、现代 +1%）；重新生成国家：奇幻 +10%、工业 +4%、现代 +4%、科幻 +4%。
  剖析（工业，生成一次、重新生成八次）：人口一步里一格的成分（`composeCell`）一格一格拷贝取值的对象、每个组合排一次键（`tupleKey`）占了约四分之一；
  每个文化的偏好倍数都把“组的 + 文化的”逐格再判断一遍（历史上的四个时代的文化都没写自己的偏好，算出来和组的一样）；
  国家往外长每走一步要看一遍格局的代价（`if (nExtra) for …`，第七十三轮起）；种族王国每个种族把所有的格过一遍。
  国家格局本身是新的功能（3d22942 上没有），工业、奇幻、科幻多出来的主要是它们。
- 岩性（erod）：区域 +8%、星球 +6%，带库 +3%，带人文的几个时代 −11% 到 +8%。这一路的代码（高程、气候、水、地物）3d22942 以来没改过；
  同一个提交对照自己七次，岩性 214 / 216 ms（+1%）；单独跑同一个提交三次，科幻的岩性 238、272、298 ms——水一段 26 或 42–52 ms 两种（像是垃圾回收落在不落在这一笔里），
  七次的中位数落在哪一边是碰巧的。第三十一轮已经记过：区域岩性一笔在 190–350 ms 之间。冷暖笔同样（区域 56 / 57，星球 100 / 85）。
- 主线程：默认的地貌底图第七十二轮起有图例，每画一笔都把所有的格数一遍（Map 逐格读写），键里两个 `JSON.stringify`（地形类别、资源的表）。
  资源库里的生态编辑器（第七十二轮）：占比、陆地分布按世界对象缓存，每份快照都是新的世界，就整个重算；面板每次重画都新建 ctx。

## 改了什么（都逐值不变）

### 主线程

- **图例**（`src/ui/domain/legend.ts`）：格数按 编号数组、陆地、湖 三个数组缓存（换生态的名字颜色、换内容时不重数）；0–255 的编号数在定长的表里，别的（−1 之类）照旧进 Map。
  缓存的键里内容（地形类别、资源、文化……）按对象比：内容是不可变的，改了就是新的对象，主线程收到的快照里内容没换时也是同一个对象（`src/content-post.ts`）。
  集团、时代照旧按字比（它们在每份快照里都是新的对象，很小）。每个数组、每种底图记最近的一份。
- **地图上的图例**（`shownLegend`）：同一种底图、要重数所有的格时（画了一笔，生态的数组换了），先显示上一份，浏览器空闲时数好再换上（`requestIdleCallback`，
  最多等 300 ms）；换底图、第一次显示、没有 `requestIdleCallback` 的浏览器和测试里当场算。只有按格数的四种（地貌、生态分区、地形类别、资源）这样，别的照旧当场算。
- **生态编辑器**（`src/ui/ecology/chart.ts`）：占比按 生态、陆地、湖，陆地分布按 年均温、湿润、陆地、湖 缓存；气候图的底图按像素的那一份重画（`BiomeChart.tsx`），换了世界对象、数组没变时不重画。
- **资源库面板**（`LibPanel.tsx`）：ctx 用 `useMemo`，只在世界、资源库换了时是新的；顶上一行（标题的下拉、撤销、更多、文件、重新生成）是 `memo`，面板里别处变了（勾选、翻页、拖滑块）不重画它们。
  它们读的别的状态都是 signal（勾选、撤销）或跟着世界一起换（重新生成的 `regenTrack`）。

### 生成人文、重新生成国家（计算 Worker）

- **一格的成分**（`core/human/population.ts` 的 `composeCell`）：组合里记每一维取的是第几个候选，不再一维一维地拷贝取值的对象；
  群体的编号先按“文化 + 各维候选的下标”拼成的一个数查（按群体表、这一份 DimPlan 记着；拼出来超过 2^53 时不拼），查不到再拼群体的键
  （`groups.ts` 的 `tupleKey` 的写法：文化 | 维的 id 按字符串排好的 id=值）去群体表里查或新给（`GroupTable.codeFor`），新的群体才建取值的对象（键按维的先后放，和以前一样）。
  维的 id 有重复时（以前后一维盖掉前一维）照以前的写法。取值的分布（`valueDistAt`）分数记在一个数组里，只为留下的几项建对象；`valueDist` 照旧给 `add-dimension.ts` 用。
- **偏好**（`generate.ts`、`habitability.ts`）：组的偏好先按双精度算一遍（`preferenceProducts`，取成单精度就是以前组的那一份）；文化没写偏好时用组的那一份数组（只读），
  写了的在组的双精度乘积上接着乘自己的几条（`preferenceFactorsAfter`）——和把两串连成一串逐格算的连乘先后一样，中间也是双精度，所以逐位相同。
  文化圈里同一份偏好只开一次方（`cultures.ts` 的 `prefSqrt`）。
- **国家往外长**（`countries/grow.ts`）：格局的代价在长之前合成一个函数（一条时就是它，几条时按先后一条接一条）；没有时走不带这一行的 `stepTo`（和第七十二轮以前一样）。
  内置的时代都至少有一条（中世纪是集权帝国、汗国两条），所以常走的是合成的那一份。
- **种族王国**（`patterns/race-realms.ts` 的 `classify`）：所有的格只过一遍（以前每个种族一遍），每个种族照旧按格的先后加，和不变；种族的先后照取值的先后（后面按这个先后圈地方）。
- 格局的多少是 0 时本来就什么都不建（各模块开头的 `use.amount > 0`），没有要改的。

## 还比 3d22942 慢 5% 以上的

- 加工：没有。`bench.ts` 里一步只做一次的数，在几次对照里会在 ±10% 里跳（岩性、冷暖笔、画河、放岛轮流被标出来，同一个提交对照自己也有 +5%），
  编译好以后的（`bench-steady.ts`）与 3d22942 相同。
- 生成人文：奇幻 +1%（8 ms），是种族王国（第七十五轮的新功能，3d22942 没有）；和有它的第七十八轮比 −5%。
- 带库、带人文的世界里另外标过一次的 `library`（导入时代库，+16% → 这一次 +2%）、`rerollFjord`（现代 +7%，十一次）、`latShift`（带库 +6%，十一次）也是这样跳的一步一次的数，
  在别的几次对照里是 −3% 到 +3%。

## 没做的

- 生态编辑器、资源库面板没有单独的测速（拖滑块时的重画次数要在浏览器里看）；改的都是“少算一遍”，结果的测试见上。
- 人口一步剩下的大头是取值的噪声（`noiseAt`，每个候选每格一次）与城市、道路（第六十八轮以来没改过），这一轮没动。
