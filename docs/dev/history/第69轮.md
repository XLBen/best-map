# 第六十九轮的设计

这一轮改了什么见 [更新记录](../../更新记录.md)；现在的文件见 [开发说明](../../开发说明.md) 与 [ui.md](../ui.md)。只理界面的分层，**行为一点不变**：金标准、快照（`src/ui/__snapshots__/tool-replay.json`）、着色器的哈希一个都没重录，`core/` 一行没动。

## 为什么理

走查第六十八轮时看到界面的引用绕成了圈、几处靠绕路才接上：

- `src/state.ts`（2212 行）被 112 个界面文件引用，自己又引用 `ui/copy`、`ui/biomeRange`、`ui/shell/noticeTimer`。
- 工具表 `defs/tools.ts`（1024 行）引用五个面板、四个工具文件和底部条的部件，模块里跑三个 `effect`；`state.ts` 的 `registerToolSwitch` 就是为了绕开这个圈。
- 运行时的引用有一个 10 个文件的圈：`defs/tools → panels/settlements → packs/panel-open → packs/page-actions → packs/row-actions → defs/tools`，还经 `defs/extras → panels.tsx → Inspector → ArchiveBox`；另有 `ContentEditor ↔ editors`、`PageChildren ↔ PageItem`。
- 逻辑写在组件文件里，`.ts` 引用 `.tsx`（`lib-keys.ts → LibBasket.tsx`、`row-actions.ts → Scripts.tsx、islandTypes.tsx`）。
- `components/` 不是叶子：`Slider.tsx` 读写工具的选项，`TypePicker`、`SelectionActions` 读状态、开资源库。
- Esc 的先后写死在 `keys.ts` 的一长串 if/else 里（为此引用了六个模块），另有四处在捕获阶段自己接 Esc。
- 两处在整个页面里 `querySelector`：“去看看”后滚到高亮的行，地图量底部条有多高。

## 分层的规则（`src/ui/layering.test.ts`）

只看运行时还在的引用（`import type`、全是 `type` 的花括号不算，读法与第三十轮的 `worker-imports.test.ts` 相同，分到 `src/testing/imports.ts` 两边共用），测试文件不算：

1. `components/` 只引用 `core/`、库和 `components/` 自己。
2. `defs/` 不引用 `panels/`、`tools/`（含把它们一起导出的 `tools.ts`）和任何 `.tsx`。
3. `src/` 下的 `.ts` 不引用 `.tsx`。
4. `src/state.ts` 不引用 `src/ui/`。
5. `src/ui/` 与 `state.ts` 之间没有引用圈（Tarjan 求强连通分量，大于一个文件的就是圈）。

另查：引用 `register-all` 以后，`PANEL_KEYS` 里的部件都登记了，每个工具都有 `create`。规则写进了 [ui.md](../ui.md) 的“分层”。改之前用同样的读法数过：违反 1 的 9 条、2 的 20 条（另有 `defs/extras.tsx` 本身是 `.tsx`）、3 的 9 条、4 的 3 条，圈 3 个（10、2、2 个文件）；改完全是 0。

## effect 的先后

模块里的 `effect` 在引用时就建好，先后跟着模块的引用顺序。以前五个模块里有：`map/modes.ts`、`panels/lakes.tsx`、`panels/rivers.tsx`、`provincePanel.tsx`、`defs/tools.ts`（三个），按引用顺序算（与 ES 模块一样深度优先、后序）依次是第 354、400、401、403、406 个模块，工具表的三个在最后。preact signals 里同一个信号变了，先建的 effect 先跑（“偏好里存着人文的模式时换上去”与“这一层没了回到地貌”谁先跑会影响结果），所以 `startToolEffects()` 要在它们之后、第一次画界面之前：放在 `main.tsx` 的 `render` 之前。改完那四个模块是第 330、455、456、459 个，工具表的三个在 `main.tsx` 里建，先后与以前相同；第一次跑时没有世界，三个都直接返回，和以前在模块里时一样。

## Esc 的栈（`shell/escape.ts`）

先照改之前的 `keys.ts` 写好 `shell/escape-order.test.ts`（全部开着，一下一下按 Esc，记下每一下关的是哪一层；没有世界时向导关不上、也不往下传；地图上的一笔没取消到时往下走），在旧代码上通过，再换成栈，照样通过。

一层是一个函数：开着就做完并返回 `true`，没开着返回 `false`。先后只由 `ESC_RANK` 定（数大的先问），和谁先登记无关。

捕获阶段由 `App.tsx` 在 window 上挂一个 `onEscapeCapture`（第三个参数 `true`），用掉了就 `stopPropagation`，与以前三处各自挂的一样拦在输入框、面板自己的键盘之前。冒泡阶段是 `keys.ts` 的 `onKeyDown`，只调 `runEscape(e, 'bubble')`。一直在的状态（信号）在它所在的模块里 `pushEscape` 登记一次，判断的还是原来的信号，所以不画界面也能测；组件里开着才有的小窗口用 `useEscape`（挂着并且 `on` 时在栈里，函数每次取最新的）。

⌘S、⌘Z（面板里最后点的是哪里：`lastPress`）、回车、数字键照旧在 `keys.ts`，一行没改。

没并进栈的：`lib-keys.ts` 的 Esc（焦点在面板里时先清搜索、再收右栏）挂在面板元素上，看的是事件落在哪个框里；并进栈就排不到“输入框离开框”之前，行为会变，所以留着。名字框、`RefPicker`、`PickBox`、档案里的框自己接 Esc 的也照旧。

## 不在整个页面里找元素

- **滚到高亮的行**：以前 `lookAt` 和“从别的库加”加完后 `setTimeout(60)` 在整个页面里 `querySelector('.lp-hl')`（后者只找左栏 `.lp-main`）。现在 `flashRows(rows, 'hl', { smooth, main })` 只设信号、记下要滚；列表的每一行（`PageList` 的 `Row`、`PageChildren` 的子项）用 `useFlashScroll(ref, kind, id)`：画好后在 effect 里，高亮着就把自己报上来，同一次画的都报完后（微任务）按页面上的先后（`compareDocumentPosition`）取第一行滚到中间，只滚一次。仍是第一行、`block: 'center'`，“去看看”不慢慢滚、“从别的库加”慢慢滚；`main` 时只看在左栏的行（看自己的祖先 `.lp-main`）。等不到（列表没画出这一行）300 ms 后就算了，以前是 60 ms 时找不到就算了。
- **底部条的高度**：`ContextBar` 的 `.bottombar` 挂上时把自己填进 `shell/bottom-bar.ts` 的 `bottomBarRef`，地图的 `barLift` 量它（还在页面上才算）。量法、缓存、何时作废都没改（抽屉开关、资源库变宽时底部条只挪位置不变大小，要按位置量，所以给的是元素而不是一个高度）。

## 没能完全一样的

- 捕获阶段的三层（问话、拖卡片、脚本框的帮助）同时开着时，以前一下 Esc 三个都关（三个监听都挂在 window 上，`stopPropagation` 拦不住同一处的别的监听），现在只关最上面的问话。要同时开着得在拖卡片的半途弹出问话，实际碰不到。
- 滚到高亮的行：从 60 ms 后找一次改成画好就滚（通常早几十毫秒），找不到时多等到 300 ms。
