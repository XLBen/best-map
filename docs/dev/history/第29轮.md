从开发说明里搬来（第四十一轮）。这一轮改了什么见 [更新记录](../../更新记录.md)；现在的文件见 [开发说明](../../开发说明.md) 与 docs/dev/ 下的各篇。

## 资源包的树、只放用到的与压缩（第二十九轮）

世界里只放用到的，拿掉的都在资源包里；资源包分两层，世界里记着每一项来自哪个包。

- **嵌套的资源包**（`core/packs.ts`）：`PackNode = {id, name, description?, 各段…, packs?}`，`ResourcePack extends PackNode`。顶层多一个 `packs`，小包按 `nodeSchema(depth)` 严格地查（`PACK_DEPTH = 2`：资源包 ▸ 小包 ▸ 小包，第二层的小包不能再有 `packs`；一层最多 `PACK_MAX_SUBPACKS` 个）。`parsePack` 递归（`parseSections` / `parseChildren`），出错写“小包“乙”里的小包“丙”：……”。旧文件没有 `packs`，照旧读。
  - 读树：`ownItems(node, key)` 这一层的；`packItems(pack, key)` 整棵树的（同一个 id 只算先出现的，共用的是同一项）；`subPacks`、`walkPacks(node, fn(n, path))`、`findPack(node, path)`、`packPaths(pack, key, id)`。`packCounts`、`packSummary`、`defaultPicks`、`packProblems`（不同小包里同 id、内容不同的才算重复）都按整棵树。
  - `planPack(world, node, picks, {path?})`：node 可以是一个小包；每条启用命令带上 `from = [...path ?? [pack.id], ...它第一次出现的小包]`（`withFrom`，只给 `ORIGIN_OPS` 里的命令）。
  - `packFromWorld(world, picks, {..., byKind: true})`、`nestByKind(pack)`：按种类分小包（小包的 id 是段名）；`addToPack(pack, [{kind, item}])`：存进“来自《世界名》”这样的包（一模一样的不重复存，同 id 不同的换掉，满了的列在 `full`）。
- **内置的树**（`core/packs/builtin-base.ts` 是主干，`core/packs/builtin-tree.ts` 在“奇幻”大包里补上奇幻的生态、河、湖、星球形态；都由现有常量拼成，不复制数据。计算 Worker 里只引用主干：不带 `packs.ts` 和奇幻的数据，引擎打包成 data: 地址才不超长；`builtin-tree.ts` 载入时用 `useFullTree` 把查法换成完整的树，所以界面里 `isBuiltinSame` 也认得奇幻的那几样，Worker 里它们算“不是内置原样”。测试逐项对主干与完整的树里的路径）：`builtinPacks()` 每个内置时代一个大包（id 就是时代的 id），小包 `era`、每个维度一个（id 是维度 id，取值与 `ensureHumanContent` 带进来的一样：`eraValues`）、`governments`、`factions`（时代列的；没列的是写了这个时代的）、`resources`（时代列的、不是通用的）、`cultures ▸ <组>`（`defaultGroups`，组 + 文化 + 文化的地名风格，中文·默认不放）；奇幻另有 `biomes`（带 `fields`）、`rivers`、`lakes`、`forms`。`common`：`base`（地形类别、通用资源、城市等级、地标、点的类型、中文·默认；总在、只显示）、`nature`（`DEFAULT_SPECIES`）、`names ▸ <地区>`（`STYLE_REGIONS`，没列的放 `other`）、`cultures ▸ <组>`（没有时代默认带的组）。
  - 没被任何时代列出的政体、派系按 `homeEra` 归：自己写的 `eras` 里第一个内置时代 → 按类别 `CATEGORY_ERA` → 中世纪（现在的 46 种、30 种都被列出了，这条管以后加的）。
  - `builtinOrder(store, builtin)`：生成时复制回来的内置项排回内置的先后（取值、政体的先后会影响挑哪一个），清理过再生成与第一次一样。
  - `bringGovernment(world, id)`（`countries.ts`）：国家档案换成、新建国家用一种收掉了的内置政体时复制回来、记来源。
  - `builtinItems()` 每一项和它在哪几个包里（完整路径）；内置的岛的 id 不能写进资源包（`islandTypeSchema` 拒绝），只在这里列在 `BASE_PATH`。`builtinItem(kind, id)`、`builtinOrigin(kind, id, prefer?)`、`isBuiltinSame(kind, item)`（也认用到世界时 `finalize` 过的样子：关了自然生成的奇幻生态、河、湖）、`originOf(small, kind, id, item?)`（记着的；没记、与内置一模一样的按树）。
  - `src/library.ts` 的 `BUILTINS` 换成这几个大包（键是大包的 id）；以前的“奇幻生态示例”“地名风格示例”在“奇幻”“通用 ▸ 地名”里，`FANTASY_PACK`、`NAME_STYLES_PACK` 常量照旧在（生态抽屉等处用）。
- **来源**（`core/content/origin.ts`）：`small.origin[种类][id] = 包的路径`。`ORIGIN_OPS`（`set_content`、`add_species`、`update_species`、`set_river_type`、`set_lake_type`、`set_island_type`、`add_field`）多一个可选的 `from`（`originSchema`）；`commands.ts` 的 `run` 包住 `runOp`：执行完 `setOrigin`（批量里每一条也经过这里）。改一项没写 `from` 时来源照旧。每条命令最后 `tidyOrigins`：不在世界里了的去掉。生成人文、国家时从内置复制进来的由 `recordBuiltinOrigins` 记树里的位置（优先世界的时代的大包）。都在小状态里，撤销、重放一样。
- **拿掉的项**：`applyCommand` 前后各取一份 `contentSnapshot`（放在 `small.content` 的种类按 `small.content`，总在的内置项不在里面；以前的种类按原来的放法；星球形态不算），比出 `removed: RemovedItem[]`（`{kind, id, name, item, builtinSame, origin?}`）和 `added: ContentRef[]`。引擎记在 `Engine.lastRemoved`（最近一次 exec），Worker 的 exec 回复带 `removed`（`src/protocol.ts`）。界面拿它把不是内置原样的存进资源库；同一步里带进来又收掉的不算。
- **生成时的清理**（`core/human/prune.ts`）：第二十八轮的几条之外，取值只留有人的（不再留这个时代每一维的全部）、政体只留有国家用的、派系只留有国家用的（没写影响力的国家按时代的派系自动算，`eraFactions` 的那几个都算在用；`usage.ts` 的派系也这样数）。仍然只去掉与内置一模一样的：自己做的、改过的只由用户移出或整理时移出。`dropBroughtContent` 在 `remove_human`（时代、取值、文化组、文化、它们的地名风格，加上政体、派系）、`remove_countries`（政体、派系）之后去掉带进来的。`ensureHumanContent(world, era, groups)` 的组可以带 `cultures`：只复制点名的文化。`ensureGovContent` 的兜底（时代一个政体都没有）不再复制全部 46 / 30 种，只复制 `nearestEra`（同 id；否则按维度：物种 → 科幻、种族 → 奇幻、意识形态 → 现代、民族认同 → 近现代、其余中世纪）的那一套。
  - 这几条改了生成后世界里的内容，推导的取值编号（`popValue`，按 `dimensionValues` 的下标）跟着变；人口、领土的原因数组不变。
- **整理本世界**（`core/content/unused.ts`、`core/tidy.ts`、命令 `tidy_content {items?}`）：
  - `unusedContent(world)`：政体、派系、取值按 `usage.ts`；生态是 `dominant` 里没有、没涂过的（一格长生态的陆地都没有时不算）；河湖的种类是推导的 `riverType` / `lakeType` 里没有、没画、没选的（规则自动套上的算用到）；自定义场是移出上面那些之后没有内容写到（`fieldRefs`，其余内容的 JSON 里 `field:x`、`field('x')`）、也没画过（全是 0）的。
  - `planTidy(engine, {only?})`（`Engine.planTidy`）：在 `engine.clone()` 上执行 `tidy_content`，`mapDiff` 逐值比较地图（生态、河湖的种类、生态对周围的影响、植被的颜色、地形类别、资源、宜居度、人口、文化、文化组、维度的取值、国家、地名；编号按 id 比，只在用到时才有的数组按全是 0）。先整批；不过时按 `TIDY_KINDS` 一批批、再一项项，不过的留在 `kept`（`{kind, id, name, reason}`）。结果 `{command, removed, kept}`。`only` 给界面“整个小包移出、只移没在用的”用。
  - 命令按 `items` 逐项执行“移出”的那条命令（`removeCommand`：`remove_species`、`remove_river_type`、`remove_lake_type`、`remove_field`、`set_content null`），不在世界里的跳过，在用的报错；省略 `items` 时按 `unusedContent` 移出（不比较地图）。
- **压缩世界文件**（`core/compact.ts`）：`compactWorldDoc(doc, {mesh?}) → {doc, changed, verified, dropped, removed, kept}`、`compactDoc(doc)`。`Engine.fromDoc(doc, mesh, {onStep})` 重放并记下每条新加、移出的内容；加了又被明确移出的两条、加了以后一直没用上（最后的整理会移出）的那条，中间没有别的命令提到这个 id（JSON 里的字样）就去掉（彼此提到、都要去掉的一起去掉）；末尾补上引擎执行时记下的那条 `tidy_content`。压缩后重放，`worldDigest`（`core/digest.ts`：原因、全部推导、地物、小数据；顶层空的列表、表按没有）必须与“原来的 + 整理”一样，不一样退回“原来的 + 整理”（`verified: false`）。`splitWorldContent(world)`：打开世界文件时拆出不是内置原样的内容（`fromWorld` + `exportItem`，带记着的来源）。

## 资源库两栏、按包分组、拿掉的存进资源库（第二十九轮 界面）

核心那一半见上一节；界面这一半让“资源包的树”“来源”“拿掉的项”“整理”“压缩”在资源库、选择器、向导、打开与导出里用上。

- **两棵树**（`src/ui/packs/repo.ts` 的 `packTree(world, library, kind?)` → `{world, library}`；`kind` 省略或 `'all'` 是全部种类）。节点 `TreeNode {key, name, description?, path, entry?, node?, base?, loose?, children, rows, count, on}`，项照旧是 `RepoRow`（多了 `path`：在资源库的树里的位置，添加时作 `planPack` 的 `{path}` 记进来源）。
  - 资源库一栏：资源库里的每个包（`library.value`：内置的大包、我的、来自《世界名》、装上的）走一遍，每一层的 `ownItems` 成一行；路径 `[资源库的键, 小包…]`；`BASE_PATH` 那一层 `base`（只显示）。状态照旧是 `statusOf`，加了一个一次列表里共用的 `kind.inWorld` 缓存，世界里没有同 id 的直接是“不在本世界”（不再每项跑一遍 `planPack`）：大陆世界上整棵树约 40 ms。
  - 本世界一栏：每一种 `kind.inWorld(world)` 的每一项按 `originOf(small, kind, id, item)`（记着的；没记、与内置一模一样的按内置的树）插进 `[大包, 小包…]` 的节点，名字按资源库里的包，先后照资源库（`walkPacks` 的先后）；没有来源的进最后的 `离群`。状态是 `worldStatus`（都在本世界；总在的内置项 `always`、改过的 `modified`，内置中文、星球形态锁着）。
  - `filterTree(nodes, query, hideOn?)`：名字、id 对上的项和它们所在的包（包名对上整个留着）；`hideOn` 只留不在本世界的（“从资源库添加…”打开时 `filter: 'off'`）。`treeRows(n)` 整棵子树的项。
  - `packAddCommand(n, world)`：一个包或小包里列着的、还不在本世界、没锁着的项按 `planPack(world, n.node, picks, {path: n.path})` 一整步（标签“添加到本世界：“政体””），每条带 `from`。`packRemoveRefs(n)`：左栏一个包能交给整理的项（`small.content` 的种类和生态、河湖的种类；不含总在的、锁着的、世界默认的风格），界面拿去 `planTidy({only})`，在用的、移出后地图会变的留着。
- **`RepoPanel.tsx`**：顶上 `KindSelect`（全部 / 一种）、搜索、选了一种时“新建”；`RepoState.kind` 默认 `'all'`，`filter` 只用 `'off'`（右栏只列不在本世界的，写成一个可以去掉的小标签），`entry` 右栏只看一个包并整个展开。两栏 `Column`，每行 `NodeRow`（▸、名字、数、“全部添加 / 移出没用到的”）或 `ItemRow`（色块、名字、种类简称、右边“添加”或 ✓ / “移出”和定位）；点名字在下面展开 `ItemDetail`（说明、示例、在用的地方、编辑、设为默认、存进资源库（只有离群的）、导出文件、从库里删除）。停一下预览照旧（`usePreview`；整包添加停在按钮上时才算命令）。编辑器照旧，`RepoEdit.kind` 记着是哪一种（种类筛成全部时也能编辑）。“⋯”：从文件导入、从本世界存进资源库、整理本世界（`packs/tidy.ts` 的 `tidyWorld`：`planTidy` → 问话 `askUser({lines})` 列出移出的、留着的 → `exec`）、资源包。窄屏（≤ 720 px）两栏上下排。`openRepo`、`openRepoKind`、`openLibraryFor`、`showInRepo` 的调法不变。
- **Worker 的整理计划**：`Request` 多了 `{kind: 'planTidy', only?}`，回复带 `tidy: TidyPlan`（`engine.planTidy`，在副本上试，世界不变）；`state.ts` 的 `planTidy(only?, label)`。
- **拿掉的不丢**（`state.ts` 的 `exec`）：回复带 `removed` 时 `keepRemoved` → `library.ts` 的 `keepInLibrary(世界名, items)`：`worthKeeping` 去掉 `builtinSame` 的、用完整的树再看一遍 `isBuiltinSame`（计算 Worker 里认不出奇幻的那几样）、资源库里任何一个包已经有一模一样的（`inLibraryAlready`）；剩下的 `addToPack` 进 `packIdFor("来自《名》")` 这个包（按种类分小包，`mine: true`），`installPack`，提示“N 项存进了资源库”。世界名 `worldName()`：连着的我的地图、打开的文件名（`fileHint`）、最大的一块陆地。
- **打开世界文件**（`ui/maps/store.ts` 的 `openFile` → `splitOpened`）：`splitWorldContent(world)` 交给 `keepInLibrary(文件名, …)`；再 `planTidy(undefined, null)`（不挡工具），有能移出的就 `showNotice("有 N 项没用到，可以整理", {label: '整理…', run: tidyWorld})`（`state.ts` 新的一句话提示，只带一个按钮）。
- **压缩写出去的文件**（`state.ts` 的 `compactForSave(doc)`）：存进我的地图（`saveNew`、`saveMap`）、导出世界文件（`exportCurrent`、我的地图里的“导出”）先过它。开一个导出 Worker 发 `CompactJob {compact: doc}`（`protocol.ts`），`src/compact-job.ts` 的 `compactJob` 跑 `compactWorldDoc(doc, {mesh})`，回 `CompactReply`；`verified` 才用压缩后的，不然用原来的。期间 `busy` 写“正在整理世界文件…”。末尾整理移出的自己做的照样存进资源库。不在计算 Worker 里做（要重放两遍，而且 `compact.ts` 引用完整的内置树，进不了 data: 地址）。导出 Worker 不隔离：`onlyBuiltinScripts(doc)`（脚本的源码都在内置的树里）不成立时不重放，回 `skipped`，原样写出去。自动保存连着的我的地图（`syncLinked`）不压缩。
- **旧的生态文件**（`ClimateChart.tsx` 的 `importBiomeFile`）：和资源包一样 `readPack` → `openPackImport`，只装进资源库，不再整套换掉世界里的生态。
- **按包分组**：
  - 选择器：`TypeChoice` 多了 `id`；`TypePicker` 给了 `library`（种类）时按 `originGroups(items, kind, world, library)` 分段：都没写 `group` 的、写了 `id` 的项按来源的大包的名字分（先后照资源库），离群放最后，只有一段时不写小标题；没写 `id` 的（恢复自动、无、自动）留在最前。地名风格、地形类别、资源、岛、河湖的种类、城市等级、点的类型、取值的列表都带了 `id`；文化（按文化组）、地标（自然、人造）照旧按自己的 `group`。
  - 向导、重新生成（`ui/human.ts`）：`choiceGroup(kind, item, small, lib, scope, builtinFlat?)`——本世界的按记着的来源（没有的是“离群”），资源库的按内置的树（时代 `builtinFlat` 合成“内置”）或资源库里第一个有它的包（都没有时“本世界”）；`groupByPack(items, labelOf)`。`HumanChoices` 的时代卡片、文化组（建议的与“更多文化组”）按它分，小标题 `h6.choice-group`。星球形态按 `FormChoice.pack` 分；`formChoices` 改用 `packItems`（内置的形态在“奇幻 ▸ 星球形态”这个小包里，原来只读顶层，列不出来）。
  - `importCommands`：资源包里的时代带时代和它的维度的取值（同一个包里、写了这个时代或没写时代的、不与内置同 id 的），文化组带组、组所在小包里的文化和这些文化的地名风格（那个小包里没有这一组的文化时整个包里找）；每条带 `from`。政体、派系不带（生成时按需复制、生成后清理）。
