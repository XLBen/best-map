## 内容种类的登记表（第二十轮）

一种内容（地名风格、生态、河 / 湖 / 岛的种类、星球形态、自定义场、地形类别、资源、时代、人口维度的取值、文化组、文化、政体、派系、城市等级、地标类型、自定义点的类型；以后的……）在 `core/content/registry.ts` 的表里登记一次（`registerKind`），资源包的段、数、列表的一行（“生态 5 · 河流 4”）、格式检查、问题检查、撞 id 改名、用到世界、从世界导出、资源库的分类、编辑器的字段表都由它来，不再各处手写。现有的几种登记在 `core/content/kinds.ts`（登记的先后就是列表、检查的先后）；脚本引用、改名的小工具在 `core/content/refs.ts`（`packs.ts` 照旧导出）。

- **`ContentKind<T>`**（第二十一轮多了三项：`arrays`——`set_content` 会改的原因数组，撤销记录先记下；`afterSet(world, idsBefore)`——改完之后的整理，停用一种地形类别、资源后画过的格按 id 换编号；`alwaysOn(id)`——总在世界里的内置项开关不能动的原因；第三十轮去掉了，基础的内容也是普通内容）：`id`（命令、`small.content` 里用：`nameStyle`）、`label`（全称“地名风格”）、`short`（列表里的简称）、`order`（用到世界的先后：场 0 → 河 10 / 湖 11 / 岛 12 → 生态 20 → 地名风格 30）、`schema`（一项的 zod 格式）、`idOf` / `nameOf`（省略时是 `item.id` / `item.name`）、`inWorld(world)`（世界里启用的项）、`builtin()`（内置的项；第三十轮去掉了，改由内置的树给出：`builtinOf(kind)`，见“时代包与只读世界内容”）、`enable(item, world)` / `disable(id, world)`（命令）、`fields`（编辑器的字段表，见下）、`blank()`（编辑器“新建”的样子）、`notes(item)` / `samples(item, seed)`（编辑器里不挡启用的提醒、随机示例，见“资源库与通用编辑器”）、`pack`（资源包里的一段）。
- **两种放法**：
  - 新的种类写 `store: 'content'`：放在 `small.content[种类 id]: Record<id, 一项>`（复制进世界，打开不依赖资源库；第一次启用之前没有这一项，全部停用后去掉，所以没用过的世界与以前逐字节相同）。命令是通用的 `set_content {kind, id, item | null}`（null 是停用），按 `schema` 检查、`check(item, world)` 额外检查（不行就抛 `CommandError`）、`maxInWorld` 限数，重算到 `dirty(before, after, world)` 给的那一层（`'none' | 'names' | 'human' | 'vegetation' | 'solve' | 'climate' | 'elevation'`，与 `Dirty` 一一对应）。历史写“启用 / 修改 / 停用 + 全称 + “名字””。
  - 以前就有的种类照旧放在原来的地方、用原来的命令（`small.species` + `add_species`、`small.riverTypes` + `set_river_type`……），登记表只经 `inWorld` / `enable` / `disable` 适配，重放结果不变。
- **`pack`**：`key`（段名）、`aliases`（读旧文件时也认的段名：`textPacks` 读进 `nameStyles`）、`max`（一个文件里最多几项）、`listed`（列出来、可勾选；自定义场跟着生态、类型自动加，不列）、`checked`（默认勾上）、`note`（不能用到世界时的说明）、`read(raw, alias)`（读旧写法：文字包补上 `kind`、不合规的 id 换成合规的）、`write`、`defaultPick`、`withId`（撞 id 改名：种子用原来的、名字带编号）、`rewrite`（包里别的项改名时跟着改引用）、`finalize`（加进世界前最后一步：没写“自然生成”的关掉）、`fieldsOf`（要先有的自定义场）、`fromWorld` / `exportItem`（从世界导出）、`problems(items, ctx)`（不挡导入的问题，`ctx` 有包里各段的 id、自定义场、模板能用的词表）。
- **资源包**（`packs.ts`）：顶层格式按登记表建（严格：不认识的段报错）；`parsePack` 逐段按 `schema` 查、出错的位置写全称；`packSummary`、`packCounts`、`packProblems`（先查各段重复的 id，再按登记的先后调各段的 `problems`）、`defaultPicks`、`planPack`（加了、跳过的按登记的先后列，命令按 `order`）、`packFromWorld` 都是通用的。`PackPicks` 按段名给 id 列表，另有 `defaultStyle`（用了之后世界默认用这种地名风格，命令 `set_name_style`）。`packSection(key)` / `packSections()` 取段，`canApply(kind)` 是能不能用到世界。
- **编辑器的字段表** `FieldDesc`：`{key, label, type, hint?, optional?, options?, min?, max?, step?, of?, value?, when?}`，`type` 是 `text | longtext | number | bool | color | enum | tags | weighted | list | map | script | json`；`list` 每一项、`map` 每个值是对象时的字段写在 `of`，`map` 的值不是对象时写在 `value`；`when: {key, is}` 是只在同一层另一个字段等于某个值时才有（地名风格的模板式 / 音译式）。太复杂的（生态的耐受条件）先写 `json`，通用编辑器给原样的 JSON。
- **小工具**：`allKinds()`、`kindOf(id)`、`kindByPackKey(key)`、`itemId(kind, item)`、`itemName(kind, item)`、`contentItems(small, kind)`、`enableCommand(kind, item, world)` / `disableCommand(kind, id, world)`（有 `enable` 用它，`store: 'content'` 的用 `set_content`）、`isEnabled(kind, world, id)`、`updateKind(id, patch)`（换掉几项，测试用）。
- **加一种内容**：在 `content/kinds.ts`（或那一种自己的模块里，被 `kinds.ts` 引用）写 `registerKind({...})`，`store: 'content'`；起名、生成等用到它的地方按 id 引用、缺了退回默认（见 `name-styles.ts` 的 `styleFor`、`missingStyles`）。资源包、资源库的列表、编辑器不用另改。

## 地名风格的写法（第二十轮）

一个世界可以启用好几种地名风格（`small.content.nameStyle`），世界有一个默认的（`small.nameStyle`，没有这一项是内置的 `zh-default`；第三十轮起中文·默认也是 `small.content.nameStyle` 里的普通一项，没选时是世界里第一种），地物、省份可以单独选一种。格式与起名在 `core/name-styles.ts`，内置的几种在 `core/packs/names/`（一个 JSON 一种，在 `packs/names/index.ts` 的 `FILES` 里加一行就进了 `BUILTIN_STYLES` 和资源库里的“地名风格示例” `NAME_STYLES_PACK`）。

内置 27 种（先后见 `index.ts`）：中文·默认；日本·汉字、朝鲜半岛·韩语（模板式带读音表）；仿各地语言的音译式 20 种——英格兰、法兰西、西欧·日耳曼（德语）、低地·荷兰语、伊比利亚·西班牙语、意大利、古罗马·拉丁、希腊、北欧·诺斯、东欧·斯拉夫、阿拉伯、波斯、草原·突厥、印度·梵语、东南亚·马来、东南亚·泰、非洲·斯瓦希里、阿兹特克·纳瓦、安第斯·克丘亚、大洋洲·波利尼西亚；幻想 4 种——精灵、矮人、兽人、海民（自造的音和词）。音译式的通称照那种语言的写法写在原文里（Río X、Kuh-e X、Mae Nam X），中文意译（X河、X山）；中文里有约定俗成写法的照写（Kuala X → 瓜拉X、Sungai X → 双溪X、Chiang X → 清X、X-sur-Y → Y河畔X）。

- **哪一处用哪种**：`styleFor(world, target)` 是唯一的判断（`target` 是 `{feature, override?}` 或 `{province}`）：自己选的（地物是 `featureNames[键].style`，命令 `set_feature_style {key, style | null}`；省份是 `ProvinceMeta.style`，命令 `set_province {id, style | null}`，换了就按新风格重新起名）→ 世界默认（`set_name_style {id | null}`）→ 内置中文。选的风格停用了就按世界默认，`missingStyles(small)` 列出这些地方给界面提示。第二十二轮在“自己选的”和“世界默认”之间接上“当地文化的风格”，只改这一个函数。
- **种子与留着的名字**：用的风格不是世界默认时，种子后面加 `:风格 id`；是世界默认时与以前一样，所以只用内置中文的世界名字一个不变（金标准没有重录）。起名的办法（`keptNames` 的 `ctx`）里的风格标识：内置中文是旧的文字包标识（没换过时是 `-`），别的是风格内容的哈希，改了风格的内容留着的名字就不再用。`GeoFeature.style` 只在用的不是世界默认时才有（界面上的“风格”读它）。
- **原文**：起出来的名字是 `{zh, orig}`。`GeoFeature.orig`、`ProvinceMeta.orig` 只在有原文时才有；改名（`rename_feature` / `set_province` 的 `orig`；只改中文名时原文去掉，“换一个”也去掉）、留着的名字（`KeptName.orig`）、固定下来的河（`Guide.autoOrig`，跟着 `autoName`）、新编号的省（命令里的 `provinceOrig`，与 `provinceNames` 一起记、一起用）都带着它。`features.csv` 只在有原文时在 `name` 后面多一列 `orig`。显示中文 / 原文 / 两者见 `core/name-display.ts`（`nameText`、`nameLines`；界面的 `state.ts` 的 `nameMode`，叠加层的 `OverlayState.nameMode`）。
- **旧的文字包**：`small.wordPack` + `set_word_pack`（第三十轮去掉了：中文·默认是世界里的普通内容，直接改它）；新的做法是启用一种风格再设为默认。资源包里旧的 `textPacks` 一段、单独的文字包文件都读成模板式的风格。

**模板式**（`kind: 'template'`）就是以前的文字包，另可带读音表：

```json
{
  "id": "ja-kanji", "name": "日本·汉字", "kind": "template",
  "lists": { "pre": ["白", "高", "松"], "mid": ["川", "浜", "岡"] },
  "types": {
    "island": { "patterns": [{ "p": "{pre}{mid}島", "w": 3 }, { "p": "{pre}島" }], "byTag": { "cold": [{ "p": "{pre}雪島" }] } },
    "lake": { "patterns": [{ "p": "{pre}{mid}湖" }] }
  },
  "readings": { "白": "shira", "浜": "hama", "島": "shima", "湖": "-ko", "大陸": " Tairiku" }
}
```

- `lists`：词表；`types`：每类地物的模板（`{词表名}` 换成那个词表里的一项，同一个名字里尽量不重复用字），`w` 是权重；`byTag`：地物带这个情境标签时 65% 用这里的。`{__species}` 是生态区的生态名字（起名时才放进去）。
- `readings`：汉字（一个或几个）→ 原文，按最长匹配把整个名字读一遍，读不全时没有原文；每个词（空格隔开）的第一个字母大写。词尾的通称写成 `-ko`、` Tairiku` 这样带连字符或空格的。复合词的读法（连浊）写成几个字的一项。

**音译式**（`kind: 'phonetic'`）先拼外文、再音译：

```json
{
  "id": "west-germanic", "name": "西欧·日耳曼", "kind": "phonetic",
  "syllables": {
    "onsets": [["k", 3], ["v", 2], ["br", 1], ["", 1.5]],
    "nuclei": [["a", 4], ["i", 3], ["ei", 1]],
    "codas": [["", 6], ["l", 2], ["r", 2.5]],
    "first": [["k", 3], ["v", 2]],
    "last": [["", 2], ["l", 2], ["n", 2]]
  },
  "length": [[1, 3], [2, 5], [3, 1]],
  "lists": { "town": ["burg", "dorf", ["heim", 0.8]], "isle": ["ey", "holm"] },
  "forbid": ["aa", "^ng", "^a$"],
  "types": {
    "province": { "patterns": [{ "p": "{root}{town}", "zh": "{name}" }], "byTag": { "coastal": [{ "p": "{root}hafen" }] } },
    "island": { "patterns": [{ "p": "{root}{isle}", "zh": "{name}岛" }] },
    "lake": { "patterns": [{ "p": "{root}see", "zh": "{root}湖" }] },
    "biome": { "patterns": [{ "p": "{root}", "zh": "{root}{__species}" }] }
  },
  "translit": { "ka": "卡", "vi": "维", "r": "尔", "l": "尔", "s": "斯", "burg": "堡", "len": "伦" }
}
```

- 词根：音节数按 `length`（`[音节数, 权重]`），每个音节 = 声母 + 韵核 + 韵尾（`''` 是没有），第一个音节的声母用 `first`、最后一个的韵尾用 `last`（省略时同 `onsets` / `codas`）。带权重的一项写 `"k"` 或 `["k", 3]`。
- `forbid`：不许的写法（小写比较）：`"aa"` 任何地方，`"^ng"` 开头，`"r$"` 结尾，`"^a$"` 整个词根就是它。词根拼出来碰上就重拼，整个原文碰上就换一个模板重来。
- `types` 里的写法：`p` 是原文（`{root}` 拼一个词根，`{root2}` 另拼一个，`{表名}` 取 `lists` 里的一项，其余照抄；拼出来的部分在词首（开头、空格或连字符后）大写，照抄的原样）；`zh` 是中文（省略时把整个原文音译；`{name}` 是整个原文的音译，`{root}`、`{表名}` 是那一段的音译，`{__species}` 是生态名字，其余照抄）。通称在中文里意译（“{root}湖”“{name}岛”），城镇的词缀跟着音译（“{name}”）。没写的类型按 `default`、`island`、第一个。
- 音译 `transliterate`：原文转小写，从左往右取音译表里最长的一段；但一段以辅音结尾、后面紧跟元音时先试短一些的（辅音归后面的音节：vilen → vi·len 维伦，不是 vil·en 维尔恩），都不行再用它。空格写成“·”，连字符、撇号略过；表里一个字母也对不上的写成 `fallback`（省略时略过）。`vowels` 是元音字母（省略为 aeiouy 和常见的带符号元音）。例：Karvilsburg → kar（卡尔，由 ka + r）· vil（维尔）· s（斯）· burg（堡）→ 卡尔维尔斯堡。
- 音译表怎么写：先写“辅音 × 元音”的格子（ba 巴、be 贝、bi 比……）和单独的元音（a 阿、e 埃……），再写单独的辅音（在词尾、辅音前：l 尔、r 尔、s 斯、t 特、n 恩、m 姆……），再写常见的韵（an 安、ban 班……）、复合元音（ei 艾、au 奥），最后写词缀（burg 堡、heim 海姆）整段先认。用 `west-germanic.json` 做样子；格子大的可以写个小脚本生成（只是生成 JSON，不进代码）。

**写一种新风格时**：

1. id 用小写字母、数字、连字符（`slavic-east`），名字“地区·语言”（“东欧·斯拉夫”）。只写自己的音节规则、词缀和音译表，不搬真实的地名表（模板式的汉字词表是常用字，不是地名）。
2. 每类地物都写（`continent island archipelago peninsula ocean sea bay strait lake river range peak plateau plain basin desert forest tundra icecap wetland biome province region spot`），省份至少有 `coastal river mountain sea waste` 几个情境（`byTag`）；地物的情境标签还有 `cold hot dry wet high volcanic small large big`。
3. 放进 `core/packs/names/`，在 `index.ts` 的 `FILES` 里加一行。`name-styles-builtin.test.ts` 会查每一种：格式合格、`styleProblems`（用到了不存在的词表）与 `styleNotes`（音译表写不出的字母）都为空、名字是“地区·语言”、每类地物都写了、省份的情境写全、同一个种子同一个名字、中文名只有汉字和“·”、音译式和带读音表的都有原文、起出来的名字不碰上自己的不许的写法、200 个里重名少。
   - **不许的写法查的是整个原文**：不能碰上模板里照抄的字和词表里的词（`"ee"` 会让每个 `{root}meer` 都被拒、重试到底），只查词根的写法要写得窄一些（`"^the$"`），或者干脆不写。
   - 以元音开头的词缀（`-ia`、`-abad`）接以元音结尾的词根很难看：把“元音 + 词缀开头”写进不许的写法（`"aia"`、`"eabad"`），碰上了就换一个词根；这类禁写不要多到大部分词根都被拒。
   - 中文要把通称放在名字前面又不想带上通称的音译（`Lago de X` → “X湖”），可以写 `zh: "{root}湖"`；要整段音译又不要通称时，把那几个通称在音译表里写成空的（`"río": ""`），再用 `{name}`——只用在词根里不会出现的长词上。
   - 粗话、不雅的音（各语言常见的几个）写进不许的写法；音译用字避开不好的字（死、鬼、屎……）。
4. 看一看起出来的样子：`sampleNames(style, type, 数量)`（编辑器里的随机示例也用它）。

## 资源库与通用编辑器（第二十轮；第二十八轮以前叫资源库）

“世界 → 资源库”（`src/ui/packs/RepoPanel.tsx`）第二十轮起按登记表列出内容：左边是 `repoKinds()`（列出来的几种，地名风格在前），右边是 `repoRows(kind, world, library)` 给的一行一项。第二十九轮改成两栏、按包的树（`packTree`，见“资源库两栏、按包分组”），`repoRows` 照旧给新建、复制避开的 id 和测试用，下面讲的状态、命令、编辑器两栏共用。

- **一项从哪来**（`RepoRow.source`）：`builtin`（登记的 `builtin()` 和内置的包，同一项只列一次）、`mine` / `imported`（资源库里的包）、`world`（世界里有、资源库里哪一项都对不上的：这个世界里做的、别人的世界带来的）。`pack` 是它所在的包（只在世界里的包一层），启用时照资源包的规则走。
- **启用没有**（`RepoStatus`）：世界里有一模一样的（内置的生态本来就在世界里）→ 开着；否则按 `planPack` 加进世界时的样子（没写“自然生成”的关掉、改了名的引用……）与世界里的比，一样就是开着（`worldId` 是世界里那一项的 id）；同 id 不同内容时启用后改名（`rename`）。`locked` 是开关不能动的原因：没有世界、不能用到世界的种类（`canApply`，星球形态）、内置中文、有 `styleProblems` 的地名风格。
- **命令**：`toggleCommand`（关着是 `planPack` 的那一整步，改写标签为“启用 + 全称 + 名字”；开着是登记的停用命令，停用的是世界默认的地名风格时加一步 `set_name_style null`）、`defaultStyleCommand`（启用着的直接 `set_name_style`，没启用的启用和设为默认一起）。都是一步。执行前 `untrustedScripts` 有没信任过的就问（`askUser` 带上脚本），信任了再执行。
- **停一下预览**：鼠标进一项（或它的“默认”）就把它开关之后的命令交给 `previewWorld`，结果放进 `adjustPreviewWorld`（键是命令的 JSON，点下去时 `execAdjust` 直接采用）：会变的格描边，新生态的格按颜色淡淡涂上，底下写一句。只多一种可选的地名风格不算（地图上不变）；改世界默认的写“地名按这种风格重起”。点过之后鼠标移开之前不再预览，一项没了（换了类、筛掉、打开了编辑器）时一并去掉。
- **编辑**：生态、河流类型、湖泊类型、岛的种类（`DEDICATED`）打开各自的编辑器（生态抽屉、`openWaterTypeEditor`、`requestIslandTypeEditor`），只对世界里启用着的；别的种类用通用编辑器（内置的、开关不能动的复制一份改）。“新建”同理（有自己编辑器的在那里新建，别的用 `blank()`，id 用 `freeId` 避开）。
- **通用编辑器**（`ContentEditor.tsx`，逻辑在 `fields.ts`）按 `kind.fields` 画：`text / longtext / number / bool（Toggle）/ color / enum（四个以内 Seg，多了 select）/ tags（空格、逗号、顿号隔开）/ weighted（一行一项：字、权重，权重空着是 1，'' 也能写）/ list（每项按 of）/ map（键、值；值按 value 或 of）/ script（只是源码）/ json（有 of 时按 of 画成一组字段，没有时是原样的 JSON 框，写坏了不换上）`。一组字、带权重的字、map 的键在框里写完、离开框时才换上。列表、map、带权重的项多（8 项以上）时收起来，有错的展开。`setField`：可以不写的字段空了去掉；改的是别的字段 `when` 指着的那个（地名风格的“写法”）时，看不见的字段去掉、新看得见的必填字段按类型补上默认值（词表、各类地物两边都有，留着）。检查 `editorIssues`：`itemErrors`（`packs.ts`，按登记的格式、中文说明）+ `check`（挡启用的），出错的位置按字段表的名字说（`pathLabel`：“各类地物 · island · 模板 · 第 1 个 · 写法”），写在那个字段下面和最下面；`notes` 是不挡的提醒。登记了 `samples` 的种类在下面写随机示例（地名风格：每类地物 4 个，“换一批”换种子）。按钮：复制、存进资源库（`saveItem` 存进“我的资源”，同 id 换掉）、用到世界（登记的启用命令：`set_content` 已有同 id 时是修改）。
- **登记表为编辑器多的两项**：`notes(item)`（提醒）、`samples(item, seed)`（随机示例）。加一种 `store: 'content'` 的内容时写上 `fields`、`blank`，资源库、编辑器、资源包就都有了；要自己的编辑器时在 `RepoPanel.tsx` 的 `editRow`、`newItem` 里接上。
- **地名、省份里的风格**（`styles.ts`）：`styleChoices`（世界里启用的，内置中文在前）、`featureStyleCommand`（写在落到这个地物上的改名的键上，`overrideKeyOf`）、`restyleProvincesCommand`（没锁定、没自己选风格的省一个个 `set_province {style: null}`，一个 batch）、`restyleOffer`（世界默认不是内置中文、或有省名带原文时才提）、`missingCount`。底部条的“风格 ▾”是 `TypePickerButton` + `TYPE_PANELS.featurestyle`，省份在它的“⋯”里列 `TypePicker`。
