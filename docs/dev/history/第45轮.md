# 第四十五轮的设计

这一轮改了什么见 [更新记录](../../更新记录.md)；现在的文件见 [开发说明](../../开发说明.md) 与 docs/dev/ 下的各篇。

用户要的：“资源库放到左上角，让资源库更易编辑”。批准的做法：顶栏最左边一个“资源库”按钮，从左上角展开；编辑器放在右栏、列表留在左栏；引用从带搜索的下拉里选；倾向画成表（能按时代）；文化组的倾向、时代的等级比例、格局都能改；原样的 JSON 框都换成成块的控件；改内置的一项不另起 id、写“改过”、能“恢复内置”；双击改名、拖动换先后；记着收起的样子与上次的种类（存不了时照常用）；长列表只画看得见的行。不碰计算。

## 位置

- 顶栏左边那组最前面是“资源库”（`shell/TopBar.tsx` 的 `RepoButton`，图标 `Boxes`），再点一下关上（`store.ts` 的 `toggleRepo`）；打开时关掉别的弹出面板。“世界”菜单里的“资源库…”照旧。
- 面板仍在 `top: 60px; left: var(--sp-2)`（就在按钮下面），宽 `min(980px, 100% - 16px)`；`transform-origin: top left` 的 160 ms 展开（`repo-unfold`，减少动画时不放）。

## 布局：左栏列表，右栏详情与编辑器

- 以前两栏是“本世界 | 资源库”，点“编辑”时编辑器盖住整个面板。现在左栏是这两段上下摊成的一长列（各自能收起），右栏是选中的那一项：名字、种类与来源、说明、示例、在用的地方，一排按钮（添加到本世界 / 移出本世界、定位、恢复内置、编辑（生态、河、湖、岛开各自的编辑器）、设为默认、存进资源库、导出文件、从库里删除），下面就是它的字段。
- 选中就摊开字段（`edit.ts` 的 `startEdit`）：在本世界的从世界里的那一份改起；不在的从资源库里那一份改起，记下它来自哪个包（`from`）。编辑器记着开始时的样子（`RepoEdit.base`），和它不一样才算改过：“用到本世界”在本世界的项没改过时灰掉，多一个“还原”。
- 世界变了（撤销、重做、别处改了）而编辑器里没改过时，编辑器换成新的样子（`RepoPanel` 里按选中的那一行的 `item` 再 `startEdit`）；改过的不动。用到本世界之后不再算改过；新建、复制的用到后选中本世界里的那一行。
- Esc：先取消选中（右栏收起），再按一次关上（`shell/keys.ts`）。窄屏（≤ 720 px）左右两栏上下排，各占一半。
- `RepoPanel.tsx` 原来 939 行，按职责拆开：`RepoPanel.tsx`（外壳、展开的状态）、`RepoList.tsx`（左栏）、`RepoDetail.tsx`（右栏）、`RepoPreview.ts`（停一下预览，原样搬）、`repo-actions.ts`（各个按钮做的事）、`edit.ts`（编辑的规则，不碰界面）、`lines.ts`（摊成一长列）、`prefs.ts`（记着的样子）。

## 长列表只画看得见的行

- `lines.ts` 的 `treeLines` 把两段的树按展开的样子摊成一行一行（段、包、项、空），每行一样高（`LINE_H` = 28，就是 `--h-sm`）；`visibleRange` 按滚动的位置给出要画的那几十行（上下各多画 8 行）。`RepoList` 外面撑出整列的高度，里面那几十行 `translateY` 挪到看得见的地方。原来每次展开一个包就把里面几百行都画出来，每一行还要算一遍“添加”的命令（`planPack`）。
- 每一行的“添加”只在鼠标停着、点下去时才算命令（以前每画一行算一次）；能不能添加看状态就够（`!on && !locked`）。
- 量到的（Chrome，1400×900，演示世界；机器很忙，平均负载约 20）：种类“文化”、搜索 “a”（全展开）一长列 858 行、画出来 32 行；“全部”、搜索 “a” 1638 行；打开面板 23 ms；换种类、搜索、滚动整列都没有超过 50 ms 的长任务（PerformanceObserver 的 longtask），只在第一次滚动时有一次 328 ms（之后几次复现不出来，像是别的事）。选中一个文化摊开编辑器有一次 54 ms。
- `packTree` 本身（Node、1.2 万格的世界、全部内置包，七次的中位数）：全部种类 29.6 ms（第四十四轮 22.4 ms：多出来的是本世界每一项要看是不是改过的内置项），只看文化 0.9 ms（不变）。冷启动的第一次约 250 ms，第四十四轮也一样（建内置的索引）。

## 引用从下拉里选

- 字段表（`FieldDesc`）多了 `ref`（text、tags 的值引用什么）、`keyRef`（map、title 的键引用什么）。值是内容种类的 id，或三种不是内容的：`dimension`（时代里的维度，另加政体 `government`：倾向里政体也算一维）、`govCategory`（政体的类别：`CATEGORY_NAMES` 的和政体里写到的）、`tolerance`（生态的条件：内置的场、离某种河湖、自定义场）。
- 写了的：文化的组与地名风格、文化组的地名风格、取值与取值组的维度、取值的组、政体的类别、换说法与限谁用里的文化组 / 文化 / 取值组 / 取值、称号的键（国家等级）、派系来源的维度 / 取值 / 文化 / 文化组、派系基础的键、地标的文化组与政体类别、地标名字的键（文化或文化组）、点“当作城市”的等级、格局与时代的各等级、水体的“只在这些生态里”、规则里的生态、生态侵占的目标、耐受条件的场。
- `refs.ts` 的 `refOptions(ref, {world, lib})`：本世界的在前，再按资源库的先后，同一个 id 只列一次；文化的说明是组名、取值带维度（倾向的表按它筛）、国家等级按高低排。按（资源库、世界的小状态）缓存。`searchRefs`：名字、id、说明里有这几个字的，开头就对上的排前面，最多列 80 个，其余写“还有 N 个”。
- `RefPicker.tsx`：按钮写选着的名字（悬停写 id），点开是搜索框和一列（色块、名字、灰色的说明 · id）；方向键、回车、Esc；列表里没有的 id 也能照写（“用“xxx””，只认字母数字下划线连字符）；能不写的多一行“（不写）”。一组引用（tags）是一排小块，最后一个“添加”。

## 倾向的表

- 新的字段种类 `tendencies`（`byEra` 是按时代的那一份）。文化组、文化的两个字段画在同一张表里（`TendencyEditor.tsx`）：表上面选“不分时代”或某个时代（写过的时代后面写“· 写了”），行是维度，每行几个取值：色块、名字、权重（数字框，0–1000）、占这一维的百分比、删除；行末“添加”从这一维的取值里选（政体那一维列政体），表下“添加维度”。文化下面写沿用文化组的几维（每维前三个）。
- 规则在 `tendency.ts`（不碰界面）：权重 1 存回只写 id 的样子；一个时代删空了去掉这个时代，整份删空了去掉字段。格式照 core 的 `weightedIdsSchema`。
- 用数字框不用滑块：一行里几个取值并排，滑块放不下；权重没有上限的意义（比例才有），旁边的百分比就是比例。

## 原样的 JSON 框都换掉了

新加的字段种类：`tuple`（固定几位的数，`items` 是每一位）、`tuples`（一组固定几位的）、`title`（称号：一种写法，或“键 → 一种”的表）、`titleList`（几种称号的写法）、`tendencies`。查过全部登记的种类（`library-edit.test.ts` 一层层往下走）：没有不带 `of` 的 `json` 了。

| 字段 | 以前 | 现在 |
| --- | --- | --- |
| 时代的年份 | `[最早, 现在]` | `tuple`：两个数字框 |
| 时代的国家等级比例（以前不在字段表里，只能改 JSON 文件） | — | 按国家等级的比例表（每级一个数，旁边写百分比） |
| 时代的国家关系（以前不在字段表里） | — | 邦联、联邦、同盟的个数，附庸的种类各占多少，帝国 / 联邦 / 同盟 / 成员邦的称号（`titleList`） |
| 时代的无主地 | 少了 `bandKm` | 加上“划进国家” |
| 地名风格的音节数 | `[[音节数, 权重], …]` | `tuples`：一行两个数，能拖动 |
| 政体的国家称号、统治者称号；换说法里的两项 | `json`（按 key 认出来换成一行一种） | `title`，键从国家等级里选（另有“其余”） |
| 地标类型的名字写法 | `json` | `title`，键从文化、文化组里选 |
| 河流、湖泊类型的岸边的影响 | `json` | 范围、变暖变冷、变湿变干 |
| 生态的耐受条件、样子、对周围的影响、地名设定 | `json` | 列表（条件从场里选）、花纹与颜色、气候与侵占（目标从生态里选）、类型名与起名模板 |
| 星球形态的配方、微调 | `json` | 各项的数字框、开关，几个范围是 `tuple` |
| 格局的各等级占多少 | 键手写 | 按国家等级的比例表 |

- 可以不写的一组字段没写时只有一个“添加”，写了的右上角能删掉整个（以前没写时画出一个假的空对象）。
- 生态、星球形态的这几个字段在资源库里看不到（生态有自己的编辑器，星球形态在“调整 → 星球形态”里改），换掉是为了字段表完整、导出的资源包检查时说得清位置。
- 原样的 JSON 框（`JsonInput`）留着：以后登记的种类写了不带 `of` 的 `json` 时还能编辑。音节数没给默认值：刚换成音译式时照旧说“音节数：至少要有一个”（`repo.test.ts` 查着）。

## 改内置的一项

- 以前编辑不在本世界的内置项是复制一份（`id-2`，名字带编号）。现在从内置的那一份改起，用到本世界时同一个 id、同一个名字，命令带上 `from`（它在内置的树里的位置）。没改就点“用到本世界”的照“添加”（按资源包的规则）。本世界里已有同 id 的另一份（不是这一项改过的）时才另起 id。
- 改过：`repo.ts` 的 `builtinOriginal`——来源记的是内置的树（或没记）、内置的树里有同 id 的一项、内容不一样（`isBuiltinSame` 不算），给出内置的原样。本世界那一段的行写“改过”；资源库那一段里记着的那个内置包的同一项算在本世界（打勾，也写“改过”），不再写“添加后叫 X 2”。别的时代包里的同一项照旧（添加后改名）。
- 恢复内置（`edit.ts` 的 `restoreCommand`）：整项换回内置的原样，来源照旧，一步、可以撤销。只给整项换掉的几种（放在 `small.content` 的，河、湖、岛的种类）；生态的命令是按字段改的，不给。
- 编辑器的“复制”照旧另起 id（名字带编号）。

## 双击改名、拖动换先后

- 双击名字原地改：本世界里的是一步命令（`改名为“X”`，`renameCommand`），我的资源里的直接改资源库（`library.ts` 的 `editMineList`：按路径找到小包的那一段，改完照格式查一遍再存）。名字按这一种的格式查（空的、太长的说为什么）。内置的、装上的包里的不能改名。
- 拖动：我的资源里的项在同一个小包、同一种里换先后（`sameShelf`、`reorderById`）。本世界里的不能拖：先后是编号（文化、取值的编号在人口数据里），换了人文的数据就乱了，要改 core 才行，这一轮不碰。
- 编辑器里的列表（换说法、限谁用的几条——第一条满足的起作用、规则、喜欢的地方、音节、称号、带权重的一组、音节数）左边有把手，拖动换先后（`editors.tsx` 的 `useDragSort`、`fields.ts` 的 `moveItem`）。

## 记着的样子

- `prefs.ts`：`localStorage` 的 `map2.repo` 存上次的种类、展开的包（最多 300 个）、收起的段。读、写、连拿 `localStorage` 这个属性都包在 try 里；抛错、读回坏的时照默认（全部、都收起、两段都展开）。存不了时 `saveRepoPrefs` 返回 false，界面照常用（只是关上再打开不记得）。只看一个包时的整个展开不记。

## 测试

- `src/ui/packs/library-edit.test.ts`（13 个）：字段表里没有原样的 JSON、引用写着是哪一种；选文化组（列着、名字与颜色、按名字和 id 搜、选了格式照样对）；维度、取值的维度、文化的组名、国家等级的先后、称号的键；倾向的表（改权重、权重 1 存回 id、加删取值、按时代加一维、删空了去掉）；本世界的内置国家等级改了用到本世界（id、名字不变、两段都写改过、恢复内置换回原样）；不在本世界的内置文化组改了直接用（不另起 id、记来源、没改时照添加）；能编辑的种类；本世界的一项改名（一步、空的太长的不行）；我的资源能改名能拖、只能拖到同一个小包；记着的样子（读写、坏的、读写抛错、拿 `localStorage` 抛错时资源库照样开、存得了时用上次的种类）；410 个文化全展开时画出来的不到 45 行。
- `repo.test.ts`、`countries-ui.test.ts` 照旧通过（`isTitleField` 改成认 `title` 这一种，两处的键不变）。没有快照要重录（界面的快照只有 `tool-replay.json`，与资源库无关）。

## 速度

- 不碰计算：core 里只改了字段表（编辑器用的说明），计算 Worker 不读它。
- `node tools/bench-median.mjs 5 --against 25d9356`（第四十四轮的最后一个提交）：工具判定加工都没有比旧的慢 5% 以上。第一次（平均负载约 20–30）island +5%、climateBrush +8%、paintLandPreview −10%，再跑一次（负载约 5）paintLand −20%、relief +4%、island +0%、climateBrush −15%：都是机器忙闲的起伏，计算的代码没有动。
- 全部测试（负载约 30 时）1748 个里 8 个超时或超预算（`planet`、`outline`、`undo-cache`、`river-pack`、`river-speed`、`tools/realism`），都是计算的测试，单独重跑都通过。
