# 第六十一轮的设计

这一轮改了什么见 [更新记录](../../更新记录.md)；现在的文件见 [开发说明](../../开发说明.md) 与 docs/dev/ 下的各篇。

用户要的：右上角一个小的“导入”：选一个库，勾要的内容，下面列“还会带上：……”（依赖自动勾上，可以取消），不会留下找不到的引用。导入一个需要某变量的政体时，变量跟着来。

## 闭包

`core/packs/closure.ts`。`importPreview({ source, target, picks, off, on })` 给出窗口要写的一切，`importCommand`（世界）、`importToPack`（库）写入，都从它来。引用只从第四十九轮的表读（`linkTable`、`stripLinks`、`renameLinks`、`settleIds`），没有另写“谁引用谁”。第四十九轮的 `dependencyClosure` 没有用：它不知道目的地有什么、不认取消、不走变量，所以这里有自己的走法，读同一张表。

| 引用的类别 | 导入时 | 取消 |
| --- | --- | --- |
| `hard` | 带 | 去得掉的（`link.drop`）能取消，去掉这条引用；去不掉的（文化的组、脚本里写的）锁着，写“少了它 X 用不了” |
| `auto` | 带 | 能取消，去掉这条引用。`only` 就是解除限制，窗口写“取消后解除这条限制，谁都能用” |
| `strip` | 不带。目的地有同 id 的目标时留着，没有时去掉 | |

勾组时带上“组里有什么”（文化组的文化、取值组的取值），标 `member`，能单独取消。读的是融入的表（`RELATIONS`）。依赖带来的组不带：一个政体 `only` 写了 29 个文化组（原住民议会）时，只带这 29 个组，比重 0，不带它们的文化。

**为什么**：每一项记着从哪里走到的（“社会主义共和国 需要 革命左翼”），最多写三句，再多写“等 N 处”。

**去掉的引用**：同一处只说一次（派系的一条来源写了变量和取值，是一处），写目标的名字，收在“去掉的引用”里。

## 变量

变量不是一项内容，写在目的地的时代里；取值、取值组是它的一部分，带它就一起带（取值不单独列，算一项）。

**什么算要变量**：`hard`、`auto` 的引用（取值的维度）；还有派系**主要靠的那一维**（`NEEDS`：来源里权重加起来最大的那一维）。派系的来源在表里是 `strip`，全带的话社会主义共和国的自由派会多拖一个民族认同（自由派：意识形态 6、民族认同 2.2），奇幻世界一下多两个变量；全不带的话导入后派系没有来源，变量也不来。

- 主要的那一维：按 `auto` 算。目的地没有这一维时带整个变量；有这一维时（比如科幻的 `ideology`）写到的取值单独带。
- 别的维：`strip`，去掉那几条来源。这个变量列在“可以带上”，默认不勾，勾上才加、才留下这几条。文化的倾向写到的变量同样列在这里。

**世界里**：batch 里先加各项，最后 `add_dimension`（第五十四轮，只算新变量），要写明加到世界的时代（`human.era`，没有人文时第一个时代）。

**库里**：写进目的地第一个时代的 `dimensions`，`{ required: true, added: true }` 和世界里一样，用这个库新建世界时也是原地分开，不和别的维排列组合。

**目的地没有时代**（新建的世界还没生成人文、空的库）：带上来源里提供这个变量的时代，写“意识形态 写在 现代 里”。不要这个时代时变量也不带，来源去掉。

**上限**：一个时代最多 8 个变量，超了不加，写明。

## 比重

依赖带来的文化组写 `weight: 0`，生成时不参与（`generate.ts` 第五十轮就这样）；世界里“文化 ⋯”的默认选择也不勾它（`human.ts` 的 `beyondWeights`）。勾的组保留比重，比重是 0 的去掉这个 0（和 `packImportPlan` 的“点名了”一样）。

比较不看 `weight`：`cultureGroup` 的 `sameIgnore`（第四十九轮留的）。所以依赖带来的 `weight: 0` 再导入一次还是同一项。

## 已经有了、撞名

比的是**导入时的样子**：引用去掉、比重写好之后。所以同样的勾选再导入一次全部已经有了（门槛一每一轮都查）。

但是原样也算：从中世纪库建的世界，文化写着别的时代的倾向（`eraTendencies.modern`），世界里只有中世纪这个时代，这条引用“找不到”，来源那份和世界那份都写着。只比导入时的样子的话，这个文化去掉引用后和世界那份不一样，就改名成 `-2`。第一版真的这样：中世纪导入中世纪的副本，476 项全部改名。现在目的地那份和来源原样相同、或和导入时的样子相同，都算已经有了（门槛：`从一个库导入它的副本：一项都不加`）。

**已经有了的项不再往下走**：目的地那一份有它自己的依赖。认出来以后引用可能少一些，再算一遍；`skip` 只增不减，所以停得下来。撞名的（内容不同、id 相同）交给 `settleIds`，改名、引用跟着改，和第四十九轮一样。

**取消的依赖目的地有同 id 的**：引用留着，指到目的地那一份，不改名。

## 窗口

`src/ui/packs/ImportDialog.tsx`，逻辑在 `page-import.ts`。

- **看内置的库、导入的库时点“导入”**：先问。“导入本世界”（从这个库挑）、“复制成我的库”（复制后导入到副本）、取消。没有世界时只有后两个。
- **目的地**：面板正在看的本世界或我的库。
- **来源**：`LibraryPick` 的下拉（内置、我的、导入的，不列目的地自己），“读文件…”读 `*.map2pack.json`（`readPack`：只解析不运行脚本）。读了文件时有“装进资源库…”，走旧的 `PackDialog`。
- **勾**：按种类分组（先后同首页），默认收着，能搜索（名字、id、灰字），组的勾选框勾整组，先画 60 行。还有一段“变量”：来源的时代写了、目的地的时代没有的，能直接勾。行上灰字写已经有了、同 id 内容不同、还会带上、会改名。
- **确认**：世界里按最新的世界再算一遍（`queueWorld`），有没信任过的脚本时先问（`runTrusted`）；库里 `libEdits.setPack`：先 `parsePack`（读不回来的不写），一步撤销，马上写整个库。导入到库不问脚本：库里的脚本到用进世界时才问。
- **从别的库加**：列表上一个按钮、上级页面“加 X”的下拉里多列别的库的（灰字写哪个库，同 id 列第一个库）。选一个打开窗口并勾好它；上级页面上的还带着 `onto`：导入时放到这个上级下面，同一步。

## 旧路

`PageList` 的“添加”“全部添加”走 `addRows`：同一个闭包。不用加变量时直接加（单独加一个政体也带上派系），提示“还带上了：……”；要加变量、放不下、带不了时先打开窗口。替用户定的：加变量会动人口，所以要看一眼。

没动的：旧面板的 `addCommand`、`packAddCommand`（`RepoList`，第 63 轮删）；档案里换政体的 `addFromLibrary`（第五十三轮，带派系，不带变量和限谁用的组）：换政体不该顺手加变量。它可能留下 `only` 写到的、世界里没有的组，和以前一样。

## 安排

`importIntoPack` 留目的地的 `arrange`（`nestByKind` 带着），来源的不看。有测试。

## 写进库的位置

`importIntoPack` 以前全放进按种类分的小包。文化组放在那里新世界带不上（第五十九轮 `addItem` 同样的理由），所以有“文化”小包时放进它下面自己的小包（比重 0 的小包点名才带），文化跟着组；取值、取值组放进同一维的小包。也不再 `structuredClone` 整个目的地：包是不改动的数据，没碰的小包和原来是同一个对象。

## 替用户定的

- 内置的库上点导入：问，不是灰掉。
- 派系只把**主要的那一维**算要带的变量（上面写了），社会主义因此只带意识形态。第 61 轮的例子就是这样要的，代价是自由派少两条来源，勾“民族认同”就留着。
- `addRows` 要加变量时开窗口，别的直接加。
- 勾组带上组里的文化，依赖带来的组不带。
- 单独勾一个文化时，组是依赖，比重 0：这个文化不会生成。要它参与就勾组。
- 变量带上全部取值，不能只挑几个。
- 已经有的组（比重 0）再勾一次不会改比重：导入只加东西，不改目的地的项。要参与在文化组页面改比重，或“文化 ⋯”里勾上。
- 取消依赖时目的地有同 id 的：指到目的地那一份。

## 量到的

**闭包的速度**（Node，`importPreview`，目的地是库，负载约 5；世界做目的地没有单独量）。中世纪勾全部（727 项，含文化、92 种风格）：

| 目的地 | 第一次 | 之后几次 |
| --- | --- | --- |
| 空的库 | 103 ms（含建来源的引用表） | 22–42 ms |
| 奇幻的副本 | 112 ms | 32–34 ms |
| 中世纪的副本（全部已经有了） | 29 ms | 20–22 ms |

勾一项（伊克塔）1–2 ms。第一次超过 50 ms：要建表、算比较用的字，只有一次，所以没有再压。之后的都在 50 ms 以内。优化之前（每次比一遍 JSON）奇幻 450 ms、中世纪 720 ms，所以有了 `contentKey`、`strippedItem` 这两个按对象记的表，已经有了的项也不再进 `settleIds`。

**编辑不变慢**：计算 Worker 打包和 0ba085c 逐字节相同（sha1：`worker-CTbdWy9H.js` 17e6cea3、`mesh-worker` bc829346、`export-worker` ad113040、`storage-worker` 3a8d7f83），所以应用里的编辑一步都不可能变慢。`core/` 的改动只有新文件、`importIntoPack`、两个 `export`。下面是照规矩量的（`bench-median 5`，负载 4–8，一次一个任务）：

| | 对 0ba085c 标出来的 | 同一份代码对照自己（`--against HEAD`）标出来的 |
| --- | --- | --- |
| `--library` | 没有（`libEdit` 1.27 → 1.13、`libUndo` 2.94 → 2.87、`libRedo` 1.26 → 1.12、`libContent` 1.24 → 1.18、`libPost` 1.01 → 1.01 ms） | 没有量 |
| 区域 | `erod` +6%、`island` +10%、`latShift` +9% | `paintLand` +5%、`latShift` +6%、`hotRelief` +12% |
| `--globe` | `relief` +13%、`tempBrush` +15%、`paintLand` +17%、`island` +24%、`reroll` +5%、`rerollFjord` +12%、`river` +16%、`lake` +6%、`humidity` +6%、`latShift` +5%、`hotRelief` +6% | `relief` +23%、`rivers` +42%、`coast` +41%、`paintLand` +10%、`island` +11%、`reroll` +21%、`rerollFjord` +8%、`lake` +15%、`humidity` +30%、`latShift` +12% |

代码完全一样时比这还宽，所以这些标记不算数。**标了但没有单独量的**：这一轮没有做同进程交替（第 57 轮的做法），`erod`、`island`、`latShift`、`tempBrush`、`river`、`hotRelief` 这些步骤靠的是 Worker 逐字节相同，和表里的宽度。

**画法**：`compose-ab --against 0ba085c` 714 组 0 组不同；`overlay-ab --against 0ba085c` 直接画、一串帧都 0 字节不同。

**金标准**：一个都没重录，`src/testing/frozen/` 没动。

**门槛一**：六个库两两 30 对，世界和库各 6 轮，每轮随机抽 1–12 项（固定种子），40% 的依赖随机取消，30% 的可选变量随机勾上。新的找不到的引用 0 条；导入后每一项都通过格式检查；同样的勾选再导入一次 0 项；世界一步撤销回到原样。这里的“世界”是只有内容的 1000 格世界，有人文的世界在门槛二。库里本来就有的（比如政体写到世界没带的文化组）不算新的。

**界面**在无头 Chrome 里真的走过：奇幻世界导入社会主义（窗口、还会带上、取消依赖、确认），时代多了意识形态，撤销、重做；“国家 ⋯ → 重新生成”后伊薇法秘法领变成“伊薇法人民共和国 社会主义共和国”。读文件 + 撞名（`liberals` → `liberals-2`）。内置库上问话、复制成我的库、导入、撤销、重做、刷新不丢。上级页面的下拉选别的库的派系，一步撤销。窄窗口 420 px 没有横向滚动。没有试过：触摸屏；列表上的“添加”走窗口的那条路只有测试（界面上点的那个没加变量，走的是直接加）；有脚本的文件导入世界时的信任问话。

## 坑

- **第 62 轮**：世界里导入的项 `small.origin` 记着来源的库，`originId` 记改名前的 id（`planPack` 写的）。去掉了引用的项和库里的不一样，第 62 轮的“和来源的差异”会标成改过：比较时要想好（比如也按 `stripLinks` 的结果比，或者先说明）。依赖带来的组比重 0，比较忽略 `weight`，不标。
- **第 62 轮**：“用库里的版本”用在时代上要留着世界加过的变量（`added`），这一轮导入加的也是 `added`。
- **第 62 轮**：`regenLine` 只写在窗口里和提示里，“重新生成”按钮那一轮做。
- **第 63 轮**：`repo.ts` 的 `addCommand`、`packAddCommand` 只有旧面板在用了，删 `Repo*` 时一起删。
- **同 id 不同意思的变量**：现代的 `ideology` 叫“意识形态”，科幻的 `ideology` 叫“阵营”，取值不同。两个库都导入时算同一个变量，取值放在一起。id 相同就是同一维，第五十二轮换库时也这样。
- **`contentKey` 按对象记比较用的字**：包和世界里的项不能就地改（一直是这样）。改了的话这里会认错。
- **不在 Worker**：`closure.ts`、`NEEDS`、`OFF_NOTES` 只在主线程，所以计算 Worker 一个字节都没变。不要写进 `link-rules.ts`、字段表（第一版这样写过，Worker 就变了）。
