# 第三十轮的设计

从开发说明里搬来（第四十一轮）。这一轮改了什么见 [更新记录](../../更新记录.md)；现在的文件见 [开发说明](../../开发说明.md) 与 docs/dev/ 下的各篇。

## 时代包与只读世界内容（第三十轮）

时代就是资源包；基础、自然、中文地名、星球形态也都是普通的包。生成、起名、宜居度、资源、城市地标只读世界里的内容，计算 Worker 里不再有内置数据。前面几节里“总在世界里的内置项”“生成时从内置的复制进来”“内置中文（`small.wordPack`）”的说法以这一节为准。

- **内置数据只在主线程**：时代、取值、文化组、文化（`core/packs/eras/`）、政体与派系（`governments/`）、地名风格（`names/`）、城市等级与地标与点（`settlements/`）、地形类别与通用和奇幻的资源与岛的种类（`packs/base.ts`）、13 种生态（`packs/nature.ts`）、六种星球形态（`packs/planet-forms.ts`）、写实与地图册两种画风（`packs/map-styles.ts`，第三十八轮）、奇幻的生态河湖形态，都只由内置的树（`packs/builtin-tree.ts`）引用；引擎的代码一个都不引用。`src/worker-imports.test.ts` 从 `src/worker.ts` 起顺着 import 走一遍，走到的文件里不能有 `core/packs/` 下的；`tools/isolated-engine.test.ts` 查打包出来的计算 Worker 里没有内置的政体、时代名。打包好的程序里计算 Worker 做成 data: 地址从 1,358,360 字符降到 925,960（开发时现打包的：不压缩 2,288,892 → 1,615,088，已在上限以内不必再压缩；压缩后 1,816,332 → 1,215,040）。
- **登记表的内置项由树给出**（`content/registry.ts`）：去掉了 `ContentKind.builtin()` 与 `alwaysOn()`。`builtin-tree.ts` 载入时 `useBuiltinSource({items, same})` 接上，`builtinOf(kind)`（资源库列内置的）、`isBuiltinCopy(kind, item)` / `notBuiltin(kind, items)`（导出时去掉内置原样的）在主线程按树查；计算 Worker 里查到的都是“没有”。`RemovedItem` 不再带 `builtinSame`，“是不是内置原样”由界面按树判断（`library.ts` 的 `worthKeeping` 本来就再看一遍 `isBuiltinSame`）。
- **时代包**（`builtin-tree.ts`，数据在 `packs/eras/*.json`）：
  - 时代项只有规则：`dimensions`、`popDensity`、`sparsity`、`urbanization`、`unclaimed`、`seaClaimKm`、`countryKm2`、`tiers`、`relations`、`years`（`eraSchema` 去掉了 `governments`、`factions`、`defaultGroups`、`cultureGroups`、`resources`）。
  - 时代文件多一段 `pack`：`governments`、`factions`（按列的先后）、`cultures`（默认带的文化组与权重）、`resources`（基础之外的，只有奇幻）；`index.ts` 读成 `ERA_PACKS`。取值、政体、派系、地标文件里写的 `eras` 只用来归包（`VALUE_ERAS`、`GOV_ERAS`、`LANDMARK_ERAS`），读进来的项不带它；`popValue`、`cultureGroup`、`government`、`faction`、`landmarkType` 的格式去掉了 `eras`：在不在世界里就是能不能用（`dimensionValues`、`eraGovernments`、`eraFactions` 都是世界里的全部，按加进世界的先后）。
  - 大包的小包：`era`、每个维度一个、`governments`、`factions`、`resources`（奇幻）、`landmarks`（这个时代的地标：自己的和不分时代的，按 landmarks.json 的先后）、`cultures ▸ <组>`（小包带 `weight`：默认的权重，`PackNode.weight`，`parsePack` 认）；奇幻另有 `biomes`、`rivers`、`lakes`、`forms`。通用（`common`）：`base`（地形类别、通用资源、城市等级、不分时代的地标、点、岛的种类）、`nature`（13 种生态，写明 `natural: true`）、`names ▸ zh`（中文·默认）与按地区的几个、`forms`（星球形态）、`styles`（画风，第三十八轮）、`cultures ▸ <组>`。文化组的小包也带上组里文化用的中文·默认。
- **生成只读世界里的内容**（`human/generate.ts`）：
  - `generate_human {packs, groups, totalPop?, seed?, countries?, settlements?}`：`packs` 是勾选的包（资源库里的路径，按先后），记进 `small.human.packs`。规则用 `ruleEra(small, packs)`：第一个包下面（`small.origin` 的路径以它开头）的时代；都对不上时世界里第一个时代。`small.human.era` 是定下来的那个时代，`worldEra` 照旧读它；维度只用它的。`regenerate_human`、`generate_countries`、`regenerate_countries` 多了可选的 `packs`、`groups`。
  - 去掉了 `ensureHumanContent`、`ensureGovContent`、`bringGovernment`、`nearestEra`、`builtinOrder`、`recordBuiltinOrigins`：内容由界面先加进世界（见下）。档案里换成世界里没有的政体时 `set_country` 报错“世界里没有政体“x”：先从资源库添加它”，界面先发一条带 `from` 的 `set_content`。
  - 生成后的清理（`prune.ts`）照第二十九轮的规则，但不论是不是内置原样：没用到的都移出，移出的列在命令结果里，界面把不是内置原样的存进资源库。所以清理过之后再生成国家、人文，界面要再发一遍加内容的命令（世界里有的跳过，先后排回包里的）。
- **加内容的命令**（`core/packs/import.ts`，主线程）：`packImportPlan(library, {packs, groups?, extra?}, world?)` / `packImportCommands(...)`：
  - `library` 是 `ResourcePack[]`（内置的大包，键就是 id）或 `{key, pack}[]`（资源库）。`packs` 里第一个带时代项的包给规则（只带它的那一个时代项）；时代包（树里有时代项的）只带生成要用的几种：时代、规则时代的维度的取值、政体、派系、地标、城市等级、点的类型、选了的文化组（组、组里的文化、它们用的地名风格）；奇幻包里的生态、河湖、资源要单独勾那个小包（`['fantasy', 'biomes']`）。别的包整个带进来。`groups` 省略时是勾选的包里的全部组；选了、勾选的包里没有的组在资源库里找第一个有它的小包。星球形态不带。
  - 合成一个包交给 `planPack`（`PlanOptions.origin` 让每一项的来源是它原来所在的小包，`label`），一整步 batch；世界里已有一模一样的跳过，同 id 不同的改名。最后对取值、政体、派系、文化组、文化、地标类型各发一条 `order_content {kind, ids}`：列着的排进它们占着的位置（与以前的 `builtinOrder` 一样），清理过再加回来的排回包里的先后，重新生成与第一次一样。
  - `newWorldContentCommands(library?, packs = DEFAULT_WORLD_PACKS)`：新世界默认加的基础、自然、中文地名、画风（`[common, base]`、`[common, nature]`、`[common, names, zh]`，第三十八轮起还有 `[common, styles]`）。向导新建（`ui/forms.ts` 的 `newWorldCommands`）把它们放在第一步里、`set_worldgen` 之前；缩略图请求（`thumb`）带 `content`；测试的 `engineFor`、`continents` 默认先执行它（`bare` 时不）。
- **缺了就跳过**（`content/missing.ts` 的 `missingNotes(small, scopes)`）：`applyCommand` 的结果多了 `skipped: string[]`（batch 里每一条的合起来），`Engine.lastSkipped`，Worker 的 exec 回复带 `skipped`（`noop` 的回复也带），界面说一次。
  - 新世界（`set_worldgen` 带 reset）：没有生态 → 植被为空（主导生态是 −2，没有一种适合）；没有地形类别 → 类别层为空，通行难度、宜居度、资源规则里的类别都按平地（`rules.ts` 的 `compileRule`：写了平地的条件满足，别的不满足）；没有资源 → 没有资源层；没有岛的种类 → 放的岛都是普通的岛（`terrain.ts` 的 `PLAIN_ISLAND`，编号 0；世界里有岛的种类、只是没有这一种时照旧报错；没有碎岛时岛链不换碎岛）；没有地名风格 → 不起名（`NO_STYLE`，名字是空的）。
  - 生成人文：没有时代、或选的文化组世界里一个文化都没有 → 不生成（已有的人文去掉），说明在 `skipped` 的最前面；`regenerate_*` 遇到这种情况报错。没有政体 → 不生成国家（`growCountries` 里一个都没有时 `small.countries` 去掉）；没有派系 → 国家没有派系。没有城市等级 → 不放城市、道路（`generateCities` 只去掉自动的；已有的城市按 `PLAIN_RANK` 显示）；没有地标类型 → 不放地标。
- **基础是普通内容**：
  - 地形类别、资源、城市等级、地标、点的类型：`worldTerrainClasses`、`worldResources`、`worldCityRanks`……只读 `small.content`（以前内置的总在、世界里同 id 的换掉内置的）。编号按世界里的先后；新建时按内置的先后加进来，与以前的编号相同。宜居度的倍数写在类别自己身上（`habitability`，内置的与以前的 `CLASS_HABITABILITY` 相同），没写为 1。
  - 岛的种类：`small.islandTypes` 里有内置的五种（新建时按大陆岛、低平岛、珊瑚岛、小礁、碎岛加进来，编号 1–5 与以前相同）；`islandTypeSchema` 不再拒绝内置的 id，多了 `hint`。删掉一种时这种岛变成世界里的大陆岛（没有时 0）。只有带起名模板的种类的岛打 `itype:` 标签（以前是自己的都打），加上、去掉模板时重算地物。
  - 地名风格：中文·默认是 `small.content.nameStyle` 里的普通一项；去掉了 `small.wordPack`、`set_word_pack`。世界默认 `worldStyleId`：选了的（还在世界里），否则世界里第一种，一种都没有时 `''`；`set_name_style null` 是“不选”。起名的风格标识都是内容的哈希。生态、河湖、岛的种类自带的中文模板在风格是音译式、或缺词表时用 `chineseTemplate(small)`（世界里的中文·默认，没有时第一种模板式的）。
- **生态自己带算法要的字段**（`speciesSchema`）：`habitability`、`movement`（以前就有）、`group`（新：`desert | forest | tundra | icecap | wetland`，涂出来的一片按这一类识别、起名；没写时自己的一片是“生态区”，大片的地区按地形归类）。去掉了按 id 查的 `BIOME_HABITABILITY`、`BIOME_MOVEMENT`、`features.ts` 的内置生态表；13 种内置生态的值与原表逐个相同（`era-packs.test.ts` 逐个对），金标准不变。没写时的估法照旧（宜居度按地形与气温，通行按 `TERRAIN_MOVEMENT`，没有时 1）。`defaultSmall` 不再有生态。
- **星球形态**：以前向导里写死的 `PLANET_TYPES` 是“通用 ▸ 星球形态”里的六个形态（`BUILTIN_PLANET_FORMS`，id 照旧：continents、continent、fragmented、archipelago、ocean_islands、blank）；海洋星球的“岛多少 0.7”写在 `profile.islands` 里。用它们新建的世界与以前逐值相同（测试逐种对原因与推导）。`presets.ts` 只留生成器种类的叫法 `planetKindName(type, islands?)`（历史里的“新世界“像地球””、形态的“从哪种星球改起”）。
- **清掉的**：`FANTASY_PACK`、`FANTASY_PACK_ID`、`NAME_STYLES_PACK`（测试里用 `testing/fixtures.ts` 的 `FANTASY_SAMPLE`、`NAME_STYLES_SAMPLE`），`builtin-base.ts` 并进了 `builtin-tree.ts`；信任的内置脚本是整棵内置的树（`trust.ts`）。
- **世界文件第 6 版**（`doc-version.ts`）：新世界的命令里多了加内容的一步，生成人文带 `packs`，旧文件打开时说“旧版本的世界文件打不开”。
- **界面**：这一轮核心只做了让界面照旧能用的最少改动——向导第一排的星球是“通用 ▸ 星球形态”的形态，生成人文的命令是“加时代所在的大包 + 生成”一整步（`ui/human.ts` 的 `importCommands`、`eraPack`、`eraPackGroups`），资源库里基础的内容能移出，`exec` 的 `skipped` 用提示条说一次。勾选几个包、规则来自哪个包、缺内容时“从资源库添加…”在界面那一轮做（见下一节）。
- **测试**：`human/era-packs.test.ts`（不先加时代包时写明缺什么；七种设置下生成与清理过再生成国家的摘要与第二十九轮的代码逐个相同（`r29-digests.json` 是用第二十九轮的代码记的）；来源；中世纪 + 奇幻的规则与合集、顺序反过来；单独勾奇幻的生态；`order_content`；什么都不勾、只缺城市等级与地标、没有政体时各自跳过；生态与地形类别的字段与原表；没有生态的世界；六种星球形态；树的结构），`src/worker-imports.test.ts`。重录的摘要：`golden-full.json` 的 `small`（地区、星球各一个），`solver-identity` 的 `world`、`replay`（核对过 digestWorld 除了 `small` 与第二十九轮逐值相同），`raster-identity` 的 `world.json`（四个），`population.test.ts` 的金标准里 `small.human` 去掉 `packs` 后照旧；国家、城市地标的金标准没有变。

## 勾选资源包（第三十轮 界面）

新建向导的“内容”、“文化 ⋯”里的生成人文与“换时代、文化组…”共用一份选择：勾选的包（资源库里的路径，按勾选的先后）与文化组。逻辑在 `src/ui/packChoice.ts`（不碰界面，测试直接调），界面是 `components/PackChecklist.tsx`。

- **资源库的包**（`libRoots(lib)`）：`library.value` 里内置的大包在前，再是我的、装上的（`lib` 里没有内置的时补上 `builtinPacks()`，测试用）。内置的、装上的一视同仁。`nodeAt`、`packLabel`（“通用 ▸ 基础”）、`packHint`（时代包写“时代”，别的写 `packSummary` 的前两种）。
- **勾选**：`packState(packs, path)` 是 on / covered（上一层勾着）/ partial（下面有勾着的）/ off；`togglePack` 勾上时排在最后、下面勾着的小包并进来，它默认带的文化组（`defaultGroupsOf`：小包写了 `weight` 的；一个都没写时包里的全部组，权重 1）跟着勾上；去掉时只由它提供的组跟着去掉。`makeRule` 把一个时代包挪到最前面。新建默认 `defaultPacks`：`DEFAULT_WORLD_PACKS` + `FORMS_PATH` + 中世纪（没有时第一个时代包）；已有的世界第一次生成 `worldDefaultPacks`：默认的几个里在用的 + 时代包。
- **规则**（`rulePack(packs, lib, small?)`）：勾选的包里第一个树里有时代项的，`era` 是那个包的第一个时代项；资源库里找不到时按世界记着的来源（`ruleEra`）。文化组 `packGroups(packs, lib)`：勾选的包里的组，按包、包里的先后，同一组只列一次（记 `pack`：勾着的那个包，界面按它分段；`weight`：小包写的默认权重）。
- **加进世界的命令**（都用 `core/packs/import.ts` 的 `packImportCommands`，带 `from`）：
  - `splitPacks` 分成带时代的与不带的。新建：`worldContentCommands(c, lib, human)` 把不带时代的包整个加进来（要生成人文时只带选了的组），`newWorldCommands` 放在第一步、`set_worldgen` 之前；`humanImportPicks(c, null)` 只带时代包（选的组去掉第一步已经带了的），和 `generate_human {packs: 全部勾选的, groups}` 一起是第二步（`human.ts` 的 `generateCommand`）。
  - 已有的世界（`humanImportPicks(c, small)`）：时代包同上；不带时代的包 `inUse`（`small.human.packs` 里有，或 `small.origin` 里有来自它的项）时只补生成后会清理掉的几种（取值、政体、派系、文化组、文化、地名风格：`extra` 带 picks），没在用的整个加进来。所以自己移出的地形类别、生态不会因为重新生成又加回来。`withPackImports`（重新生成人文、生成 / 重新生成国家之前）按 `small.human` 再加一遍。
  - `regenerateWith`：包与文化组都没变、总人口自动时 null；规则的包与时代都没变时 `keepManual`，变了时国家也重新长。
- **向导**（`Wizard.tsx`）：“内容”一步放 `PackChecklist`（一块地区第 5 步、整个星球第 4 步），“人文”里的 `HumanChoices` 不带勾选（`packs={false}`）。缩略图按 `worldContentCommands(c, lib, false)` 画（按不带时代的包的路径记下，换文化组不重画）。星球形态 `formsInPacks(choices, packs)`：勾选的包里的列着，别的收在“其他包里的形态”（选着的、勾选的包里一个都没有时展开）；`FormChoice` 多了 `path`。
- **缺了内容**：Worker 的 `init` 回复也带 `skipped`（新建的每条命令的合起来）；`state.ts` 的 `skippedNote`（`noteSkipped`），`exec`、新建都设它，新建、打开别的世界时清掉。`shell/SkippedBanner.tsx` 画在提示条上面：一句话（`skipped.ts` 的 `skippedSummary`），几条时“详情”，“从资源库添加…”`openRepo({kind, filter: 'off'})`（`skippedKind` 认出“没有 X”是哪一种，只缺一种时筛成它）。
- **档案里的政体**（`countries.ts`）：`governmentChoices(w, current, lib)` 给 `{gov, path?}`：本世界的，加上 `small.human.packs` 里本世界没有的（`itemsInPacks`）；`governmentCommand` 对本世界没有的先 `addFromLibrary`（`packImportPlan` 的 extra 只挑这一项，同 id 不同内容时用改过的 id），再 `set_country`，一个 batch。`titlePreview` 收政体对象，`fragTitle` 收时代对象（不再读内置常量）。
- 别的：`ClimateChart` 的“示例生态…”打开资源库里第一个有本世界没有的生态的包；`PackDialog` 认内置的包从 `library.value` 读；`repo.ts` 的 `TreeNode.base` 去掉了（“通用 ▸ 基础”是普通的包）。
