# 开发说明

给改代码的人看：程序怎么搭起来的、文件在哪里、怎么测、哪些规则不能破、现在有多快、还差什么。用法见 [使用说明](使用说明.md)，每一轮改了什么见 [更新记录](更新记录.md)。

## 常用命令

```bash
npm install
npm run dev        # 开发服务器，默认 http://localhost:5173（.claude/launch.json 里用 5191）
npm test           # 全部测试
npm run test:fast  # 改代码时常跑的那部分（跳过最慢的几个文件）
npm run golden     # 只跑金标准：提速、重构后结果必须逐值不变
npm run typecheck  # 只查类型
npm run build      # 查类型后打包（一键开启用的就是打包好的程序）
npx tsx tools/generate.ts --seed 3 --out out/seed3   # 命令行批量生成并导出
npx tsx tools/hash.ts                                 # 各层结果的哈希，用来核对 Node 与浏览器是否逐值一致
npx tsx tools/bench.ts --globe                        # 整个星球（新建的类地星球，6.26 万格）各步的耗时；后面写格数可改
npx tsx tools/bench.ts --globe --pack fantasy --hash  # 整个星球 + 奇幻包逐步计时，最后打出世界的哈希
node tools/bench-median.mjs                           # 跑几次 bench 取中位数
```

浏览器控制台里 `await __map2Bench()` 测平移缩放每帧的耗时（`src/render/bench.ts`，按固定的镜头脚本同步地画，窗口藏着时也能测；只看同一台机器上的前后对照）。

一键开启（`启动-Mac.command`、`启动-Windows.bat` → `tools/launch.mjs`）：检查 Node 的版本；第一次（或 `package-lock.json` 改过）先装依赖；地图已经开着就只打开浏览器（代码在它打包之后更新过时提醒关掉重开）；否则先打包（源码没变时跳过），再用 vite preview 开在 http://localhost:5191，打包失败时退回开发服务器。地址固定是因为浏览器按地址保存世界。

## 架构

### 世界与流水线

- **世界的数据**（`core/world.ts`）分两类：**原因**是用户通过命令编辑的（陆海、抬升、岩性、气候微调、自定义场、省份归属，以及约束、河道引导等小对象）；**推导**是流水线从原因算出的（高程、气候、水文、植被、冲突）。
- **命令**（`core/commands.ts`）：zod 校验，是改世界的唯一入口；世界文件就是种子、设置加命令记录。
- **引擎**（`core/engine.ts`）：持有世界、命令历史与推导缓存。命令改原因 → 标记从哪一层开始重算 → 流水线：高程 → 气候（基础）→ [约束求解 → 修正场] → 水文 → 河的类型 → 植被 → 冲突检查 → 人文的几层（第二十一轮：地形类别、资源、山峰，见“地形类别、资源、格的档案”；第二十二轮：宜居度与人口的几层，见“时代、文化、人口”，挪到地物之前：地名跟着当地的文化；第二十三轮：国家的一层，见“国家与政体”）→ 地物；地名、省份随后按变了的格修补。执行、撤销整步生效，中途出错回到原样。
- **重算到哪一层**（`commands.ts` 的 `Dirty`）：None < Names（只重新起名）< Human（第二十一轮：只重算人文的几层，再重新起名；自然的推导一个不动。第二十二轮的人口、文化的编辑、生成人文都在这一层；单独一条的 Human 命令不整理湖省、名字变了的都是换了风格时不比地物留名字）< Vegetation < Solve < Climate < Elevation。Human 及以下的步不进撤销缓存（撤销时重算这一段，几十毫秒），Worker 对 Human 的步发只带变了的数组的快照（Names 及以下才发轻快照）。
- **气候的基础**按自然求解的高程算（含湖的碗，不含只挖河床的河），所以画河、改河不改气候和山名，也不重算高程与气候。
- **湖底**：放的湖在高程里挖（浅滩、湖盆、一两个深处，可以低于海平面）；自然的湖在水文、植被算完之后才按离岸距离修深（`hydrology.ts` 的 `shapeLakeBeds`，只改湖格的 `d.elevation`，不改水面与流向），每次重算都从地形重新来，所以与编辑历史无关。
- **岛的种类**（第十四轮）：每格记在原因里的 `causes.islandType`（Uint8；0 不是放的岛，1–5 内置的（第十八轮在最后加了碎岛），6 起是 `small.islandTypes` 的下标 + 6；环礁潟湖的海格另加 `LAGOON_BIT` 0x80）。放岛、岛链写在新长出的陆地与潟湖上；画陆地 / 海、恢复原样画笔中心七成以内的格清掉；`set_worldgen` 新世界清零。命令 `set_island_type`（新建或整份换掉，最多 64 种）、`remove_island_type`（这种岛变成大陆岛、后面的编号往前挪，潟湖标记不变）都记撤销（`islandType`、`province` 两个数组）。它和别的原因数组一样进检查点、撤销缓存、快照（`Object.entries(causes)`）；轻快照另带一份（删种类那一步只重新起名）。颜色（`colors.ts` 的 `lithLayer` 与 `cellLayers` 里自己选的颜色）、潟湖、归哪种省、起名（`features.ts` 的 `itype:` 标签）都按它，不再按可蚀性认。
- **破碎度**（第十八轮）：`causes.fragment`（Uint8，0–255，可选：第一次打碎、放碎岛时才建，撤销到那之前时 `UndoRecord.dropFragment` 去掉它，所以没打碎过的世界与以前逐字节相同，金标准不用重录）。只改**画法**：
  - 格以下的海岸（同一条公式写在 `subcell.ts` 的 `pointIsLand`、`rasterizeWorld`，`display.ts` 的 `displayCellAt`、`displayCoastAt`、`shoreCrossing`，着色器 `FS_TERRAIN`、`FS_TERRAIN_PLANET`、极地的那一份）：每格的破碎度 / 255 在三角形里插值成 fv；fv > 0 时 `s = clamp(sv, −D, D) + 海岸细节 + weight · 200 · q · m`（`subcell.ts` 的 `fragCoast`，着色器里是 `renderer.ts` 的 `FRAG_GLSL`）：q = 1 − (1 − fv)³，D = 260 → 20（插值的海岸值压近海岸线），m = clamp(|n|·3, 0, 1)·2 − 1，n 是一层更细的噪声（`fragNoise` / `fragNoise3`，每格 1.3 个噪声单位、3 个八度：|n| 大处冒出碎岛，零线是陆上的裂缝）。weight 与海岸细节相同（格心为 0），格心的陆海不变，气候、河流、生态照旧按整格算。fv = 0 的像素不走这里（与以前逐位相同）。碎岛的高度 `2 + 0.5·min(s, 60)`（边上一圈沙滩），破碎的海面水深 ×(1 − 0.85·fv)（只是画法）。
  - 海岸值纹理从 R32F 换成 RG32F：r 海岸值、g 破碎度（`packCoast`；`setLayers`、幽灵按行上传）；顶点着色器给 `vFrag`。按陆海判的那一套（`causes.land`，湖面算陆地）里湖面格的破碎度按 0（`fragLand`）；画面上的海岸场（`displayCoast().frag`）湖面照样有。缓存的键都加上了 `causes.fragment`（`displayCoast`、`colors.ts` 的 `staticLayers`、地物的 `terrain` 段）。
  - 颜色：破碎的格没有对岸时（四周全是海的碎岛、陆地中间的裂缝）对岸的颜色按 `colors.ts` 的 `fragColors`（往外 6 圈里最近的陆地 / 水面格的颜色，没有时按气候：冻原、沙地、草地，加雪）；只给破碎度 > 0 的格。
  - 省份：碎岛（画成陆地、落在海格里的像素）的格是 `island-types.ts` 的 `landPixelCells`：破碎的海格是它自己，离破碎的海格两步以内的海格是最近一圈里最碎的那格，别的照 `landProvinceCells`（没打碎过时就是它，同一个数组）。着色器的 `provCell` 先看扭曲后的格破碎不破碎（`fragCell`，纹理的 g），再照旧找附近的陆地格、最后 `landCellOf`；`display.ts` 的 `provinceCell` / `sameKindNear`、导出的 `rasterizeWorld` 同一个规则。悬停“这里”说“X 群岛 · 碎岛 · 浅海”。
  - 名字：破碎度 ≥ 64 的海格连成的每一片在 `features.ts` 的群岛分组里当一个“岛”（三步海路以内的岛、碎岛并在一起），组里碎岛格够 3 格就是群岛（`archipelago`，锚点在最大的岛上，没有岛时在最大的一片碎岛上）。
  - 命令：`fragment {cells, t, strength 0.1–1, mode: blocks | coast, size: 画笔半径 km}`（`terrain.ts` 的 `fragmentStroke`）。裂成碎块按裂缝图 `crackAt`（世界种子 + 格的位置：抖动格点的 Voronoi，平面按 (x, y)、星球按单位球面上的三维位置；碎块大小 `crackBlockSize` = max(3.5 格, 半径 · (0.7 − 0.35·力度))，裂缝半宽 `crackHalfWidth` = 0.6–0.95 格，外圈收窄），裂缝上的陆地 landness 压到 −(海岸噪声的幅度 + 60)（与画海相同），孤零零的单格陆地也成海；只打碎海岸只抬离岸 1–2 步的破碎度、不改陆海（`Dirty.Vegetation`：只重认地物）。放碎岛（内置的“碎岛”，形状 `frag`）是 `fragStamp`：一片按 `islandGeometry`（与不规则的岛一样的轮廓）抬破碎度，不改陆度、不记岛的种类；岛链的 `fragRatio` 按链上的编号（`chainFragAt`）把一部分岛换成碎岛。`restore_terrain` 按画笔权重退回破碎度（`restoredFragment`），画陆地 / 海与恢复原样画笔中心、陆海变了的格清零（`applyTerrain` 的 `clear`）。幽灵海岸的 `GhostEdit.frag` 带将来的破碎度（放碎岛、岛链、画陆地 / 海、恢复原样）；打碎用确切预览。
- **湖与省份**：湖是推导出来的，命令执行时还不知道。引擎在推导算好之后（`Engine.fixLakeProvinces`）按新的湖整理湖与陆地的省份，结果与撤销记录并进这一步，并记进命令（`provinceFix`），重放、重做时不用推导照着改。
- **预览**在世界的副本上执行（`core/preview-world.ts` 只带变了的数组），松手时直接采用，不再算第二遍。确切预览分阶段算，阶段之间可以停下：接着画、松手执行别的命令时不再等它算完（最多等一个阶段，通常 0.1–0.6 秒）。
- **随机**（`core/rng.ts`）：所有随机都从世界种子派生，按地图上的位置取、与格数无关，命令重放结果逐值一致。

### 线程与隔离

- **主线程**（`src/state.ts`）：世界的只读视图（网格本地构建，原因与推导来自 Worker 的快照）加界面状态。快照只带变了的推导数组（只变了一片的只带那几格），只改了名字、省份时只把这些发回来；数组用 `transfer.ts` 转交、不复制。
- **计算 Worker**（`src/worker.ts`）：持有引擎。用户的脚本只在这里跑，主线程上只用 acorn 解析、不编译（`src/ui/script-syntax.ts`）。
- **隔离**：计算 Worker 尽量从 data: 地址开（`engine-spawn.ts`，代码来源见 `engine-source.ts`：打包好的程序里取 Vite 单独打包的引擎文件的文字；开发时由 `tools/isolated-engine.ts` 在开发服务器上现打包 `/__map2/engine.js`，开发时也隔离；不压缩，做成 data: 地址超长时（第二十三轮起内置的内容多了）才压缩）。这样它没有来源、受页面 CSP 管，读不到 IndexedDB，也不能联网。开起来先自查三项（`isolation-probe.ts`：来源为空、打不开存档、页面规则管得到它），全过才说隔离了；在一个页面里隔离运行过以后不会悄悄换成不隔离的线程。取不到时退回普通 Worker（问话里照实说）。
- **存储 Worker**（`storage-worker.ts` + `checkpoint-store.ts`）：与页面同源、只做存储、从不运行脚本。检查点（星球约 34 MB，连同几千步的命令）不经过主线程：主线程开一条 MessageChannel，一头给存储 Worker、一头给计算 Worker；计算 Worker 写好检查点直接发给存储 Worker，另给主线程发步号，主线程核对与命令记录一模一样后才让存储 Worker 写下。
- **看护**（`src/sandbox.ts`）：看门狗只在脚本运行期间计时（Worker 每 250 毫秒报一次平安），4 秒没有消息判定卡住，电脑睡眠、后台节流不算；1.5 秒以上告诉界面（带“停下”）。主线程留一份完整的命令记录：卡住、停下、Worker 崩了时停掉它，正在等的请求都回失败，用检查点加命令记录恢复到这一步之前；恢复时又卡住就开安全模式。安全模式在一个 Worker 里从第一次新建、打开起固定，换模式时另开一个 Worker。
- **网格 Worker**（`mesh-worker.ts`）：新建、打开时在别的线程建网格，打包后转交（`core/mesh-pack.ts`，拆包得到与就地建的逐值相同的网格），并存进浏览器，下次直接读（键带上打包格式的版本）。最多等 6 秒，之后在主线程自己建。
- **导出 Worker**（`export-worker.ts`）：游戏文件包、整张地图的栅格化、编码、打包，进度发回顶部，可以取消。

### 检查点与保存

- **自动保存**存在 IndexedDB（`src/idb.ts`，库是第 6 版），只写变了的那些命令；IndexedDB 用不了时退回 localStorage。
- **检查点**：引擎的完整状态（原因、推导、历史）。打开时直接恢复，不必重放所有命令。版本号：打包好的程序里是引擎文件的地址（文件名带内容哈希），开发时是引擎文件内容的哈希。
- **我的地图**（`src/maps.ts`）：IndexedDB 的 `maps`（列表要用的一小条：名字、时间、地区还是星球、格数、缩略图）与 `mapDocs`（整个世界文件）两张表，总在同一个事务里写；连着哪一张记在自动保存里。刷新后只是打开过的地图不再重写。
- **世界文件的版本**（`core/doc-version.ts`）：现在是 5，只认 5。单独放一个小文件，主线程打开文件、读自动保存时也要查，不必引进整个引擎。旧版本一律打不开、不去重放，代码里不留旧存档的写法。

### 缓存与性能设计

结果全部逐值不变（见“测试”）；每一项提速都有自己的“新旧算法逐位相同”测试。

- **撤销缓存**：最近几步的完整推导结果都存着（地区 8 步、星球 6 步，相同的数组几步共用，合计不超过 200 MB），撤销、重做直接换回；更早的从那一步影响到的那一层重算。
- **按内容缓存**：气候里和地形有关的那部分（风、水汽输送图、洋流）、汇流，地形没变就不重算；星球气候分层缓存（只取决于纬度的、只取决于海陆的各留两份）；地物识别按地形缓存，只改气候时不重找陆块、海、山脉。
- **只算变了的**：重画一片只重算圈里的格；高程按陆块复用（没改过的陆块原样留着）；离海岸、离河的距离场从上一份改起；省份只修补变了陆海的格、起名线性；生态脚本按格记住结果，只重算输入变了的格；生成器的采样按网格缓存。
- **内核**：噪声内核去掉闭包，高程的噪声因子按网格缓存；汇流路由（`core/routing.ts`，Priority-Flood 填洼后按最陡下降，结果无环）的缓冲区在迭代间复用；约束求解试算不分配对象；类型化数组的堆（`core/heap.ts`，优先级相同时先进先出，平地上的顺序可复现）。
- **画面**：平移、缩放时半分辨率画、挪用带边距（0.35）的场景，渲染器的场景、叠加层的河、地名在同一帧重建（`motionEpoch`），停下 250 毫秒补全分辨率并分两帧做（这一帧地图、下一帧叠加层）；移动中海岸线按场景放大的倍数淡一些、颜色按同一个场景像素取，省界、轮廓按画面像素补偿，深浅与停稳时一样；缩小到一格不到 6 像素时河沿中线分档缓存（Path2D 每加一个点约一微秒），放大后只加看得见的河；着色器不算看不见的细节；河的图层（overlay.ts 的 `riverLayer`，停稳与移动中各一张）画成一张离屏画布，渲染器上传成纹理、在合成着色器里按每像素的陆海混进去（只在陆地上，排在省界、高亮之前；`version` 变了才上传，导出每块另画 `riverLayerTile`）；省份着色、省界、高亮取格用合成着色器的 `provCell`，与 core/display.ts 的 `provinceCell` 同一条规则（水面像素只取水面格；陆地像素取到水面格时改取 `PROVINCE_LAND_RING` 上第一个陆地格，再没有时取 `island-types.ts` 的 `landProvinceCells` 表——每个水面格、小礁离它最近的陆地省的格，CPU 上沿网格一圈圈找，上传成 `uLandCell` 纹理；导出 `subcell.ts` 的 `rasterizeWorld` 用同一张表）；高程纹理两个通道（`packElevation`：高程与 colors.ts 的 `shoreElevation`——陆地格上是挨着的水面里最浅的高程），水下的水深、浅水只按第二个通道插值；改完后的闪烁不每帧重画整张图；编号层用不读纹理的顶点着色器；MapView 不在每帧查 DOM。
- **投影（整个星球的等面积、球形）**：镜头的 x、y 在投影平面上（`projection.ts`，等距圆柱时镜头上没有 `proj`，走原来的路，逐像素不变）。编号层、地形层、切线层照旧画成等距圆柱的一块“场景”（`sceneNeed` 按画面上 25 × 25 个点反算出要的范围与东西、南北两个方向的密度，密度按 2^¼ 取整，受纹理边长与像素总数所限）；合成着色器（`FS_COMPOSE_PROJ`，由星球的合成着色器替换出来）每个像素按投影反算回世界坐标再到场景上取，省界、轮廓看的相邻像素、0.6/1.2 格的圆圈都在世界坐标上，一格合几个像素按这个像素自己的比例。看得见整个半球、或者看得见极点时场景是整圈经度（转动球只重新合成，每帧约 3 ms）；放大后只画看得见的一块，现在的场景还盖得住、密度够（移动中五折、停稳九折以上、不密过 2.2 倍）就照用。球形看着极地（纬度 20° 以上、画面上有离极点 30° 以内的地方）时场景改成以极点为中心的等距方位投影，用球面上真正的三角形与 Voronoi（`polarGeometry`，只取离那一极 0.95 以内的），格的坡度在顶点换到那个平面上的方向再插值——等距圆柱的显示三角网在极点附近横跨很宽的经度，投影到球上会成放射状的条纹。河的图层画在场景那一块上（`riverLayerScene`，极地的场景逐点换算），合成时按场景上的位置取。叠加层另画（`overlay-proj.ts`：点按投影算，线沿大圆加密后逐点投影，球的背面、等面积的左右两边断开）。工具只经过 `env.zoom`（`effectiveZoom`：投影正中的比例）与指针（`screenToWorld` 反算，投影之外给边上的一点、不在地图上；极地的场景时按 `nearestCell` 取格）。
- **还慢的**：改海陆时整个星球的洋流、风、地名，要更快得多线程计算（见“待办”）。

## 文件结构

- `core/`：纯计算，不依赖 DOM，Node 与浏览器共用
  - 网格与几何：`mesh.ts` 网格（平面、球面两种）；`sphere.ts` 球面网格（斐波那契撒点、球面 Delaunay、显示用的三角网、最近格）；`mesh-pack.ts` 网格的打包与拆包；`geo.ts` 整个星球的几何（经度绕回、球面距离、大圆、球面上的圆）
  - 地形：`generate.ts` 随机世界（地壳高度、板块、火山锥）；`planet-gen.ts` 整个星球的生成器（球面上的板块、大陆块、热点岛链）；`planet-form.ts` 星球形态的格式；`terrain.ts` 组合地形、画笔、放岛、岛链（`fillSeaPockets`：陆地围住、不挨地图边、不超过 `POCKET_MAX` 格的海块并回陆地，环礁潟湖除外（`lagoonTest`：记着 `LAGOON_BIT` 的海格）；`landAfter` 按同一规则给预览；放岛只添陆地；放岛按种类的形状、高低、岩石长出陆地，并在 `StampResult.types` 里给出要记的种类）；湖里的岛（第十五轮：`placeIsland` 按岛心分海里、湖面、干的陆地；`lakeIslandStamp` 只抬岛心所在的那个湖里不挨岸的格，`keepLakeOpen` 让剩下的湖面连成一片，不改陆度、抬升、岩性，只给出种类与 `StampResult.heights`；`combineStamps`、`chainIslands` 收一个 `LakeSource`，只在有岛心落在陆格上时才取推导里的湖面，整条链都在海上时与以前逐值相同；`islandGeometry` 是从 `islandStamp` 拆出来共用的轮廓）；`island-types.ts` 岛的种类（第十四轮：内置的大陆岛、低平岛、珊瑚岛、小礁与 `small.islandTypes` 里自己的，编号、`provinceLand`——省份按格分陆海时归海省的岛算海，湖里的岛（定了高度的格）算陆地、`lakeSeaIsles`、`landProvinceCells`）；`elevation.ts` 抬升-侵蚀稳态（`finishElevation` 里 `pocketLakes` 三格以上的并回小块挖成湖；第十四轮去掉了 `volcanoes`，`lagoonFloor` 按潟湖的标记挖浅）、海底（`seafloor`：按只走海格的离岸距离给大陆架、坡折、陆坡、陆隆，洋底目标深度来自生成器的 `sea` 分量与 `terrain.ts` 的 `seabedFields`；输入逐字节相同时用上一次的结果，改了一小片海陆只重算离改动约 1500 km 以内的格，与整个重算逐位相同）与湖底（`lakeBedShape`）；第十五轮起最后把 `causes.islandHeight` 定下的高度换上（湖里的岛：湖面 + 按种类算的高出湖面多少，放岛时记进原因；`hydrology.ts` 里这些格永远不是湖面），`placedLakeAnchor` / `placedLakeCell` 是放的湖在水文、湖类型、选湖里认的那一格（湖心放了岛时取碗里最近的水面格）；`routing.ts` 汇流路由；`stats.ts` 地形统计量（测试与 `tools/terrain-stats.ts` 共用）
  - 气候与水：`climate.ts` 日照温度、风带季风、山挡风、水汽输运；`planet-climate.ts` 整个星球的气候；`sphere-flow.ts` 球面上的输送（绕星球一圈的风带不剪断）；`ocean.ts` 简化洋流与海面温度；`hydrology.ts` 填洼汇流、湖、径流；`rivers.ts` 河流折线（第十二轮：河口在画面上的岸线上，`riverRibbon` 是河画出来的带子：加密、宽度平滑不减、源头收尖、河口张开、画的时候才加的细小弯曲，屏幕与 `rivers.bmp` 共用；第十三轮：`normalMouth` 河口沿岸线法向进水、最后 1.5 格不急转（`maxTurn`），`tidyMouths` 去掉海岸边的源头小河、挤在一起的河口小的沿岸挪开（`shiftMouth`）或接得顺时并进大河（`mergeMouth`），`branchStart` 分出去的一股顺着干流分出来）；`river-pack.ts` 地图上的河在计算 Worker 里描好打包（河线与带子几块连续的数组，随快照、预览世界转交，主线程 `overlay.ts` 的 `seedRivers` 拆开直接用，与主线程描的逐位相同；描河读的东西按内容没变时用上一次的）；`display.ts` 画面上的一点画的是哪一格，以及画面上的海岸场（`displayCoast`：湖面取负，着色与河口共用；`shoreCrossing` 找画出来的岸线）
  - 水体类型：`water-types.ts` 河流类型、湖泊类型共用的部分（格式里相同的几项、只能有 match 的脚本、改了哪几项从哪一层重算、岸边的远近）；`river-types.ts` 河流类型（每格是哪一种河、河岸场）；`lake-types.ts` 湖泊类型（每个湖是哪一种）；`effects.ts` 生态、河湖对周围冷暖干湿的影响
  - 生态：`species.ts` 生态类型（色块 + 条件 + 耐受曲线）；`vegetation.ts` 适宜度 / 竞争 / 扩散 / 长在哪里（只在某个岛上、圈的范围里、不自然生成）/ 不计水体类型的一遍植被（baseBiomes）；`constraints.ts` 涂生态的反推与“没涂成”的原因、“就这样”；`biome-look.ts` 生态在地图上的样子（颜色脚本、花纹与发光的算式，屏幕与缩略图共用）；`biome-scripts.ts` 生态的脚本在世界上运行
  - 人文（第二十一轮，见“地形类别、资源、格的档案”）：`human/rules.ts` 按格的条件（地形类别的自动规则、资源的分布规则共用）；`human/terrain-class.ts` 地形类别（内置 14 种、世界里的列表、自动分类、画过的）；`human/resources.ts` 资源（内置通用 18 种、奇幻 5 种、按噪声分布）；`human/peaks.ts` 山峰；`human/cells.ts` 格的小地名与档案；`human/kinds.ts` 两种内容登记进登记表；`human/index.ts` 流水线里的一步 `computeHuman` 与给界面的函数。第二十二轮（见“时代、文化、人口”）：`human/era.ts` 时代、取值、文化组、文化的格式与世界里的列表；`human/pop-kinds.ts` 这四种登记进登记表；`human/habitability.ts` 宜居度与偏好；`human/context.ts` 生成的各步共用的 `GenContext`；`human/generate.ts` 生成（分步、复制内容、重新生成）；`human/cultures.ts` 文化圈；`human/population.ts` 人口、修补、笔刷；`human/groups.ts` 人口群体的编号与每格的成分；`human/layers.ts` 人口的几层、图例、档案的人口一栏、每省的人口；`human/culture-style.ts` 地名跟着文化；`human/space.ts` 面积、距离、噪声、按份额长；`packs/eras/` 内置的 6 个时代（一个 JSON 一个）、几个时代共用的取值（`values/` 下一维一个）与 23 个文化组（`cultures/` 下一个 JSON 一组）。第二十三轮（见“国家与政体”）：`human/government.ts` 政体、派系的格式与世界里的列表、称号；`human/gov-kinds.ts` 这两种登记进登记表；`human/countries.ts` 生成国家（两步）、颜色、名字、历史；`human/country-names.ts` 国名的地名部分、人名；`human/country-edit.ts` 改国家的命令、整理、改地形后的修补；`human/country-layers.ts` 国家的一层、国界的分组、颜色、统计、派系的影响力、国名的位置；`human/flags.ts` 旗帜的规则与 SVG；`packs/governments/` 内置的政体与派系（一个 JSON 一组）

    取这一步之前的湖面（岛心在海里时不取，与以前一样快），所以重放、撤销、检查点逐值一致；批量命令里推导不是最新的：岛心在陆格上的单个岛拒绝，岛链跳过这些岛。

### 工具怎样组织

- 接口在 `src/ui/tools/api.ts`：`Pointer`（地图坐标、格、屏幕坐标、画出来的是哪一格）、`Preview`（高亮的格、图形、一句话、省份预览、幽灵海岸、将来的世界）、`ToolHandler`（`down / move / up / click / cancel / leave / preview / backdrop`……）、`ToolEnv`（地图给工具的缩放与“这一点是哪个地名”），还有几个工具都用的小工具（地图上的距离、整个星球的经度绕回、世界的编号）与 `guard`。
- 正在计算时：每个工具在动手的地方用 `guard('queue')`（只是在算前面的编辑时照样能用，松手后排队）或 `guard('refuse')`（`isBusy`，河、剪刀、合并、重画这一片……要按最新的世界算，前面的算完以前不动手）。
- `tools/brush.ts` 是画笔（`Stroke` 一笔、`brushTool` 通用的画笔：圈、排队、拖滑块时在最后停的地方预览、停一下的确切预览）；`tools/gestures.ts` 是几个工具共用的手势：圈一片（`lassoAdd`、`lassoShapes`）、点一下或拖出大小（`startDrag`、`dragTo`、`sizeLine`、`movedAway`）、湖里的岛的确切预览（`lakeIsleExact`、`lakeIsleRelease`）、数连通块（`groupCount`）。
- 按类：`terrain.ts`（画陆地 / 海、放岛、岛链、堆山、打碎、重画、恢复）、`nature.ts`（涂生态、拖动扩张、擦除生态、选生态的范围）、`climate.ts`（冷暖、干湿、擦除冷暖干湿、自定义场）、`water.ts`（放湖）、`provinces.ts`、`names.ts`、`measure.ts`（量距离）、`human.ts`（第二十一轮：画地形类别、资源，Alt+点吸取）、`culture.ts`（第二十二轮：文化笔刷、人口笔刷、发源地）；画河、删除河湖在 `river/tool.ts`。core 里的规则（画笔中心 `brushCore`、碎化恢复 `fragmentAfter`……）从 core 导出直接调用，不在界面里再写一份。
- 工具读选项（`options`）只读真正的设置；每放一个岛、一条岛链自动换的形状编号是 `tools/terrain.ts` 的 `islandVariant`、`chainVariant`，不在 `options` 里（换形状不让别的确切预览作废）。冷暖、干湿各有各的力度（`tempAmount`、`moistAmount`）。
- **加一个工具**：在 `tools/` 下（或 `river/`）写它的工厂函数，返回 `ToolHandler`；再在 `defs/tools.ts` 的工具表 `SPECS` 里加一条，键就是它的 id——`ToolId` 由这张表推出来，类别里的工具列表按表里的先后推出来（底部工具条、数字键的顺序就是它）。要手指光标写 `cursor: 'pointer'`；离开时要清掉的东西写 `onLeave`；它的选中状态变了地图要重画就写 `watch`（读一下那个信号）；要在地图上沿着选中的东西画光写 `focus`。一类工具开着时地图上多画的（高亮、省名、地名、河道标记）写在类别表的 `map` 里，离开这一类要清掉的写在类别的 `onLeave`。
- 换工具都走 `setTool`（面板里、工具里经 `state.ts` 的 `switchTool`），不直接写 `tool.value`：离开的工具与类别的清理、底部条的预览、量距离、鼠标旁的话都在那里清掉。
- 底图只在“图层”里换；工具表里写了 `view` 的工具（第二十一轮：地形类别、资源；第二十二轮：文化、人口、发源地）是例外——开着时 `setTool` 把底图换成它那一层，换到没写 `view` 的工具时换回原来的；这期间在图层里换过底图就不动（`defs/tools.ts` 的 `switchView`）。`view` 可以写成函数（人口笔刷按模式：改成分 `culture`、改人数 `popDensity`、改一个维度 `dim:维度 id`），选项变了时底图跟着换（底图还是工具换上的那一层时）；世界里没有那一层（`defs/layers.ts` 的 `viewAvailable`：没有人文时人口的几层都没有）时不换；底图那一层在世界里没了（删除人文、换了时代、打开别的世界）时回到工具换上之前的那一层，又有了时再换上。
- 测试：`src/ui/tool-replay.test.ts` 是一串脚本化的手势交给各个工具后发出的命令、提示与预览（`__snapshots__/tool-replay.json`，第十九轮拆分之前录下，之后不重录：变了就是行为变了；第十九轮 C 改字时重录过一次，核对过只有提示、正在计算的字和命令的 `label` 这些文字变了，结构与其余的值一个没变）；`tool-defs.test.ts` 查工具表与类别、换工具的清理、冷暖干湿的力度、`Settle`。

### 界面的样子

一套 token、每种控件一个组件（第十九轮 B）。改界面时只从这里取，不在别处另写颜色、字号、圆角。

- **token**（`src/styles.css` 最上面的 `:root`）：字号 `--fs-xs/sm/md/lg` = 11 / 12 / 13 / 15；圆角 `--r-sm/md/lg` = 6 / 10 / 14，圆点 `50%`、胶囊 `--r-pill`；阴影 `--shadow-sm`（滑块、开关的圆点）、`--shadow-lg`（浮在地图上的）；间距 `--sp-1…4` = 4 / 8 / 12 / 16；控件高 `--h-sm` 28、`--h-md` 32；灰阶 `--field --bg --surface --line --faint --muted --text`；叠在任何底上的白 `--fill`（按钮的底、毛玻璃的边）、`--hover`（悬停，只有这一个值）、`--press`（按下、开着、滑轨）；毛玻璃 `--glass --glass-strong`；强调 `--accent --accent-bg --accent-line`；警告 `--warn --warn-text --warn-bg`；危险 `--danger --danger-text --danger-bg`；另有 `--ok --mark --sea --scrim --mono --sheet-w`（抽屉的宽，底部条按它居中）。十六进制、rgba 只在 `:root` 里写。
- **按钮**没有边框：淡淡的底（`--fill`），悬停在任何底上叠同一层 `--hover`（`background-image`），选着的 `.on` / 主要的 `.primary` 是 `--accent-bg`，弹出面板开着的 `.open` 是 `--press`。图标由 `App.tsx` 的 `LucideProvider` 统一成 16 / 粗细 1.8，顶栏写 `size={18}`；各处不再写大小。
- **控件各一种**（`src/ui/components/`）：
  - `Slider.tsx`：全界面的滑块。`Slider` 给位置（0–1）和写出来的数，拖动时 `onDraft`、松手 `onCommit`、拖着时被取消 `onCancel`、方向键 `onStep`；`stacked` 是面板里的两行样子，`note` 写在下面；`linear(lo, hi, step)` 是等间距的换算；`OptionSlider` 是底部条上工具的滑块（值在 `options` 里，换算在 `shell/sliders.ts`）。不再用原生的 `<input type="range">`。
  - `Toggle.tsx`：开 / 关一项设置（无人区、锁定、省份着色、图层里显示什么、自然生成……）。从一组里挑几样（从世界存进仓库带哪些、只长在哪些地方、地名的几组）照旧是勾选框 `label.check`；仓库里每一项的“用在这个世界”是 `Toggle`。
  - `common.tsx` 的 `Seg`：几个里选一个（底部条上工具的模式也是它；`swatches` 色块、`off` 现在不起作用）。
  - `TypePicker.tsx`：选“哪一种”——底部条上的按钮 `TypePickerButton` 和弹出的列表 `TypePicker`。河、湖、岛（放岛、岛链）的六个列表都是它，`App.tsx` 的 `TYPE_PANELS` 写着每个列表的标题和种类表。一项写了 `group` 时按它分段（第二十二轮：文化按文化组列）。
  - `Legend.tsx`（第二十一轮）：图例，`{title, items: {color, label, count?}[], open, onToggle}`；都写了 `count` 时右边写百分比。按类着色的底图的图例由 `ui/legend.ts` 的 `legendFor(world, mode)` 给（地形类别、资源、生态分区：只列世界里有的，按格数从多到少，资源的“无”排最后；按着色用的数组缓存），`shell/MapLegend.tsx` 放在左下角量距离按钮上面（跟着 `cornerLift` 抬）。第二十二轮加了文化、文化组、时代的每一维（`humanLegend`，`count` 是人数）与宜居度、人口密度（色带上的五档，没有 `count`）；以后的国家底图在 `legendFor` 里加一种就行。
  - `SelectionActions.tsx`：选中一样东西时的换一个、恢复自动、锁定、在地图上看、删掉、取消选择，河、湖、地名、省份共用。河、省的底部条只放常用的几个，其余用 `menu` 布局放进它们的“⋯”（`PanelId` 的 `river`、`province`）；`MenuItem` 是“⋯”里的一行。
- **列表行一种** `.item`（菜单、地名、河、湖、涂过的地方、类型列表），`.list` 是可以滚的一列，`.item.big` 是弹窗里带缩略图的大行（我的地图、资源包）；仓库里的一项是 `.repo-card`（悬停时亮，鼠标停着时地图上预览）。（`.row` 早就是“一行排开”的布局类，所以列表行叫 `.item`。）
- **小标题**一种 `h5`；**说明文字**一种 `.hint`；**弹窗、问话的标题** `h2` / `h3`（同一个字号）。
- 要用户确认、起名字用 `state.ts` 的 `askUser` / `askText`（`shell/Ask.tsx` 的问话框），不用浏览器的 `confirm` / `prompt`。

### 文字

界面上的字要克制：短、不加修饰、不解释怎么实现的（第十九轮 C）。新加的字照这里写。

- **标签**：名词或两个字的动词（“删除”“定位”“擦除”“锁定”），不带“这条 / 这个 / 一下 / 一个”。**空状态**写名词短语（“没有河”）。**弹窗、弹出面板的标题**用名词（“河的种类”），不用问句。
- **说明**（悬停、`.hint`、提示条）：一句话，尽量不超过 20 个字；不用比喻；不写“真的 / 直接 / 其实 / 就 / 系统 / 一下 / 真正”；不写开发细节（轮次、像素数、文件名、函数名）；括号里的旁注移进悬停或删掉。
- **只讲一次的**：“停一下先看结果”和“Esc 取消”只写在帮助里，各个工具的说明不再写。
- **工具的说明**（`defs/tools.ts` 的 `how`）：一句话，只在工具按钮的悬停里显示，如“按住涂，抬高陆地”。
- **历史摘要**（`core/commands.ts` 的 `summary`、界面给命令写的 `label`）：“动作 对象 · 数值”，如“画河 · 约 120 km”“删除湖”“堆山 · 36 格”“改名为“X””。对象的名字用中文引号“”，不用「」。
- **省略号**“…”只用在会打开弹窗的按钮上，和“正在计算…”这类进行中的提示。
- **同一件事只写一处**：讲同一件事的说明收成常量（`src/ui/copy.ts`：信任脚本、自动起名、按类型的规则判断、锁定河、气候带；无人区用 `core/provinces.ts` 的说明），不在各处各写一句。
- **统一的叫法**：

| 用 | 不用 | 意思 |
|---|---|---|
| 恢复 | 恢复原样、退回 | 回到生成时的样子（工具“恢复”） |
| 擦除 | 擦掉、去掉 | 去掉涂上去的（擦除冷暖干湿、擦除生态） |
| 删除 | 删掉、移除、去掉 | 删除东西；地名不是删除而是“隐藏 / 显示” |
| 关闭 | 关上、收起、知道了 | 关掉面板、提示；结束一种模式用“完成” |
| 直径 | 大小、起点 | 画笔、岛、湖的大小（河的“大小”是水量，照旧） |
| 力度 | 强度 | |
| 省份 | 省 | 海上的省份叫“海省” |
| 自然生成 | 自己出现 | |
| 自动、恢复自动 | 换回内置、恢复默认、按规则 | |
| 锁定 | 固定 | 锁定河（走向不再随地形挪）、锁定名字、锁定省份 |
| 新建 | 新增 | |
| 没涂成 | 没长出来、未涂成 | 涂了但没长成的生态 |
| 正在计算… | 还在算、计算中 | 正在算的提示 |
| 定位 | 在地图上看 | 把镜头移到选中的东西 |

### 内容种类的登记表（第二十轮）

一种内容（地名风格、生态、河 / 湖 / 岛的种类、星球形态、自定义场、地形类别、资源、时代、人口维度的取值、文化组、文化、政体、派系；以后的……）在 `core/content/registry.ts` 的表里登记一次（`registerKind`），资源包的段、数、列表的一行（“生态 5 · 河流 4”）、格式检查、问题检查、撞 id 改名、用到世界、从世界导出、仓库的分类、编辑器的字段表都由它来，不再各处手写。现有的几种登记在 `core/content/kinds.ts`（登记的先后就是列表、检查的先后）；脚本引用、改名的小工具在 `core/content/refs.ts`（`packs.ts` 照旧导出）。

- **`ContentKind<T>`**（第二十一轮多了三项：`arrays`——`set_content` 会改的原因数组，撤销记录先记下；`afterSet(world, idsBefore)`——改完之后的整理，停用一种地形类别、资源后画过的格按 id 换编号；`alwaysOn(id)`——总在世界里的内置项（内置的地形类别、通用资源）开关不能动的原因，仓库的 `statusOf` 按它锁上）：`id`（命令、`small.content` 里用：`nameStyle`）、`label`（全称“地名风格”）、`short`（列表里的简称）、`order`（用到世界的先后：场 0 → 河 10 / 湖 11 / 岛 12 → 生态 20 → 地名风格 30）、`schema`（一项的 zod 格式）、`idOf` / `nameOf`（省略时是 `item.id` / `item.name`）、`inWorld(world)`（世界里启用的项）、`builtin()`（内置的项，仓库里总在）、`enable(item, world)` / `disable(id, world)`（命令）、`fields`（编辑器的字段表，见下）、`blank()`（编辑器“新建”的样子）、`notes(item)` / `samples(item, seed)`（编辑器里不挡启用的提醒、随机示例，见“仓库与通用编辑器”）、`pack`（资源包里的一段）。
- **两种放法**：
  - 新的种类写 `store: 'content'`：放在 `small.content[种类 id]: Record<id, 一项>`（复制进世界，打开不依赖仓库；第一次启用之前没有这一项，全部停用后去掉，所以没用过的世界与以前逐字节相同）。命令是通用的 `set_content {kind, id, item | null}`（null 是停用），按 `schema` 检查、`check(item, world)` 额外检查（不行就抛 `CommandError`）、`maxInWorld` 限数，重算到 `dirty(before, after, world)` 给的那一层（`'none' | 'names' | 'human' | 'vegetation' | 'solve' | 'climate' | 'elevation'`，与 `Dirty` 一一对应）。历史写“启用 / 修改 / 停用 + 全称 + “名字””。
  - 以前就有的种类照旧放在原来的地方、用原来的命令（`small.species` + `add_species`、`small.riverTypes` + `set_river_type`……），登记表只经 `inWorld` / `enable` / `disable` 适配，重放结果不变。
- **`pack`**：`key`（段名）、`aliases`（读旧文件时也认的段名：`textPacks` 读进 `nameStyles`）、`max`（一个文件里最多几项）、`listed`（列出来、可勾选；自定义场跟着生态、类型自动加，不列）、`checked`（默认勾上）、`note`（不能用到世界时的说明）、`read(raw, alias)`（读旧写法：文字包补上 `kind`、不合规的 id 换成合规的）、`write`、`defaultPick`、`withId`（撞 id 改名：种子用原来的、名字带编号）、`rewrite`（包里别的项改名时跟着改引用）、`finalize`（加进世界前最后一步：没写“自然生成”的关掉）、`fieldsOf`（要先有的自定义场）、`fromWorld` / `exportItem`（从世界导出）、`problems(items, ctx)`（不挡导入的问题，`ctx` 有包里各段的 id、自定义场、模板能用的词表）。
- **资源包**（`packs.ts`）：顶层格式按登记表建（严格：不认识的段报错）；`parsePack` 逐段按 `schema` 查、出错的位置写全称；`packSummary`、`packCounts`、`packProblems`（先查各段重复的 id，再按登记的先后调各段的 `problems`）、`defaultPicks`、`planPack`（加了、跳过的按登记的先后列，命令按 `order`）、`packFromWorld` 都是通用的。`PackPicks` 按段名给 id 列表，另有 `defaultStyle`（用了之后世界默认用这种地名风格，命令 `set_name_style`）。`packSection(key)` / `packSections()` 取段，`canApply(kind)` 是能不能用到世界。
- **编辑器的字段表** `FieldDesc`：`{key, label, type, hint?, optional?, options?, min?, max?, step?, of?, value?, when?}`，`type` 是 `text | longtext | number | bool | color | enum | tags | weighted | list | map | script | json`；`list` 每一项、`map` 每个值是对象时的字段写在 `of`，`map` 的值不是对象时写在 `value`；`when: {key, is}` 是只在同一层另一个字段等于某个值时才有（地名风格的模板式 / 音译式）。太复杂的（生态的耐受条件）先写 `json`，通用编辑器给原样的 JSON。
- **小工具**：`allKinds()`、`kindOf(id)`、`kindByPackKey(key)`、`itemId(kind, item)`、`itemName(kind, item)`、`contentItems(small, kind)`、`enableCommand(kind, item, world)` / `disableCommand(kind, id, world)`（有 `enable` 用它，`store: 'content'` 的用 `set_content`）、`isEnabled(kind, world, id)`、`updateKind(id, patch)`（换掉几项，测试用）。
- **加一种内容**：在 `content/kinds.ts`（或那一种自己的模块里，被 `kinds.ts` 引用）写 `registerKind({...})`，`store: 'content'`；起名、生成等用到它的地方按 id 引用、缺了退回默认（见 `name-styles.ts` 的 `styleFor`、`missingStyles`）。资源包、仓库的列表、编辑器不用另改。

### 地名风格的写法（第二十轮）

一个世界可以启用好几种地名风格（`small.content.nameStyle`），世界有一个默认的（`small.nameStyle`，没有这一项是内置的 `zh-default`），地物、省份可以单独选一种。格式与起名在 `core/name-styles.ts`，内置的几种在 `core/packs/names/`（一个 JSON 一种，在 `packs/names/index.ts` 的 `FILES` 里加一行就进了 `BUILTIN_STYLES` 和仓库里的“地名风格示例” `NAME_STYLES_PACK`）。

内置 27 种（先后见 `index.ts`）：中文·默认；日本·汉字、朝鲜半岛·韩语（模板式带读音表）；仿各地语言的音译式 20 种——英格兰、法兰西、西欧·日耳曼（德语）、低地·荷兰语、伊比利亚·西班牙语、意大利、古罗马·拉丁、希腊、北欧·诺斯、东欧·斯拉夫、阿拉伯、波斯、草原·突厥、印度·梵语、东南亚·马来、东南亚·泰、非洲·斯瓦希里、阿兹特克·纳瓦、安第斯·克丘亚、大洋洲·波利尼西亚；幻想 4 种——精灵、矮人、兽人、海民（自造的音和词）。音译式的通称照那种语言的写法写在原文里（Río X、Kuh-e X、Mae Nam X），中文意译（X河、X山）；中文里有约定俗成写法的照写（Kuala X → 瓜拉X、Sungai X → 双溪X、Chiang X → 清X、X-sur-Y → Y河畔X）。

- **哪一处用哪种**：`styleFor(world, target)` 是唯一的判断（`target` 是 `{feature, override?}` 或 `{province}`）：自己选的（地物是 `featureNames[键].style`，命令 `set_feature_style {key, style | null}`；省份是 `ProvinceMeta.style`，命令 `set_province {id, style | null}`，换了就按新风格重新起名）→ 世界默认（`set_name_style {id | null}`）→ 内置中文。选的风格停用了就按世界默认，`missingStyles(small)` 列出这些地方给界面提示。第二十二轮在“自己选的”和“世界默认”之间接上“当地文化的风格”，只改这一个函数。
- **种子与留着的名字**：用的风格不是世界默认时，种子后面加 `:风格 id`；是世界默认时与以前一样，所以只用内置中文的世界名字一个不变（金标准没有重录）。起名的办法（`keptNames` 的 `ctx`）里的风格标识：内置中文是旧的文字包标识（没换过时是 `-`），别的是风格内容的哈希，改了风格的内容留着的名字就不再用。`GeoFeature.style` 只在用的不是世界默认时才有（界面上的“风格”读它）。
- **原文**：起出来的名字是 `{zh, orig}`。`GeoFeature.orig`、`ProvinceMeta.orig` 只在有原文时才有；改名（`rename_feature` / `set_province` 的 `orig`；只改中文名时原文去掉，“换一个”也去掉）、留着的名字（`KeptName.orig`）、固定下来的河（`Guide.autoOrig`，跟着 `autoName`）、新编号的省（命令里的 `provinceOrig`，与 `provinceNames` 一起记、一起用）都带着它。`features.csv` 只在有原文时在 `name` 后面多一列 `orig`。显示中文 / 原文 / 两者见 `core/name-display.ts`（`nameText`、`nameLines`；界面的 `state.ts` 的 `nameMode`，叠加层的 `OverlayState.nameMode`）。
- **旧的文字包**：`small.wordPack` + `set_word_pack` 照旧，意思是“换掉内置中文风格的内容”；新的做法是启用一种风格再设为默认。资源包里旧的 `textPacks` 一段、单独的文字包文件都读成模板式的风格。

**模板式**（`kind: 'template'`）就是以前的文字包，另可带读音表：

```json
{
  "id": "ja-kanji", "name": "日本·汉字", "kind": "template",
  "lists": { "pre": ["白", "高", "松"], "mid": ["川", "浜", "岡"] },
  "types": {
    "island": { "patterns": [{ "p": "{pre}{mid}島", "w": 3 }, { "p": "{pre}島" }], "byTag": { "cold": [{ "p": "{pre}雪島" }] } },
    "lake": { "patterns": [{ "p": "{pre}{mid}湖" }] }
  },
  "readings": { "白": "shira", "浜": "hama", "島": "shima", "湖": "-ko", "大陸": " Tairiku" }
}
```

- `lists`：词表；`types`：每类地物的模板（`{词表名}` 换成那个词表里的一项，同一个名字里尽量不重复用字），`w` 是权重；`byTag`：地物带这个情境标签时 65% 用这里的。`{__species}` 是生态区的生态名字（起名时才放进去）。
- `readings`：汉字（一个或几个）→ 原文，按最长匹配把整个名字读一遍，读不全时没有原文；每个词（空格隔开）的第一个字母大写。词尾的通称写成 `-ko`、` Tairiku` 这样带连字符或空格的。复合词的读法（连浊）写成几个字的一项。

**音译式**（`kind: 'phonetic'`）先拼外文、再音译：

```json
{
  "id": "west-germanic", "name": "西欧·日耳曼", "kind": "phonetic",
  "syllables": {
    "onsets": [["k", 3], ["v", 2], ["br", 1], ["", 1.5]],
    "nuclei": [["a", 4], ["i", 3], ["ei", 1]],
    "codas": [["", 6], ["l", 2], ["r", 2.5]],
    "first": [["k", 3], ["v", 2]],
    "last": [["", 2], ["l", 2], ["n", 2]]
  },
  "length": [[1, 3], [2, 5], [3, 1]],
  "lists": { "town": ["burg", "dorf", ["heim", 0.8]], "isle": ["ey", "holm"] },
  "forbid": ["aa", "^ng", "^a$"],
  "types": {
    "province": { "patterns": [{ "p": "{root}{town}", "zh": "{name}" }], "byTag": { "coastal": [{ "p": "{root}hafen" }] } },
    "island": { "patterns": [{ "p": "{root}{isle}", "zh": "{name}岛" }] },
    "lake": { "patterns": [{ "p": "{root}see", "zh": "{root}湖" }] },
    "biome": { "patterns": [{ "p": "{root}", "zh": "{root}{__species}" }] }
  },
  "translit": { "ka": "卡", "vi": "维", "r": "尔", "l": "尔", "s": "斯", "burg": "堡", "len": "伦" }
}
```

- 词根：音节数按 `length`（`[音节数, 权重]`），每个音节 = 声母 + 韵核 + 韵尾（`''` 是没有），第一个音节的声母用 `first`、最后一个的韵尾用 `last`（省略时同 `onsets` / `codas`）。带权重的一项写 `"k"` 或 `["k", 3]`。
- `forbid`：不许的写法（小写比较）：`"aa"` 任何地方，`"^ng"` 开头，`"r$"` 结尾，`"^a$"` 整个词根就是它。词根拼出来碰上就重拼，整个原文碰上就换一个模板重来。
- `types` 里的写法：`p` 是原文（`{root}` 拼一个词根，`{root2}` 另拼一个，`{表名}` 取 `lists` 里的一项，其余照抄；拼出来的部分在词首（开头、空格或连字符后）大写，照抄的原样）；`zh` 是中文（省略时把整个原文音译；`{name}` 是整个原文的音译，`{root}`、`{表名}` 是那一段的音译，`{__species}` 是生态名字，其余照抄）。通称在中文里意译（“{root}湖”“{name}岛”），城镇的词缀跟着音译（“{name}”）。没写的类型按 `default`、`island`、第一个。
- 音译 `transliterate`：原文转小写，从左往右取音译表里最长的一段；但一段以辅音结尾、后面紧跟元音时先试短一些的（辅音归后面的音节：vilen → vi·len 维伦，不是 vil·en 维尔恩），都不行再用它。空格写成“·”，连字符、撇号略过；表里一个字母也对不上的写成 `fallback`（省略时略过）。`vowels` 是元音字母（省略为 aeiouy 和常见的带符号元音）。例：Karvilsburg → kar（卡尔，由 ka + r）· vil（维尔）· s（斯）· burg（堡）→ 卡尔维尔斯堡。
- 音译表怎么写：先写“辅音 × 元音”的格子（ba 巴、be 贝、bi 比……）和单独的元音（a 阿、e 埃……），再写单独的辅音（在词尾、辅音前：l 尔、r 尔、s 斯、t 特、n 恩、m 姆……），再写常见的韵（an 安、ban 班……）、复合元音（ei 艾、au 奥），最后写词缀（burg 堡、heim 海姆）整段先认。用 `west-germanic.json` 做样子；格子大的可以写个小脚本生成（只是生成 JSON，不进代码）。

**写一种新风格时**：

1. id 用小写字母、数字、连字符（`slavic-east`），名字“地区·语言”（“东欧·斯拉夫”）。只写自己的音节规则、词缀和音译表，不搬真实的地名表（模板式的汉字词表是常用字，不是地名）。
2. 每类地物都写（`continent island archipelago peninsula ocean sea bay strait lake river range peak plateau plain basin desert forest tundra icecap wetland biome province region spot`），省份至少有 `coastal river mountain sea waste` 几个情境（`byTag`）；地物的情境标签还有 `cold hot dry wet high volcanic small large big`。
3. 放进 `core/packs/names/`，在 `index.ts` 的 `FILES` 里加一行。`name-styles-builtin.test.ts` 会查每一种：格式合格、`styleProblems`（用到了不存在的词表）与 `styleNotes`（音译表写不出的字母）都为空、名字是“地区·语言”、每类地物都写了、省份的情境写全、同一个种子同一个名字、中文名只有汉字和“·”、音译式和带读音表的都有原文、起出来的名字不碰上自己的不许的写法、200 个里重名少。
   - **不许的写法查的是整个原文**：不能碰上模板里照抄的字和词表里的词（`"ee"` 会让每个 `{root}meer` 都被拒、重试到底），只查词根的写法要写得窄一些（`"^the$"`），或者干脆不写。
   - 以元音开头的词缀（`-ia`、`-abad`）接以元音结尾的词根很难看：把“元音 + 词缀开头”写进不许的写法（`"aia"`、`"eabad"`），碰上了就换一个词根；这类禁写不要多到大部分词根都被拒。
   - 中文要把通称放在名字前面又不想带上通称的音译（`Lago de X` → “X湖”），可以写 `zh: "{root}湖"`；要整段音译又不要通称时，把那几个通称在音译表里写成空的（`"río": ""`），再用 `{name}`——只用在词根里不会出现的长词上。
   - 粗话、不雅的音（各语言常见的几个）写进不许的写法；音译用字避开不好的字（死、鬼、屎……）。
4. 看一看起出来的样子：`sampleNames(style, type, 数量)`（编辑器里的随机示例也用它）。

### 仓库与通用编辑器（第二十轮）

“世界 → 仓库”（`src/ui/packs/RepoPanel.tsx`）按登记表列出内容，不按包：左边是 `repoKinds()`（列出来的几种，地名风格在前），右边是 `repoRows(kind, world, library)` 给的一行一项。

- **一项从哪来**（`RepoRow.source`）：`builtin`（登记的 `builtin()` 和内置的包，同一项只列一次）、`mine` / `imported`（资源库里的包）、`world`（世界里有、仓库里哪一项都对不上的：这个世界里做的、别人的世界带来的）。`pack` 是它所在的包（只在世界里的包一层），启用时照资源包的规则走。
- **启用没有**（`RepoStatus`）：世界里有一模一样的（内置的生态本来就在世界里）→ 开着；否则按 `planPack` 加进世界时的样子（没写“自然生成”的关掉、改了名的引用……）与世界里的比，一样就是开着（`worldId` 是世界里那一项的 id）；同 id 不同内容时启用后改名（`rename`）。`locked` 是开关不能动的原因：没有世界、不能用到世界的种类（`canApply`，星球形态）、内置中文、有 `styleProblems` 的地名风格。
- **命令**：`toggleCommand`（关着是 `planPack` 的那一整步，改写标签为“启用 + 全称 + 名字”；开着是登记的停用命令，停用的是世界默认的地名风格时加一步 `set_name_style null`）、`defaultStyleCommand`（启用着的直接 `set_name_style`，没启用的启用和设为默认一起）。都是一步。执行前 `untrustedScripts` 有没信任过的就问（`askUser` 带上脚本），信任了再执行。
- **停一下预览**：鼠标进一项（或它的“默认”）就把它开关之后的命令交给 `previewWorld`，结果放进 `adjustPreviewWorld`（键是命令的 JSON，点下去时 `execAdjust` 直接采用）：会变的格描边，新生态的格按颜色淡淡涂上，底下写一句。只多一种可选的地名风格不算（地图上不变）；改世界默认的写“地名按这种风格重起”。点过之后鼠标移开之前不再预览，一项没了（换了类、筛掉、打开了编辑器）时一并去掉。
- **编辑**：生态、河流类型、湖泊类型、岛的种类（`DEDICATED`）打开各自的编辑器（生态抽屉、`openWaterTypeEditor`、`requestIslandTypeEditor`），只对世界里启用着的；别的种类用通用编辑器（内置的、开关不能动的复制一份改）。“新建”同理（有自己编辑器的在那里新建，别的用 `blank()`，id 用 `freeId` 避开）。
- **通用编辑器**（`ContentEditor.tsx`，逻辑在 `fields.ts`）按 `kind.fields` 画：`text / longtext / number / bool（Toggle）/ color / enum（四个以内 Seg，多了 select）/ tags（空格、逗号、顿号隔开）/ weighted（一行一项：字、权重，权重空着是 1，'' 也能写）/ list（每项按 of）/ map（键、值；值按 value 或 of）/ script（只是源码）/ json（有 of 时按 of 画成一组字段，没有时是原样的 JSON 框，写坏了不换上）`。一组字、带权重的字、map 的键在框里写完、离开框时才换上。列表、map、带权重的项多（8 项以上）时收起来，有错的展开。`setField`：可以不写的字段空了去掉；改的是别的字段 `when` 指着的那个（地名风格的“写法”）时，看不见的字段去掉、新看得见的必填字段按类型补上默认值（词表、各类地物两边都有，留着）。检查 `editorIssues`：`itemErrors`（`packs.ts`，按登记的格式、中文说明）+ `check`（挡启用的），出错的位置按字段表的名字说（`pathLabel`：“各类地物 · island · 模板 · 第 1 个 · 写法”），写在那个字段下面和最下面；`notes` 是不挡的提醒。登记了 `samples` 的种类在下面写随机示例（地名风格：每类地物 4 个，“换一批”换种子）。按钮：复制、存进仓库（`saveItem` 存进“我的资源”，同 id 换掉）、用到世界（登记的启用命令：`set_content` 已有同 id 时是修改）。
- **登记表为编辑器多的两项**：`notes(item)`（提醒）、`samples(item, seed)`（随机示例）。加一种 `store: 'content'` 的内容时写上 `fields`、`blank`，仓库、编辑器、资源包就都有了；要自己的编辑器时在 `RepoPanel.tsx` 的 `editRow`、`newItem` 里接上。
- **地名、省份里的风格**（`styles.ts`）：`styleChoices`（世界里启用的，内置中文在前）、`featureStyleCommand`（写在落到这个地物上的改名的键上，`overrideKeyOf`）、`restyleProvincesCommand`（没锁定、没自己选风格的省一个个 `set_province {style: null}`，一个 batch）、`restyleOffer`（世界默认不是内置中文、或有省名带原文时才提）、`missingCount`。底部条的“风格 ▾”是 `TypePickerButton` + `TYPE_PANELS.featurestyle`，省份在它的“⋯”里列 `TypePicker`。
- **中文 / 原文 / 两者**：`state.ts` 的 `nameMode` 存在偏好里（`map2.prefs` 的 `names`，`parsePrefs` 不认识的值用默认的），图层面板的 `setNameMode` 改。

### 地形类别、资源、格的档案（第二十一轮）

人文的第一批：每格一种地形类别、最多一种资源、一份档案（小地名、备注），山峰。都只读自然的推导，不反向改地形（`core/human/`）。

**地形类别**（`human/terrain-class.ts`，内容种类 `terrainClass`，资源包的段 `terrainClasses`）：
- 一项：`{id, name, color, exportColor?, terrain?（导出给游戏的地形名）, description?, priority, rules: 按格的条件[], fallback?, ore?（档案里写“无矿”）, peaks?（这一类里算山峰）, movement?（通行难度，平原 1，以后的道路用）}`。
- 内置 14 种（仿 EU4）：平原（兜底）、草原、干草原、丘陵、高原、山地、山峰、森林、林地、丛林、沼泽、沙漠、冻原、冰川。阈值按生成的世界标定：陆地坡度的中位数约 1.3 m/km、九成以下约 9；丘陵是坡度 ≥ 4.5（或海拔 ≥ 700 且坡度 ≥ 2.5），山地是海拔 ≥ 1900（或 ≥ 1100 且坡度 ≥ 7），山峰是海拔 ≥ 3000 且坡度 ≥ 8（或 ≥ 4200 且坡度 ≥ 3），高原是海拔 ≥ 1100 且坡度 ≤ 4；植被类的按生态的 `terrain`（forest、jungle、steppe、desert、arctic、marsh）与湿润指数。新建的类地星球上约是平原 23%、草原 12%、丘陵 12%、干草原 10%、山地 9%、冰川 9%。
- **世界里有哪些**（`worldTerrainClasses(small)`）：内置的 14 种总在（不用启用、不能停用，像内置中文风格）；`small.content.terrainClass` 里同 id 的一项换掉内置的那一种（`set_content` 改颜色、规则……，停用它就换回内置的），别的 id 是新加的，排在内置的后面（按启用的先后，最多 64 项）。编号 = 列表里的下标 + 1。
- **自动分类**（`classifyTerrain`）：每格取规则满足的类别里 `priority` 最大的（一样大时排在前面的），一条都不满足时取写了 `fallback` 的那一类；只给干的陆地（陆地、不是湖面）分，水面为 0。地形类别的规则里不能写 `classes`（`check` 拒绝）。
- **按格的条件**（`human/rules.ts` 的 `cellRuleSchema`，资源共用）：`elevMin/Max`（m）、`slopeMin/Max`（m/km）、`tempMin/Max`（年均温）、`moistMin/Max`（P/PET）、`wetMin/Max`（地形湿度）、`latMin/Max`（纬度绝对值）、`terrain`（生态的地形）、`biomes`（生态 id）、`classes`（地形类别 id，只用于资源）、`coast`、`river`（流量够画成河）、`lake`；写了的几项都满足才算，一项有几条规则时满足任何一条就算。编辑器里每一项是一个可以不写的字段（`RULE_FIELDS`、`RESOURCE_RULE_FIELDS`）。

**资源**（`human/resources.ts`，内容种类 `resource`，段 `resources`）：
- 一项：`{id（不能是 none）, name, color, icon?（界面按它画）, category: farm | wood | herd | fish | ore | luxury | magic（农、林、牧、渔、矿、奢侈、奇幻，CATEGORY_LABEL）, description?, rules, rarity（能长的格里约多少比例有它）, weight（几种都能长时谁占上）, cluster（成片的大小，km）, seedKey?}`。
- 内置的通用 18 种总在：粮食、牲畜、鱼、木材、盐、石料、铁、铜、锡、金、银、煤、宝石、香料、毛皮、葡萄酒、丝、茶。奇幻 5 种（秘银、魔晶、龙骨、灵木、星陨铁）是内置的但默认不在，在仓库里启用（`set_content`）。列表、编号同地形类别（`worldResources`）。第二十二轮由时代包选用。
- **分布**（`distributeResources`）：每格在规则满足的资源里取 `weight × (取值 − 门槛)` 最大的那种，都不到门槛时没有。取值是按地图上的位置（km）的两层噪声（成片的 + 四分之一的细噪声，星球上按单位球面 × 半径取三维噪声），种子是世界种子 + `resource:` + seedKey（省略时 id）；门槛是这种取值的 1 − rarity 分位（固定种子标定一次）。所以与格数无关、同一个世界同样的结果。每种资源每格的取值按网格记下（`fieldOf`，单精度，最多 48 份），只画资源、改规则时只查表。山地、山峰上能长的只有矿（石料、铁、铜……）与宝石（奇幻的除外），所以山地上是矿或者没有（“无矿”）；新建的类地星球上约四成的陆地没有资源。

**推导与原因**（`world.ts`）：
- `derived.terrainClassAuto` / `terrainClass`（生效的：画过的用画的）、`resourceAuto` / `resource`、`peak`（1 是山峰）都是每格一个 Uint8，空白世界里全是 0。没画过时生效的与自动的是同一个数组。`computeHuman`（`human/index.ts`）每次都换上新的数组、不就地改：撤销缓存与发给主线程的上一份照旧共用。只重算人文的几层时（`computeHuman(w, d, false)`）自动的类别在规则、生态没变时照用上一份（按数组记下当时的规则），自动的资源在规则、生效的类别都没变时照用上一份。
- `causes.terrainClass`（0 自动，否则编号）、`causes.resource`（0 自动、255 明确没有 `RESOURCE_NONE`、否则编号）：可选，第一次画时才建，撤销到那之前时去掉（`UndoRecord.dropArrays`），新世界（`set_worldgen` 的 reset）清零。只画陆地格；变成海的格留着画过的值（水面不分类别），又变回陆地时照旧。
- `small.cells`：格的编号 → `{name?, orig?, salt?, note?}`，第一次写之前没有这一项，空了就去掉。
- 没用到这些的世界：原因、小数据里一项都不多。人文的推导数组（`HUMAN_DERIVED`）不进金标准的 `digestWorld`（金标准记下时还没有它们），它们自己的金标准在 `human/human.test.ts`（地区与星球各一组）。

**命令**：
- `set_cell_class {cells, class: id | null}`：这些格（只算陆地）画成这一类，null 恢复自动。历史“地形类别“山地” · 36 格”“地形类别恢复自动 · 36 格”。`Dirty.Human`。
- `set_cell_resource {cells, resource: id | 'none' | null}`：'none' 是明确没有，null 恢复自动。“资源“铁” · 12 格”“去掉资源 · 12 格”“资源恢复自动 · 12 格”。`Dirty.Human`。
- `set_cell {cell, name?: string | null, orig?: string | null, salt?, reroll?: true, note?: string | null}`：小地名（null 恢复自动；原文跟着名字，只改中文名时去掉）、换一个（reroll 盐加一，或直接写 salt，自己起的名字去掉）、备注（null 去掉）。`Dirty.None`。
- `set_content {kind: 'terrainClass' | 'resource', ...}`：改、加、停用；`Dirty.Human`。停用新加的一种时画成它的格恢复自动、后面的编号往前挪（`remapCodes`，资源的 255 不动），都记进撤销。

**山峰**（`human/peaks.ts`）：干的陆地上比相邻的格都高（一样高时编号小的算）、海拔 ≥ `PEAK_MIN`（1000 m）、生效的地形类别写了 `peaks`（内置的山地、山峰）的格。山脉的主峰（地物 `peak`，海拔 ≥ 2600 m）一般就在里面。

**格的小地名**（`human/cells.ts` 的 `cellName`）：自己起的（`small.cells`）；否则按 `styleFor(world, {cell})`（第二十一轮加的目标：这一格所在省份的风格，没有时按世界默认；第二十二轮起省份没选风格时按这一格的文化，见“时代、文化、人口”）起：山峰用风格的 `peak` 模板，别的用 `spot`（情境标签 coastal、river、mountain、cold、sea），种子“世界种子:cell:格:盐”（风格不是世界默认时加风格 id）。不上地图、不进 taken（可以与地物重名）。没有加新的地物类型，内置的 27 种风格都写了 `peak` 与 `spot`。

**给界面的**（都从 `core/human` 导出）：
- `cellArchive(world, cell)`：`{cell, surface: land | lake | sea, name, orig?, custom, feature?（山脉的主峰：名字是地物的，改名用这个键 rename_feature）, style, note?, elevation, lat, lon, province, provinceName?, biome?, terrainClass?: {id, name, color, auto, autoId?}, resource?: {id, name, color, icon?, category, categoryLabel}, resourceAuto, resourceNone?（“无矿”/“无”）, peak?: {name, orig?, elevation, feature?}}`。主峰在格自己起了名字时用格的。
- `peakCells(world)`（按海拔从高到低，按 `derived.peak` 缓存）、`peakMarks(world, limit?)`（地图上画全部山峰：格、位置、名字、海拔、主峰的地物键）。
- `worldTerrainClasses(small)`、`worldResources(small)`、`classCode` / `classAt`、`resourceCode` / `resourceAt`、`classColors(world)` / `resourceColors(world)`（编号 → RGB，0 为 null）、`BUILTIN_CLASSES`、`GENERAL_RESOURCES`、`FANTASY_RESOURCES`、`CATEGORY_LABEL`、`RESOURCE_NONE`、`provinceHuman(world, d)`（每省格数最多的类别、资源）。
- 图层：按 `derived.terrainClass` / `derived.resource` 的编号取 `classColors` / `resourceColors`，0 不着色。

**界面**（第二十一轮 UI）：
- 底图 `terrainClass`、`resource`（`render/colors.ts` 的 `humanFlat`：地貌上按格平涂，资源底图里没有资源的陆地是 `NO_RESOURCE` 灰；不画生态的花纹）；`colorSignature` 在改过、加过类别或资源时带上它们的颜色。
- 山峰图层（`overlays.peaks`，默认关）：`render/overlay.ts` 的 `peakLabels(world)` 把 `peakMarks` 变成键带 `PEAK_KEY` 的假地物，排在别的地名之后（地名里已有的主峰不重复），放大到 `PEAK_NAME_ZOOM` 才标名字，之前画小三角（相隔 `PEAK_GAP` 像素以上，按海拔先后）；点击命中不给它们。导出整张地图时同样画。
- 画笔：`tools/human.ts`（`dryLand` 只涂干的陆地，`options.terrainClass` / `options.resource`：'' 恢复自动、'none' 无），底部条的选择在 `panels/human.tsx`（`TYPE_PANELS` 的 `classpick`、`resourcepick`）。
- 格的档案：`ArchiveBox.tsx` 画在 `Inspector` 里，命令在 `archive.ts`（`renameCommand`、`rerollCommand`、`autoNameCommand`、`cellClassCommand`、`cellResourceCommand`、`noteCommand`；`archive.feature` 有值时走 `rename_feature` / `reroll_feature`）。右键点地图（不拖，`map/input.ts`）调 `state.ts` 的 `pinCell`：`pinnedCell` 钉住、`hereOpen` 展开卡片；钉住时 `lastHoverCell()` 给钉住的格，档案可以改，地图上画一个黄圈；收起卡片、新建或打开世界时不再钉住。没钉住时档案只读。

### 时代、文化、人口（第二十二轮）

人文的第二批：一个世界一个时代，人口按宜居度分到各格，每格记人数最多的 4 个人口群体（群体 = 文化 + 时代每一维的取值），文化圈就是“每格人口里占多数的文化”，地名跟着当地的文化。都只读自然的推导，不反向改地形（`core/human/`）。生成的顺序是 文化圈 → 国家（第二十三轮，见“国家与政体”）→ 人口 → 国家的移民。

**四种内容**（`human/era.ts` 的格式，`human/pop-kinds.ts` 登记；都是 `store: 'content'`，命令 `set_content`，改了重算到 `human`）：

| 种类 id | 全称 | 资源包的段 | 世界里 | 内置的 |
|---|---|---|---|---|
| `era` | 时代 | `eras` | `small.content.era` | `BUILTIN_ERAS` |
| `popValue` | 人口维度的取值 | `popValues` | `small.content.popValue` | `BUILTIN_POP_VALUES` |
| `cultureGroup` | 文化组 | `cultureGroups` | `small.content.cultureGroup` | `BUILTIN_CULTURE_GROUPS` |
| `culture` | 文化 | `cultures` | `small.content.culture` | `BUILTIN_CULTURES` |

内置的不是总在的（不像地形类别）：在仓库里启用，或者生成人文时自动复制进来（`generate.ts` 的 `ensureHumanContent`：时代、它那几维的内置取值、用到的文化组、世界里一个文化都没有的组的内置文化、文化用的内置地名风格；世界里已有同 id 的不动）。世界里的列表按启用的先后（`worldEras` / `worldPopValues` / `worldCultureGroups` / `worldCultures`），编号 = 下标 + 1，0 是没有；某一维的取值 `dimensionValues(small, 维度 id, 时代 id?)`（只列属于这一维、不限时代或包括这个时代的）。

**偏好**（`preferenceSchema`）：按格的条件（与地形类别的规则同一种写法，见上一节的“按格的条件”，可以写 `classes`）加一个倍数 `factor`（0–20）。写了的几项都满足时宜居度乘以它，几条都满足时连乘。例：`{ "classes": ["mountains", "peaks"], "factor": 4 }`（矮人喜山）、`{ "coast": true, "factor": 1.5 }`、`{ "tempMin": -2, "tempMax": 16, "factor": 2 }`、`{ "terrain": ["desert"], "factor": 0.3 }`。

**带权重的一组 id**（`weightedIdsSchema`）：`["a", ["b", 3]]`——`"a"` 权重 1，`["b", 3]` 权重 3（编辑器的 `weighted`）。

**时代**（`eraSchema`）：

```json
{
  "id": "medieval",
  "name": "中世纪与近世",
  "description": "封建领地与王国……",
  "color": "#a0703c",
  "dimensions": [{ "id": "religion", "label": "宗教", "required": true }],
  "popDensity": 2.7,
  "sparsity": 1.6,
  "urbanization": 0.1,
  "unclaimed": { "minHabitability": 0.05, "nomads": 0.35 },
  "seaClaimKm": 0,
  "defaultGroups": [["western", 3], ["eastern", 3], ["mideast", 2], ["southasia", 2], ["slavic", 1.5], ["steppe", 1.5]],
  "cultureGroups": ["western", "eastern", "steppe", "nordic", "…"],
  "governments": [], "factions": [], "resources": ["grain", "livestock", "…"]
}
```

- `dimensions`：文化之外的维度（文化总是第一维，不写），按先后，最多 3 维。`id` 是维度的 id（取值的 `dimension`、文化的 `tendencies` 的键都用它；几个时代可以共用同一个 id，比如 `religion`），`label` 是名字（宗教、种族、民族认同、意识形态……），`required`：每个人都有这一维的取值（文化没写倾向时在这一维的全部取值里平分；不写时没有倾向的文化在这一维是空的）。
- `popDensity`：默认的人口密度，人 / km² 陆地（湖面不算）。默认总人口 = 它 × 干的陆地面积（`defaultTotalPop`）。按地球大小（陆地约 1.49 亿 km²）标定：中世纪 2.7 → 约 4 亿；青铜时代约 0.2–0.4，古典约 1.3，近世约 4，近现代约 10，现代约 50（内置的取值见下面的“内置的时代与文化”）。
- `sparsity`：人口有多集中，每格的人数 ∝ 宜居度 ^ sparsity（0.5–5；1 均匀些，青铜时代 2.5–3 挤在河谷里）。
- `urbanization`：城市化率 0–1（第二十四轮放城市时用）。
- `unclaimed`：宜居度低于 `minHabitability` 的格人口再乘以 `nomads`（0 没人住，1 照常）。青铜时代 `{0.25, 0.05}` 大片空地；中世纪、DnD `{0.05, 0.3}` 稍差的地方也住了人、游牧民住恶劣的地方；现代 `{0.01, 0.8}` 全部填满。第二十三轮国家也按它留无主地。
- `seaClaimKm`：领海（第二十三轮）：离岸多少 km 以内的海算国家的，0 是海不归任何国家。内置的按“地图上看得出一圈近海”定（近现代 40、现代 120、科幻 200），不是法律上的 22 km：一格约 100 km 时 22 km 一格都占不到。
- `defaultGroups`：新建向导默认勾的文化组与各占多少；`cultureGroups`：这个时代能用的文化组（省略时不限；只是给界面的提示，命令不拦）。
- `governments`、`factions`：这个时代能用的政体、派系（第二十三轮，见“国家与政体”）；`resources`：以后的轮次用的资源 id，现在只是存着。`countryKm2`、`years`（第二十三轮）：国家平均多大、年份的范围，见“国家与政体”。

**人口维度的取值**（`popValueSchema`）：

```json
{ "id": "ancestor-rites", "dimension": "religion", "name": "祖灵信仰", "color": "#9a6a4a",
  "description": "祭祀祖先与地方神灵。", "eras": ["antiquity", "medieval", "industrial", "modern"],
  "prefs": [{ "classes": ["hills", "mountains", "forest"], "factor": 1.5 }] }
```

- `dimension`：属于哪一维（时代的 `dimensions` 里的 id）。`eras`：只在这些时代里有（省略时不限；内置的都写明了，几个时代共用同一维的 id 时靠它分开，比如奇幻的宗教与历史上的宗教都是 `religion`）。
- `prefs`：有这一取值的人在哪里更多（矮人 × 山地）——只影响一格里的成分（这一维取哪个值），不影响一格的总人数。

**文化组**（`cultureGroupSchema`）：

```json
{ "id": "elves", "name": "精灵", "color": "#3c964b", "description": "……",
  "prefs": [{ "classes": ["forest", "woods"], "factor": 3 }, { "classes": ["desert", "steppe"], "factor": 0.4 }],
  "eras": ["fantasy"] }
```

- `prefs`：喜欢的地理：发源地按“宜居度 × 偏好”挑，扩张时偏向这些地方（走一条边的代价 ÷ √偏好），人口也更多住在这里。
- 同一个组里的文化互相兼容（第二十三轮国家用）。

**文化**（`cultureSchema`）：

```json
{ "id": "yamato", "group": "eastern", "name": "汐见人", "color": "#d26900", "nameStyle": "ja-kanji",
  "weight": 1, "description": "……",
  "tendencies": { "religion": [["ancestor-rites", 4], ["awakening", 2.5], ["sky-way", 1], ["secular", 3], ["elder-dragons", 3]] },
  "prefs": [{ "coast": true, "factor": 1.5 }] }
```

- `group`：文化组的 id。`nameStyle`：地名风格的 id（`core/packs/names/` 里的内置风格，或世界里启用的）；生成时内置的会自动启用。
- `weight`：在组里占多少（省略为 1）：组里的人按它分。
- `tendencies`：默认倾向，维度 id → 带权重的取值。生成时每格按 权重 × 取值的偏好 × e^(1.6·噪声) 再取 2.5 次方归一（噪声按地图上的位置，波长约 1200 km：同一种宗教成片），占比不到 4% 的去掉，每维最多 3 种。世界里没有的取值跳过——所以几个时代的取值可以写在同一张表里，每个时代只认它有的（上面的汐见人：中世纪认前三种，现代多认“无宗教”，奇幻只认“古龙崇拜”）。权重不分时代：同一个取值在每个时代都是同一个权重，要按时代变就用不同 id 的取值。因为取 2.5 次方，比最大的小 4–5 倍的取值只在噪声偏向它的地方成片出现。
- `prefs`：自己喜欢的地理，与组的连乘。

**写内置的时代与文化**（给写内容的人）：

1. 时代：`core/packs/eras/<时代 id>.json`，写 `{ "era": {...}, "values": [...] }`（`values` 是只属于这个时代的取值，可以省略）；在 `core/packs/eras/index.ts` 的 `ERA_FILES` 里加一行。
2. 几个时代共用的一维的取值：`core/packs/eras/values/<维度>.json`，一个数组，每项用 `eras` 写明在哪几个时代里有；在 `VALUE_FILES` 里加一行。同一个 id 只算先列的那一个（`VALUE_FILES` 在 `ERA_FILES` 前面）。
3. 文化组：`core/packs/eras/cultures/<组 id>.json`，写 `{ "group": {...}, "tendencies": {...}, "cultures": [...] }`；在 `CULTURE_FILES` 里加一行。仓库里按这几张表的先后列出。`tendencies` 是组里文化的默认倾向（格式同文化的 `tendencies`，只在文件里有，文化组本身没有这一项）：文化自己写了的那几维换掉组的（不是合并），没写的照抄组的；读进来的 `BUILTIN_CULTURES` 每个都带着完整的倾向。
4. id 用小写字母、数字、连字符；名字不超过 20 个字；颜色 `#rrggbb`。同一个时代能用的文化组、文化，同一维、同一个时代的取值，色差（CIE76）要分得开（`eras-builtin.test.ts` 查：组、取值 > 18，文化 > 14，同组的文化 > 18）；文化组、文化不要太暗、太亮、太灰。
5. 文化的名字用自己编的、有那种语言味道的（“卡尔维人”，不写“德国人”）；文化的 `nameStyle` 写内置风格的 id（见“地名风格的写法”的 27 种，每一种都有文化在用）。
6. 偏好的倍数一般 0.3–4；组的偏好决定发源地落在哪、地盘往哪长（偏好太强时组会挤在一小块里）。只写喜欢的不够时加一条不喜欢的（草原组的森林、山地 × 0.5，西欧的干草原、沙漠 × 0.7），不然地盘会被权重大的组挤到别处。倾向的权重写相对大小（3 : 1）。
7. 每个文化在它能用的每个时代（时代的 `cultureGroups` 里有它的组、组的 `eras` 里有这个时代）的每一维都要有这个时代认的倾向，不靠“每人都有”的平分（测试查）。
8. 维度的取值的名字用通用的叫法或自己编的，不照搬真实宗教的教义文字；意识形态按光谱细分时每一维最多十几种。
9. `population.test.ts` 用内置的中世纪与西欧、东亚、草原三组生成，记着金标准（改了这几样的数据就要重录那两组哈希）；`eras-builtin.test.ts` 查全部内置的内容（见“测试”）。

**世界里的数据**（`world.ts`）：
- `small.human`：`{era, seed, groups: [{id, weight, cultures?}], totalPop, perWeight, hearths: [{group, culture?, cell, locked?}], nextGroup}`——生成用的参数、每一份“生成权重”合多少人（修补新陆地用）、发源地（文化组的写 `group`，组里文化的另写 `culture`；拖过的 `locked`）、下一个群体的编号。
- `small.popGroups`：群体的编号 → `{culture, values: {维度 id: 取值 id}}`（没有这一维的取值时不写）。生成后按第一次出现的格重新编号（1 起，`groups.ts` 的 `compactGroups`）；笔刷用到新的群体时往后加（`GroupTable`）。
- 原因（可选，生成时才建，撤销到那之前时去掉，进撤销、检查点、快照）：`causes.popTotal`（Float32，每格的人数）、`causes.popGroup`（Uint16，n × 4：第 i 格是 `[4i, 4i + 4)`，按占比从大到小，0 是空位）、`causes.popShare`（Uint8，n × 4，占比 /255，4 个加起来不超过 255，剩下的是“其他”）、`causes.popManual`（Uint8，1 是笔刷、档案改过的格，第一次改时才建）。读一格用 `readComp(causes, i)`（`[{code, s}]`，s 是 0–1，code 0 是“其他”）。
- 推导：`derived.habitability`（Float32，0–1，总有，水面为 0）；只在生成过人文时有：`popDensity`（Float32，人 / km²）、`popCulture`、`popCultureGroup`（Uint16，人口里占多数的文化、文化组的编号，0 没有人）、`popValue`（Uint16，n × 维度数，按维度分段：第 k 维是 `[k·n, (k+1)·n)`，`valueLayer(world, k)` 取那一段，编号是 `dimensionValues` 的下标 + 1）、`cultureNear`（Uint16，最近的文化：从有人的格按步数往外扩，海、没人的地方也有，地名用）。占多数按 4 个群体里同一个文化（组、取值）的占比相加，“其他”不算，一样多时编号小的。`HUMAN_DERIVED` 加了 `habitability`，`POP_DERIVED` 是人口的几层；都不进金标准的 `digestWorld`。
- 没生成过人文的世界：原因、小数据里一项都不多（`habitability` 是推导，不进金标准）。

**宜居度**（`human/habitability.ts`，推导，自然改了、画了地形类别就重算，只画人口时照用上一份）：每格 = 生态的宜居分 × 冷 × 水与海岸 × 地势 × 地形类别的倍数，截到 [0, 1]，只算干的陆地。
- 生态的宜居分：生态写了 `habitability`（0–1，生态编辑器、`update_species` 改，只改它时重算到 `human`）就用它；内置的 13 种按 `BIOME_HABITABILITY`（冰盖 0.01、苔原 0.12、针叶林 0.35、温带阔叶林 0.8、温带草原 0.65、地中海灌木 0.75、亚热带常绿林 0.8、稀树草原 0.6、热带干燥林 0.6、季雨林 0.75、雨林 0.35、沼泽 0.3、荒漠 0.06）；别的按生态的地形（plains 0.8 … desert 0.07、arctic 0.08）与最适合的气温估（`biomeHabitability`）。
- 冷：年均温 0 °C 以下渐渐变少，−15 °C 以下只剩一成。
- 水：有河（流量够画成河）时先至少 0.45（荒漠里的大河两岸也能住人），再 ×1.35–1.8（河越大越多）；挨着海 ×1.3，挨着湖 ×1.2。
- 地势：海拔 1500 m 以上渐渐变少，5000 m 以上只剩 5%；坡度 ×1 / (1 + 坡度 / 30)。
- 地形类别：类别写了 `habitability`（0–3）就用它，内置的按 `CLASS_HABITABILITY`（平原、草原 1，干草原、丘陵 0.85，高原 0.75，山地 0.45，山峰 0.08，森林 0.85，林地 0.95，丛林 0.7，沼泽 0.6，沙漠 0.7，冻原 0.8，冰川 0.1）。

**生成**（`human/generate.ts` 的 `generateHuman`，分步，每一步是一个 `HumanStage {id, run(ctx)}`，共用的东西在 `GenContext`，见 `human/context.ts`）：
1. **文化圈**（`human/cultures.ts`）：
   - 发源地个数：全世界 max(组数, 陆地面积 / 2500 万 km²)，按权重分给各组，每组至少一个。按“宜居度 × 组的偏好 × (1 + 0.35·噪声)”挑，与已有的发源地隔开 0.6·√(陆地面积 / 个数)（挑不出来时放宽），装不下这一组那一份的小岛得分低；同一组的第二个靠近第一个。权重大的组先挑，每一轮每组挑一个。拖过的（`locked`）留在原处（变成了海的挪到最近的陆地）。
   - 地盘：各组从发源地按代价同时往外长（`space.ts` 的 `growByBudget`），每格归先到的那一组，一组占的“宜居的面积”（km² × 宜居度）到了按权重分的那一份就停下、让给别人，最后谁都没占到的格归最近的。代价：陆上 km × 地形类别的通行难度 × (1 + 高低差 / 600) × 过河 1.5；进湖 ×3；下海 ×8、海上 ×4、上岸 ×2（跨海贵但能过）；÷ √组的偏好。海也分给了各组。
   - 组里的文化：在组的地盘里同样挑发源地（一个文化一个）、按文化的权重分地盘。拖到组的地盘外的文化发源地那一格归这个组。
   - 结果：`ctx.groupOf`、`ctx.cultureOf`（每格是第几个组、第几个文化，−1 没有）、`ctx.hearths`。
2. **国家**（第二十三轮，见“国家与政体”：`countries` 一步在人口之前，改 `ctx.popScale`（每格人口权重的倍数）；`country-mix` 一步在人口之后）：别的步也可以用 `registerHumanStage(stage, {before: 'population'})` 插进来。`humanStages()` 列出现在的步骤。
3. **人口**（`human/population.ts`）：每格的权重 = km² × min(1.5, 宜居度 × 文化的偏好)^sparsity（宜居度低于 `minHabitability` 再 × `nomads`，× `popScale`）；每个文化分到 总人口 × 组的权重比例 × 组里文化的权重比例（地盘里没有能住人的格的文化那一份分给别的），在自己的地盘里按权重分。成分：本地的文化，文化圈边上掺邻近的文化（离另一个文化的地盘 d km，掺 0.5·e^(−d / 格距)）；每个文化各维按倾向分（见“文化”），各维的组合里取最多的 4 种。手改过的格在保留手改的重新生成里不动（总人口扣掉它们的人）。
4. 写进 `small.human`、整理群体的编号。内容（时代、组、文化、风格）缺的从内置的复制进来。

**命令**（都是 `Dirty.Human`：只重算人文的几层与名字；撤销记 `popTotal / popGroup / popShare / popManual` 四个数组）：
- `generate_human {era, groups: [{id, weight, cultures?: id[]}], totalPop?, seed?}`：生成（已有人文时整个换掉，手改的不留）。`totalPop` 省略时按时代的默认密度，`seed` 省略时用世界的种子。历史“生成人文“中世纪” · 3 个文化组 · 4.0 亿”。不认识的时代、文化组报错。
- `regenerate_human {era?, groups?, totalPop?, seed?, keepManual?}`：按记着的参数重新生成，写了的几项换掉；拖过的发源地留着（换了组时不在新组里的去掉）；`keepManual` 省略为 true（手改过的格不动）。“重新生成人文”。
- `move_hearth {group | culture, index?, cell | null, keepManual?}`：挪一个发源地（文化组的写 `group`，同组有几个时 `index` 是第几个；组里文化的写 `culture`），挪过的锁定，`cell: null` 是恢复自动；之后照 `regenerate_human` 重新生成。“挪动发源地“西方””“发源地“西方”恢复自动”。
- `remove_human {}`：去掉人文（人口清零，数组留着，小数据里的去掉）。“删除人文”。`set_worldgen` 的新世界也去掉。
- `set_pop_total {total}`：总人口按比例改（每格 × 同一个倍数）。“总人口 · 2.0 亿”。
- `paint_pop {cells, t?, mode, ...}`：人口笔刷，只画干的陆地，`t` 是画笔的权重（0–1，与 cells 对齐，省略为 1）。改过的格记 `popManual`。
  - `mode: 'share', group: {culture, values}, amount`：这个群体的占比升高 a = amount × t（每个群体 × (1 − a)，这个群体 + a），人数不变；没人的格不画。“人口“阿拉伯 · 月轮教” · 36 格”。
  - `mode: 'count', factor`：人数 × factor^t（0.01–100；Shift 反过来由界面给 1/factor）；没人的格在 factor > 1 时按最近的有人的格的成分补上一些人（世界的平均密度 × 宜居度 × (factor^t − 1)）；不到半个人的清零。“人数 ×1.5 · 36 格”。
  - `mode: 'value', dimension, value, amount`：每个群体里 a 的人这一维换成 value（传教、改宗），文化与别的维不变。“宗教改为“月轮教” · 36 格”。
- `paint_culture {cells, t?, culture, amount, typical?}`：文化笔刷：每个群体里 a 的人换成这个文化（别的维不变）；`typical` 时换成这个文化最典型的群体（`typicalTuple`：每一维取倾向里权重最大的）。“文化“法兰克” · 36 格”。
- `set_cell_pop {cell, total?, groups?: [{culture, values, share}]}`：档案里改一格（只能是陆地）：总人数、各群体的占比（0–1，不到 1 的是“其他”，超过时按比例缩）。“人口改为 5000”“修改人口”。
- 群体里的文化、取值要在世界里，维度要是这个时代的，不然报错。历史里几格是真改了的格数（已经是这个文化的格不算）。

**改地形以后的修补**（`population.ts` 的 `populationFix`，`Engine.fixPopulation`）：一步改了陆海、湖之后（推导算好之后，与湖省的整理同一个地方）：变成水面（海、湖）的格去掉人口；这一步之前是水面、现在是干的陆地、还没有人的格，按宜居度补上人（km² × (宜居度 × 最近的文化的偏好)^sparsity × `small.human.perWeight`，低于 `minHabitability` 再 × `nomads`），成分照最近的有人的格。别处的人数不动（宜居度变了也不动，要整体重来时重新生成），手改过的格只在变成水面时清掉。结果记进这一步的命令 `popFix {cells, total, groups, shares}`（重放、重做照用）与撤销记录，再重算一次人文的几层与名字。

**地名跟着文化**（`name-styles.ts` 的 `styleFor`，数据在 `human/culture-style.ts`）：一处地方用哪种风格：自己选的 → 当地占多数的文化的风格 → 世界默认 → 内置中文。“当地”：地物是它的格，省份是它的格（`{province, cells?}`），一格是它自己（格所在的省份选了风格时按省份）。占多数按人数（`popCulture × popTotal`）；一个人都没有的地方（海、荒地）按格数取 `cultureNear`。文化的风格不在世界里时跳过。按 `popCulture`、`popDensity` 两个数组（内容不变时沿用同一个）与地物的格列表缓存，只在文化变了时重新判断。没有人文的世界什么都不变。省份的名字只在新起名时按当地的文化（已有的省名不动；要换时用界面的“重起省名”）。为了让起名看得到人口的几层，第二十二轮把人文的几层挪到了认地物之前（`computeHuman` 不看地物）。

### 国家与政体（第二十三轮）

人文的第三批：领土按格画（可以有无主地），一个陆地省只属于一个国家，每国一份档案（名字、颜色、旗帜、首都、政体、主流文化与兼容的文化组、派系、外交、统治者、建国年份、历史）。生成的顺序是 文化圈 → **国家** → 人口 → **国家的移民**。政体只是“生成的倾向 + 说明”，不带游戏数值；派系由时代定义，影响力由人口构成大致算出。都只读自然的推导，不改地形（`core/human/`）。

**两种内容**（`human/government.ts` 的格式，`human/gov-kinds.ts` 登记；`store: 'content'`，命令 `set_content`，改了重算到 `human`；内置的在 `core/packs/governments/`）：

| 种类 id | 全称 | 资源包的段 | 世界里 | 内置的 |
|---|---|---|---|---|
| `government` | 政体 | `governments` | `small.content.government` | `BUILTIN_GOVERNMENTS` |
| `faction` | 派系 | `factions` | `small.content.faction` | `BUILTIN_FACTIONS` |

内置的不是总在的：在仓库里启用，或者生成国家时自动复制进来（`countries.ts` 的 `ensureGovContent`：时代的 `governments` / `factions` 列着的内置项；没列时是 `eras` 里写了这个时代的；世界里一个这个时代的政体都没有、内置的也没有时，复制全部内置的政体，保证生成得出来）。这个时代能用哪些：`eraGovernments(small, era)` / `eraFactions(small, era)`（时代列了的、世界里有的；没列时是世界里 `eras` 写了这个时代或不限时代的；再没有时是世界里全部的——时代还没有自己的政体、派系时借用别的时代的）。派系同样：内置的里一个这个时代的都没有、世界里也没有时复制全部内置的。

**政体**（`governmentSchema`）：

```json
{
  "id": "feudal-monarchy",
  "name": "封建君主制",
  "category": ["monarchy"],
  "description": "国王把土地分封给贵族……",
  "color": "#9a4b3c",
  "title": {
    "default": { "zh": "王国", "orig": "Kingdom of {name}" },
    "steppe": { "zh": "汗国", "orig": "{name} Khanate" },
    "eastern": { "zh": "国" }
  },
  "rulerTitle": { "default": "国王", "steppe": "可汗" },
  "eras": ["medieval"],
  "weight": 3,
  "size": 1, "expansion": 0.3, "coastal": 0, "urbanization": 1, "cohesion": 0.5, "vassals": 0.45, "nomadic": 0,
  "emblems": ["crown", "lion", "tower"],
  "layouts": ["cross", "tricolor-v"]
}
```

- `category`：类别（几个标签，1–8 个，每个不超过 16 字）。建议用英文 id：`monarchy` 君主制、`republic` 共和制、`theocracy` 神权、`tribal` 部落、`federation` 联邦、`empire` 帝国、`oligarchy` 寡头、`nomadic` 游牧、`dictatorship` 独裁、`democracy` 民主、`communist`、`fascist`、`corporate`、`magocracy`（`CATEGORY_NAMES` 有中文名，`categoryName(c)` 不认识的照写）。派系的基础影响力、旗帜默认的纹章按它。
- `title`：国家的称号。写法：一个字符串（`"王国"`）、`{zh, orig?}`（`orig` 是原文的写法，`{name}` 换成国名地名部分的原文：`"Kingdom of {name}"`、`"{name} Khanate"`）、或按文化换说法的表（键是**文化 id、文化组 id 或 `default`**，先看文化、再看文化组、最后 `default`，都没有时取第一项；值是前两种写法之一）。中文里写了 `{name}` 时换进去（`"大{name}朝"`），没写时接在后面（“X王国”）。`pickTitle(title, culture)`、`titled(base, title)`。
- `rulerTitle`：统治者的称号，写法同 `title`（只用中文）。省略时档案里没有称号。
- `eras`：只在这些时代里有（省略时不限）。`weight`：被挑中的多少（省略为 1）。
- 生成的倾向（都有默认值）：`size` 国土的相对大小（0.05–10，1 平均；帝国 3、城邦 0.15）；`expansion` 扩张性（0–1：越大越容易越过文化的边界，境内的异族越多，人口一步后还往异族的地方掺主流文化的人）；`coastal` 偏海岸（0–1：起点挑海边，往内陆长的代价 × (1 + 3·coastal)）；`urbanization` 城市化（0–5：首都一带的人口倍数，第二十四轮放城市也用）；`cohesion` 紧凑（0–1：下海的代价 × (1 + 3·cohesion)，越远越难长）；`vassals` 收附庸的可能（0–1）；`nomadic` 游牧（0–1：能占宜居度低于时代下限的地方，下限 × (1 − nomadic)）。
- `emblems` / `layouts`：旗帜偏好的纹章、样式（`FLAG_EMBLEMS`、`FLAG_LAYOUTS` 里的 id；省略时按类别）。

**派系**（`factionSchema`）：

```json
{
  "id": "merchants", "name": "商人", "color": "#c9a227", "description": "行会与商家……", "eras": ["medieval"],
  "base": { "republic": 1.4, "oligarchy": 1, "monarchy": 0.35, "default": 0.3 },
  "drivers": [{ "coastal": true, "weight": 0.8 }, { "dimension": "religion", "value": "sun-faith", "weight": 0.5 }]
}
```

- `base`：政体的类别 → 基础影响力（0–10）。国家的政体有几个类别写在这里时取平均，一个都没写时用 `default`（再没有为 0）。
- `drivers`：来自人口的部分（最多 16 条），每条 = `weight`（−10–10）× 这部分人占国家人口的比例。这部分人：`dimension` + `value`（某一维取某个值，如 `religion` = `sun-faith`）、`culture`、`cultureGroup`、`primary: true`（主流文化）、`minority: true`（不在兼容文化组里的人）、`coastal: true`（住在海边的格）；写了几项时取比例最小的那一项。
- 影响力（`countryFactions(world, id)`）：每个这个时代的派系 max(0, 基础 + Σ 来源)，再归一（加起来是 1，三位小数）。档案里自己定过（`set_country {factions}`）时照用定的。

**时代多的几项**（`eraSchema`，都可以不写）：`governments` / `factions`（能用的 id，见上）；`countryKm2`（“统一 ↔ 分裂”在正中时一个国家平均占多少 km² **能住人的**陆地，省略为 `COUNTRY_KM2` = 160 万；地球大小的中世纪星球上约 60–90 个国家）；`years`（`[最早, 现在]`，建国年份在这里面，省略为 `[500, 1000]`）。已有的 `unclaimed.minHabitability`（宜居度低于它的格不归国家，游牧的政体放宽）与 `seaClaimKm`（领海）现在起作用。

**文化多的一项**：`tendencies.government`（与别的维度同一种写法：`[["feudal-monarchy", 3], "theocracy"]`）——这个文化的国家更可能是哪些政体；写了时没写到的政体 × 0.15，没写时按政体的 `weight`。

**地名风格可以多写两类**（都可以不写）：`country`（国名的地名部分）、`person`（人名，统治者用）。没写时：音译式拼一个词根（原文首字母大写，中文是音译）；模板式国名用 `region` 的写法（避开“地区、之地、地方、道、一带”结尾的），人名从词表里取两个一两个字的词（`human/country-names.ts` 的 `countryBase`、`personName`）。

**写内置的政体与派系**（给写内容的人）：

1. 放进 `core/packs/governments/<名字>.json`，写 `{ "governments": [...], "factions": [...] }`（一般一个时代一个文件；几个时代共用的政体写一次，`eras` 里写上几个时代；同一个 id 只算先列的文件里的那一个），在 `core/packs/governments/index.ts` 的 `FILES` 里加一行（仓库里按这个先后列出）。时代里用 `governments` / `factions` 列出 id。
2. id 用小写字母、数字、连字符；名字用通用的政治学叫法，不超过 20 个字；说明自己写、一两句，不搬游戏文本，不带游戏数值。
3. 每个时代 5–8 种政体、3–6 个派系就够。建议的 id（`medieval` 的六种、三个派系已经有了）：
   - 青铜：`chiefdom` 酋邦、`city-state` 城邦、`temple-state` 神庙国家、`early-kingdom` 早期王国、`tribal-confederation` 部落联盟；派系 `priests` 祭司、`warriors` 武士、`elders` 长老。
   - 古典：`city-state`、`classical-republic` 共和国、`kingdom` 王国、`empire` 帝国、`tribal-confederation`、`theocracy`；派系 `aristocrats` 贵族、`commoners` 平民、`priests`、`merchants`。
   - 中世纪：`feudal-monarchy`、`merchant-republic`、`theocracy`、`tribal-confederation`、`empire`、`city-state`；`nobility`、`merchants`、`clergy`。
   - 近世：`absolute-monarchy` 专制君主制、`constitutional-monarchy` 君主立宪、`merchant-republic`、`colonial-empire` 殖民帝国、`elective-monarchy` 选举君主制、`theocracy`；`nobility`、`burghers` 市民、`clergy`、`bureaucrats` 官僚。
   - 近现代：`constitutional-monarchy`、`parliamentary-republic` 议会共和制、`federal-republic` 联邦共和国、`colonial-empire`、`one-party-state` 一党制国家、`military-junta` 军政府；`industrialists` 实业家、`workers` 工人、`military` 军方、`nationalists` 民族主义者。
   - 现代：`liberal-democracy` 自由民主制、`federal-republic`、`presidential-republic` 总统制共和国、`one-party-state`、`military-junta`、`absolute-monarchy`、`theocratic-republic` 神权共和国、`technocracy` 技术官僚制；派系按意识形态的光谱。
   - 奇幻（DnD）：`feudal-monarchy`、`elven-council` 精灵议会、`dwarven-hold` 矮人氏族、`orc-horde` 兽人部众、`magocracy` 法师统治、`theocracy`、`city-state`；`mages` 法师、`guilds` 行会、`temples` 神殿、`nobility`。
   - 科幻：`galactic-federation` 星系联邦、`stellar-empire` 星际帝国、`corporate-state` 公司国家、`technocracy`、`hive-collective` 集群；`corporations` 公司、`military`、`scientists` 科学家。
   称号写 `default` 再按文化组换说法（草原的“汗国”、东方的“朝”、日本的“幕府”这类按文化 id 写）；原文写法写 `orig`。
4. 时代的 `countryKm2` 建议：青铜约 20 万（再加上 `unclaimed.minHabitability` 高，小国林立、大片无主）、古典约 60 万、中世纪 160 万（默认）、近世约 150 万、近现代约 120 万、现代约 70 万（地球上约 200 个国家）；`years` 写那个时代的年份（青铜 `[-3000, -1200]`、现代 `[1900, 2020]`……）。
5. `countries.test.ts` 会查内置的示例（格式、每个内置的时代都生成得出国家、生成后的金标准）：改了内置的中世纪、文化、政体的数据就要重录那两组哈希（`RECORDED`，同 `population.test.ts`）。

**世界里的数据**（`world.ts`）：

- `causes.country`（Int32，每格的国家编号，−1 无主）：只记陆地（湖面也算）；海不记（领海是推导）。生成国家时才建，撤销到那之前时去掉（`UndoRecord.dropArrays`），进撤销、检查点、快照。删除国家、删除人文、新建世界时填 −1（数组留着）。
- `small.countries`：编号（1 起）→ `CountryMeta`；`small.nextCountry`：下一个编号。生成过国家才有。
- `small.human.countryRules`：`{fragmentation, seed}`——“统一 ↔ 分裂”（0 统一：国家平均大 8 倍；1 分裂：小 8 倍；0.5 按时代的 `countryKm2`，`sizeFactor(f)` = 8^(1 − 2f)）与种子。有它才算“有国家”。
- `CountryMeta`：

- 旗帜（`human/flags.ts`）：`layout` 是 `FLAG_LAYOUTS`（`plain bicolor-h bicolor-v tricolor-h tricolor-v cross nordic saltire canton chevron quartered border diagonal stripes`，`LAYOUT_COLORS` 是每种要几种颜色），`colors` 1–4 种（底色在前，少了用底色），`emblem` 是 `FLAG_EMBLEMS`（`star sun moon crown cross circle tower tree sword eagle lion wheel mountain wave`）。`makeFlag(seed, 国家的颜色, {categories, layouts, emblems})` 生成（纹章的颜色与底色分得开），`flagSvg(flag, w?, h?)` 画成 SVG 字符串（界面、导出共用）。
- 推导：`derived.country`（Uint16，每格的国家编号 = `countryList` 的下标 + 1，0 无主；陆地按 `causes.country`，海按时代的 `seaClaimKm`：从海岸往外按 km 走，离谁家的海岸近、不超过这么远的海归谁，离无主的海岸近的不归谁）。只在有国家时有；领土、陆海、国家的编号、领海都没变时照用上一份。`COUNTRY_DERIVED`；不进金标准的 `digestWorld`（没有国家的世界没有它）。

**生成**（`human/countries.ts`，两步：`countries` 在人口之前、`country-mix` 在人口之后，`humanStages()` 是 `['cultures', 'countries', 'population', 'country-mix']`；`GenContext.countries` 是 `CountryPlan {mode: generate | keep, rules, keepLocked}`，没有时这两步什么都不做，与第二十二轮逐值相同）：

1. **几个国家**：能住人的干陆地（宜居度 ≥ 时代的下限、不是锁定的国家的）面积 ÷（`countryKm2` × `sizeFactor`），最多 `MAX_COUNTRIES` = 512 个；按各文化能住人的面积（km² × 宜居度）分给文化，分到 0.4 个以上的至少一个。
2. **政体与起点**：每个文化按 `govWeights`（政体的 `weight` × 文化的 `tendencies.government`）挑够数的政体，大的先挑起点：本文化的地盘里宜居度 × (1 + 0.35·噪声) × 海岸（偏海岸的政体在海边 × (1 + 2·coastal)，内陆 × (1 − 0.6·coastal)）最高、离已有的起点不近于 0.6·√(文化的面积 / 个数) km 的格（挑不出时放宽）。
3. **往外长**：各国从起点按代价同时长（一个 Dijkstra，每格归先到的），走一条边的代价 = 文化圈的那一套（`cultures.ts` 的 `edgeCosts`）× 进别的文化（同组 × (1 + 0.6·(1 − expansion))，别的组 × (1 + 2.5·(1 − expansion))）× 内陆（× (1 + 3·coastal)）× 下海（× (1 + 3·cohesion)）÷ 强弱（√size × 0.85–1.15）× 越远越难（1 + cohesion · 已走的 / (2R)，R = √(平均面积 × size / π)），超过 20R 不长。宜居度低于下限 × (1 − nomadic)（最低 0.002，冰盖谁都不占）的干陆地不进；海能穿过、不归国家；锁定的国家的格不进。
4. **整理**：湖（连成一片的湖面）归湖岸上格数最多的那一国（没有时无主）；不连着首都、小于 max(3 格, 这国的两成)、挨着别国的小块并给接壤最多的邻国（邻国按自己的下限占不了的格成无主地）。
5. **档案**：编号接着 `nextCountry`；主流文化 = 起点的文化，兼容的文化组 = 主流的组 + 国土里能住人的面积占三成以上的组；颜色 = 主流文化的颜色按序号挪色相、深浅（与已用的不重）；旗帜、名字（主流文化的风格起地名，避开已有的国名，接政体的称号）、统治者（人名 + 称号）、建国年份（`years` 里，偏近）。
6. **外交**（只在新长出的国家之间；邻国 = 陆上接壤或隔一格海）：附庸——从小到大看，旁边大 3 倍以上、自己不是附庸的国家按它的 `vassals` ×（同组 1、别的 0.5）×（自己的 size ≤ 1 时 1、否则 0.5）的概率收下（没有附庸链）；同盟、敌对——亲近 = 同一个文化 2、同组 1、兼容的组有重的 0.5、别的 −1，同一类政体再 +0.5；亲近 ≥ 1 时三成结盟（各不超过 3 个），≤ 0 时三成半敌对（各不超过 2 个）。
7. **历史**：“{年份} 年，{文化}人建立{国名}。”＋“后来成为{宗主}的附庸。”／“此后向外扩张，境内也住着{异族}人。”（扩张性 ≥ 0.6、有占一成以上的不兼容文化）／“靠海上的贸易立国。”（偏海岸 ≥ 0.6）＋“与{…}结盟。”“与{…}不和。”（`historyText`）。
8. **人口**（人口一步之前）：`ctx.popScale` = 1 + 1.2 × 城市化 × e^(−到首都的距离 / R)，R = max(两倍格距, 0.15 × √国土面积)（只在国土里、6R 以内）。**国家的移民**（人口一步之后，`country-mix`）：扩张性 0.06 以上的国家，占多数的文化组不兼容的有人的格掺进 0.35 × 扩张性 的主流文化的典型群体（官吏、移民），手改过的格不动。
- `mode: keep`（重新生成人文、挪发源地、不换国家时）：用现有的领土，只按它调人口（首都一带、移民）。
- 锁定的国家（`keepLocked`）：领土、档案都留着；外交里指向重新生成掉的国家的去掉。

**省份跟着国界**（`provinces.ts`）：一个陆地省（陆地、无人区、湖省）只属于一个国家（无主也算一个）；海省不跟着国界（领海按格推导）。`countryKeys(world, pland)`（按格分是陆地的格是它的国家，海是 −2；没有国家时为 null，什么都不变）：
- 自动划分（`partition`：起点的间隔、生长、小省并入）与补格（`fillUnassigned`：修补、湖省的整理）都不跨国界。
- `fitProvincesToCountries(world)`：跨国界的省里格数最多的那个国家留着这个省，别的国家在这个省里的格按连成的块：小块（不到目标大小的四分之一）并进挨着的、同一个国家、同一类、没锁定、只属于这个国家的省里接壤最多的那个，别的成新省（编号接着往后，按格起名，名字由命令的 `provinceNames` 记下）。锁定的省照样切（锁定只管自动重划）。只看原因，执行、重放一样，不用另记修补。改了领土的命令、生成国家、划分省份之后都调它。
- 涂省份（`assign_province`）涂进已有的陆地省：这些格跟着这个省换国家；新建的省按国界切开。并省（`merge_province`）：并进来的格跟着 `into` 的国家。这样改了国家的这两条重算到 `Human`（国家的一层要重算）。
- 重新生成国家后省份只切不并：要整齐时重新划分省份。

**命令**（`Dirty.Human`：只重算人文的几层与名字；撤销记 `country`、`province`，生成的几条另记人口的四个数组）：
- `generate_human {…, countries?: {fragmentation?, seed?}}`：写了 `countries` 就同时生成国家（`fragmentation` 省略 0.5、`seed` 省略为人文的种子）；不写时没有国家（已有的去掉）。历史“生成人文“中世纪” · 3 个文化组 · 4.0 亿 · 14 个国家”。
- `regenerate_human {…, countries?}`：有国家时用现有的领土；写了 `countries` 时国家也重新长（锁定的留着）。`move_hearth` 同前者。
- `generate_countries {fragmentation?, seed?}`：生成国家（已有时整个换掉，锁定的也不留），参数从默认起；人口按国家重新分（手改过的格不动，等于带国家的 `regenerate_human`）。“生成国家 · 14 个”。没有人文时报错。
- `regenerate_countries {fragmentation?, seed?, keepLocked?}`：按记着的参数重新生成，写了的几项换掉；`keepLocked` 省略为 true。“重新生成国家 · 14 个”。
- `remove_countries {}`：去掉国家（人口不动）。“删除国家”。`remove_human`、`set_worldgen` 的新世界也去掉国家。
- `paint_country {cells, country: id | null}`：领土笔刷，只画陆地（湖面也算），null 是无主。“领土“X” · 36 格”“无主地 · 36 格”（格数是真改了的）。
- `new_country {cells?, name?, orig?, culture?, government?, color?, flag?}`：新建（档案自动生成：主流文化 = 这些格里人最多的文化，政体 = 时代里 `weight` 最大的，首都 = 人最多的格；写了名字时 `nameLocked`）。可以没有领土。“新建国家“X” · 12 格”。
- `merge_countries {a, b}`：b 并进 a（领土、兼容的文化组，指向 b 的外交改指 a）。“合并国家“B” → “A””。
- `split_country {id, cells?}`：cells（这个国家里的格）成新国家（同样的文化、政体、兼容的组）；不写时按离得最远的两格分成两半，没有首都的那一半成新国家。“拆分国家“X” · 分出“Y””。
- `set_country {id, patch}`：`patch` 的每一项都可以不写——`name`（'' 恢复自动；`orig` 跟着 `name`）、`color`、`flag`（null 按种子重新生成）、`government`（没改过名字时换称号）、`primaryCulture`（没改过名字时按新文化的风格重起地名；它的组加进兼容的组）、`acceptedGroups`（主流的组总在）、`factions`（null 恢复自动）、`overlord`（null 不再是附庸；不能绕成圈）、`allies` / `rivals`（整份换掉，两边都改，同盟与敌对互斥）、`ruler {name, orig?, title?}`、`founded`、`history`、`locked`。“国家“X” · 政体、改名”。
- `remove_country {id}`：领土成无主地，外交里去掉。“删除国家“X””。
- `move_capital {id, cell | null}`：首都挪到这国的一格（锁定）；null 恢复自动。“挪动首都 · “X””。
- 每条之后整理（`tidyCountries`）：首都不在领土里了换成人最多的格（没有人时离中心最近的，不再锁定；没有领土时没有首都），外交里指向没了的国家的去掉、同盟敌对两边补齐。

**改地形以后的修补**（`country-edit.ts` 的 `repairCountries`，在 `commands.ts` 的 `applyTerrain` 里、修补省份之前，只看原因，不用另记）：变成海的格不再归哪国；新长出的陆地从挨着的旧陆地按步数往外，归最近那一格的国家（挨着的是无主地就无主；四周全是海的新岛无主）。别处、手改的不动；要整体重来时重新生成国家。

**给界面的**（都从 `core/human` 导出）：
- 内容：`worldGovernments / worldFactions / governmentById / factionById / eraGovernments / eraFactions / pickTitle / titled / categoryName / CATEGORY_NAMES`、`BUILTIN_GOVERNMENTS / BUILTIN_FACTIONS`（`core/packs/governments`）、`governmentInfo(world, id)`（名字、类别的中文名、说明）。
- 列表与编号：`countryList(small)`（按编号）、`countryCodes(world)`（图层编号 → 档案，0 为 null）、`countryCells(world, id)`。
- 图层：`derived.country` 的编号；`countryColors(world)`（编号 → 国家自己的 RGB）、`countryMapColors(world, lighten = 0.45)`（地图上用的：附庸用最上面的宗主的颜色往白挪 1 − (1 − lighten)^层数，再掺两成自己的颜色——与宗主、同一个宗主的别的附庸都分得开；不是附庸的用自己的颜色）、`countryOverlords(world)`（编号 → 宗主的编号，0 不是附庸）。领海的格 `causes.land` 为 0、`derived.country` 不为 0（界面画浅色）。
- 国界：`countryGroups(world)`：每格两个值（同 `provinceGroups` 的布局，第二个总是 0），给渲染器的第二张分组纹理：有国家的格（陆地、领海）是编号，无主的陆地是 0，不归谁的海是 −1（与它相邻的不画国界：海岸线由地形画）；分组不同的相邻两格之间画国界。
- 国名：`countryLabels(world)`：每国 `{id, cells, x, y, angle, span, elong, path}`——按主体（最大的一块连着的陆地），中心、主轴（同地物标注的 `axis`，星球上跨经度接缝时展开），`path` 是沿主体弯一点的中线（主轴上的二次曲线拟合，弯得太厉害压平，5 个点从左到右——按展开的坐标比，两端颠倒时倒过来；地图坐标，星球上 x 绕回 [0, 2)，跨接缝的标注首尾的 x 可能一个近 2、一个近 0）。`labelGeometry(world, cells)` 给任意一块格。
- 档案：`countryStats(world, id)` / `allCountryStats(world)`：`{cells, areaKm2（干陆地）, lakeKm2, population, density, provinces, cultures, cultureGroups, values（每一维）: {id, name, color, people, share}[], primaryShare, minorityShare, coastalShare}`（城市第二十四轮加）；`countryFactions(world, id, stats?)`：`{id, name, color, influence}[]`；`autoCapital(world, cells)`。
- 旗帜：`flagSvg`、`makeFlag`、`flagSchema`、`FLAG_LAYOUTS`、`FLAG_EMBLEMS`、`LAYOUT_COLORS`。
- 生成的参数：`COUNTRY_KM2`、`DEFAULT_YEARS`、`MAX_COUNTRIES`、`sizeFactor`。

**导出**（`export.ts` 的 `countryFiles`，只在有国家时有）：`countries.bmp`（国家自己的颜色；海、湖用 terrain.bmp 的颜色，无主的陆地是白色，领海是国家的颜色与海的颜色各一半）、`countries.csv`（`id, name, orig, red, green, blue, government, culture, capital, population, area_km2, overlord`；capital 是格的编号）；`provinces_summary.csv` 最后加一列 `country`（省份所属国家的编号，无主为空）。README.txt 多两行。没有国家的世界这些文件、列都没有，别的文件逐位不变。

### 金标准与逐值不变的规则

- 提速、重构后结果必须逐值不变：`npm run golden` 必须过，每项提速另加一组新旧对照。
- 没涂成的建议是文字，算在 `derived.conflicts` 的哈希里：第十九轮 C 改字时重录了 `golden-full.json` 的 `derived.conflicts` 两项与 `solver-identity` 的 conflicts、world 两项，核对过清空建议的文字后逐值相同。改界面文字时别的哈希不该变。
- 第九轮去掉旧存档兼容时，金标准和各项逐值测试统一重录了一次；之后的优化必须与它们逐值相同。
- 第二十三轮（国家与政体）没有重录任何哈希：没有国家时国家的两步什么都不做（第二十二轮的人口金标准不变），`causes.country`、`small.countries`、`derived.country` 都没有，省份的划分与补格不看国界；生成的金标准另记在 `human/countries.test.ts`（地区、星球各一组：领土、档案），`raster-identity` 不用改（新文件、新列只在有国家时有）。`population.test.ts` 只改了步骤的列表（多了 `countries`、`country-mix`），`content/registry.test.ts` 多了两种内容。
- 第二十二轮（时代、文化、人口）没有重录任何哈希：宜居度、人口的几层不进 `digestWorld`（`HUMAN_DERIVED`、`POP_DERIVED`），没生成人文的世界原因、小数据一项不多、名字一个不变（地名跟着文化只在有人文时起作用；人文的几层挪到认地物之前，没有人文时起名不看它们），`raster-identity` 不用改（新文件、新列只在有人文时有）；生成的金标准另记在 `human/population.test.ts`（地区、星球各一组：人数、群体、占比、`small.human`）。
- 第二十一轮（人文的几层）没有重录金标准：人文的推导数组不进 `digestWorld`（另有 `human/human.test.ts` 的金标准）；`raster-identity` 只重录了文件列表、README.txt、provinces_summary.csv（加了两列）并记下四个新文件，别的文件逐位不变。
- 第二十轮（内容登记表、地名风格）没有重录任何哈希：只用内置中文的世界名字一个不变，新加的 `small.content`、`small.nameStyle`、`orig`、`style` 都是用到时才有。
- Node 与浏览器要逐值一致：`tools/hash.ts` 打出各层的哈希，用来对照。

## 已知限制

- 撤销只存最近几步的结果，再往前撤销要重算；排队的笔画各算一遍，画得很快时要等它们一笔一笔算完。星球上一次确切预览要几秒，太久的不自动算。
- 一块地区：东西不相接，“地图在星球上的位置”只能整体南北挪，南北跨度由建世界时的大小决定；最多约 4 万格（放大到最大时一格约 64 像素）；没有洋流。
- 整个星球的等距圆柱图两极附近被拉宽（可以换成等面积、球形投影看）；圈一片、圈地名不能绕着极点画。投影里风向、洋流、参考图不画；极地场景里虚线、双线、发光的河按实线画，导出按投影的大图受显卡纹理大小所限会软一些。
- 气候是简化的过程模型，不是 GCM：洋流是全年平均的表层流（没有深层洋流、海冰、年际变化）；季风只按大尺度海陆分布估计。
- 导出的 `terrain.bmp`、`rivers.bmp` 用的是通用配色，导入具体游戏前需要按其调色板重新映射。
- 画河、改河拖动时先画估计的样子（改的这条河按将来的样子画、会变干的河段是估计的），停一下才换成将来的整个世界；星球上要停 0.7 秒以上、算几秒。松手用的是确切的。
- 选中的自然的河的控制点取画出来的曲线化简后的点；拖一个控制点时它两边的弯曲跟着转、拉长缩短，弯点很稀时形状会比原来直一些。
- 脚本：隔离靠浏览器，不支持的浏览器上脚本在普通线程里跑；隔离时页面规则仍许连这个程序自己的网址（同源）；脚本照样能拖慢电脑、占内存。花纹、发光的着色器在个别显卡上编译不过时不另外提示。星球形态的脚本出错时提示条上没有“编辑”。
- 量距离量的是直线（星球上是大圆弧），步行天数按每天 30 km，不绕山、不绕海。
- 参考图只能“保持比例放在中间”或“拉伸铺满”，只存在这个浏览器里。
- 世界和“我的地图”只存在这个浏览器里，按网址分开；换浏览器、清数据就没了，要靠导出世界文件。
- 人文内容里城镇、道路、地标还没做（第二十一轮有了每格的地形类别、资源、小地名与备注，第二十二轮有了时代、文化圈、人口，第二十三轮有了国家与政体）；已有的省名不跟着文化换（新起的省名才按当地的文化）。内置的政体、派系只有中世纪的示例（政体 6 种、派系 3 个），别的时代还没列自己的，借用它们；时代的资源只是存着；“放地名”只是一个带名字的点。国家：重新生成后省份只切不并；历史、统治者是生成时的快照（改名不更新历史里的名字）；领海按格推导，不能按国家单独改；第二十三轮只有引擎，界面在下一步。
