# 开发说明

给改代码的人看：程序怎么搭起来的、文件在哪里、怎么测、哪些规则不能破、现在有多快、还差什么。用法见 [使用说明](使用说明.md)，每一轮改了什么见 [更新记录](更新记录.md)。

## 常用命令

```bash
npm install
npm run dev        # 开发服务器，默认 http://localhost:5173（.claude/launch.json 里用 5191）
npm test           # 全部测试
npm run test:fast  # 改代码时常跑的那部分（跳过最慢的几个文件）
npm run golden     # 只跑金标准：提速、重构后结果必须逐值不变
npm run typecheck  # 只查类型
npm run build      # 查类型后打包（一键开启用的就是打包好的程序）
npx tsx tools/generate.ts --seed 3 --out out/seed3   # 命令行批量生成并导出
npx tsx tools/hash.ts                                 # 各层结果的哈希，用来核对 Node 与浏览器是否逐值一致
npx tsx tools/bench.ts --globe                        # 整个星球（10 万格）各步的耗时
npx tsx tools/bench.ts --globe --pack fantasy --hash  # 整个星球 + 奇幻包逐步计时，最后打出世界的哈希
node tools/bench-median.mjs                           # 跑几次 bench 取中位数
```

浏览器控制台里 `await __map2Bench()` 测平移缩放每帧的耗时（`src/render/bench.ts`，按固定的镜头脚本同步地画，窗口藏着时也能测；只看同一台机器上的前后对照）。

一键开启（`启动-Mac.command`、`启动-Windows.bat` → `tools/launch.mjs`）：检查 Node 的版本；第一次（或 `package-lock.json` 改过）先装依赖；地图已经开着就只打开浏览器（代码在它打包之后更新过时提醒关掉重开）；否则先打包（源码没变时跳过），再用 vite preview 开在 http://localhost:5191，打包失败时退回开发服务器。地址固定是因为浏览器按地址保存世界。

## 架构

### 世界与流水线

- **世界的数据**（`core/world.ts`）分两类：**原因**是用户通过命令编辑的（陆海、抬升、岩性、气候微调、自定义场、省份归属，以及约束、河道引导等小对象）；**推导**是流水线从原因算出的（高程、气候、水文、植被、冲突）。
- **命令**（`core/commands.ts`）：zod 校验，是改世界的唯一入口；世界文件就是种子、设置加命令记录。
- **引擎**（`core/engine.ts`）：持有世界、命令历史与推导缓存。命令改原因 → 标记从哪一层开始重算 → 流水线：高程 → 气候（基础）→ [约束求解 → 修正场] → 水文 → 河的类型 → 植被 → 冲突检查；地物、地名、省份随后按变了的格修补。执行、撤销整步生效，中途出错回到原样。
- **气候的基础**按自然求解的高程算（含湖的碗，不含只挖河床的河），所以画河、改河不改气候和山名，也不重算高程与气候。
- **湖底**：放的湖在高程里挖（浅滩、湖盆、一两个深处，可以低于海平面）；自然的湖在水文、植被算完之后才按离岸距离修深（`hydrology.ts` 的 `shapeLakeBeds`，只改湖格的 `d.elevation`，不改水面与流向），每次重算都从地形重新来，所以与编辑历史无关。
- **岛的种类**（第十四轮）：每格记在原因里的 `causes.islandType`（Uint8；0 不是放的岛，1–4 内置的，5 起是 `small.islandTypes` 的下标 + 5；环礁潟湖的海格另加 `LAGOON_BIT` 0x80）。放岛、岛链写在新长出的陆地与潟湖上；画陆地 / 海、恢复原样画笔中心七成以内的格清掉；`set_worldgen` 新世界清零。命令 `set_island_type`（新建或整份换掉，最多 64 种）、`remove_island_type`（这种岛变成大陆岛、后面的编号往前挪，潟湖标记不变）都记撤销（`islandType`、`province` 两个数组）。它和别的原因数组一样进检查点、撤销缓存、快照（`Object.entries(causes)`）；轻快照另带一份（删种类那一步只重新起名）。颜色（`colors.ts` 的 `lithLayer` 与 `cellLayers` 里自己选的颜色）、潟湖、归哪种省、起名（`features.ts` 的 `itype:` 标签）都按它，不再按可蚀性认。
- **湖与省份**：湖是推导出来的，命令执行时还不知道。引擎在推导算好之后（`Engine.fixLakeProvinces`）按新的湖整理湖与陆地的省份，结果与撤销记录并进这一步，并记进命令（`provinceFix`），重放、重做时不用推导照着改。
- **预览**在世界的副本上执行（`core/preview-world.ts` 只带变了的数组），松手时直接采用，不再算第二遍。确切预览分阶段算，阶段之间可以停下：接着画、松手执行别的命令时不再等它算完（最多等一个阶段，通常 0.1–0.6 秒）。
- **随机**（`core/rng.ts`）：所有随机都从世界种子派生，按地图上的位置取、与格数无关，命令重放结果逐值一致。

### 线程与隔离

- **主线程**（`src/state.ts`）：世界的只读视图（网格本地构建，原因与推导来自 Worker 的快照）加界面状态。快照只带变了的推导数组（只变了一片的只带那几格），只改了名字、省份时只把这些发回来；数组用 `transfer.ts` 转交、不复制。
- **计算 Worker**（`src/worker.ts`）：持有引擎。用户的脚本只在这里跑，主线程上只用 acorn 解析、不编译（`src/ui/script-syntax.ts`）。
- **隔离**：计算 Worker 尽量从 data: 地址开（`engine-spawn.ts`，代码来源见 `engine-source.ts`：打包好的程序里取 Vite 单独打包的引擎文件的文字；开发时由 `tools/isolated-engine.ts` 在开发服务器上现打包 `/__map2/engine.js`，开发时也隔离）。这样它没有来源、受页面 CSP 管，读不到 IndexedDB，也不能联网。开起来先自查三项（`isolation-probe.ts`：来源为空、打不开存档、页面规则管得到它），全过才说隔离了；在一个页面里隔离运行过以后不会悄悄换成不隔离的线程。取不到时退回普通 Worker（问话里照实说）。
- **存储 Worker**（`storage-worker.ts` + `checkpoint-store.ts`）：与页面同源、只做存储、从不运行脚本。检查点（星球约 34 MB，连同几千步的命令）不经过主线程：主线程开一条 MessageChannel，一头给存储 Worker、一头给计算 Worker；计算 Worker 写好检查点直接发给存储 Worker，另给主线程发步号，主线程核对与命令记录一模一样后才让存储 Worker 写下。
- **看护**（`src/sandbox.ts`）：看门狗只在脚本运行期间计时（Worker 每 250 毫秒报一次平安），4 秒没有消息判定卡住，电脑睡眠、后台节流不算；1.5 秒以上告诉界面（带“停下”）。主线程留一份完整的命令记录：卡住、停下、Worker 崩了时停掉它，正在等的请求都回失败，用检查点加命令记录恢复到这一步之前；恢复时又卡住就开安全模式。安全模式在一个 Worker 里从第一次新建、打开起固定，换模式时另开一个 Worker。
- **网格 Worker**（`mesh-worker.ts`）：新建、打开时在别的线程建网格，打包后转交（`core/mesh-pack.ts`，拆包得到与就地建的逐值相同的网格），并存进浏览器，下次直接读（键带上打包格式的版本）。最多等 6 秒，之后在主线程自己建。
- **导出 Worker**（`export-worker.ts`）：游戏文件包、整张地图的栅格化、编码、打包，进度发回顶部，可以取消。

### 检查点与保存

- **自动保存**存在 IndexedDB（`src/idb.ts`，库是第 6 版），只写变了的那些命令；IndexedDB 用不了时退回 localStorage。
- **检查点**：引擎的完整状态（原因、推导、历史）。打开时直接恢复，不必重放所有命令。版本号：打包好的程序里是引擎文件的地址（文件名带内容哈希），开发时是引擎文件内容的哈希。
- **我的地图**（`src/maps.ts`）：IndexedDB 的 `maps`（列表要用的一小条：名字、时间、地区还是星球、格数、缩略图）与 `mapDocs`（整个世界文件）两张表，总在同一个事务里写；连着哪一张记在自动保存里。刷新后只是打开过的地图不再重写。
- **世界文件的版本**（`core/doc-version.ts`）：现在是 5，只认 5。单独放一个小文件，主线程打开文件、读自动保存时也要查，不必引进整个引擎。旧版本一律打不开、不去重放，代码里不留旧存档的写法。

### 缓存与性能设计

结果全部逐值不变（见“测试”）；每一项提速都有自己的“新旧算法逐位相同”测试。

- **撤销缓存**：最近几步的完整推导结果都存着（地区 8 步、星球 6 步，相同的数组几步共用，合计不超过 200 MB），撤销、重做直接换回；更早的从那一步影响到的那一层重算。
- **按内容缓存**：气候里和地形有关的那部分（风、水汽输送图、洋流）、汇流，地形没变就不重算；星球气候分层缓存（只取决于纬度的、只取决于海陆的各留两份）；地物识别按地形缓存，只改气候时不重找陆块、海、山脉。
- **只算变了的**：重画一片只重算圈里的格；高程按陆块复用（没改过的陆块原样留着）；离海岸、离河的距离场从上一份改起；省份只修补变了陆海的格、起名线性；生态脚本按格记住结果，只重算输入变了的格；生成器的采样按网格缓存。
- **内核**：噪声内核去掉闭包，高程的噪声因子按网格缓存；汇流路由（`core/routing.ts`，Priority-Flood 填洼后按最陡下降，结果无环）的缓冲区在迭代间复用；约束求解试算不分配对象；类型化数组的堆（`core/heap.ts`，优先级相同时先进先出，平地上的顺序可复现）。
- **画面**：平移、缩放时半分辨率画、挪用带边距（0.35）的场景，渲染器的场景、叠加层的河、地名在同一帧重建（`motionEpoch`），停下 250 毫秒补全分辨率并分两帧做（这一帧地图、下一帧叠加层）；移动中海岸线按场景放大的倍数淡一些、颜色按同一个场景像素取，省界、轮廓按画面像素补偿，深浅与停稳时一样；缩小到一格不到 6 像素时河沿中线分档缓存（Path2D 每加一个点约一微秒），放大后只加看得见的河；着色器不算看不见的细节；河的图层（overlay.ts 的 `riverLayer`，停稳与移动中各一张）画成一张离屏画布，渲染器上传成纹理、在合成着色器里按每像素的陆海混进去（只在陆地上，排在省界、高亮之前；`version` 变了才上传，导出每块另画 `riverLayerTile`）；省份着色、省界、高亮取格用合成着色器的 `provCell`，与 core/display.ts 的 `provinceCell` 同一条规则（水面像素只取水面格；陆地像素取到水面格时改取 `PROVINCE_LAND_RING` 上第一个陆地格，再没有时取 `island-types.ts` 的 `landProvinceCells` 表——每个水面格、小礁离它最近的陆地省的格，CPU 上沿网格一圈圈找，上传成 `uLandCell` 纹理；导出 `subcell.ts` 的 `rasterizeWorld` 用同一张表）；高程纹理两个通道（`packElevation`：高程与 colors.ts 的 `shoreElevation`——陆地格上是挨着的水面里最浅的高程），水下的水深、浅水只按第二个通道插值；改完后的闪烁不每帧重画整张图；编号层用不读纹理的顶点着色器；MapView 不在每帧查 DOM。
- **投影（整个星球的等面积、球形）**：镜头的 x、y 在投影平面上（`projection.ts`，等距圆柱时镜头上没有 `proj`，走原来的路，逐像素不变）。编号层、地形层、切线层照旧画成等距圆柱的一块“场景”（`sceneNeed` 按画面上 25 × 25 个点反算出要的范围与东西、南北两个方向的密度，密度按 2^¼ 取整，受纹理边长与像素总数所限）；合成着色器（`FS_COMPOSE_PROJ`，由星球的合成着色器替换出来）每个像素按投影反算回世界坐标再到场景上取，省界、轮廓看的相邻像素、0.6/1.2 格的圆圈都在世界坐标上，一格合几个像素按这个像素自己的比例。看得见整个半球、或者看得见极点时场景是整圈经度（转动球只重新合成，每帧约 3 ms）；放大后只画看得见的一块，现在的场景还盖得住、密度够（移动中五折、停稳九折以上、不密过 2.2 倍）就照用。球形看着极地（纬度 20° 以上、画面上有离极点 30° 以内的地方）时场景改成以极点为中心的等距方位投影，用球面上真正的三角形与 Voronoi（`polarGeometry`，只取离那一极 0.95 以内的），格的坡度在顶点换到那个平面上的方向再插值——等距圆柱的显示三角网在极点附近横跨很宽的经度，投影到球上会成放射状的条纹。河的图层画在场景那一块上（`riverLayerScene`，极地的场景逐点换算），合成时按场景上的位置取。叠加层另画（`overlay-proj.ts`：点按投影算，线沿大圆加密后逐点投影，球的背面、等面积的左右两边断开）。工具只经过 `env.zoom`（`effectiveZoom`：投影正中的比例）与指针（`screenToWorld` 反算，投影之外给边上的一点、不在地图上；极地的场景时按 `nearestCell` 取格）。
- **还慢的**：改海陆时整个星球的洋流、风、地名，要更快得多线程计算（见“待办”）。

## 文件结构

- `core/`：纯计算，不依赖 DOM，Node 与浏览器共用
  - 网格与几何：`mesh.ts` 网格（平面、球面两种）；`sphere.ts` 球面网格（斐波那契撒点、球面 Delaunay、显示用的三角网、最近格）；`mesh-pack.ts` 网格的打包与拆包；`geo.ts` 整个星球的几何（经度绕回、球面距离、大圆、球面上的圆）
  - 地形：`generate.ts` 随机世界（地壳高度、板块、火山锥）；`planet-gen.ts` 整个星球的生成器（球面上的板块、大陆块、热点岛链）；`planet-form.ts` 星球形态的格式；`terrain.ts` 组合地形、画笔、放岛、岛链（`fillSeaPockets`：陆地围住、不挨地图边、不超过 `POCKET_MAX` 格的海块并回陆地，环礁潟湖除外（`lagoonTest`：记着 `LAGOON_BIT` 的海格）；`landAfter` 按同一规则给预览；放岛只添陆地；放岛按种类的形状、高低、岩石长出陆地，并在 `StampResult.types` 里给出要记的种类）；`island-types.ts` 岛的种类（第十四轮：内置的大陆岛、低平岛、珊瑚岛、小礁与 `small.islandTypes` 里自己的，编号、`provinceLand`——省份按格分陆海时归海省的岛算海、`landProvinceCells`）；`elevation.ts` 抬升-侵蚀稳态（`finishElevation` 里 `pocketLakes` 三格以上的并回小块挖成湖；第十四轮去掉了 `volcanoes`，`lagoonFloor` 按潟湖的标记挖浅）、海底（`seafloor`：按只走海格的离岸距离给大陆架、坡折、陆坡、陆隆，洋底目标深度来自生成器的 `sea` 分量与 `terrain.ts` 的 `seabedFields`；输入逐字节相同时用上一次的结果，改了一小片海陆只重算离改动约 1500 km 以内的格，与整个重算逐位相同）与湖底（`lakeBedShape`）；`routing.ts` 汇流路由；`stats.ts` 地形统计量（测试与 `tools/terrain-stats.ts` 共用）
  - 气候与水：`climate.ts` 日照温度、风带季风、山挡风、水汽输运；`planet-climate.ts` 整个星球的气候；`sphere-flow.ts` 球面上的输送（绕星球一圈的风带不剪断）；`ocean.ts` 简化洋流与海面温度；`hydrology.ts` 填洼汇流、湖、径流；`rivers.ts` 河流折线（第十二轮：河口在画面上的岸线上，`riverRibbon` 是河画出来的带子：加密、宽度平滑不减、源头收尖、河口张开、画的时候才加的细小弯曲，屏幕与 `rivers.bmp` 共用；第十三轮：`normalMouth` 河口沿岸线法向进水、最后 1.5 格不急转（`maxTurn`），`tidyMouths` 去掉海岸边的源头小河、挤在一起的河口小的沿岸挪开（`shiftMouth`）或接得顺时并进大河（`mergeMouth`），`branchStart` 分出去的一股顺着干流分出来）；`river-pack.ts` 地图上的河在计算 Worker 里描好打包（河线与带子几块连续的数组，随快照、预览世界转交，主线程 `overlay.ts` 的 `seedRivers` 拆开直接用，与主线程描的逐位相同；描河读的东西按内容没变时用上一次的）；`display.ts` 画面上的一点画的是哪一格，以及画面上的海岸场（`displayCoast`：湖面取负，着色与河口共用；`shoreCrossing` 找画出来的岸线）
  - 水体类型：`water-types.ts` 河流类型、湖泊类型共用的部分（格式里相同的几项、只能有 match 的脚本、改了哪几项从哪一层重算、岸边的远近）；`river-types.ts` 河流类型（每格是哪一种河、河岸场）；`lake-types.ts` 湖泊类型（每个湖是哪一种）；`effects.ts` 生态、河湖对周围冷暖干湿的影响
  - 生态：`species.ts` 生态类型（色块 + 条件 + 耐受曲线）；`vegetation.ts` 适宜度 / 竞争 / 扩散 / 长在哪里（只在某个岛上、圈的范围里、不自然生成）/ 不计水体类型的一遍植被（baseBiomes）；`constraints.ts` 涂生态的反推与“没涂成”的原因、“就这样”；`biome-look.ts` 生态在地图上的样子（颜色脚本、花纹与发光的算式，屏幕与缩略图共用）；`biome-scripts.ts` 生态的脚本在世界上运行
  - 地名：`features.ts` 地理要素识别（用户圈的地名区块也在这里变成地名，前后地物配对留名字）；`names.ts` + `packs/zh.json` 文字包命名

### 金标准与逐值不变的规则

- 提速、重构后结果必须逐值不变：`npm run golden` 必须过，每项提速另加一组新旧对照。
- 第九轮去掉旧存档兼容时，金标准和各项逐值测试统一重录了一次；之后的优化必须与它们逐值相同。
- Node 与浏览器要逐值一致：`tools/hash.ts` 打出各层的哈希，用来对照。

## 速度

Node 里实测（第七轮前 → 后；浏览器里多约 0.05–0.1 秒的传输与重画）：

| 操作 | 一块地区（4 万格） | 整个星球（10 万格） |
|---|---|---|
| 改海陆（真改了海陆的一笔） | 0.75 → 0.48 秒 | 2.4 → 1.75 秒 |
| 只改冷暖干湿 | 0.37 → 0.08 秒 | 1.24 → 0.22 秒 |
| 撤销、重做 | 约 0.7 秒 → 几毫秒 | 约 2.2 秒 → 十几毫秒 |
| 重画这一片 | 0.9 → 0.33 秒 | 4.7 → 1.4 秒 |
| 新建 | 1.5 → 1.2 秒（网格另快约 3 倍） | 5.2 → 3.2 秒 |
| 重新打开（重放；有检查点时更快） | 2.5 → 0.95 秒 | 9.9 → 3.8 秒 |

| | 以前 | 现在 |
|---|---|---|
| 平移、缩放每帧 | 38–50 ms | 3–6 ms（移动时半分辨率，停下 150 ms 后补清楚） |
| 拖画笔每帧 | 46 ms | 17–19 ms |

## 已知限制

- 撤销只存最近几步的结果，再往前撤销要重算；排队的笔画各算一遍，画得很快时要等它们一笔一笔算完。星球上一次确切预览要几秒，太久的不自动算。
- 一块地区：东西不相接，“地图在星球上的位置”只能整体南北挪，南北跨度由建世界时的大小决定；最多约 4 万格（放大到最大时一格约 64 像素）；没有洋流。
- 整个星球的等距圆柱图两极附近被拉宽（可以换成等面积、球形投影看）；圈一片、圈地名不能绕着极点画。投影里风向、洋流、参考图不画；极地场景里虚线、双线、发光的河按实线画，导出按投影的大图受显卡纹理大小所限会软一些。
- 气候是简化的过程模型，不是 GCM：洋流是全年平均的表层流（没有深层洋流、海冰、年际变化）；季风只按大尺度海陆分布估计。
- 导出的 `terrain.bmp`、`rivers.bmp` 用的是通用配色，导入具体游戏前需要按其调色板重新映射。
- 画河、改河拖动时先画估计的样子（改的这条河按将来的样子画、会变干的河段是估计的），停一下才换成将来的整个世界；星球上要停 0.7 秒以上、算几秒。松手用的是确切的。
- 选中的自然的河的控制点取画出来的曲线化简后的点；拖一个控制点时它两边的弯曲跟着转、拉长缩短，弯点很稀时形状会比原来直一些。
- 脚本：隔离靠浏览器，不支持的浏览器上脚本在普通线程里跑；隔离时页面规则仍许连这个程序自己的网址（同源）；脚本照样能拖慢电脑、占内存。花纹、发光的着色器在个别显卡上编译不过时不另外提示。星球形态的脚本出错时提示条上没有“编辑”。
- 量距离量的是直线（星球上是大圆弧），步行天数按每天 30 km，不绕山、不绕海。
- 参考图只能“保持比例放在中间”或“拉伸铺满”，只存在这个浏览器里。
- 世界和“我的地图”只存在这个浏览器里，按网址分开；换浏览器、清数据就没了，要靠导出世界文件。
- 人文内容（城镇、文化、国家）和省份的上级层级、自定义属性还没做；“放地名”只是一个带名字的点。
