# 开发说明

给改代码的人看：程序怎么搭起来的、文件在哪里、怎么测、哪些规则不能破、现在有多快、还差什么。用法见 [使用说明](使用说明.md)，每一轮改了什么见 [更新记录](更新记录.md)。

## 常用命令

```bash
npm install
npm run dev        # 开发服务器，默认 http://localhost:5173（.claude/launch.json 里用 5191）
npm test           # 全部测试
npm run test:fast  # 改代码时常跑的那部分（跳过最慢的几个文件）
npm run golden     # 只跑金标准：提速、重构后结果必须逐值不变
npm run typecheck  # 只查类型
npm run build      # 查类型后打包（一键开启用的就是打包好的程序）
npx tsx tools/generate.ts --seed 3 --out out/seed3   # 命令行批量生成并导出
npx tsx tools/hash.ts                                 # 各层结果的哈希，用来核对 Node 与浏览器是否逐值一致
npx tsx tools/bench.ts [--globe] [--long]            # 加工的各步、各阶段的耗时：区域 4 万格，--globe 整个星球（类地 6.26 万格）；后面写格数可改
npx tsx tools/bench.ts --globe --pack fantasy --hash  # 整个星球 + 奇幻包逐步计时，最后打出世界的哈希
node tools/bench-median.mjs 5 -- --globe              # 跑五次 bench 取中位数
node tools/bench-median.mjs 5 --against main -- --globe --long   # 与 main 对照（见“测速与对照”）
npx tsx tools/realism-report.ts                       # 和地球比：6 个种子 × {半个星球的区域、类地星球}（见“和地球比”）
npx vitest run tools/realism.test.ts                  # 和地球比的区间（慢测试，约 40 秒；见“大格局与长河”）
```

浏览器控制台里 `await __map2Bench()` 测平移缩放每帧的耗时（`src/render/bench.ts`，按固定的镜头脚本同步地画，窗口藏着时也能测；只看同一台机器上的前后对照）。

一键开启（`启动-Mac.command`、`启动-Windows.bat` → `tools/launch.mjs`）：检查 Node 的版本；第一次（或 `package-lock.json` 改过）先装依赖；地图已经开着就只打开浏览器（代码在它打包之后更新过时提醒关掉重开）；否则先打包（源码没变时跳过），再用 vite preview 开在 http://localhost:5191，打包失败时退回开发服务器。地址固定是因为浏览器按地址保存世界。

## 架构

### 世界与流水线

- **世界的数据**（`core/world.ts`）分两类：**原因**是用户通过命令编辑的（陆海、抬升、岩性、气候微调、自定义场、省份归属，以及约束、河道引导等小对象）；**推导**是流水线从原因算出的（高程、气候、水文、植被、冲突）。
- **命令**（`core/commands.ts`，各类命令在 `core/commands/`）：zod 校验，是改世界的唯一入口；世界文件就是种子、设置加命令记录。
- **引擎**（`core/engine.ts`）：持有世界、命令历史与推导缓存。命令改原因 → 标记从哪一层开始重算 → 流水线：高程 → 气候（基础）→ [约束求解 → 修正场] → 水文 → 河的类型 → 植被 → 冲突检查 → 人文的几层（第二十一轮：地形类别、资源、山峰，见“地形类别、资源、格的档案”；第二十二轮：宜居度与人口的几层，见“时代、文化、人口”，挪到地物之前：地名跟着当地的文化；第二十三轮：国家的一层，见“国家与政体”；第二十四轮的城市、道路、地标不进推导，按世界现算，见“城市、道路、地标、自定义点”）→ 地物；地名、省份随后按变了的格修补。执行、撤销整步生效，中途出错回到原样。
- **重算到哪一层**（`commands.ts` 的 `Dirty`）：None < Names（只重新起名）< Human（第二十一轮：只重算人文的几层，再重新起名；自然的推导一个不动。第二十二轮的人口、文化的编辑、生成人文都在这一层；单独一条的 Human 命令不整理湖省、名字变了的都是换了风格时不比地物留名字）< Vegetation < Solve < Climate < Elevation。Human 及以下的步不进撤销缓存（撤销时重算这一段，几十毫秒），Worker 对 Human 的步发只带变了的数组的快照（Names 及以下才发轻快照）。
- **气候的基础**按自然求解的高程算（含湖的碗，不含只挖河床的河），所以画河、改河不改气候和山名，也不重算高程与气候。
- **湖底**：放的湖在高程里挖（浅滩、湖盆、一两个深处，可以低于海平面）；自然的湖在水文、植被算完之后才按离岸距离修深（`hydrology.ts` 的 `shapeLakeBeds`，只改湖格的 `d.elevation`，不改水面与流向），每次重算都从地形重新来，所以与编辑历史无关。
- **岛的种类**（第十四轮）：每格记在原因里的 `causes.islandType`（Uint8；0 不是放的岛，1–5 内置的（第十八轮在最后加了碎岛），6 起是 `small.islandTypes` 的下标 + 6；环礁潟湖的海格另加 `LAGOON_BIT` 0x80）。放岛、岛链写在新长出的陆地与潟湖上；画陆地 / 海、恢复原样画笔中心七成以内的格清掉；`set_worldgen` 新世界清零。命令 `set_island_type`（新建或整份换掉，最多 64 种）、`remove_island_type`（这种岛变成大陆岛、后面的编号往前挪，潟湖标记不变）都记撤销（`islandType`、`province` 两个数组）。它和别的原因数组一样进检查点、撤销缓存、快照（`Object.entries(causes)`）；轻快照另带一份（删种类那一步只重新起名）。颜色（`colors.ts` 的 `lithLayer` 与 `cellLayers` 里自己选的颜色）、潟湖、归哪种省、起名（`features.ts` 的 `itype:` 标签）都按它，不再按可蚀性认。
- **破碎度**（第十八轮）：`causes.fragment`（Uint8，0–255，可选：第一次打碎、放碎岛时才建，撤销到那之前时 `UndoRecord.dropFragment` 去掉它，所以没打碎过的世界与以前逐字节相同，金标准不用重录）。只改**画法**：
  - 格以下的海岸（同一条公式写在 `subcell.ts` 的 `pointIsLand`、`rasterizeWorld`，`display.ts` 的 `displayCellAt`、`displayCoastAt`、`shoreCrossing`，着色器 `FS_TERRAIN`、`FS_TERRAIN_PLANET`、极地的那一份）：每格的破碎度 / 255 在三角形里插值成 fv；fv > 0 时 `s = clamp(sv, −D, D) + 海岸细节 + weight · 200 · q · m`（`subcell.ts` 的 `fragCoast`，着色器里是 `renderer.ts` 的 `FRAG_GLSL`）：q = 1 − (1 − fv)³，D = 260 → 20（插值的海岸值压近海岸线），m = clamp(|n|·3, 0, 1)·2 − 1，n 是一层更细的噪声（`fragNoise` / `fragNoise3`，每格 1.3 个噪声单位、3 个八度：|n| 大处冒出碎岛，零线是陆上的裂缝）。weight 与海岸细节相同（格心为 0），格心的陆海不变，气候、河流、生态照旧按整格算。fv = 0 的像素不走这里（与以前逐位相同）。碎岛的高度 `2 + 0.5·min(s, 60)`（边上一圈沙滩），破碎的海面水深 ×(1 − 0.85·fv)（只是画法）。
  - 海岸值纹理从 R32F 换成 RG32F：r 海岸值、g 破碎度（`packCoast`；`setLayers`、幽灵按行上传）；顶点着色器给 `vFrag`。按陆海判的那一套（`causes.land`，湖面算陆地）里湖面格的破碎度按 0（`fragLand`）；画面上的海岸场（`displayCoast().frag`）湖面照样有。缓存的键都加上了 `causes.fragment`（`displayCoast`、`colors.ts` 的 `staticLayers`、地物的 `terrain` 段）。
  - 颜色：破碎的格没有对岸时（四周全是海的碎岛、陆地中间的裂缝）对岸的颜色按 `colors.ts` 的 `fragColors`（往外 6 圈里最近的陆地 / 水面格的颜色，没有时按气候：冻原、沙地、草地，加雪）；只给破碎度 > 0 的格。
  - 省份：碎岛（画成陆地、落在海格里的像素）的格是 `island-types.ts` 的 `landPixelCells`：破碎的海格是它自己，离破碎的海格两步以内的海格是最近一圈里最碎的那格，别的照 `landProvinceCells`（没打碎过时就是它，同一个数组）。着色器的 `provCell` 先看扭曲后的格破碎不破碎（`fragCell`，纹理的 g），再照旧找附近的陆地格、最后 `landCellOf`；`display.ts` 的 `provinceCell` / `sameKindNear`、导出的 `rasterizeWorld` 同一个规则。悬停“这里”说“X 群岛 · 碎岛 · 浅海”。
  - 名字：破碎度 ≥ 64 的海格连成的每一片在 `features.ts` 的群岛分组里当一个“岛”（三步海路以内的岛、碎岛并在一起），组里碎岛格够 3 格就是群岛（`archipelago`，锚点在最大的岛上，没有岛时在最大的一片碎岛上）。
  - 命令：`fragment {cells, t, strength 0.1–1, mode: blocks | coast, size: 画笔半径 km}`（`terrain.ts` 的 `fragmentStroke`）。裂成碎块按裂缝图 `crackAt`（世界种子 + 格的位置：抖动格点的 Voronoi，平面按 (x, y)、星球按单位球面上的三维位置；碎块大小 `crackBlockSize` = max(3.5 格, 半径 · (0.7 − 0.35·力度))，裂缝半宽 `crackHalfWidth` = 0.6–0.95 格，外圈收窄），裂缝上的陆地 landness 压到 −(海岸噪声的幅度 + 60)（与画海相同），孤零零的单格陆地也成海；只打碎海岸只抬离岸 1–2 步的破碎度、不改陆海（`Dirty.Vegetation`：只重认地物）。放碎岛（内置的“碎岛”，形状 `frag`）是 `fragStamp`：一片按 `islandGeometry`（与不规则的岛一样的轮廓）抬破碎度，不改陆度、不记岛的种类；岛链的 `fragRatio` 按链上的编号（`chainFragAt`）把一部分岛换成碎岛。`restore_terrain` 按画笔权重退回破碎度（`restoredFragment`），画陆地 / 海与恢复原样画笔中心、陆海变了的格清零（`applyTerrain` 的 `clear`）。幽灵海岸的 `GhostEdit.frag` 带将来的破碎度（放碎岛、岛链、画陆地 / 海、恢复原样）；打碎用确切预览。
- **湖与省份**：湖是推导出来的，命令执行时还不知道。引擎在推导算好之后（`Engine.fixLakeProvinces`）按新的湖整理湖与陆地的省份，结果与撤销记录并进这一步，并记进命令（`provinceFix`），重放、重做时不用推导照着改。
- **预览**在世界的副本上执行（`core/preview-world.ts` 只带变了的数组），松手时直接采用，不再算第二遍。确切预览分阶段算，阶段之间可以停下：接着画、松手执行别的命令时不再等它算完（最多等一个阶段，通常 0.1–0.6 秒）。
- **随机**（`core/rng.ts`）：所有随机都从世界种子派生，按地图上的位置取、与格数无关，命令重放结果逐值一致。

### 线程与隔离

- **主线程**（`src/state.ts`，第七十轮起分在 `src/state/` 下、照旧从 `state.ts` 导出）：世界的只读视图（网格本地构建，原因与推导来自 Worker 的快照）加界面状态。与 Worker 的往来在 `state/worker-host.ts`（开 Worker、请求排队、换上快照），上面一层的预览、自动保存经 `hostHooks` 接回来，不绕成圈。快照只带变了的推导数组（只变了一片的只带那几格），只改了名字、省份时只把这些发回来；数组用 `transfer.ts` 转交、不复制。
- **计算 Worker**（`src/worker.ts`）：持有引擎。用户的脚本只在这里跑，主线程上只用 acorn 解析、不编译（`src/ui/script-syntax.ts`）。
- **隔离**：计算 Worker 尽量从 data: 地址开（`engine-spawn.ts`，代码来源见 `engine-source.ts`：打包好的程序里取 Vite 单独打包的引擎文件的文字；开发时由 `tools/isolated-engine.ts` 在开发服务器上现打包 `/__map2/engine.js`，开发时也隔离；不压缩，做成 data: 地址超长时（第二十三轮起内置的内容多了）才压缩；data: 地址最长 `DATA_URL_MAX`，第二十九轮放宽到 190 万字符，Chrome 的上限是 2 MB）。这样它没有来源、受页面 CSP 管，读不到 IndexedDB，也不能联网。开起来先自查三项（`isolation-probe.ts`：来源为空、打不开存档、页面规则管得到它），全过才说隔离了；在一个页面里隔离运行过以后不会悄悄换成不隔离的线程。取不到时退回普通 Worker（问话里照实说）。
- **存储 Worker**（`storage-worker.ts` + `checkpoint-store.ts`）：与页面同源、只做存储、从不运行脚本。检查点（星球约 34 MB，连同几千步的命令）不经过主线程：主线程开一条 MessageChannel，一头给存储 Worker、一头给计算 Worker；计算 Worker 写好检查点直接发给存储 Worker，另给主线程发步号，主线程核对与命令记录一模一样后才让存储 Worker 写下。
- **看护**（`src/sandbox.ts`）：看门狗只在脚本运行期间计时（Worker 每 250 毫秒报一次平安），4 秒没有消息判定卡住，电脑睡眠、后台节流不算；1.5 秒以上告诉界面（带“停下”）。主线程留一份完整的命令记录：卡住、停下、Worker 崩了时停掉它，正在等的请求都回失败，用检查点加命令记录恢复到这一步之前；恢复时又卡住就开安全模式。安全模式在一个 Worker 里从第一次新建、打开起固定，换模式时另开一个 Worker。
- **网格 Worker**（`mesh-worker.ts`）：新建、打开时在别的线程建网格，打包后转交（`core/mesh-pack.ts`，拆包得到与就地建的逐值相同的网格），并存进浏览器，下次直接读（键带上打包格式的版本）。最多等 6 秒，之后在主线程自己建。
- **导出 Worker**（`export-worker.ts`）：游戏文件包、整张地图的栅格化、编码、打包，进度发回顶部，可以取消。

### 内容、库与面板

- **内容种类**（`core/content/registry.ts`、`kinds.ts`）：每种内容一张字段表，引用表（`content/links.ts`）、导入、编辑器都从它来。计算 Worker 只有世界里的内容；内置的库（`core/packs/builtin-tree.ts`）只在主线程。
- **库和世界各是一份**：世界里的内容独立于库，`small.origin` 记每项来自哪个库的哪个小包，和来源的差异在 `core/packs/source-diff.ts`。融入（`content/arrange.ts`、库的 `arrange`）只改面板怎么显示，运行时的数据是平的。
- **进世界只有一条路**：资源库面板上的勾（第六十七轮起看库就是添加，没有导入窗口）、下拉里别的库的项、档案里换政体都走依赖闭包（`core/packs/closure.ts`），不留下找不到的引用；生成人文、新建世界是 `core/packs/import.ts`。
- **面板**（`src/ui/packs/LibPanel.tsx`，第五十九到六十三轮）：逻辑在 `pages.ts` 和 `page-*.ts`，所有页面从“看的是哪一份 + 世界和库”算出来，本世界和库只差数据和只读。世界走命令，我的库走 `src/library-edit.ts`（单项校验、日志、延迟写入、自己的撤销）。

### 界面的分层

- **声明与登记**（第六十九轮）：`src/ui/defs/` 只声明（工具表、类别、调整、图层），不引用面板和工具；底部条上的部件按名字登记（`defs/panel-registry.ts`），每个工具做什么由 `tools/bind.ts` 接上，`register-all.tsx` 把它们都引用一次。`state.ts` 不引用界面，`components/` 不认识世界，`.ts` 不引用 `.tsx`，界面里没有引用圈；第七十轮加：面板只经 `tools/api.ts`、`tools/public.ts` 用工具，抽屉里的档案也登记（`defs/archive-registry.ts`），界面只经 `state.ts` 引用状态，领域逻辑在 `src/ui/domain/`：规则在 [dev/ui.md](dev/ui.md) 的“分层”，`src/ui/layering.test.ts` 查着。
- **Esc**：`src/ui/shell/escape.ts` 的栈，各层自己登记，先后只看 `ESC_RANK`（`keys.ts` 只问最上面的一层）。

### 检查点与保存

- **自动保存**存在 IndexedDB（`src/idb.ts`，库是第 6 版），只写变了的那些命令；IndexedDB 用不了时退回 localStorage。
- **检查点**：引擎的完整状态（原因、推导、历史）。打开时直接恢复，不必重放所有命令。版本号：打包好的程序里是引擎文件的地址（文件名带内容哈希），开发时是引擎文件内容的哈希。
- **我的地图**（`src/maps.ts`）：IndexedDB 的 `maps`（列表要用的一小条：名字、时间、地区还是星球、格数、缩略图）与 `mapDocs`（整个世界文件）两张表，总在同一个事务里写；连着哪一张记在自动保存里。刷新后只是打开过的地图不再重写。
- **世界文件的版本**（`core/doc-version.ts`）：现在是 5，只认 5。单独放一个小文件，主线程打开文件、读自动保存时也要查，不必引进整个引擎。旧版本一律打不开、不去重放，代码里不留旧存档的写法。


### 缓存与性能（摘要，详见 [docs/dev/performance.md](dev/performance.md)）

- **结果逐值不变**：每一项提速都带“新旧算法逐位相同”的测试，金标准一个都不重录（见 [测试](dev/tests.md)）。
- **按内容缓存、只算变了的**：撤销缓存存最近几步的完整推导；气候、汇流、地物、高程（按陆块的记忆）、海岸值、描河的查询按输入的内容记下，只重算变了的格或块。
- **分层**：`Dirty` 决定从哪一层重算（名字 < 人文 < 植被 < 求解 < 气候 < 高程）；只改人文、名字的命令不碰自然的推导。
- **画面**：渲染器四遍里只重画变了的那几遍（编号、地形只在镜头、图层、窗口变了时）；合成着色器先判断再跳过；叠加层什么都没变时一笔不画；移动中半分辨率、挪用带边距的场景，停稳 250 ms 补全。
- **空闲预热**：Worker 空闲时分段把按网格的缓存先算好，有请求就停。
- **不能变慢**：`node tools/bench-median.mjs 5 --against <提交>`，任何一步超过 +5% 要压回去；画法的改动用 `tools/compose-ab.mjs`、`tools/overlay-ab.mjs` 逐字节对照。
